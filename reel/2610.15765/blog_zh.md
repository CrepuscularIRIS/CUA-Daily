# ANIS：为桌面应用合成对 agent 友好的命令接口

*CUA Radar 对 arXiv 2610.15765v1（Wu、Tao、Guo）的解读。这是第三方对论文所报告内容的总结，并非作者背书。海报：`poster.png`。论文：https://arxiv.org/abs/2610.15765v1 · 代码：https://github.com/co-evolve-lab/ANIS*

*关于范围的说明：这里的 agent 不读取截图。它们通过程序化接口（应用的 SDK，或生成的类 shell 命令）来操作桌面应用，所以这是关于接口设计的结果，而不是关于 GUI 感知的结果。*

## 问题：接口是为人类设计的，却由 agent 来使用

桌面应用通过 GUI 暴露功能，而 GUI 假定用户能看到并定位控件；SDK 则假定开发者能阅读文档、理解对象模型并调试低层调用。agent 得自己完成这些工作，而且大多数应用也没有通用的命令行接口（CLI）。论文问的是：什么样的接口对 agent 好用？它把软件演化当作一个天然实验：在不同版本之间，应用的功能大体不变，但接口在变，所以固定任务、agent 和验证器，只改变所安装的版本，就能把表现的差异归因于接口的变化。

## 论文做了什么

**DeskIF-Bench** 包含 6 个应用（Writer、Impress、Inkscape、Blender、QGIS、FreeCAD）、5 个领域的 255 个任务。其中 102 个来自 OSWorld 和 OpenComputer 的复用，153 个由一个“出题 agent”合成，这个 agent 拥有解题 agent 没有的技能或特权库。每个任务都有一个检查保存后产物的确定性脚本验证器，验证方式是确认它接受参考产物、并拒绝与任务相关的扰动产物。两个骨干模型 Claude Haiku 4.5 和 DeepSeek V4 Flash，在 OpenCode 脚手架里对每个应用的四个版本运行，成功率按 pass@3 衡量（三次独立尝试中只要有一次通过就算成功）。

**跨版本结果。** 最新版本在全部 12 个“模型—应用”序列中都优于最旧版本。QGIS 在 DeepSeek 上从 41% 升到 69%，在 Haiku 上从 33% 升到 65%；Impress 从 40% 升到 58%，以及从 33% 升到 52%。轨迹分析指向三个接口属性。**可发现性**：运行时能找到的、描述清晰的操作（QGIS 的运行时描述在版本之间每个函数增长了 20%）。**粒度**：与用户目标相匹配的操作，因而需要的低层调用更少（对 Haiku 而言，QGIS 每个任务的平均操作数从 30.4 降到 21.2）。**可观察性**：能够读回自己写入的状态，论文发现它在每个版本里都有限（有 581 条轨迹报告了完成，但保存下来的产物没有通过验证）。

**ANIS（Agent-Native Interface Synthesizer）** 把这些属性变成一个构建阶段和一个运行阶段，而不改动应用本身：

- **原子命令。** ANIS 在运行中的应用内部发现能力（已注册的操作、对象内省、菜单），让 LLM 为每个能力构建一次调用并执行，只保留那些效果在保存并重新打开产物之后仍然存在的命令。命令按产物对象分组，只要存在读取器，每个可写属性都会配上一条读命令。
- **目标级命令。** 从 agent 的轨迹中，ANIS 找出在至少三个请求里重复出现的命令子序列，检查它们是否实现了一个共享的产物级子目标，只有在于源产物的干净副本上重放能复现保存后的状态，才把它们作为具名命令发布。

ANIS 和基线 CLI-Anything 的接口，都是用 Claude Code 配合 Claude Opus 4.8 生成的。在 CUA Radar 板上，这篇论文属于 K29 模式，即 planner 与 grounder 的接口。

## 论文报告的结果

扩展后的基准加入了 76 个 Calc 任务和 37 个 GIMP 任务（共 368 个任务、8 个应用）；Calc 和 GIMP 在方法开发中被排除在外。总体成功率（%）和每个任务的在线 token 数：

| 接口               | DeepSeek V4 Flash | Token | Claude Haiku 4.5 | Token |
|--------------------|-------------------|-------|------------------|-------|
| 原生 SDK           | 68.5              | 84.4K | 61.4             | 85.0K |
| CLI-Anything       | 17.4              | 67.0K | 15.8             | 67.0K |
| ANIS，原子命令     | 72.3              | 22.6K | 64.9             | 23.0K |
| ANIS，加目标级命令 | 74.5              | 21.2K | 67.4             | 22.0K |

论文报告相对原生 SDK，在 DeepSeek 上 token 减少 73.2% 和 74.9%。在 DeepSeek 上逐个应用来看，ANIS 在 QGIS（77.8 和 81.5 对 68.5）、Writer（89.3 对 76.8）、GIMP、Calc、Impress 和 Inkscape 上高于原生 SDK，但在 Blender（45.7 和 51.4 对 54.3）和 FreeCAD（77.4 对 96.8）上低于它。

## 论文自带的对照说明了什么

**CLI-Anything 为什么这么低。** ANIS 暴露的命令数量超过它的 20 倍，CLI-Anything 失败的任务中有 98.7% 被归因于缺少命令。对于 ANIS 自己在 FreeCAD 上的差距，28.6% 的失败是缺少所需的命令；论文解释说，FreeCAD 和 Blender 的操作依赖隐含的对象关系，更难自动验证。

**观察命令。** 在 DeepSeek 上，通过指令禁止使用观察（读取）命令，会让总体成功率从 72.3 降到 60.3，下降 12.0 个百分点；Calc 从 63.2 降到 32.9，Writer 从 89.3 降到 69.6，而 GIMP、Impress 和 Inkscape 没有变化。对轨迹的审计没有发现被禁止的命令被使用。

**目标级命令。** 在 8 个应用上共合成了 10 个命令；它们使 Blender 的成功率提高 5.7 个百分点，Calc 提高 5.2，QGIS 提高 3.7，其余五个应用不变。在另一个 7:3 的划分上（258 个训练任务、110 个留出任务），由训练轨迹合成的 7 个命令，把留出任务的成功数从 110 个中的 64 个提高到 67 个（58.2% 到 60.9%）。

**文档。** 给使用原生 SDK 的 agent 提供离线的官方文档，对总体成功率的影响是：Kimi K2.5 为 +1.4，Haiku、DeepSeek 和 Claude Opus 4.6 分别为 -1.1、-1.7 和 -1.9，所以论文报告没有一致的收益。

## 证据偏薄之处

- 论文对每个设置只报告一个成功率：没有方差，而且 pass@3 是一个比较宽松的标准，三次尝试中只要有一次成功就算。
- token 数字统计的是任务 agent 的在线使用量。用 coding agent 为每个应用生成接口需要 17.1 到 36.4 小时，这部分成本不在 token 对比里。
- 目标级命令的主要结果使用的命令，是从被评测的同一批任务中挖掘出来的；CUA Radar 的记录标注了这种重叠（反模式 AP5），而留出划分上的提升更小（110 个任务中多 3 个）。
- 观察命令的消融只在一个骨干模型上做，而且是通过指令而不是真正移除这些命令。
- ANIS 在 Blender 和 FreeCAD 上低于原生 SDK。
- 任务、验证器和接口都是在 LLM 的协助下构建的，论文在其 AI 使用声明里承认了这一点。

## CUA Radar 的解读

CUA Radar 给这篇论文打 **66 分（★★）**，证据等级 **online**。记录认可：在真实应用上做的、以产物为准的验证，两个骨干模型，两个基线接口，观察命令的消融，经过验证的验证器以及已发布的代码。它标注了构建目标级命令所用数据与评测之间的重叠（AP5），把 held-out 评测和预算匹配记为 partial，把方差记为未报告。CUA Radar 没有重跑任何实验；本文所有数字都来自论文（版本 v1）。
