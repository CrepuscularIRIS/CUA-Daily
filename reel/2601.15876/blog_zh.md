# EvoCUA：用自带检验器的合成任务训练桌面智能体

*CUA Radar 对 arXiv 2601.15876v2（Xue、Peng、Huang 等；美团及合作单位）的解读。本文是第三方对论文所报告内容的整理，并非作者背书。海报见 `poster.png`。论文：https://arxiv.org/abs/2601.15876v2 · 代码：https://github.com/meituan/EvoCUA*

## 问题：静态轨迹的收益在递减

原生 computer-use 智能体大多靠模仿固定的交互记录数据集来训练。论文认为，这种被动模仿很难捕捉长程电脑任务中的因果动态，继续堆静态数据的边际收益在下降。要改为从交互中学习，论文指出三个障碍：合成的任务常常不可行（智能体为不可能的目标写出看似合理的计划）；大规模交互需要支持异步沙箱 rollout 的基础设施；不加约束的探索代价过高，必须把训练集中在策略能力边界上的任务。

## EvoCUA 是什么

EvoCUA 是一个原生桌面智能体。它唯一的感知输入是截图；论文在上下文中保留最近 5 张截图，更早的历史压缩成文本。每一步它先写一段推理，再从统一动作空间（Table 6）中选一个动作：基于坐标的鼠标动作（移动、单击、双击、三击、拖拽、滚动）；键盘动作，包括分开的 `key_down` 和 `key_up`，因此可以按住 Shift 之类的修饰键；以及两个控制原语：`wait` 和带成功/失败状态的 `terminate`。它在 CUA Radar 板上的模式是 K13（checker-first 任务合成），属于“把奖励建立在可执行检验器上”这一族。

方法由四部分组成。

1.  **Verifiable synthesis（可验证合成）。** 一个 VLM“任务架构师”接收（角色、能力、资源）三元组，同时写出任务指令、ground truth 和可执行的验证器代码。代码在真实沙箱里运行，报错信息回灌给模型，直到能够执行。随后过滤任务：用参考智能体 rollout，比较奖励模型与评估器给出的通过率，对两者差异显著的任务做人工抽查。三重 decontamination 会去除与基准查询语义等价的指令、应用初始化配置相同的任务，以及与现有评测脚本重叠的评估器。论文称最终得到数万条可验证数据。
2.  **基础设施。** Docker 内嵌 QEMU-KVM 虚拟机，定制的 Ubuntu 22.04 镜像（修正键位映射、注入字体），异步网关加分布式调度器。论文称一分钟内可拉起数万个沙箱，稳定支撑超过 100,000 个并发沙箱。
3.  **Cold start 之后做 RFT（rejection-sampling fine-tuning）。** 约 1k 条轨迹，推理由 hindsight 方式生成（目标澄清、观察摘要、终止前自检、反思），用来确立动作空间和输出格式。RFT 只保留成功的 rollout，用 pass@k 引导的调度分配 rollout 预算，把算力集中在边界任务上，并用 judge 模型屏蔽冗余步骤。
4.  **Step-level DPO。** 对失败轨迹，找出它在与成功参考轨迹状态功能等价的前提下首次偏离的那一步，在该步构造偏好对（选中动作对被拒动作），并在下一步构造第二个偏好对：偏好显式反思而不是盲目继续。随后用改进后的策略重复 RFT 加 DPO 的循环。

所以训练信号是生成的验证器对最终环境状态给出的稀疏、二值、结果级判定，加上失败对成功的偏好对。论文使用的基座是 Qwen3-VL-Thinking（8B、32B）和 OpenCUA（7B、32B、72B）。

**在线（OSWorld-Verified，pass@1，Table 1）。** 步数预算写在表里，各行并不相同。

|-----------------------|----------|-----------|
| Qwen3-VL-8B-Thinking  | 100      | 30.6%     |
| Step-GUI-8B           | 100      | 40.2%     |
| **EvoCUA-8B**         | 50       | **46.1%** |
| Qwen3-VL-32B-Thinking | 100      | 41.0%     |
| OpenCUA-72B           | 100      | 45.0%     |
| UI-TARS-2-2509        | 100      | 53.1%     |

论文写明：EvoCUA-32B 比 OpenCUA-72B 高 11.7，比 UI-TARS-2-2509 高 3.6，在同为 50 步的预算下比 Claude-4.5-Sonnet 低 1.4；EvoCUA-8B 为 46.1%，Step-GUI-8B 为 40.2%，论文称两者起点是同一个 Qwen3-VL-8B 基座。

**离线（grounding 与通用能力，Table 2；与上表不可比）。** 对 OpenCUA-72B 基座，训练后论文报告 ScreenSpot-v2 93.47、ScreenSpot-Pro 63.24、OSWorld-G 67.65，对比 OpenCUA-72B 的 92.90*、60.80* 和 66.95。32B 模型情况不同：ScreenSpot-Pro 为 49.76，Qwen3-VL-32B-Thinking 为 57.10*；MMMU 为 68.11，对比 78.10*。8B 模型的 ScreenSpot-v2 为 85.21，对比 90.09。（带 \* 的值是论文从其他公开报告中引用的。）论文把 32B 的下降归因于其非 thinking 的通用数据与 thinking 风格基座不匹配，并指出输出变短（2,514 对 3,620 个 token）。

## 论文自带的对照实验

**组件消融（Table 3，32B）。** 相对上一阶段的绝对增益：统一动作空间 +4.84，cold start +2.62，RFT +3.13，offline DPO +3.21，第二轮 RFT 加 DPO +1.90。表中没有说明所用基准，也没有给出基础分数。五项增益之和为 15.7‡，而 Table 1 对基座模型给出 56.7 − 41.0 = 15.7‡；但论文正文写的是相对基座 +15.1，两者之间论文没有说明。

**第二个基座（Table 4，OpenCUA-72B）。** cold start +2.14，RFT +3.69，offline DPO +3.02，迭代训练 +1.82。完全不做 cold start、只做三轮 RFT 则是 +8.12。

**经验规模（Table 5，早期 OpenCUA-72B 迭代，仅 RFT）。** 第 1 轮 20k 样本：+2.61；第 2 轮 226k：+6.79；第 3 轮 1M：+8.12。作者指出，模型越强，对噪声的容忍度越低，因此数据质量和 on-policy 对齐会限制进一步扩展。

**Pass@k 与步数（Figure 6）。** 32B 模型在所有 k 上相对基座都保持正增益，在 k = 16 时达到峰值 +4.93。最大步数从 15 增加到 50，32B 模型相对其 15 步结果提升 +16.25。

**实践经验（Section 6.5）。** 作者基于一千多次实验、总计超过 100 万加速卡小时，报告：成功轨迹必须经过激进的步骤级过滤，否则会出现动作混叠和循环重复；轻量 cold start 优于重型 cold start；on-policy 数据很重要；terminate 正样本的密度需要校准。

## 证据偏薄的地方

- **预算与方差。** 论文自己指出，EvoCUA 的结果是在严格 50 步约束下取得的，而基线通常需要 100 步才能达到峰值。每个格子只有一个分数，没有随机种子或置信区间，并且论文说，即使 temperature 为 0，成功率也会因系统扰动而波动。
- **没有留出的应用划分。** Decontamination 去除与基准在语义、配置和评估器上的重叠；任务由浏览器、Excel、Word 等桌面应用合成，论文没有报告单独留出的应用集合。
- **检验器质量。** 验证器和奖励模型过滤通过沙箱 rollout 交叉验证，并对差异大的任务人工抽查；论文没有给出假阳性或假阴性率。
- **离线退步。** 32B 模型在多个离线基准上低于其基座，作者预计升级后的 thinking 风格通用数据集能解决这一点。
- **在线 RL 仍是初步工作。** Section 7 提出了一个步骤级策略优化变体（STEPO），并在图中与 GRPO 在 OpenCUA-32B 上做对比；作者说尚未进行充分的训练和基准评测。上面的 OSWorld 数字来自前述离线合成流水线。
