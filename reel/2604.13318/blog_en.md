# WebXSkill: skills that a web agent can both run and read

*A CUA Radar reading of arXiv 2604.13318v2 (Wang, Wu, Zhang, Zhang, Yao, Faisal, Peng, Qin, Nath, Lin, Bansal, Zhang, Rajmohan, Gao, Yao). This is a third-party summary of what the paper reports, not an endorsement by the authors. Poster: `poster.png`. Paper: https://arxiv.org/abs/2604.13318v2 · Code: https://github.com/aiming-lab/WebXSkill*

## The problem: skills are either readable or executable

The paper argues that existing skill formats leave a **grounding gap**. Textual workflows such as AWM describe what to do in natural language, but the agent still has to turn every instruction into concrete browser actions, which brings grounding errors back. Code-based skills such as SkillWeaver and WALT can be executed directly, but they are deployed as opaque calls: the agent cannot see the internal logic, so it cannot adapt or recover when execution fails halfway.

## What WebXSkill is

The agent is a web browser agent built on the browser-use framework. At each step it observes a textual description of the page (the accessibility tree) and a screenshot, and emits an action from a primitive set (click, input, scroll, navigate and so on) until it signals completion or the step budget runs out. Backbones are GPT-5 and Qwen3.5-122B-A10B (Int4), plus two smaller Qwen models in a side study. On the CUA Radar board the pattern is C19, accumulating reusable knowledge from agent runs, under experience and memory retrieval. In the paper’s setup the backbone LLM is used as is; no fine-tuning is described.

A skill pairs a **parameterized action program** with **step-level natural-language guidance**. Each skill has a name, description, typed parameters and action steps; every step carries a guidance string, an action type, a target-element reference and `{{param}}` parameters. Three stages produce and use skills:

1.  **Skill extraction.** An LLM reads trajectories from SynthAgent (synthetic tasks generated by exploring each target website; 2,500 for WebArena and 600 for WebVoyager), picks reusable action subsequences, abstracts concrete values into typed parameters, and writes guidance for each step. Candidates are de-duplicated online (name, Jaccard similarity, embedding similarity), and each kept skill is executed in a test environment and discarded if it fails to run.
2.  **Skill organization.** Skills are indexed in a graph whose nodes are generalized URL patterns (for example `gitlab/*/*/-/issues/*`). At inference the current page URL is matched to nodes, up to 20 candidate skills are surfaced, and skills whose target elements are not on the page are filtered out. Cross-site transfer uses embedding retrieval instead.
3.  **Skill deployment.** In **grounded mode** each skill becomes a callable tool (prefixed `fg_`) and the runtime replays its steps by matching elements against the current DOM; the guidance stays visible as a planning aid. In **guided mode** the agent activates a skill with `use_skill`, receives the steps as instructions, and carries them out with its own browser actions; automated execution is disabled, so it can re-plan if a step fails. A “mix” mode lets the agent choose.

The “training” signal is therefore the LLM’s abstraction of synthetic trajectories, filtered by whether the skill runs. The paper states that benchmark instructions, labels, outcomes and execution trajectories are not supplied to task synthesis or skill extraction.

## Results as reported

All results are **online** task success (%) with a **30-step budget** for every method. WebArena uses the 154-task cleaned subset on self-hosted sites; WebVoyager uses 11 live sites (four were excluded because of site changes or reCAPTCHA); Online-Mind2Web has 300 tasks, judged here with GPT-4.1, GPT-5.1 and WebJudge-7B. The paper reports no offline step or grounding accuracy.

**WebArena (Table 2, overall):**

| Method                   | GPT-5    | Qwen3.5-122B |
|--------------------------|----------|--------------|
| Vanilla (ReAct)          | 59.7     | 45.5         |
| Vanilla + MAP            | 63.0     | 47.1         |
| SkillWeaver              | 37.4     | 43.8         |
| WALT                     | 42.9     | 44.2         |
| **WebXSkill (Grounded)** | **69.5** | 48.7         |
| **WebXSkill (Guided)**   | 68.8     | **53.9**     |

**WebVoyager (Table 3, GPT-5):** Vanilla 71.9, MAP 74.4, WebXSkill grounded 86.1, guided 82.7, guided with only WebArena skills (“Guided + WA”) 85.1. **Online-Mind2Web (Table 4, GPT-5, GPT-4.1 / GPT-5.1 / WebJudge):** Vanilla 59.00 / 53.33 / 61.33; MAP 60.33 / 57.33 / 68.67; grounded 68.67 / 67.00 / 72.00; guided 67.33 / 63.33 / 70.00; Guided + WA 67.33 / 66.00 / 68.00.

Re-deploying SkillWeaver and WALT skills inside WebXSkill gives 59.7 and 62.3 with GPT-5. The paper states that grounded mode improves on Vanilla by 14.2 points and on MAP by 11.7 on WebVoyager, and that Guided + WA is 10.7 points above MAP there, with an 8.1% relative improvement over MAP on Online-Mind2Web. SkillWeaver and WALT were not run on the live-site benchmarks because their skills for live sites are not released and their acquisition pipelines are not feasible there. For the efficiency analysis, grounded mode averages 9.3 steps on WebArena (Vanilla 10.4, guided 10.5), with a skill usage rate of 70.8% of tasks and an invocation rate of 16.5% of steps.

The paper reports a **model-dependent deployment preference**: GPT-5 slightly favors grounded mode, while Qwen3.5-122B favors guided mode. The same split appears with Qwen3.6-35B-A3B (59.09 grounded vs 57.79 guided on WebArena) and Qwen3.5-9B (44.16 vs 49.35). Mix mode mostly picks grounded (97.1% and 96.2% of choices) and scores 66.2 and 42.2.

## What the paper’s own controls say

**Component ablation (Table 10, WebArena, GPT-5, grounded 69.5).** Without skill verification 55.2; without the skill graph (flat library) 59.1; without step guidance 60.4; with mix mode 66.2; with skills extracted from test-set trajectories 68.2. The paper concludes that verification contributes most, and that organization and guidance each add substantially.

**Retrieval (Table 9).** With the same 591-skill library, a flat search reaches 59.1, DOM matching 65.6, and the URL graph 69.5. The paper says DOM matching gains 6.5 points over flat and the graph adds another 3.9.

**Skills from other methods.** Inside WebXSkill, SkillWeaver and WALT skills gain 22.3 and 19.4 points on WebArena.

**Test-set leakage checks.** The synthetic-skill library (69.5) is compared with an oracle library built from test-set trajectories (68.2). In Table 9 the authors also remove 196 synthetic sources judged similar to test tasks, leaving 548 verified skills and 68.8. Growing the corpus from 25% to the full set takes the library from 105 to 591 skills and success from 62.8 to 69.5.

**Cross-site transfer.** Guided + WA uses skills extracted only from WebArena and reaches 85.1 on WebVoyager without target-site programs. The paper attributes this to step guidance surviving a change of website.

**Failure analysis.** Of failed WebArena trajectories, the paper attributes 38% to post-skill reasoning (the skill ran, the agent failed later) and 36% to no skill being invoked, and concludes that most failures come from agent-level decisions, not skill design.

## Where the evidence is thinner, in the paper’s words

- The skills are extracted by SynthAgent “on synthetic tasks for each benchmark website”, so the test websites are also the websites used for skill building. The held-out evidence is the cross-site Guided + WA result, which is reported for GPT-5 on WebVoyager and Online-Mind2Web.
- The tables report single numbers with no seeds, runs or standard deviations. WebArena here is a 154-task subset.
- SkillWeaver and WALT are compared only on WebArena; the live-site tables have only Vanilla and MAP as baselines.
- For Qwen3.5-122B the grounded result (48.7) is close to Vanilla (45.5) and MAP (47.1); the clearer gain there is in guided mode (53.9).
- The limitations section says the library inherits the blind spots of the synthetic data. Cost is reported as steps and skill counts only.
- Online-Mind2Web is scored by model judges (three of them); the paper does not report a human validation of those judges.

## CUA Radar’s read

CUA Radar scores this paper **81 (★★★)**, evidence level **transfer**. The record credits online evaluation on three benchmarks, strong baselines, a matched 30-step budget, a component ablation, and released code, and counts step efficiency as partial cost reporting. It marks the held-out question as partial because skills are built from synthetic tasks on each benchmark site, leaves variance as unclear, and lists the judge check as untested. It also flags anti-pattern AP5, synthesis or exploration data overlapping the evaluation sites. The radar did not rerun any experiment; every number here comes from the paper (version v2).
