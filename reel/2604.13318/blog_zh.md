# WebXSkill：网页智能体既能执行、又能读懂的技能

*CUA Radar 对 arXiv 2604.13318v2（Wang、Wu、Zhang、Zhang、Yao、Faisal、Peng、Qin、Nath、Lin、Bansal、Zhang、Rajmohan、Gao、Yao）的解读。本文是第三方对论文所报告内容的整理，并非作者背书。海报见 `poster.png`。论文：https://arxiv.org/abs/2604.13318v2 · 代码：https://github.com/aiming-lab/WebXSkill*

## 问题：技能要么能读，要么能执行

网页智能体刚填完一个搜索表单，下一次遇到类似的表单，往往还得从头推理。近期工作用“技能”（skill）保存经验来缓解这一点，而论文认为现有技能形式存在一个 **grounding gap**。AWM 这类文本工作流用自然语言描述该做什么，但智能体仍要把每条指令翻译成具体的浏览器动作，grounding 错误随之回来。SkillWeaver、WALT 这类基于代码的技能可以直接执行，但以不透明调用的方式部署：智能体看不到内部逻辑，执行中途出错时无法调整或恢复。论文还指出，这些技能库通常以扁平列表的形式呈现，不管智能体当前在哪个页面。

## WebXSkill 是什么

智能体是基于 browser-use 框架的网页浏览器智能体。每一步它观察页面的文本描述（accessibility tree）和一张截图，从原语动作集合（click、input、scroll、navigate 等）中输出动作，直到宣告完成或步数预算用尽。论文用 GPT-5 和 Qwen3.5-122B-A10B（Int4）作为骨干模型，并在一个较小的实验中加入 Qwen3.6-35B-A3B 和 Qwen3.5-9B。在 CUA Radar 板上它属于 C19（从智能体自身运行中积累可复用知识），归在经验与记忆检索之下。论文的设置里骨干 LLM 是原样使用的，没有描述微调。

一个技能把**参数化的动作程序**和**逐步的自然语言指引**配成一对。每个技能有名称、描述、带类型的参数和一串动作步骤；每一步包含指引文字、动作类型、目标元素的引用（标签名、文本、HTML 属性）以及写成 `{{param}}` 的参数。三个阶段负责产生和使用技能：

1.  **Skill extraction（技能抽取）。** LLM 读取 SynthAgent 生成的轨迹（SynthAgent 通过探索各目标网站合成任务；WebArena 用 2,500 个，WebVoyager 用 600 个），找出可复用的动作子序列，把具体取值抽象为带类型的参数，并为每一步写指引。候选技能先做在线去重（精确名称、函数名的 Jaccard 相似度、再用 text-embedding-3-small 做嵌入相似度），由 LLM 决定新增、更新或跳过。保留下来的技能还要在测试环境中实际执行，跑不通就丢弃。失败的轨迹也会被挖掘，因为其中可能包含有用的子任务。
2.  **Skill organization（技能组织）。** 技能被索引到一张图里，节点是泛化的 URL 模式（例如 `gitlab/*/*/-/issues/*`）。推理时用当前页面 URL 匹配节点，每页最多呈现 20 个候选技能，目标元素不在页面上的技能会被过滤。跨站迁移时，智能体改用对技能描述和指引的嵌入检索。
3.  **Skill deployment（技能部署）。** 在 **grounded mode** 中，每个技能成为一个可调用工具（前缀 `fg_`），运行时把技能的步骤与当前 DOM 中的元素匹配并依次回放，指引仍对智能体可见，作为规划辅助。在 **guided mode** 中，智能体用 `use_skill` 激活技能，把步骤当作指令，用自己的浏览器动作去完成；自动执行被关闭，所以某一步失败时它可以重新规划。还有一个 mix 模式，让智能体自己在两者之间选择。

因此这里的“训练信号”是 LLM 对合成轨迹的抽象，再按技能能否跑通来过滤。论文声明，基准的指令、标签、结果和执行轨迹都没有提供给任务合成或技能抽取。

## 论文报告的结果

所有结果都是**在线**任务成功率（%），所有方法统一 **30 步预算**。WebArena 使用清理后的 154 个任务子集（自托管网站）；WebVoyager 使用 11 个在线网站（另有四个因网站变化或 reCAPTCHA 被排除）；Online-Mind2Web 有 300 个任务，这里用 GPT-4.1、GPT-5.1 和 WebJudge-7B 三个判定器评分。论文没有报告离线的单步或 grounding 准确率。

**WebArena（表 2，总体）：**

| 方法                     | GPT-5    | Qwen3.5-122B |
|--------------------------|----------|--------------|
| Vanilla（ReAct）         | 59.7     | 45.5         |
| Vanilla + MAP            | 63.0     | 47.1         |
| SkillWeaver              | 37.4     | 43.8         |
| WALT                     | 42.9     | 44.2         |
| WebXSkill + SkillWeaver  | 59.7     | 43.5         |
| WebXSkill + WALT         | 62.3     | 44.2         |
| **WebXSkill (Grounded)** | **69.5** | 48.7         |
| **WebXSkill (Guided)**   | 68.8     | **53.9**     |

**WebVoyager（表 3，GPT-5）：** Vanilla 71.9，MAP 74.4，WebXSkill grounded 86.1，guided 82.7，仅使用 WebArena 技能的 guided（“Guided + WA”）85.1。**Online-Mind2Web（表 4，GPT-5，依次为 GPT-4.1 / GPT-5.1 / WebJudge）：** Vanilla 59.00 / 53.33 / 61.33；MAP 60.33 / 57.33 / 68.67；grounded 68.67 / 67.00 / 72.00；guided 67.33 / 63.33 / 70.00；Guided + WA 67.33 / 66.00 / 68.00。

论文写明：在 WebVoyager 上，grounded 模式比 Vanilla 高 14.2 个点，比 MAP 高 11.7；Guided + WA 比 MAP 高 10.7 个点；在 Online-Mind2Web 上相对 MAP 有 8.1% 的相对提升。SkillWeaver 和 WALT 没有在在线网站基准上运行，原因是它们没有发布在线网站的技能，其获取流程在线上不可行。效率方面，grounded 模式在 WebArena 上平均 9.3 步（Vanilla 为 10.4，guided 为 10.5），技能使用率（UR）为 70.8% 的任务，调用率（IR）为 16.5% 的步骤。

论文报告了**与模型相关的部署偏好**：GPT-5 略偏好 grounded，Qwen3.5-122B 偏好 guided。Qwen3.6-35B-A3B（WebArena 上 grounded 59.09，guided 57.79）和 Qwen3.5-9B（grounded 44.16，guided 49.35）也出现同样的分化。mix 模式在 GPT-5 的决策中 97.1% 选 grounded，在 Qwen3.5-122B 中 96.2%，得分分别为 66.2 和 42.2。

## 论文自带的对照实验

**组件消融（表 10，WebArena，GPT-5，grounded 为 69.5）。** 去掉技能验证 55.2；去掉技能图（改用扁平库）59.1；去掉步骤指引 60.4；mix 模式 66.2；使用从测试集轨迹中抽取的技能 68.2。论文的结论是验证贡献最大，组织和指引各自也有可观的贡献。

**检索（表 9）。** 在同一个 591 个技能的库上，扁平搜索 59.1，DOM 匹配 65.6，URL 图 69.5。论文说 DOM 匹配比扁平搜索高 6.5 个点，图在此基础上再加 3.9 个点。

**别人的技能。** 把 SkillWeaver 和 WALT 的技能放进 WebXSkill 中重新部署，在 WebArena 上分别升到 59.7 和 62.3；论文报告提升为 22.3 和 19.4 个点。这是论文用来区分“智能体外壳”与“技能质量”的办法。

**测试集泄漏检查。** 合成技能库（69.5）与用测试集轨迹构建的 oracle 库（68.2）作对比。在表 9 中，作者还移除了被判定与测试任务相似的 196 个合成来源，剩下 548 个已验证技能，成绩 68.8。把合成语料从 25% 增加到全部，技能库从 105 增长到 591 个，任务成功率从 62.8 增长到 69.5。

**跨网站迁移。** Guided + WA 只使用从 WebArena 抽取的技能，在 WebVoyager 上达到 85.1，没有目标网站的程序。论文把原因归于：步骤指引在网站变化后仍然有效，而固定的动作脚本不行。

**失败分析。** 对 WebArena 的失败轨迹，论文把 38% 归因于技能之后的推理（技能执行成功，智能体后面出错），36% 是没有调用任何技能，并据此认为大多数失败来自智能体层面的决策，而不是技能设计。技能执行成功率因网站而异，Shopping 为 96%，CMS 低至 52%。

## 论文自己承认的薄弱处

- 技能由 SynthAgent“在每个基准网站的合成任务上”抽取，所以测试网站同时也是构建技能所用的网站。留出性证据是跨网站的 Guided + WA 结果，它是在 GPT-5 上、针对 WebVoyager 和 Online-Mind2Web 报告的。
- 表中都是单个数字，没有随机种子、重复运行或标准差。这里的 WebArena 是 154 个任务的子集。
- 技能类基线（SkillWeaver、WALT）只在 WebArena 上比较；在线网站的表里只有 Vanilla 和 MAP 两个基线。
- 对 Qwen3.5-122B，grounded 的 48.7 与 Vanilla（45.5）、MAP（47.1）接近；更明显的提升出现在 guided 模式（53.9）。
- 论文的 limitations 一节说，技能库会继承上游合成数据的盲区，URL 图主要为站内检索设计。成本以步数和技能数量报告，没有美元或延迟数字。
- Online-Mind2Web 由三个模型判定器评分；论文没有报告对这些判定器的人工验证。

## CUA Radar 的判断

CUA Radar 给这篇论文打 **81 分（★★★）**，证据等级 **transfer**。记录肯定了三个基准上的在线评测、较强的基线、对齐的 30 步预算、组件消融和已发布的代码，并把步数效率算作部分的成本报告。留出问题标为 partial，因为技能是在每个基准网站的合成任务上构建的；方差标为 unclear，判定器检验标为 untested。同时标出了反模式 AP5，即合成或探索数据与评测网站重叠。CUA Radar 没有复现任何实验，本文所有数字均来自论文（版本 v2）。
