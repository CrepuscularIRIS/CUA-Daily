# VideoAgentTrek：把 39,000 个无标注教程视频变成 computer-use 训练数据

*CUA Radar 对 arXiv 2510.19488v1（Lu、Xu、Wang、Wu、Wang、Wang、Yang、Su、Chen、Chen、Mao、Zhou、Lin、Hui、Yu）的解读。这是第三方对论文所报告内容的总结，并非作者背书。海报：`poster.png`。论文：https://arxiv.org/abs/2510.19488v1 · 代码：https://github.com/xlang-ai/VideoAgentTrek*

## 问题：演示数据是有的，标签没有

训练 computer-use agent 需要把截图和精确的动作配成对：点击坐标、输入的字符串。在这个规模上做人工标注非常昂贵。互联网上有大量录屏教程，人们在里面点击和输入，但这些录像没有结构化的动作标签：光标看得见却没有被追踪，输入的文字出现在屏幕上却没有被提取，每个动作的时间点是隐含的。论文要问的是：模型能不能把这些标签恢复出来，用它们训练 agent 是否有帮助。

## VideoAgentTrek 是什么

VideoAgentTrek 是一条数据管线加一套两阶段训练方案。它训练出来的 agent 是 Qwen2.5-VL-7B，输入是最近最多五张截图加上自己此前的思考和动作历史，输出一句简短的思考和一个动作（带坐标的点击、输入、滚动、按键）。论文报告这个基座模型在 OSWorld 上的成功率为 4.5%。在 CUA Radar 板上，它属于 R03 模式，即挖掘人类录屏视频。

管线分三部分：

1.  **收集与过滤。** 用种子查询和标签起步，当某个频道抽样的视频中至少 80% 质量合格时就扩展到整个频道，得到 55,000 个候选视频（约 10,000 小时）。ScreenFilter 是一个基于 YOLOv8x 的光标检测器，保留“至少 80% 的帧含光标且持续 6 秒以上”的片段；最终剩下 7,377 小时。
2.  **Video2Action，一个逆动力学模块。** 事件检测器（Qwen2.5-VL-7B，用 154 小时录屏和 OpenCUA 的交互日志做全参数微调）输入视频、不需要提示，输出带起止时间的 GUI 事件类型。第二个模型读取每个片段并预测参数（点击坐标、字面文本）。随后 GPT-5 Medium 根据动作、参数、动作前后的画面和周围的语音转写，为每一步写一段简短的“inner monologue”。
3.  **训练。** 应用到 39,000 个视频、平均每个约 39 步，得到 152 万步、约 260 亿 token。第一阶段是在这些视频轨迹上做一个 epoch 的继续预训练（加入少量 grounding 数据对）。第二阶段是在 80 亿 token 的人类轨迹（来自 OpenCUA 和 AGUVIS）上做监督微调，使用对话格式。

因此训练 agent 的信号是逆动力学模型产生的标签，然后是人类示范。第一阶段使用 32 张 H100，约 60 小时。

## 论文报告的结果

OSWorld-Verified 是 online 评测：真实桌面，369 个 Ubuntu 任务。AgentNetBench 是 offline 评测：100 个任务，按步评分。两者使用同一个 Qwen2.5-VL-7B 基座。

| 模型 | OSWorld-Verified，20 步（3 次运行均值） | OSWorld-Verified，50 步（1 次运行） | AgentNetBench 步成功率（offline） |
|----|----|----|----|
| 基座 | 4.5 | 未报告 | 38.5 |
| 只有第二阶段（SFT-only） | 9.3 | 9.27 | 64.1 |
| 第一阶段 + 第二阶段 | 14.13 | 15.78 | 69.3 |

摘要里的头条数字，15.8% 对 9.3%，相对提升 70%，比较的是单次 50 步运行和 SFT-only 的数字。在 20 步下，论文自己报告的是 14.13% 对 9.3%，提升 4.83 个百分点（相对 52%）。三次 20 步运行的结果，第一阶段加第二阶段为 14.68、13.57 和 14.13，SFT-only 为 9.42、9.13 和 9.42。

## 论文自带的对照说明了什么

**数据规模。** 使用 0%、50%、100% 的第一阶段视频 token，再做同样的第二阶段，得到 50 步下的 OSWorld-Verified 成功率为 9.3、13.3 和 15.7，AgentNetBench 步成功率为 64.1、68.1 和 69.3。

**步数预算。** 把预算从 20 步提高到 50 步，SFT-only 模型基本不变（9.3 到 9.27），带第一阶段的模型则从 14.13 提高到 15.78。论文把这归因于长视频轨迹（42.1% 超过 20 步，平均长度 39.25 步）。

**标签质量如何？** 在 23 小时的留出视频、20,282 个标注事件上，事件检测器的精确率为 0.88，召回率为 0.70，其中点击的 F1 为 0.82，拖拽为 0.62；按键较弱（精确率 0.40，召回率 0.08）。动作参数没有自动的真值，所以作者人工判断了 500 个真实视频上的预测：总体准确率 0.658，其中点击 0.713，滚动 0.735，输入 0.671，拖拽 0.366，按键 0.362。

## 证据偏薄之处

- 论文没有说明哪些 OSWorld 应用（如果有的话）被排除在训练之外；CUA Radar 的记录把 held-out 评测标为 unclear。
- 只有三次 20 步运行能给出波动范围，没有标准差或区间；50 步的结果是单次运行。
- 比较的是“只有第二阶段”和“第一阶段 + 第二阶段”。论文没有包含一个把同样的第一阶段 token 预算花在其他数据上的对照，所以数据规模曲线是说明视频标签作用的主要证据。
- AgentNetBench 和第二阶段使用的人类轨迹都出自所引用的 OpenCUA 工作（Wang et al., 2025b）；论文没有说明两者是否不相交。
- 标签质量参差不齐：人工检查的动作参数中有 0.658 被判为正确，拖拽和按键低得多。论文称这些参数“足够准确，可用于轨迹构建和下游训练”。
- 论文报告了训练的算力（例如第一阶段 32 张 H100、约 60 小时）和过滤器的吞吐量（每个 GPU 日约 840 小时视频），但没有给出整条标注管线的总成本。

## CUA Radar 的解读

CUA Radar 给这篇论文打 **68 分（★★）**，证据等级 **online**。记录认可：在 OSWorld-Verified 上做了 online 评测并对比了同基座的 SFT-only 基线、有步数预算对照、有数据规模消融、对事件检测器在留出视频上做了检查，并宣布开源工具；记录没有标注 flag，同时把 held-out 评测标为 unclear、方差标为未报告。CUA Radar 没有重跑任何实验；本文所有数字都来自论文（版本 v1）。
