# Hierarchical Memory Tree：把“任务需要什么”和“某个网站怎么做”分开存

*CUA Radar 对 arXiv 2603.07024v1（Tan、Gao、Wu）的解读。这是第三方对论文所报告内容的总结，并非作者背书。海报：`poster.png`。论文：https://arxiv.org/abs/2603.07024v1*

## 问题：被记住的步骤带着网站特有的包袱

web agent 常常把记忆存成过去成功的轨迹，也就是观察和动作构成的扁平序列。论文认为，这把两种寿命不同的东西混在了一起：高层的意图（订机票）可以跨网站迁移，而动作细节（点击按钮 `#btn-123`）则不能。在一个没见过的网站上检索出这样的轨迹，可能会让正确的意图配上根本不存在的元素。作者把这称为 intention-execution entanglement，并描述了两个后果：workflow mismatch（检索到的动作对源任务正确，但对当前阶段不对，例如在选定商品之前就点击结账）和 context pollution（冗长的原始轨迹挤占提示词）。

## HMT 是什么

Hierarchical Memory Tree（HMT）是一种记忆结构加一套推理流程；不训练任何模型。agent 读取简化后的 DOM 或 accessibility tree，对元素发出 CLICK、TYPE 等操作。在 CUA Radar 板上，这篇论文属于 K27 模式，即经验记忆检索。

**记忆构建。** 只从成功的轨迹出发，由 LLM 构建三层：

1.  **意图层。** 把原始指令改写成标准化的意图加约束，采用固定的 JSON 格式，这样同一请求的不同说法会共享同一个任务节点。
2.  **阶段层。** 把轨迹切成连续的子目标（“搜索航班”“筛选结果”），每个子目标带有可观察的前置条件和后置条件（“搜索结果可见”“价格筛选已应用”）。一致性检查涵盖覆盖度、顺序、连续性和最小长度；检查失败时，相邻片段会被合并。
3.  **动作层。** 每一步变成一个动作模式，配上语义化的元素描述（role、label、相对位置），而不是原始的元素标识符。

offline 时，记忆由一份成功轨迹数据集（Mind2Web 的训练划分）一次性构建。online 时，记忆从空开始，评测流中每一个成功的 episode 都会被抽象并加入。

**阶段感知的推理。** 检索是自上而下的：先找任务节点，再找子目标，子目标的打分混合了嵌入相似度和与当前页面的词面重叠（条件匹配的权重为 0.3）。Planner 抽象出当前页面，与检索到的子目标的前置、后置条件匹配，选出一个阶段并给出置信度。如果前两名子目标之间的差距或置信度偏低，它会扩大候选集；如果仍然不行，就回退到不带记忆的基础策略。然后 Actor 拿到步骤范例，利用其中的语义描述在当前页面上选出匹配的元素，而不是照抄 ID。所有组件的骨干都是 temperature 为 0 的 GPT-4。

## 论文报告的结果

**online：WebArena** 任务成功率（%），所有领域，总分是论文给出的加权总分。

| 方法 | 总计 | Shopping | CMS | Reddit | GitLab | Maps | 平均步数 |
|----|----|----|----|----|----|----|----|
| WebArena baseline | 14.9 | 14.0 | 11.0 | 6.0 | 15.0 | 16.0 | 12.4 |
| SteP | 33.0 | 37.0 | 24.0 | 59.0 | 32.0 | 30.0 | 8.5 |
| AWM | 35.5 | 30.8 | 29.1 | 50.9 | 31.8 | 43.3 | 5.9 |
| Flat Retrieval（作者的消融基线） | 32.1 | 28.5 | 25.8 | 47.0 | 28.5 | 39.0 | 6.5 |
| **HMT** | **38.7** | 33.8 | 34.1 | 52.5 | 37.6 | 42.2 | 5.2 |

HMT 在总分、CMS 和 GitLab 上最高；SteP 在 Reddit 和 Shopping 上更高，AWM 在 Maps 上更高，作者把后者归因于地图交互依赖空间坐标，文字描述的帮助较小。

**offline：Mind2Web** 步成功率（%）。

| 方法                | Cross-task | Cross-website | Cross-domain |
|---------------------|------------|---------------|--------------|
| MindAct             | 36.2       | 30.1          | 26.4         |
| AWM（offline 记忆） | 45.1       | 33.7          | 32.6         |
| AWM（online 记忆）  | 43.6       | 33.9          | 35.5         |
| **HMT**             | **48.5**   | **39.7**      | **37.1**     |

在训练中见过网站的 cross-task 上，论文说 HMT 与 AWM 相当；任务级成功率对所有方法都很低（HMT 在三个划分上分别为 4.6、3.2 和 1.9，offline 记忆的 AWM 为 4.8、2.3 和 0.7）。

## 论文自带的对照说明了什么

**消融。** 在 WebArena 总任务成功率上：完整版 38.7；去掉置信度回退 37.8；去掉前置/后置条件 36.2；使用原始元素标识符 34.5；去掉 planner 33.5；使用扁平记忆 32.1。在 Mind2Web 的 cross-website 步成功率上，使用原始标识符会把它从 39.7 降到 12.4。

**机制检验。** 在 Mind2Web cross-website 上，真值步骤的 Recall@5，HMT 为 84.2%，扁平检索为 65.8%。定位目标元素的成功率，使用原始标识符时在 cross-task 上为 92.1%，在 cross-website 上只有 12.4%，而使用语义描述时为 76.8%。

**效率。** 相比对原始 HTML 做扁平检索，平均上下文为 3,120 个 token 对 11,450 个，每步延迟 3.5 秒对 5.2 秒，每个任务成本 0.11 美元对 0.38 美元，尽管现在推理分成了两个阶段。

## 证据偏薄之处

- 论文报告的是单个数字：没有随机种子、标准差或区间，也只有一个骨干模型（GPT-4）。
- 基线的数字按表中印刷的给出；论文没有说明它们是否在相同设置下重新运行过，也没有报告预算匹配。
- 效率对比和消融基线，都是作者自己的扁平检索变体。
- Mind2Web 的任务级成功率对所有方法都很低，最强的提升体现在 cross-website 划分的步成功率上。
- 定性的失败包括：含糊的 grounding（一个泛泛的 “more” 描述匹配到了干扰按钮），以及在单页应用上期待 URL 变化的僵硬后置条件造成循环。
- 记录标注了数据重叠（反模式 AP5）；论文没有给出代码链接。
