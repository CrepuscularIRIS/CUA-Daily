# ExpSeek：只在自身熵升高时才去“求助经验”的搜索智能体

*CUA Radar 对 arXiv 2601.08605v2（Zhang、Zhang、Yu、Nie、Wu、Yue、Liu、Li）的解读。本文是第三方对论文所报告内容的整理，并非作者背书。海报见 `poster.png`。论文：https://arxiv.org/abs/2601.08605v2 · 代码：https://github.com/WYRipple/ExpSeek*

## 问题：经验只在任务开始前给一次

许多智能体会复用过往经验：存储的轨迹、提炼出的模式，或在线更新的记忆。论文观察到，这些方法大多把经验以全局上下文的形式被动注入，放在任务开始之前。智能体运行时观察不断变化，第一步之前写好的一段经验，到第六步未必还适用。作者还认为时机很重要：每一步都去取经验代价高，很少去取又会让困惑中的智能体得不到帮助。

## ExpSeek 是什么

这是一个网页搜索智能体，不是 GUI 智能体。它遵循 ReAct 循环：每一步先写一段 thought，然后调用工具或给出答案。它有两个工具：Search（搜索引擎，返回 URL 和摘要片段）和 Visit（打开 URL，返回由摘要模型压缩后的内容）。它只感知文本，通过工具调用和最终的 answer 标签行动。智能体为 Qwen3-8B 和 Qwen3-32B，使用非思考模式，temperature 为 1.0，top-p 为 0.95，ReAct 最多 30 步（超过即记为失败）。看板上的架构模式是 K27：把过往经验检索进上下文。

机制由三部分组成。

1.  **由“错误三元组”构成的经验库。** 对每个训练问题，智能体采样五次，并把成功与失败的轨迹配对。工具模型（Qwen3-235B-A22B-Instruct-2507）把失败轨迹与成功轨迹对照，给每一步打上对/错标签，并为每个错误步骤写一个三元组：Behavior（智能体看到并做了什么）、Mistake（哪里出错）、Guidance（指出方向，但不直接给答案）。三元组被归入主题（topic），process step 和 answer step 各有独立的库。训练集取自 WebWalkerQA 每个难度的 25%（170 个问题，随机种子 0），其余为测试数据。
2.  **熵触发器。** 每一步有一个 step entropy，即该步回复的平均 token 熵。在训练步骤上，论文发现正确步骤的熵低于错误步骤（Kolmogorov-Smirnov 统计量：process step 为 0.1998，answer step 为 0.3809），但 process step 的区分度较弱（AUC 0.6223），answer step 较好（AUC 0.7187）。对每种步骤类型拟合一个 logistic regression 得到决策边界，再做 1000 次 bootstrap 重采样得到 95% 区间。Table 1 给出了这些区间，例如 8B 的 process step 为 \[0.314, 0.413\]。推理时，熵低于下界则触发概率为 0，高于上界则为 1，中间线性上升。被引导过的步骤之后的下一步不会再被引导。
3.  **引导生成器。** 触发后，经验模型（同样是 Qwen3-235B-A22B-Instruct-2507）阅读历史，选出三个最相关的主题，并依据这些主题下的三元组，针对当前情形写出引导。对 process step，引导附加在工具返回之后；对 answer step，引导作为观察返回，智能体可以修改答案或继续调用工具。

整个过程不更新任何权重：智能体由自身输出的熵以及由带标签的失败案例库生成的引导文本所驱动。

## 论文自带的对照实验

**process 与 answer 步骤（Table 2）。** 只引导 process step，8B 为 36.59；只引导 answer step 为 39.06；完整 ExpSeek 为 41.50。32B 上分别为 40.81、41.20 和 45.32。论文报告的下降幅度为 8B 的 4.91 和 2.44、32B 的 4.51 和 4.12，并把仅引导 answer step 时下降较小，归因于 answer step 的熵区分度更清晰。

**触发方式对比（Table 3，Qwen3-8B）。** 在 GAIA 上，从第一步起持续干预、使用同一个经验模型的规则触发，准确率 38.81，每题 9.52 步、329.71 秒；用 Claude-sonnet-4 做 reward model 触发，准确率 39.47，8.55 步、370.82 秒；熵触发为 36.89，5.75 步、127.57 秒；无经验为 29.13，4.47 步、66.94 秒。论文将其解读为准确率相近而熵触发成本更低（按论文的说法，在 GAIA 上规则触发的步数和时间分别是熵触发的 1.7 倍和 2.6 倍）。需要注意，在 GAIA 上两个替代方案的准确率数字更高；在 xbench 上熵触发为 37.20，对比 36.40 和 36.60。用最相近的检索经验（text-embedding-v4）代替生成引导，GAIA 为 30.92，xbench 为 27.80。

**相对无引导的成本。** ExpSeek 比 vanilla ReAct 用更多步数和时间：在 xbench 上为 5.73 步、143.81 秒，对比 3.31 步、51.06 秒。每次引导还要运行一个 235B 模型，且除 30 步上限外，论文没有报告与基线对齐的计算预算。

**规模与迁移。** 用 4B 或 30B 的经验模型代替 235B 仍然有效；4B 模型在 GAIA 和 xbench 上分别把 32B 智能体提升 5.2% 和 9.7% 个点。互换 8B 与 32B 的经验库会损失准确率（32B 智能体使用 8B 的库，GAIA 为 40.33，xbench 为 37.20，对比 43.88 和 42.00）。论文称，每个主题只保留一条经验时，经验模型仍能保持较高准确率；完全移除经验库会使性能下降，但仍保留相当的准确率。

**Pass@3（Table 5）。** 平均 Pass@3，8B 为 61.89，32B 为 64.96，无经验时分别为 48.99 和 56.21。

## 论文自己承认的薄弱处

- 只报告了五次运行的均值，没有标准差或置信区间，因此从论文无法得知运行间的波动。
- 评分使用 LLM 评判，论文没有报告对该评判器的检验。
- 论文自述的局限：“The current threshold estimation relies on the training set and the tool model’s assessment of step quality; more accurate strategies need to be investigated.”（当前阈值估计依赖训练集和工具模型对步骤质量的评估，需要研究更准确的策略。）
- 经验来自 WebWalkerQA 训练题，所以其测试划分属于同分布；只有 GAIA、SEAL-Hard 和 xbench 是分布外。

## CUA Radar 的判断

CUA Radar 给这篇论文打 **73 分（★★★）**，证据等级 **online**。分数反映：真实网页基准上的评测、三个留出基准、更强的基线变体、步数与时间成本报告、process/answer 消融，以及已发布的代码。预算对齐被标为部分满足，方差和对评判器的检验均未报告。判定记录还标出了阈值对训练集和工具模型的依赖。CUA Radar 没有复现任何实验，本文所有数字均来自论文（版本 v2）。
