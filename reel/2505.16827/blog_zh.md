# GUI-explorer：免训练的手机智能体，自己探索应用并记下每次点击的效果

*CUA Radar 对 arXiv 2505.16827v1（Xie、Shao、Chen、Zhou、Li、Liu、Zhang、Nie）的解读。本文是第三方对论文所报告内容的整理，并非作者背书。海报见 `poster.png`。论文：https://arxiv.org/abs/2505.16827v1 · 代码：https://github.com/JiuTian-VL/GUI-explorer*

## 问题：模型并不了解这个应用

论文从多模态大模型手机智能体的两类失败出发：一是会误读 UI 组件，二是对应用的知识已经过时。文中的例子是 QQ Music 里的听歌识曲图标，GPT-4o 认错了，而熟悉该应用的用户一眼就能读对。应用本身也在频繁更新（论文引用 Amazon Shopping 在 2024 年有 30 个版本迭代），设计也各不相同（一个购物应用有购物车，另一个可能没有），所以每次变化都重新训练或微调模型，被论文称为代价过高。作者希望智能体不更新任何参数就能获得特定应用的知识。

## GUI-explorer 是什么

**智能体本身。** 这是一个 Android 智能体。每一步，GPT-4o 接收任务、截图、带编号框的同一张截图（来自无障碍树的 Set-of-Mark，简称 SoM）、元素列表和一段引导文本。动作通过 JSON 动作表给出，并按索引指向元素：click、long press、scroll、文本输入、keyboard enter、navigate home / back、open app、wait、answer，以及 complete / infeasible 状态。在 CUA Radar 板上它属于 C19，“从智能体自身运行中积累可复用的应用知识”，归在经验与记忆检索这一族下。

**阶段 1：以应用结构为锚点生成目标。** 系统读取应用的 manifest，收集开发者声明的 activity（例如音乐应用里的分享到动态、驾驶模式）。这些“探索锚点”连同当前截图交给 MLLM，由它提出至多 k 个候选任务。锚点的作用是避免模型提出指向不存在组件的任务。

**阶段 2：深度优先探索。** 每个任务最多执行若干步；然后环境恢复到父状态，再执行下一个兄弟任务。论文在 AndroidWorld 和 SPA-Bench 上都使用分支因子 10、最大深度 5、步数上限 30，由此自动得到 1,300 多条知识条目，覆盖 46 个应用。

**阶段 3：挖掘状态转移。** 对相邻两个观察以及之间的动作，抽取器输出一个 key（被操作 UI 元素的视觉图块）和一个 value（一小段文字，说明操作它会发生什么，如“点击该按钮会打开搜索历史”）。前后屏幕几乎相同的转移（用感知哈希判断）会被丢弃，因为这个动作没有效果。当 key 的嵌入几乎一致（阈值 0.99 及以上）且 value 不冗余时，新条目会并入已有条目。这一步不需要成功标签或奖励，只要求转移是有效的。

**阶段 4：测试时检索与排序。** 对当前屏幕上的每个 UI 元素，智能体用 SigLIP 嵌入检索相似的已存图块；随后 MLLM 对候选条目两两比较其与指令的相关性，再用归并排序把比较结果变成排序。排在前面的条目成为提示词中的“动态引导”（dynamic guidance）。

## 论文报告的结果

下表均为在线任务成功率（%），基座模型都是 GPT-4o；论文每格只给一个数值，没有种子数或置信区间。

| 智能体           | SPA-Bench 单应用英文 Level 3 | AndroidWorld（116 个任务） |
|------------------|------------------------------|----------------------------|
| AppAgent         | 14.0                         | 14.9                       |
| AutoDroid        | 12.0                         | 15.7                       |
| M3A              | 42.0                         | 40.5                       |
| Aria-UI          | 未列出                       | 44.8                       |
| **GUI-explorer** | **53.7**                     | **47.4**                   |

表 1 还列出 MobileAgentV2（20.0）、SeeAct（12.0）、CogAgent（0）和 DigiRL（0）；表 3 还列出 Aguvis（37.1）、Ponder&Press（34.5）、UGround（32.8）、SeeAct（15.5，GPT-4-turbo）、DigiRL（0.9）以及人类参考 80.0。表 1 的前 7 行取自 SPA-Bench 论文；其他基线据称来自“各自的基准论文”。引言说相对已有方法的提升在 2.6% 到 11.7% 之间，这与表格吻合（53.7 对 M3A 的 42.0；47.4 对 Aria-UI 的 44.8）。但第 5.2 节写的是“相对 M3A 绝对提升 28.1%”，这个数字表格并不支持。

**离线，单列。** 作者还构建了 GUI-KRB：500 个人工筛选的样本，覆盖 8 个类别、43 个应用，用专家关键词给模型对“某个 UI 元素有什么功能”的回答打分。它是知识基准，不是任务成功率基准。错误率（越低越好），先“先验知识”后“动态理解”：Qwen2-VL 22.8 / 19.8，Qwen2.5-VL 16.6 / 14.0，Gemini 2.0 Flash 15.2 / 11.2，GPT-4o 18.2 / 13.4，GUI-explorer 6.8 / 6.4。GUI-explorer 一行以 Qwen2-VL-72B-Instruct-GPTQ-Int4 为基座，这是作者为检验鲁棒性特意选的最弱模型。

## 论文自带的对照实验

- **SPA-Bench 上的引导消融。** 去掉由 transition-aware 知识构成的动态引导，性能下降 12.2%。图 4 比较了无引导、在别的环境（AndroidWorld）中挖掘的引导、以及在同一环境（SPA-Bench）中挖掘的引导。正文说跨环境引导相对无引导提升 4.3%；图中标注的数值为 41.5‡、46.3‡ 和 53.7。
- **排序器。** 在 GUI-KRB 上关闭排序器：先验知识错误率 9.8 对 6.8，动态理解 6.8 对 6.4。附录 F 比较了替代方案：直接 LLM 判断 8.8，置信度打分 7.6，滑动窗口排序 6.8，论文方法 6.8。滑动窗口在精度上打平；作者认为归并排序更易并行。
- **去掉元数据。** 只用截图生成目标，在两个 AndroidWorld 应用（Retro Music 和 Broccoli）的任务上，不探索为 16.7，仅截图探索为 22.2，完整方法为 33.3。论文正文没有给出任务数，规模很小。
- **迁移到网页（离线）。** 仅在 Android 上挖掘的知识用于 Multimodal-Mind2Web 的“website”划分（20 个样本）：宏平均元素准确率 45.97 到 47.26，宏平均步准确率 42.31 到 43.05。作者称提升“较小”。
- **成本。** 表 2 给出每步平均：检索 7.120 秒，排序 28.462 秒，推理 30.796 秒，总计 66.378 秒，总成本 0.064 USD。排序占时间的 42.9%。正文中的“0.0015 USD/step”只指排序部分（表 2 中为 0.015，单位是 0.1 USD）。
- **挖掘出的知识是否可靠。** 作者指出 GUI-KRB 的动态理解任务等价于他们的抽取步骤，GPT-4o 在其上的准确率为 86.6%。
- **错误分析。** 附录 E 把失败分为感知错误（例如把实心图标读成未收藏）、推理错误（本应替换文字却追加文字）和知识缺失（在错误的设置菜单里一直搜索直到步数用完）。

## 证据较薄弱之处

- **探索与评测重叠。** 取得 SPA-Bench 完整结果的引导，是通过探索 SPA-Bench 环境（“in-environment”）挖出来的。探索用的应用并不是留出应用。跨环境版本最接近留出测试，其提升更小。
- **没有方差。** 论文没有为任一基准报告种子、重复次数或置信区间。
- **预算是否对齐不明。** 除了 GUI-explorer 的 30 步探索上限，论文没有讨论基线的步数预算，且若干基线数值是从其他论文抄来的。
- **仅限移动端。** 作者在局限中说明：锚点依赖 Android manifest，因此网页和桌面不能直接适用；排序器偏慢（每步 28.5 秒）。伦理声明提到每步约 66 秒。
- 大部分实验在单张 RTX 4070 笔记本 GPU（8GB）上运行；GPT-4o 以 API 方式调用。

## CUA Radar 的判断

CUA Radar 给这篇论文打 **72 分（★★★）**，证据等级 **online**。分数反映论文所报告的证据：两个基准上的在线评测、较强的基线、成本报告、组件消融、在自建基准上对挖掘知识的检验，以及已发布的代码。判定记录同时把种子与方差标为未报告，步数预算是否对齐标为不明，留出应用标为部分满足，并标出探索环境与评测环境重叠这一问题。CUA Radar 没有复现任何实验，本文所有数字均来自论文（版本 v1）。
