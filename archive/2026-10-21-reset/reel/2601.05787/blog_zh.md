# BEPA：把少量框架智能体轨迹变成端到端 GUI 智能体可吸收的 on-policy 引导

*CUA Radar 对 arXiv 2601.05787v2（Wang、Zhang、Zhang、Qian、Lu）的解读。本文是第三方对论文所报告内容的整理，并非作者背书。海报见 `poster.png`。论文：https://arxiv.org/abs/2601.05787v2 · 代码：https://github.com/LEON-gittech/Verl_GUI.git*

## 问题：学生模仿不了的专家

在 OSWorld-Verified 上，论文报告 Agent S2、Jedi-7B w/ o3 这类 framework-based 智能体的成功率为 33.00 到 42.40，而 UITARS1.5-7B、OpenCUA-7B 这类端到端（E2E）策略只有 23 到 24 左右。OSWorld-Verified 只提供几百个可交互、可验证的任务，专家轨迹还得靠强智能体在环境里运行并逐条验证才能得到。论文因此问：如何用 RLVR（可验证奖励的强化学习）把少量这样的专家轨迹最大限度地用于训练 E2E 策略。

最直接的做法是把专家轨迹混入 on-policy RL。论文认为这很脆弱，原因有二。结构上，framework 轨迹交织了 planner、executor、grounder 多个角色，常用 API 级的工具动作，单个“截图到动作”的策略无法直接模仿。分布上，即便转换了格式，这些轨迹仍然远离基座策略。作者报告：静态的整合方式无法缩小差距，甚至会让 UITARS1.5-7B 比纯 GRPO 更差。

## BEPA 是什么

**智能体。** 被训练的是 UITARS1.5-7B，一个端到端桌面智能体。每一步它观察截图和任务指令，输出一段文字推理加一个 UI-TARS 动作：click、drag、scroll、type、hotkey、left double-click、right-click、wait 或 finished，坐标为像素位置。论文聚焦完整桌面控制（OSWorld-Verified，369 个任务，每个任务在全新的虚拟机快照中执行，上限 15 步）。它在 CUA Radar 板上的模式是 K20，归入“在自身、回放和修正过的轨迹上训练策略”。

**机制。** BEPA（Bi-Level Expert-to-Policy Assimilation）是加在 GRPO 训练上的一个组件，分两层。

- **LEVEL-1，self-rolled execution（自我重跑）。** 把每条成功的 Agent S2 轨迹由 GPT-4o 抽象成一段简短的自然语言计划，附加到任务指令后，让基座策略自己在环境中执行。通过 OSWorld 验证器的 rollout 组成种子集。115 条专家轨迹中（论文给出的重跑成功率为 76%）保留 88 条。因为轨迹由策略自己生成，比原始专家轨迹更接近策略的分布。
- **LEVEL-2，off-policy assimilation（对齐式吸收）。** 用种子集初始化每个任务一份缓存。GRPO 训练中，只要当前策略在某任务上成功，就用其一条成功 rollout（默认随机选）替换缓存。当 N = 8 条 on-policy rollout 全部失败且缓存非空时，用缓存轨迹替换第一条失败轨迹，并且使用原始指令而不带计划前缀。这样组内至少有一个正信号；优势按组归一化，目标函数是 PPO 式的裁剪目标。

**训练信号** 是 OSWorld 的确定性二值验证器。训练使用 N = 8、学习率 1e-6、4 个 epoch，不含 KL 项。专家来源是 Agent S2（115 条成功轨迹）。训练任务：从 Agent S2 或基座策略 Pass@5 能解的 150 个任务池中，取 120 个再加 8 个其他任务，组成 128 个任务的训练集；池中剩余的可解任务加上其他任务构成 241 个任务的留出集。

## 论文报告的结果

以下 OSWorld-Verified 数字均为**在线**成功率（%），步数预算 15。“Overall”是在全部 369 个任务上 3 次运行的均值 ± 标准差；各划分的列在论文中没有标准差。

| 方法              | Overall          | 训练集（128） | 留出集（241） |
|-------------------|------------------|---------------|---------------|
| UITARS1.5-7B      | 22.87 ± 0.97     | 55.12         | 5.74          |
| GRPO              | 23.60 ± 1.15     | 58.02         | 5.32          |
| Trace Replacement | 23.91 ± 2.35     | 66.50         | 1.29          |
| LUFFY             | 24.11 ± 2.10     | 65.44         | 2.16          |
| **BEPA**          | **32.13 ± 0.25** | **73.23**     | **10.30**     |

论文写明，BEPA 相对 UITARS1.5-7B 提升 +9.26 个点（相对 +40.5%），相对 GRPO 提升 +8.53 个点（相对 +36.1%）。SFT（17.65）、SFT+RL（14.74）和 RL+SFT（20.88）都低于基座策略的 22.87。同一张表还列出 Agent S2 的 33.00 和 GUI-Owl-7B 的 32.10，它们是不同的系统。

**Online-Mind2Web**（真实网站，300 个任务，由该基准的 WebJudge 以 o4-mini 作为评判模型打分）：BEPA 的平均成功率为 28.52，UITARS1.5-7B 为 23.28，GRPO 为 24.81，LUFFY 为 24.79。论文把它作为留出基准；评判模型是基准自带的，论文没有另外报告对它的检验。

**MMBench-GUI 是离线评测**（单张截图，不与环境交互），这里单独列出：L1 内容理解上，BEPA 在 easy、medium、hard 分别为 90.46、91.91、92.60，GRPO 为 85.43、88.75、91.05。L2 元素定位上，BEPA 的平均值 basic 为 88.76、advanced 为 61.56，GRPO 为 85.48 和 59.56。L3、L4 未报告，因为写作时它们的任务配置尚未公开。

## 论文自带的对照实验

**组件消融（Table 1，overall，3 次运行）。** Trace Replacement 为 23.91，LEVEL-1 变体 27.30，LEVEL-2 变体 29.74，完整 BEPA 为 32.13。在 54 个任务的 expert-only 集合上（专家能解而未训练基座在 Pass@5 下解不出的任务），对应数字为 18.52、25.93、29.18 和 35.19。论文的解读是：LEVEL-1 让专家解法变得可达，但熵明显下降、迁移有限（留出集 5.05）；LEVEL-2 让引导保持对齐（留出集 7.48）。论文除方法描述外，没有更详细地给出这些变体的定义。

**分布诊断。** 在 BEPA 会触发缓存更新的 19 个任务子集上，原始 Agent S2 轨迹在基座策略下有 58.33% 的 token 概率低于 0.2（与 on-policy 参考的 JS 散度为 0.2040）；只做格式转换为 32.48%（0.1676）；LEVEL-1 为 10.53%；LEVEL-2 为 19.88%，对比 on-policy 的 26.95%，JS 为 0.0366。论文称这些是描述性统计，不是正式检验。

**敏感性（3 次运行）。** 组大小 N = 4、8、16 分别为 29.85 ± 1.12、32.13 ± 0.25 和 33.40 ± 0.58。缓存更新规则 Random、Highest LogProb、Shortest Step 分别为 32.13、33.12 和 33.55；作者认为在标准差重叠的情况下，差异很小。

**其他专家与基座（单次运行）。** 以 Agent S2 为专家时 BEPA 为 32.40，以 GUI-Owl 为 31.55，两者结合为 34.71，对比 UITARS1.5-7B 上 GRPO 的 24.50。在 OpenCUA-7B 上用 Agent S2 时，BEPA 为 31.98，基座为 24.30。分领域表标注为最佳单次运行成功率。

## 证据偏薄之处

- **训练与测试同属一个基准。** 128 个训练任务和 241 个留出任务都来自 OSWorld-Verified，Overall 是对两者的平均。训练集上达到 73.23，留出集上为 10.30。
- **主要结果只用一个基座。** 论文的局限部分写明，研究只在 GUI 类电脑使用基准上实例化 BEPA，使用特定的基座、以 Agent S2 和 GUI-Owl 作专家来源，并使用特定的计划抽取流程。
- **成本。** 论文介绍了 Verl-GUI 训练框架，但没有给出一次运行的耗时或费用。
- **多应用任务。** BEPA 在多应用任务上有 8 次成功，而 Agent S2 为 22 次（Figure 15）。作者的解释是：当基座策略和专家轨迹都远离目标分布时，仅靠 bi-level assimilation 不够。
- Table 1（均值）与 Table 7（最佳单次运行）里的基线数字略有不同，例如 UITARS1.5-7B 为 22.87 对 23.66。
