# UI-TARS：只看截图的“原生”GUI agent，用自己修正过的轨迹训练

*CUA Radar 对 arXiv 2501.12326v1（Qin、Ye、Fang、Wang、Liang 等；字节跳动 Seed 与清华大学）的解读。这是第三方对论文所报告内容的总结，并非作者背书。海报：`poster.png`。论文：https://arxiv.org/abs/2501.12326v1 · 代码：https://github.com/bytedance/UI-TARS*

## 问题：agent 框架依赖通用模型和手写的粘合层

许多 GUI agent 把 GPT-4o 这类通用模型包在提示词、工具模块和手写工作流里，常常读取各平台不一致的 HTML 或 accessibility tree。论文主张做“原生 agent”：由一个模型把感知、动作、推理和记忆融合在一起，以截图为输入、端到端训练。它认为的障碍是数据：从框架转向 agent 模型“带来了一个根本性的数据瓶颈”，因为大规模、标准化的真实 GUI 交互记录很稀缺。

## UI-TARS 是什么

UI-TARS 只看截图（保留最近 N = 5 次观察，以及此前的思考和动作），通过一个跨桌面、移动端和网页统一的动作空间来行动：点击、拖拽、滚动、输入、快捷键以及少数控制类动作。每个动作之前，它会先写一段显式的“thought”。在 CUA Radar 板上它属于 K25 模式，即带生成思考的动作轨迹，归在轨迹级策略训练之下。

论文列出四个要素：

1.  **感知数据。** 大规模 GUI 数据集，涵盖元素描述、密集 caption、状态转移 caption、问答和 set-of-mark 提示。
2.  **统一的动作建模。** 跨平台标准化的动作、大量动作轨迹（自己标注的加上标准化后的开源数据），以及把元素描述与坐标配对的 grounding 数据。
3.  **System-2 推理。** 抓取并过滤约 600 万份 GUI 教程，并向收集到的轨迹中注入推理模式：任务分解、长期一致性、里程碑识别、试错和反思。
4.  **用在线轨迹迭代改进。** 模型在数百台虚拟 PC 上执行人工编写和模型生成的任务指令。轨迹要经过基于规则的 reward、VLM 打分阈值和部分人工审核。标注员还会标注错误修正和“post-reflection”恢复步骤。修正后的步骤用于监督微调，“修正动作与错误动作”的配对用于 DPO。改进后的模型再收集下一轮轨迹。

训练从 Qwen-2-VL 起步（这里报告的是 7B 和 72B 两个版本），使用约 500 亿 token，分三个阶段：继续预训练、annealing（得到的模型称为 UI-TARS-SFT）和 DPO（UI-TARS-DPO）。

## 论文报告的结果

在线基准，仅用截图。OSWorld 有 369 个任务，分数是 3 次运行的平均；AndroidWorld 有 116 个任务，在真实模拟器上运行。Table 9 中没有标注步数的 OSWorld 行，按 15 步上限处理。

| 模型                     | OSWorld，15 步 | OSWorld，50 步 | AndroidWorld  |
|--------------------------|----------------|----------------|---------------|
| Aria-UI + GPT-4o（框架） | 15.2           | 未报告         | 44.8          |
| Aguvis-72B               | 10.3           | 未报告         | 26.1          |
| Claude Computer-Use      | 14.9           | 22.0           | 27.9          |
| UI-TARS-7B-SFT / DPO     | 17.7 / 18.7    | 未报告         | 33.0 / 未报告 |
| UI-TARS-72B-SFT          | 18.8           | 未报告         | 46.6          |
| **UI-TARS-72B-DPO**      | **22.7**       | **24.6**       | 未报告        |

论文指出，72B-DPO 在 15 步下的 22.7 与给了 50 步预算的 Claude（22.0）相当，并称 50 步下的 24.6 是 OSWorld 上新的最优结果。在 AndroidWorld 上，72B-SFT 的 46.6 超过了此前最好的框架（44.8）和 agent 模型（26.1）。离线结果在论文的其他部分报告，这里单独放在一旁：例如 72B 模型在 VisualWebBench 上为 82.8，GPT-4o 为 78.5；在 ScreenSpot-Pro 上为 38.1。

## 论文自带的对照说明了什么

**DPO。** 在 OSWorld、15 步下对比 SFT 和 DPO 模型：72B 从 18.8 提高到 22.7，7B 从 17.7 提高到 18.7。论文的解读是：负样本帮助模型更好地区分较优和较差的动作。这是论文报告的唯一一个组件消融，而且 DPO 只在 OSWorld 上评测；其他基准使用的是 SFT 模型。

**规模。** 72B 比 7B 的领先幅度在 online 上大于 offline，论文据此认为规模会提升 system-2 推理，并认为只看 offline 基准可能无法反映实时环境下的能力。

**System 1 与 system 2（offline）。** 在三个 in-domain 基准上用 best-of-N 采样，N = 1 时 system 2 略低于 system 1，N = 16 和 64 时明显领先；在 out-of-domain 的 AndroidWorld（N = 1）上，论文报告 system 2 显著领先。具体数值只在图中给出。

## 证据偏薄之处

- 没有报告标准差或区间；只有 OSWorld 说明是 3 次运行的平均。
- 论文没有说明 OSWorld 的应用或任务是否与训练用的在线轨迹任务重叠。它只把 AndroidWorld 称为 out-of-domain（没有对应的训练数据）；CUA Radar 的记录把 held-out 评测标为 unclear。
- Table 9 中有些步数预算没有标注，按表注的 15 步上限处理；50 步的比较只有一个基线，即 Claude。
- DPO 模型没有在 AndroidWorld 上评测，所以 46.6 来自 SFT 模型。
- 人工标注员会审核轨迹并标注修正，所以这个闭环并非全自动。VLM 打分过滤器在论文中没有被验证，训练算力也只给出了约 500 亿 token。

## CUA Radar 的解读

CUA Radar 给这篇论文打 **67 分（★★）**，证据等级 **transfer**。记录认可：两个基准上的 online 评测、与 Claude 相同的步数预算、OSWorld 上 3 次运行的平均，以及一个 DPO 对比；摘要说明模型已在所链接的仓库开源，但记录里把代码标为 unclear。held-out 环境、方差和轨迹过滤器的验证在记录中为未报告。CUA Radar 没有重跑任何实验；本文所有数字都来自论文（版本 v1）。
