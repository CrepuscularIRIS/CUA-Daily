# Player-1：用合成经验学习游戏操控的 computer-use 模型

*CUA Radar 对 arXiv 2610.20584v1（Ouyang、Wang、Hu 等）的解读。本文是第三方对论文所报告内容的整理，并非作者背书。海报见 `poster.png`。论文：https://arxiv.org/abs/2610.20584v1 · 代码：https://github.com/TencentARC/Player-1*

## 问题：演示数据覆盖的状态很有限

Computer-use agent 读取屏幕、操作键鼠。游戏是更难的考验：需要精确瞄准、持续移动和多个输入同时进行，而且画面变化很快。论文指出，游戏演示数据只覆盖智能体可能遇到的状态中的一小部分（“cover only a limited portion of the states an agent may encounter”），可扩展的交互式训练环境很难获得，为商业游戏编写程序化奖励也很困难。论文的核心问题是：合成经验能否让游戏操控超越监督初始化（SFT），并且这种提升能否迁移到 RL 训练集之外的游戏。

## Player-1 是什么

**智能体。** 每一轮，策略接收任务指令、当前截图和一小段历史（两个最近的视觉-动作轮次，加两个更早的仅动作轮次），输出推理文本和动作。它是“截图输入、键鼠输出”的游戏智能体，在 Minecraft、ViZDoom 和浏览器游戏中评测，并在一款商业游戏中做了定性展示。基座模型为 Qwen3.5-9B 和 Qwen3.5-35B-A3B。在 CUA Radar 板上，这篇论文属于 pattern K13：从 checker/规格出发合成任务，使可验证奖励在构造上就存在。

**扩展的动作空间。** 在常规 computer-use 动作之外增加三类：relative pointer motion（归一化的相对位移，用于没有可见光标时控制视角）、sustained inputs（按键或鼠标按钮持续按住一个完整控制步）、composite actions（两个或更多兼容输入在一步内并发执行，例如按住 W 的同时点按 Space）。

**监督初始化。** 6,044 条筛选后的游戏轨迹（295,097 个轮次、172 款游戏，采样控制时长约 16.4 小时），来自公开数据集和自有录制。由 VLM（Gemini 3.8 Flash）为每条轨迹标注任务指令和逐轮视觉推理。Minecraft 是占比最大的单个游戏，有 1,236 条轨迹。两种规模的模型都用 action-balanced sampling 做两个 epoch 的 SFT。

**Player-1-Gym。** 十六个合成的 2D/3D 环境，基于作者自建的引擎，按控制需求分为五类：瞄准（2）、战斗（5）、驾驶（4）、导航（4）、UI 交互（1）。外观、相机、场景和控制响应都会随机化。每个环境定义累计游戏分数，每步的分数增量即奖励。策略只看到截图和任务文本；分数由特权状态计算，不使用学习得到的 judge。

**强化学习。** 同步 PPO，critic 为 9B 稠密模型，共 200 步，每步 256 个 episode 在 16 个环境间平均分配，每个 episode 最多 50 轮。由于各环境奖励尺度不同，advantage 按环境分别归一化。论文没有给 composite actions 设置显式奖励。

## 论文报告的结果

下面所有评测都是在线的游戏 rollout；论文中没有离线 step accuracy 基准。不同基准的指标不同，因此分表列出。基线沿用各自原生的预处理和推理流程。

**MineDojo-300**（300 个 Minecraft 任务，每任务 8 次试验；成功率 %，总体一列附论文给出的 95% 任务 bootstrap 区间）：

| 方法                    | Combat | Harvest | Overall \[95% CI\]         |
|-------------------------|--------|---------|----------------------------|
| GameWAM（最强外部基线） | 14.00  | 9.88    | 12.63 \[10.79, 14.54\]     |
| Qwen3.5-9B              | 11.75  | 4.13    | 9.21 \[7.50, 11.00\]       |
| Player-1-9B-SFT         | 12.50  | 6.63    | 10.54 \[8.67, 12.50\]      |
| **Player-1-9B**         | 52.31  | 10.38   | **38.33** \[35.13, 41.58\] |
| Qwen3.5-35B-A3B         | 8.69   | 6.00    | 7.79 \[6.25, 9.46\]        |
| Player-1-35B-A3B-SFT    | 30.31  | 9.50    | 23.38 \[20.63, 26.21\]     |
| **Player-1-35B-A3B**    | 55.56  | 12.00   | **41.04** \[37.83, 44.29\] |

论文给出的相对 SFT 的提升：9B 为 27.8 个百分点，35B-A3B 为 17.7 个百分点。9B 在八次试验中至少成功四次的任务数从 20 增至 136。

**ViZDoom-10**（十张地图，每图 50 次试验，平均 scaled return）：

| 方法 | Precision shooting | Goal navigation | Mobile combat | Survival | Overall |
|----|----|----|----|----|----|
| GameWAM | 0.1175 | -0.1285 | 1.1860 | 0.1424 | 0.3938 |
| Player-1-9B-SFT | 0.4403 | 0.1839 | 0.5293 | 0.5423 | 0.4361 |
| Player-1-9B | 1.0772 | 0.5974 | 0.3033 | 0.7927 | 0.6922 |
| Player-1-35B-A3B | 1.0423 | 0.2628 | 0.5960 | 0.8979 | 0.7236 |

**GameWorld**（170 个浏览器游戏任务，34 款游戏，每任务 3 次试验）：

| 方法             | Success (%) | Progress (%) |
|------------------|-------------|--------------|
| Qwen3.5-9B       | 10.39       | 29.22        |
| Player-1-9B-SFT  | 13.14       | 31.43        |
| Player-1-9B      | 15.88       | 34.45        |
| Qwen3.5-35B-A3B  | 13.14       | 33.49        |
| Player-1-35B-A3B | 17.25       | 38.79        |

论文还以 Watch Dogs 2（SFT 和 RL 中都未出现的商业游戏）展示了 Player-1-9B 的定性案例（步行导航、上车、驾驶），没有给出数字。

## 论文自带的对照实验说明了什么

**SFT 与 RL 的分离。** 论文在表中把两个阶段分开：对 9B，SFT 把 MineDojo-300 成功率从 9.21 变为 10.54，RL 再提高到 38.33；对 35B-A3B，仅 SFT 为 23.38，RL 后为 41.04。

**SFT 初始化的作用。** 在 Minecraft 开发任务上，9B 经 100 步 RL：先 SFT 再 RL 从 17.67% 升到 51.67%，从基座模型直接 RL 则从 12.67% 升到 16.67%。

**环境数量的 scaling。** 固定预算 25,600 个 episode、100 步 RL，从同一个 SFT checkpoint 出发，分别使用 2、4、8、16 个训练环境；论文图 7 显示 Minecraft 开发任务成功率随环境数量增加而上升。具体数值只出现在图中，此处不引用。

**Composite actions。** 在 in-suite 验证中，含 composite action 的轮次占比从 RL 开始时的 64.7% 升到 50 步后的 85.4% 和 100 步后的 93.2%，期间没有对此设置显式奖励。

**训练曲线。** 16 个环境上的平均 episode return 和游戏得分在 200 步中上升，早期最快；35B-A3B 曲线最终略高于 9B。

## 证据偏薄之处

- **迁移并不均匀。** GameWorld 上 9B 的 progress 从 31.43 升到 34.45，success 从 13.14 升到 15.88。在 ViZDoom 上，9B 的 mobile combat 在 RL 后为 0.3033，SFT 后为 0.5293，而 GameWAM 在该类别为 1.1860。
- **Minecraft 对 SFT 并非未见。** RL 套件里没有 Minecraft 环境，但 Minecraft 是 SFT 数据中占比最大的单个游戏（1,236 条轨迹）。论文所说的“RL 训练套件之外”是针对 RL 而言。
- **区间。** MineDojo-300 给出了 95% bootstrap 区间；ViZDoom 和 GameWorld 的表只给单个数值。
- **基线处理。** 外部模型使用各自的预处理、分辨率和动作适配器，规模也不同。论文说明其重点是已发布的游戏控制和 computer-use 策略，而非专有 API 模型，理由是完整评测的估算成本（每个模型最多 3.14 million 个决策轮次）。
- **开发任务。** 消融和 scaling 的数字使用 Minecraft 开发任务；论文没有说明这些任务与 300 个最终任务的关系。
- **成本。** SFT 使用 32 块 NVIDIA H200 约 24 小时，一次 200 步 RL 使用 64 块 H200 约 36 小时。

## CUA Radar 的判断

CUA Radar 给这篇论文打 **75 分（三星）**，证据等级 **transfer**。判定记录认可：在线评测、RL 套件之外的游戏、MineDojo-300 上的置信区间、区分基座/SFT/RL 模型的基线，以及组件消融；预算对齐和成本报告标为部分满足。判定记录标出了反模式 AP2（用合成环境替代真实目标）；论文的应对是上述三个外部基准。Radar 没有重跑任何实验，本文所有数字均来自论文（v1 版本）。
