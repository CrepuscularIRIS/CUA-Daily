# WebAgent-R1: training web agents with end-to-end multi-turn RL

*A CUA Radar reading of arXiv 2505.16421v2 (Wei, Yao, Liu, Zhang, Lu, Qiu, et al.; University of Virginia, Amazon, Georgia Tech). This is a third-party summary of what the paper reports, not an endorsement by the authors. Poster: `poster.png`. Paper: https://arxiv.org/abs/2505.16421v2 · Code: https://github.com/weizhepei/WebAgent-R1*

## The problem

RL has improved LLMs most visibly on single-turn tasks such as math. Web tasks are different: the environment changes as the agent acts, horizons are long, and each observation is a page of HTML that can span thousands of tokens. The paper’s argument against existing web-agent RL is about the data pipeline, not the algorithm. Off-policy and iterative methods (AWR, DigiRL, WebRL) train on trajectories generated by older versions of the agent, so they need replay buffers, trajectory filtering, or a separately trained outcome reward model (WebRL trains one to label GPT-4-generated data). The paper gives a concrete failure mode: if the agent is asked to log out of an account and later edit the profile, off-policy data collected before logout never contains the login behavior, so the agent keeps assuming access it no longer has. On-policy, end-to-end RL sees the consequences of its own actions, but has to survive multi-turn context growth — hence the two engineering contributions below.

## What WebAgent-R1 is

The agent is a **text-only web agent** on WebArena, a self-hostable environment spanning five sites: Reddit (social forum), GitLab (collaborative coding), CMS (content management), Map (open street maps), and OneStopShop (shopping). At each step it observes the task instruction plus the current page’s HTML — no screenshots, no accessibility tree. It answers in a `<think> ... </think> <answer> ... </answer>` format with **one action per turn**: a python-style call `do(action, argument, element)` from a fixed space (Click, Right Click, Type, Search, Hover, Scroll Up/Down, Press Enter, Switch Tab, Select Dropdown Option, Wait, Go Backward/Forward) or `exit(message)` to stop. Element targets are ids in the simplified HTML. On the CUA Radar board this is pattern **K20**, trajectory-level policy training, with the parent pattern “train the policy on own, replayed and corrected trajectories” — except this paper deliberately drops the replay.

Training has two stages:

1.  **Behavior cloning (BC).** SFT on the public 9,460 trajectories (1,186 valid training samples) that WebArena-Lite provides, learning to imitate expert actions conditioned on the full history. This warm-up is what makes RL work later.
2.  **End-to-end multi-turn RL, M-GRPO.** For each task the agent rolls out a group of G trajectories in **parallel browser instances** — same starting page, independent cookies and contexts — and updates the policy with a multi-turn extension of GRPO: the advantage of every action token in every trajectory is the group-relative value of that trajectory’s binary reward, (r − mean(r))/std(r), inside a PPO-style clipped objective with KL regularization. Loss is computed only on action tokens. Two mechanisms make this practical: **dynamic context compression** (once an observation has been acted on, it is replaced in later turns by a stub such as “Simplified HTML”; actions are never dropped) and vLLM-based rollouts.

The **training signal is exactly the environment’s rule-based binary reward** (success = 1, else 0), from WebArena’s built-in rubrics: string match, URL match, or program execution against the final page state. No reward model, no reward shaping, no extra data.

Implementation: full-parameter fine-tuning of Qwen2.5-3B and Llama-3.1-8B on 8 A100-80GB GPUs; SFT lr 5e-5, batch 128; RL lr 1e-6, batch 16, KL coefficient 0.001, clip ratio 0.2, context 16,384, 1,024 new tokens.

## Results, as reported

All numbers are **online** success rates on WebArena-Lite (165 human-verified evaluation tasks; the remaining 647 tasks are the RL training pool). Rule-based rubrics decide success; no offline step metric is reported. Seeds and variance are not reported. Baseline finetuning numbers follow the paper’s rule of taking the higher of the authors’ reproduction and the literature value.

| Method (backbone)                                | Average SR         |
|--------------------------------------------------|--------------------|
| Qwen2.5-3B / Llama3.1-8B / Qwen2.5-32B prompting | 6.1 / 8.5 / 16.9   |
| GPT-4o / GPT-4o-Turbo / QwQ-32B prompting        | 13.9 / 17.6 / 22.4 |
| OpenAI o3 / o4-mini prompting                    | 39.4 / 36.9        |
| BC (Qwen2.5-3B) → **WebAgent-R1**                | 20.0 → **33.9**    |
| BC (Llama3.1-8B)                                 | 20.6               |
| Filtered BC / AWR / DigiRL (Llama3.1-8B)         | 23.0 / 28.5 / 30.3 |
| WebRL (Llama3.1-8B)                              | 42.4               |
| **WebAgent-R1 (Llama3.1-8B)**                    | **44.8**           |

Per-site (Llama3.1-8B, WebAgent-R1 vs WebRL): Reddit 47.4 vs 63.2, GitLab 56.7 vs 46.7, CMS 57.1 vs 54.3, Map 23.1 vs 36.7, Shopping 44.4 vs 31.1 — the average win hides two sites where WebRL is ahead.

**Out-of-distribution.** On WebVoyager (25 sampled tasks per domain, 5 domains unseen in WebArena, Qwen2.5-3B), WebAgent-R1 averages 32% against 8.8% for prompting and 12% for the SFT variant, winning every domain (Allrecipes 28%, Amazon 24%, Arxiv 24%, Coursera 44%, Google Map 40%).

## What the paper’s own controls say

- **Initialization ablation (Qwen2.5-3B).** Skipping BC (“WebAgent-R1-Zero”) starts RL from 6.1% and *drops* to 4.8% after RL — the off-the-shelf model emits ill-formed actions and rarely earns reward. BC on long-CoT traces generated by QwQ-32B (“WebAgent-R1-CoT”) starts higher, 24.5%, but improves less under RL, to 30.3%, versus 20.0% to 33.9% for plain BC; the authors’ hypothesis is that deterministic long-CoT patterns constrain exploration.
- **Fair comparison with WebRL.** WebRL uses extra GPT-4-generated data, so for Llama3.1-8B the paper initializes its own RL from WebRL’s public checkpoint and uses only the original 647 training tasks.
- **Thinking-format prompting.** Adding the `<think>` format to the prompt alone lifts Qwen2.5-3B from 3.2% to 6.1%, Llama3.1-8B from 4.8% to 8.5%, and o4-mini from 15.9% to 36.9%, while single-turn response length barely moves (139 → 142 tokens) and interactions rise (6 → 17 for the 3B). The paper reads this as a test-time scaling axis: more interaction turns, not longer single responses; a separate analysis shows success rising consistently as the interaction cap grows for prompting, SFT and RL agents.

## Where the evidence is thinner, in the paper’s words

- Text-only: “our current approach … consider\[s\] only textual input for the web tasks,” while visual layout and colors may help.
- Reward availability: “such reward functions may not be readily available in other interactive scenarios, such as open-ended travel planner agents, where task goals are ambiguous and no clear reference or verifiable outcome is available.”
- Action space: the agent is “trained with a fixed set of predefined actions (e.g. click, type), which can limit its flexibility.”
- Beyond the paper’s own list: no seeds or variance anywhere; the RL exploration tasks and the evaluation tasks are different tasks but the same five WebArena sites (the judgment record flags this as AP5, with WebVoyager as the OOD counter-evidence); training dynamics and test-time-scaling curves are shown only as figures without printed values.
