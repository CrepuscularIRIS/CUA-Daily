# DeAction：在执行之前拦截偏离任务的 computer-use 动作，并给出反馈的护栏

*CUA Radar 对 arXiv 2602.08995v2（Ning、Jones、Zhang、Ye、Ruan、Li、Gupta、Sun）的解读。这是第三方对论文所报告内容的总结，并非作者背书。海报：`poster.png`。论文：https://arxiv.org/abs/2602.08995v2 · 代码：https://github.com/OSU-NLP-Group/Misaligned-Action-Detection*

## 问题：动作偏离了用户的本意

computer-use agent 有时会采取偏离用户原始意图的动作。论文区分了三类：遵循被注入到环境中的恶意指令、因自身错误造成有害的副作用，以及做其他与任务无关的事情（例如打开无关的应用）。它指出现有防御的三个缺口：许多方法绑定固定的策略或已知的攻击类型；现有基准给整条轨迹打标签，而不是给单个动作；以及简单地拦截一个动作会让任务停滞，而不是帮助 agent 恢复。

## DeAction 是什么

DeAction 是一个位于 computer-use agent 和机器之间的护栏。它没有训练：它是一组 LLM 提示词，不需要访问 agent 内部，可以配合任何 agent 使用。当 agent 提出一个动作时（这里的 agent 通过 pyautogui 代码行动），DeAction 先把它扣下，在任何东西被执行之前，对照用户的任务来判断。

1.  **叙述式摘要。** 每个步骤执行之后，把“观察、动作、观察”的三元组转成一小段文字描述。这些摘要取代原始截图作为历史，并且与执行并行生成。
2.  **快速检查。** 一次 LLM 调用，给出一句话的理由，要么批准明显对齐的动作，要么把它送往下一步。它的定位是针对常规步骤的保守过滤器。
3.  **系统化分析。** 分四个部分：注入分析（截图里是否含有可能把 agent 带偏的指令）、动作理解、结果预测，以及带可读理由的“是否错位”判断。
4.  **迭代修正。** 错位的动作不会被直接拦下。agent 会收到结构化的反馈，说明原因（例如注入、有害结果或意图不一致），然后提出修订，修订再被检查，最多 3 轮。

在 CUA Radar 板上，这篇论文属于 C34 模式，即注入防御与隔离。

## 论文报告的结果

**在 MisActBench 上的 offline 检测。** 这是作者自己建立的基准，包含 558 条轨迹和 2,264 个人工标注的动作步骤，其中 1,264 个是对齐的。它把对 OS-Harm、DoomArena、RedTeamCUA 和 RiOSWorld 的攻击所产生的轨迹，与在良性任务中合成的非预期行为结合在一起。把错位动作当作正类，F1 如下：

| 骨干模型          | Task Shield | InferAct | DeAction |
|-------------------|-------------|----------|----------|
| Qwen3-VL-32B      | 58.4        | 61.6     | 70.7     |
| Claude Sonnet 4.5 | 66.6        | 64.3     | 80.4     |
| GPT-5.1 Instant   | 65.1        | 64.7     | 79.4     |
| GPT-5.1 Thinking  | 66.9        | 62.3     | 82.8     |

论文指出，Task Shield 和 InferAct 常常召回率很高，但精确率只有 50% 左右，而 DeAction 的精确率最高达到 89.9%。

**online 评测。** RedTeamCUA（50 个高风险的端到端任务，间接提示注入，50 步上限）给出攻击成功率（ASR，越低越好）和攻击下的效用（UA，越高越好）；OSWorld（15 步上限）给出任务成功率（SR）。护栏使用 GPT-5.1 Instant，最多修正 3 次。

| Agent             | 防御                   | ASR         | UA          | OSWorld SR  |
|-------------------|------------------------|-------------|-------------|-------------|
| Claude Sonnet 4.5 | 无                     | 60.0        | 44.0        | 42.9        |
| Claude Sonnet 4.5 | DeAction               | 6.0         | 76.0        | 40.7        |
| OpenAI CUA        | 无                     | 42.0        | 82.0        | 26.0        |
| OpenAI CUA        | DeAction               | 4.0         | 84.0        | 30.7        |
| OpenCUA-72B       | 无                     | 32.0        | 48.0        | 39.0        |
| OpenCUA-72B       | DSP / PromptArmor      | 24.0 / 26.0 | 52.0 / 44.0 | 38.3 / 35.2 |
| OpenCUA-72B       | Task Shield / InferAct | 22.0 / 22.0 | 58.0 / 70.0 | 36.6 / 36.5 |
| OpenCUA-72B       | DeAction               | 2.0         | 60.0        | 39.6        |

论文报告每个 agent 的 ASR 都降低了 90% 以上，OSWorld 的成功率“相当，有时还有提升”。在 OpenCUA-72B 上，InferAct 的 UA 更高（70.0 对 60.0），但延迟也更高。

## 论文自带的对照说明了什么

**成本与路由。** 护栏推理占一个平均 28.1 秒的步骤中的 7.2 秒（25%）。快速检查直接批准 45% 的动作，每个只需 3.2 秒。16% 的步骤被标记为错位，其中 78% 最终被修正，62% 一次修订就修好了。

**消融**（MisActBench 的 566 步子集，GPT-5.1 Thinking）。只用快速检查：F1 为 77.8，耗时 4.2 秒；只用系统化分析：80.1，13.1 秒；默认的两阶段设计：79.9，11.3 秒。把系统化分析的模型降为 GPT-5 mini，F1 掉到 70.8；而快速检查与摘要器同时换成 GPT-5 mini，F1 为 80.4，成本降低 65%。叙述式摘要每步用 41 个 token，而每张截图超过 1K 个 token，每步延迟约 11 秒，而使用截图时为 18 秒。在 online 使用更便宜的配置时，三个 agent 的 ASR 都是 8.0。

**失败模式。** 论文列出：伪装得很好的恶意指令会骗过快速检查；在解读基于坐标的动作时 grounding 不足；以及对任务相关性的理解过于狭窄。恶意指令遵循是最容易检测的类别；两个由内部产生的类别更难检测和分类。

## 证据偏薄之处

- 这 50 个 RedTeamCUA 任务，是原始基准中攻击成功率最高的那些，所以 ASR 测的是最困难的情形。每个任务相当于 2 个百分点；没有报告重复运行或随机种子。
- 其他防御方法在 online 评测里只在 OpenCUA-72B 上运行。
- OSWorld 的 no-defense 数字取自 OSWorld 排行榜，没有重新运行，而 DeAction 的运行用了 15 步上限，所以 SR 的比较并不是匹配的。
- MisActBench 由同一批作者构建，标签比例较平衡；论文指出，若真实流量以对齐动作为主，快速检查会绕过更多步骤。
- CUA Radar 的记录把 held-out 评测、方差和代码标为 unclear；论文首页链接了一个项目主页。

## CUA Radar 的解读

CUA Radar 给这篇论文打 **67 分（★★）**，证据等级 **online**。记录认可：两个基准上的 online 评测、四个基线、匹配的最多 3 次修正、运行时成本、组件消融，以及由人工标注的检测基准；记录没有标注 flag。CUA Radar 没有重跑任何实验；本文所有数字都来自论文（版本 v2）。
