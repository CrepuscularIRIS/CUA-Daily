# Component routing：GUI 智能体的经验，哪些该进权重，哪些该留在提示词里

*CUA Radar 对 arXiv 2610.01787v1（Wu、Ding、Huang）的解读。本文是第三方对论文所报告内容的整理，并非作者背书。海报见 `poster.png`。论文：https://arxiv.org/abs/2610.01787v1 · 代码：论文称“Code and data will be released”，未给出链接。*

## 问题：同一份经验，两个去处，结论相反

自我改进的 GUI 智能体会保留自己产生的轨迹，再把它们还给智能体：要么拿来微调，要么检索进提示词。比较这两个去处的研究在工具类和网页类任务上结论不一。论文把原因归结为“经验的单位”：一条轨迹捆绑了性质不同的条目，所以关于整条轨迹的结论取决于其中各类条目的占比。论文举的例子是天气应用：对整条轨迹做微调，学到了搜索框在哪里，却丢掉了“要在预览页点 Add 才算保存城市”。

## Component routing 是什么

对象是手机 GUI 智能体。每一步记录截图、结构化的应用状态、屏幕元素，以及带目标元素的动作；动作使用各个骨干模型自己的原生 tap / type / swipe 动作空间（坐标）。平台是移动端：模拟手机 MobileGym 和 Android 应用 AndroidWorld。在 CUA Radar 板上它属于 K27，“把存储的过往经验检索进智能体上下文”，机制是经验记忆加上“进权重还是进上下文”的决策。

智能体先在训练应用上跑一批任务，成功与失败的轨迹都保留。基于规则的抽取器把这个经验池拆成四类组件，每个条目带一个可跨回合识别的 key：

- **Locators（G，定位器）：**某个命名元素在屏幕上的位置；训练样本是截图加对该元素的点击。
- **Procedures（P，流程）：**在同一任务族内反复出现的三个连续动作目标。
- **State facts（F，状态事实）：**某个动作成功前必须满足的前置条件，取自同一目标上一次失败、一次成功的尝试。
- **Lessons（L，教训）：**在某状态下失败的动作，配上之后在该状态下成功的动作。

每类组件可以送往**上下文**（最相似的 5 条笔记附在提示词里，按状态相似度排序、精确匹配优先）、**权重**（LoRA，rank 16，3 个 epoch，学习率 10^-5；lessons 用偏好优化，其余用监督微调），或者两者都用。两条路线使用同样抽取出的条目，并在同样的留出实例上评测。训练信号来自环境的确定性 checker 对经验池回合的判定，不使用模型裁判。

在任何训练之前，对经验池测量两个性质。**Recurrence（复现度）**r：条目的 key 在无关任务中重新出现的频率。**State-conditionality（状态条件性）**：条目是否有用取决于当前状态与其来源状态的匹配程度（用经验池算出代理量 kappa_0）。一个线性规则 score = alpha r - beta kappa_0 - gamma，用其他骨干家族的路由增益拟合，score 为正就送往权重。路由增益 = 权重路线的留出成功率减去上下文路线的留出成功率，在同样的实例上计算。

## 论文报告的结果

以下均为**在线**留出成功率（%），由各环境的 checker 判定，3 个随机种子的均值（论文表中下标为标准差）。骨干模型为 GUI-Owl-1.5-8B、Qwen3-VL-8B、ScaleCUA-7B，每个模型同时充当生产者和消费者。MobileGym：20 个应用，224 个留出模板（在已练习应用上的新模板 165 个，未见应用上 59 个），每个种子 1 106 个实例。AndroidWorld：58 个留出任务，每个 4 个实例，每个种子 232 个。论文没有报告离线的步骤准确率或 grounding 准确率。

| 方法（MobileGym）            | GUI-Owl-8B | Qwen3-VL-8B | ScaleCUA-7B |
|------------------------------|------------|-------------|-------------|
| 基础智能体                   | 21.6       | 16.7        | 19.2        |
| Self-retry（三次尝试）       | 26.4       | 20.6        | 24.6        |
| Success-filtered fine-tuning | 22.2       | 17.3        | 20.0        |
| 全部进上下文                 | 29.6       | 27.3        | 28.7        |
| 全部进权重                   | 28.6       | 28.0        | 27.3        |
| **Routed（按规则分配）**     | **34.8**   | **30.5**    | **34.3**    |
| 反向分配                     | 25.2       | 24.4        | 23.2        |

| 方法（AndroidWorld）   | GUI-Owl-8B | Qwen3-VL-8B | ScaleCUA-7B |
|------------------------|------------|-------------|-------------|
| 基础智能体             | 23.6       | 17.8        | 24.0        |
| Self-retry（三次尝试） | 26.1       | 22.7        | 27.2        |
| 全部进上下文           | 33.6       | 28.0        | 29.0        |
| 全部进权重             | 29.0       | 28.2        | 29.5        |
| **Routed**             | **33.3**   | **33.2**    | **32.6**    |
| 反向分配               | 27.7       | 23.4        | 27.9        |

论文的总结是：在三个骨干、两个环境上平均，routing 比每个骨干更好的单一去处高 +3.5 个点，比反向分配高 +7.8。在 MobileGym 上相对更好单一去处的平均领先为 +4.4；在 AndroidWorld 上，Qwen3-VL-8B 为 +5.0，ScaleCUA-7B 为 +3.2，GUI-Owl-8B 上与之持平（表 E.2 中相对全部进上下文为 -0.3，区间 -2.6 到 +2.0）。最强的整条轨迹基线 self-retry 在 MobileGym 上比 routing 低 +9.3 个点。

按组件看，MobileGym 上跨骨干汇总的路由增益：locators +4.9、lessons +1.5（权重占优），procedures -4.2、state facts -4.1（上下文占优）。留出一个骨干家族拟合的规则在 24 个单元中 24 个预测对了符号，其中 19 个的区间不含零。

## 论文自己的对照实验怎么说

**只改一个性质的干预（MobileGym，相对基础智能体的增益）。**把同样的笔记改成仅按任务文本检索、去掉状态条件，procedures 损失 3.9 个点，state facts 损失 3.4 个点；论文的解读是，上下文路线买到的是“条件”而不是“内容”。微调前把每个 procedure 条目复制 8 份，权重路线提升 +3.5，procedures 的路由增益从 -4.2 变为 -0.8（在 Qwen3-VL-8B 上越过零）；state facts 的变化为 +3.6。

**对测量工具本身的对照。**来自其他应用的随机笔记使基础智能体变化 -1.6；打乱 key 或打乱训练标签后，结果与基础智能体相差在 1.1 个点以内。论文据此认为，提示词格式本身和微调本身都不会产生这些增益。

**生产者与消费者。**无论笔记由哪个模型产生都有帮助（8B 消费者用自己的 procedures 得 +3.6，用 32B 模型的得 +4.8）。用另一个家族的样本微调反而有害（-7.5），而自己 procedures 上的权重增益大部分是“练习”（只用自己的 procedures 为 +0.6，用全部样本为 +0.9）。

**成本（附录 H，MobileGym，GUI-Owl-8B）。**Routed 训练用 6.1 GPU 小时，全部进权重为 15.4；routed 的提示词 token 数是基础智能体的 1.07 倍。

## 证据偏薄之处（引用论文原话）

- 预算：“Two quantities the budget does not equalize are reported in Appendix H: the notes block that the context route adds to every prompt, and the adapter training run that the weights route adds.” Self-retry 每个实例用三次尝试，其他方法各一次。
- AndroidWorld 的单元“repeat the pattern with the wider intervals of a smaller task set”；lessons 偏向权重，但“a margin whose interval includes zero in half of the cells”。
- 这里的“留出”指留出模板。经验所用的应用也出现在“practiced applications 上的新模板”一档（MobileGym 224 个模板中占 165 个）；只有未见应用一档（59 个）和 AndroidWorld 的 8 个留出应用才是未见应用。
- 规则用 24 个单元拟合（三个 7 到 8B 骨干、两个环境），所有方法共用一个 LoRA 配置。代码和数据尚未发布，只是声明将发布。
