# MAGNET：带有两种会随应用变化而演化的记忆的移动端 GUI agent

*CUA Radar 对 arXiv 2601.19199v2（Sun、Zhang、Wang、Wei）的解读。这是第三方对论文所报告内容的总结，并非作者背书。海报：`poster.png`。论文：https://arxiv.org/abs/2601.19199v2*

## 问题：应用会变，而基于旧版本训练的 agent 会失效

应用更新会重新设计图标但不改变其功能（论文的例子是 Twitter 变成 X），也会重新组织工作流而不改变目标（通过另一条导航路径来设置货币）。论文认为，基于历史数据训练的 agent 在这种漂移下会失败，而现有的记忆系统大多只存文字形式的工作流，对按钮长什么样一无所知。它观察到有两样东西在更新前后保持稳定：语义稳定性（更新后的元素仍然支持同样的动作）和意图稳定性（即使步骤变了，高层的任务目标依然不变）。

## MAGNET 是什么

MAGNET 是一个用于 Android 的 planner–actor agent，带有两种记忆，不需要训练。agent 看到截图、一小段对屏幕的文字描述和自己的动作历史，通过点击（针对一个边界框）、滚动以及 home 等系统按键行动。在 CUA Radar 板上，这篇论文属于 K27 模式，即经验记忆检索。

- **程序性记忆（给 planner）** 对应意图稳定性。每个条目是一个任务类别名称，加上带占位符（如 \[AppName\]）的高层步骤。planner 为新请求检索最相似的工作流，并把目标分解成子任务。条目的构建方法是：先对指令聚类（MiniCPM-Embedding，在相似度图中取最大团），再提示 planner 对每个簇的轨迹做抽象。
- **静态记忆（给 actor）** 对应语义稳定性。每个条目把一段功能描述（“点击搜索图标开始搜索”）与元素的裁剪图像配成一对。actor 通过把子任务文本与功能描述匹配来检索图块，并把它们作为视觉范例；对于 OS-Atlas 这类输入格式固定的 grounding 模型，则把检索到的图块在屏幕上做模板匹配，画出一个提示。条目由“屏幕、动作、屏幕”三元组构建，区域由 OmniParserV2 提取，描述由 Qwen2.5-VL-32B 生成。把它应用到 AITZ、GUI-Odyssey 和 Amex 上，得到 UI-40K 数据集，共 41,009 个条目、20,618 个不同的功能意图。
- **演化与排序。** 只有成功的轨迹才会更新记忆：加入新的工作流，新增或合并新的“元素—功能”对，重复项被丢弃。检索时先取语义上最接近的候选，再按保留分数 R = exp(-g/n) 排序，其中 g 是自上次使用以来的间隔，n 是该条目的检索次数，所以被频繁使用的条目衰减得更慢。

## 论文报告的结果

**online，AndroidWorld Easy 划分（61 个任务）。** 所有 agent 使用 Qwen2.5-VL-32B，并共享同样的动作预算。带记忆的 agent 先通过自我探索来构建记忆：MAGNET 在这 61 个任务上跑三遍，Agent-S 跑一轮探索任务，AppAgent 为每个应用跑一个探索任务。

| 方法       | 任务完成率 (%) |
|------------|----------------|
| M3A        | 32.78          |
| AppAgent   | 34.43          |
| Agent-S    | 40.98          |
| **MAGNET** | **42.62**      |

论文报告相对 AppAgent 高 8.2 个百分点，相对 Agent-S 高 1.6 个百分点。‡ 在 61 个任务中，42.62% 和 40.98% 分别对应完成 26 个和 25 个任务，所以相对 Agent-S 的优势只有一个任务（这个任务数是我们自己的算术，论文中没有写）。

**offline 的步级准确率**（in-distribution 子集，成功率 / grounding 准确率）。用 Qwen2.5-VL-32B 时，MAGNET 在 AITZ 上为 43.50 / 43.78，在 GUI-Odyssey 上为 50.16 / 51.91，在 Amex 上为 62.84 / 71.53；无记忆的 COAT 分别为 41.09 / 39.28、48.13 / 49.38 和 59.68 / 67.69。论文指出，经过参数调优的专用模型绝对分数更高，例如 Atlas-Pro-7B 在 AITZ 上为 66.64；用 Gemini-2.5-Pro 时，MAGNET 在 AITZ 上达到 52.77，且无需针对任务训练。

## 论文自带的对照说明了什么

**记忆消融（offline）。** 在 Qwen2.5-VL-32B 的 in-distribution 子集上，GUI-Odyssey 的成功率从无记忆时的 48.13 升到 48.62（仅静态）、49.72（仅程序性）和 50.16（两者都有）；Amex 从 59.68 升到 60.20、62.34 和 62.84。论文认为程序性记忆贡献更大（Amex 上 +2.66，静态为 +0.52），并解释静态记忆效果小，是因为静态的 offline 基准里很少出现模型没见过的图标。没有 online 的消融。

**跨架构。** 在五种 planner–actor 组合和三个数据集上，记忆平均带来 2.3 个百分点的成功率提升和 2.7 个百分点的 grounding 准确率提升，其中最大的提升（成功率 4.2 个百分点）来自 Qwen planner 搭配 OS-Atlas actor。

**分布漂移（offline）。** 在模板漂移、应用漂移和领域漂移的子集上，静态记忆在 Qwen 下带来 +0.1 到 +0.9 的小幅提升，而程序性记忆则从模板和应用漂移下的轻微退化变化到领域漂移下的中等提升；用 Gemini-2.5-Pro 时提升为 +0.2 到 +1.4。图中的数值在正文里没有给出。

**持续适应（online）。** 以 Amex 的记忆热启动，AndroidWorld 上的成功率在三轮迭代中从 31.14 升到 37.70、39.34 和 40.98，同时检索到的条目中仍来自 Amex 库的比例从 100% 降到 26%（程序性）和 18%（静态）。

## 证据偏薄之处

- online 测试只有 61 个任务，没有随机种子或方差，而相对 Agent-S 的头条优势只有一个任务（‡）。
- online 的记忆是通过在随后要评测的同一批任务上跑三遍构建的，而且各基线得到的探索量不同；CUA Radar 的记录标注了这种重叠（反模式 AP5）。
- 分布漂移的结果只有 offline 的，而且那里的提升很小。
- 两种记忆没有 online 的消融。
- 没有报告成本，论文没有给出代码链接，并且 Table 1 把 COAT 标为 Qwen2.5-VL-32B，而附录说 COAT 使用的是 Gemini-2.5-Pro。
