# 维护规则

当前方法与执行约定以 [research/scoring](../research/scoring/README.md) 为唯一权威入口。旧评分/选题/Reel 已按用户要求撤下，不能重新发布或自动续跑。领域卡和原始材料保留。

| 角色 | 范围 |
|---|---|
| Grok | 只收候选写 inbox，不评分 |
| 当前 CC 总控 | 固定范围，派批，核对覆盖/算术，维护进度，按授权提交 |
| 6.1 Sol 内置 Subagent | 单次完成整批领域卡判据与证据评价，只写分配的批次 |
| Opus 5.5 | 少量候选原文核对、Reel 制作和实际视觉 QA |

默认 4 个评分 Subagent 并行，每批 10–20 篇，滚动补位；配置已有，不探测重配。禁止另起无头 Claude、API 调用框架或新调度平台。本次清理没有启动评分；只有后续明确的执行任务才按新提示词运行。

评分只消费已有领域卡；不同领域范围/权重不混用，原 15＋31 不进入逐篇分类。缺材料留状态，不能以零分冒充；不按匹配卡数、录用率、名气、代码链接加分。

历史文件保存于本地仓库外，云端只保留撤下说明与 Git 历史。完整原文、.forge、密钥和日志不提交；公共输出只保留必要引用。已有原文优先复用，不重抓全部语料。

每个 worker 只拥有自己的批次/作品，不操作 git，不撤销他人修改。总控使用明确文件列表提交，不使用 git add .；推送按用户授权，不强推。

make check 是离线结构检查，不验证论文结论。历史 score/board 命令保持拒绝执行；不要复活旧批次工具。新记录和作品是否存在以当前 run/selection 为准，不能由文档完成推断执行完成。
