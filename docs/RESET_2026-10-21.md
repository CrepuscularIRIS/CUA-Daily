## 发现与处理

1. 三套旧公式都用 `10 * (1 - F_yes / F_total)` 计避免失败分，未知 failure 也会贡献“没有失败”的分；仅有代码 URL 也会获得 10 分。
   新草案取消这两项自动奖励，代码状态与模式适配单列。
2. 旧 fetch_fulltext 丢弃附录并裁剪正文，HTML 不存在时只保留摘要；旧流程允许这些材料进入评分。
   新流程需要核对完整材料，缺材料明确 needs_fulltext，未解决维度保留 unknown 和分数区间，不给低分代替缺材料。
3. GUI 与 Embodied 旧分数权重几乎复制；新提案按各项目研究对象定制，主张类型单独展示，evidence_level 不再重复加分。
4. Embodied 旧 README 尚有计数占位符。现已改为实际 17 张主卡 / 58 张子卡，并退出旧榜单状态。
5. Embodied 本地 `.forge/domains/embodied-agent-harness-v1/profile/expectations.json` 的 basis 明确指出没有 reviews/labels，
   条目来自 paper_practice / paper_limitation。GUI 的既有 profile 也含这些来源标签。
   不能把此类资产统称为真实审稿共识，更不能声称新权重已被实证校准。
6. Reel 的低质量/同质化是用户提出的重做原因，本次不声称已独立逐张审核全部旧成品。旧成品统一退出展示，重做提示词要求逐篇机制策划与渲染审核。
