# GUI Agents — ResearchStudio / Open Scientist 评分草案 v2.2

状态：**draft_uncalibrated**，2026-10-21。替代同日初版七维草案；未重评论文、未冻结权重、未建立有效新排名。
方法来源和适配关系见 [DESIGN_BASIS](../docs/DESIGN_BASIS.md)。本文是雷达的完成论文评分设计，不是 ResearchStudio 官方评分器。

## 先确定比较对象

在桌面、移动端或 Web 界面感知并执行动作的 agent，以及相关架构、grounding、训练、环境模型、benchmark 与 verifier。纯 API agent、只生成 UI 代码和具身机器人分流到其他项目。

主问题：改变了感知—规划—动作—反馈中的哪一环，在线任务是否真的完成，提升来自该环还是更强的模型/更多步骤？

先声明 `claim_type`：`system_method`、`component_training` 或 `evaluation_resource`，并写一条可检验的中心主张。
同领域也按主张类型分别展示，不把 benchmark、grounding 组件和完整 agent 混成单榜。
A/B 是收录类型，不是质量等级。`docs/EVIDENCE.md` 的 evidence_level 继续单列，**不重复加分**。


## 先分析，后算分

逐篇完成 [REVIEW_WORKSHEET](REVIEW_WORKSHEET.md)：
完整材料 → 操作签名 → 最近邻/谱系与 gap identify → 方法回应 gap 的链条 → 模式执行与审稿期望 → 主张-证据核对 → 评分与独立复核。
原始事实提取阶段不看旧分数、录用结果、名气或 Reel；证据包固定后才评价。模式卡先从语料逆向得到，之后服务逐篇评价。
已有卡片继续使用；先核其来源和适用条件，并按 [PATTERN_PROTOCOL](PATTERN_PROTOCOL.md) 对每篇做原15+31识别及领域映射；有缺口才版本化更新。

必须分开回答两种“保留”：**方法怎样选择并留存改动**；**雷达为什么把论文选入 Reel**。后者由评分及阈值决定，不能证明前者有效。
对声称留存收益的论文，写出修改前状态 → 候选 → 选择信号/数据 → 接受与拒绝 → 持久化位置 → 后续使用 → 独立结果。
GUI/具身的非自我改进论文不硬套 retained：记录静态设计或组件/训练贡献，按自己的中心主张评价。

## 评分轴与领域权重

| 轴 | 分值上限 | 本领域的判据 |
|---|---:|---|
| G：Gap 与问题位置 | 15 | 定位感知、grounding、上下文、规划、动作执行或完成判定的具体瓶颈；区分静态单步任务与真实交互任务。 |
| M：方法质量与 problem-fit | 25 | 说明改变哪条 observe–act–feedback 路径、信息可见性或训练目标；说明它如何解决该瓶颈，而非仅多加角色。 |
| X：机制执行与模式条件 | 20 | 检查 agent loop 的历史压缩、动作空间、错误恢复、回退与验证器接口；按已有 C/K 卡的生效条件判断。 |
| E：主张的证据支撑 | 40 | 固定模型/环境/预算的交互成功率；可执行判据或经过校验的 judge；未见网站/应用与重复运行、延迟成本。 |

G 看问题及最近邻之间有无可证实的残余瓶颈；M 看具体操作为什么对准它；X 看操作与所需条件是否真正落实；E 看结果是否支持所宣称的改变。
**匹配某张卡不加分，匹配更多卡不加分，模式新颖或老旧都不直接加减分。** 未匹配可写 `outside_taxonomy`，照样完整评价。
同一引用可支持多项判断，但每项必须回答不同问题，不重复奖励同一个事实。

E 的分值进一步固定如下（已包含在总分中，不额外相加）：

| 证据项 | 分值上限 |
|---|---:|
| 结果/测量与验证器可信度 | 10 |
| 因果归因与替代解释 | 10 |
| 留出、污染与主张范围 | 10 |
| 统计、失败分母与边界 | 5 |
| 预算公平与实际成本 | 5 |

这些权重是基于领域目标的**提案**，不是从录用率或审稿投票拟合出来的事实。最终锚点须从本领域模式卡、审稿期望与校准例子导出。
ResearchStudio IdeaQuality 的 A/B/C 评价的是没有实验的 idea；这里借鉴问题位置、方法质量、problem-fit，并新增完成论文必需的证据轴，不能套用其原总分。

## 分档锚点

所有 G/M/X 和 E 的五个子项取 0–4；1、3 表示相邻锚点之间的有理由判定。

| 项 | 0 | 2 | 4 |
|---|---|---|---|
| G | 完整核对后仍无具体问题/最近邻，或 gap 前提被反证 | 有真实局限，但最近邻比较、影响范围或残余问题不完整 | 具体重要瓶颈有来源；最近邻与方法谱系清楚，剩余缺口边界明确 |
| M | 操作无法回应所述问题，或推理被直接反证 | 有具体机制与部分因果解释，关键假设仍薄弱 | 操作、信息和假设解释可重建，与朴素替代的差异能提出可区分预测 |
| X | 方法中的关键操作/生效条件缺失或互相矛盾 | 主要步骤有描述，保留/恢复/接口或关键条件仍不清楚 | 操作链、信息权限、选择/留存或相应静态流程可重建；适用条件、失败与迁移边界清楚 |
| E 各项 | 经完整查找未报告适用的必要证据，或证据反驳主张 | 有相关结果，关键控制、覆盖或统计缺口尚存 | 与中心主张匹配的对照和结果充分，强替代解释经过检验，重复/独立证据与边界清楚 |

M 的逻辑可检验性不等于结果已验证；X 的方法描述完整不等于已经带来提升；效果只在 E 中判。
每个 E 子项要结合对应审稿期望补充本领域 0/2/4 的真实锚点，冻结前不得直接套表量产。
“机制合理但提升没证实”可以在 M/X 有评价，同时在 E 较弱；总分不能掩盖核心主张未获支持。

## 审稿期望怎样进入评分

按 [DESIGN_BASIS](../docs/DESIGN_BASIS.md) 的来源分级提取 expectation：稳定 ID、具体要求、`applies_when`、来源引用和强度。
逐篇给出 `applicable`、`met / partial / unmet / unknown / challenged_with_evidence`、理由、证据及映射的评分项。
没有真实 review 也使用论文实践/局限归纳出的审稿期望；不能把它写成实际 reviewer 原话或录用因果。
期望是针对主张的检查问题，不是对所有论文的统一清单。允许有证据地挑战常规基线/评测方式。
`not_applicable` 必须解释主张与范围；**不能临时删评分轴、缩分母抬分**。冻结的类型解释决定如何评价。

## 主张类型与留存结论

- `system_method`：评价所声称的系统变化与闭环结果；声称 retained 必须追踪选择/留存/后续任务，只有选择集提高不能称 retained。
- `component_training`：评价接口、数据/教师可见性、训练与部署、组件效果；不声称在线成功就不强求在线标签，不把组件结果外推成整机能力。
- `evaluation_resource`：G 是真实评测缺陷，M 是任务/指标/验证器如何修复，X 是协议与标注执行，E 是真值核验、对照审计、独立覆盖、误差与成本；没有自有 agent 不扣分。
- 负结果/审计论文按其中心主张是否被支持评价，不以正向提升为入选前提。

`claim_support = supported / scoped / unsupported / contradicted / unresolved`，与分数并列。
`scoped` 必须同时保留作者原主张与证据支持的窄结论，不改窄原主张重算高分。
`evidence_level` 按 [EVIDENCE](../docs/EVIDENCE.md) 原规则单列，不加标签奖励。
只有实际阅读证据支持时才给 retained / improver / online / transfer；作者报告与我们实际复现永远分开。

## 算术与缺失

`S = (wG*rG + wM*rM + wX*rX + Σ evidence_weight_j*rE_j) / 4`，显示一位小数，内部保留未四舍五入值。
权重总和 100；E 的子项权重和必须等于 wE。coverage 是已判定项的权重之和 / 100。
未知项按 0 和 4 分别算区间 L/U；只要仍有 unknown，总分为 null，不能用区间中点排名。
`not_reported` 仅在对应完整材料及相关附录被查过、搜索范围记录后成立；对应适用项可计 0。
材料缺失写 needs_fulltext / needs_evidence；找不到全文不能伪装为论文没做。没有报告失败不等于没有失败。
代码链接、star、venue、名气、录用结果、模式录用率、旧分数、海报质量不进入算式。

## 校准、冻结与实施边界

1. 先审计既有卡片/期望的来源；为适用期望建立到 G/M/X/E 的映射。先做这一层，再评论文。
2. 每项目预登记 6 篇开发 + 12 篇留出，覆盖类型、机制、证据强弱、缺材料和无匹配模式；开发集用于修订锚点。
3. 生产和校准均使用用户指定双席：6.1 Sol 与 Sonnet 5.5 对同批全文独立初评，Opus 5.5 逐篇核查并聚合。两席不互看，Opus处理所有实质分歧，不平均消解；详情见 [总控提示词](../docs/agents/LOCAL_SCORING_PROMPT.md)。
4. 冻结候选前补齐每项 0/2/4 实例；记录 rubric、卡片、期望、材料、模型和会话版本/hash。
5. 建议验收：版本/引用绑定错误为 0，关键语义分歧已解决，缺材料不会出分；至少 8 个可评分留出对，中位差 ≤5，至少 90% 差 ≤10。
   同模型独立上下文仍非人工 gold；这些是一致性工程门槛，不证明科学正确。两轮未过则停批量并诊断。
6. 冻结后按 BATCH_CONTRACT 核对结构与算分，使用执行端已有能力逐批重评；不以新建调度平台为前提。日常 agent 不能随意改 rubric/卡片以让论文通过。
7. 评分审核完成后才按 [REEL_SELECTION](../docs/REEL_SELECTION.md) 选题。调阈值不改权重，不重算模型判断。

当前只交付设计、工作表与提示词；未实现新 scorer/selector/publisher，也未运行 Open Scientist study 或开始批量重评。
