# gui：领域卡匹配索引

从现有卡片直接提取名称和操作签名，剔除录用/论文数量等统计；按需回原卡看适用条件和反例。它是检索入口，不替代完整卡片或原文证据。

| 主卡 ID | 名称 | 操作签名 |
|---|---|---|
| gui:agent_initiated_user_interaction | Let the Agent Decide When to Involve the User | add an ASK / intervention channel to the action space (or a per-step confidence head) → build need-to-ask labels (human annotators, ambiguous-task synthesis by deleting instruction content, or critic-scored probing) → train or prompt the decision → insert the user's answer or actions into the history → score task success together with ask timing/precision and human step share, against autonomous and always-human baselines |
| gui:agent_loop_context_control | Structure the Prompted Agent Loop: Context, Hierarchy and Post-Action Reflection | observe → (describe) → reason over plan / progress summary → act → reflect on before/after state → update summary and focus memory → manager replans or worker continues → self-declared stop |
| gui:calibrate_simulator_to_real | Calibrate a Simulator or Digital Twin to the Real Target | reconstruct the target environment (task-scoped) → replay/compare against real logs → learn residual or calibrate/debias → train or evaluate in the twin → co-train or validate on real data |
| gui:environmental_injection_attacks | Hijack Agents Through the Environment and Measure Attempt vs Completion | pick the channel the attacked stage reads (HTML attribute / rendered UI / writable content / image) → place the injection near the target or at the trigger page (optionally optimise or retarget it) → run the agent → score attempt (judge or intermediate measure) and completion (executable check of the adversarial goal) → attribute success to components |
| gui:experience_memory_retrieval | Retrieve Past Experience and Knowledge into Context | run episodes (often self-supervised exploration) → summarise / embed and store keyed by task/state → retrieve nearest experience (+ web knowledge) → plan subtasks and act → replan on failure |
| gui:exploration_driven_task_synthesis | Synthesise Tasks from Exploration and History | explore the environment (random, DFS, instrumented) → store history/coverage → infer or propose intents/instructions → filter by feasibility, difficulty, judge → execute and train |
| gui:high_resolution_target_localisation | Localise Small Targets with Resolution, Zoom, Verification and Pointer Heads | encode the screenshot (low-res global view + high-res detail channel, or with redundant tokens skipped) → propose a target (coordinate tokens or patch attention) → crop/zoom around the proposal → re-ground or verify the crop against the goal → click the first verified target |
| gui:injection_defense_isolation | Defend Agents Against Untrusted Observations: Prompting, Gating and Isolation | identify untrusted inputs → (in-context) mark, paraphrase or detect them / (gating) mark sensitive actions PENDING for user confirmation / (isolation) label data, hide it behind variables, query it via a quarantined LLM with typed outputs, check calls against flow policies or fix a branching plan before observing → measure ASR and benign utility under attack |
| gui:learn_and_train_in_gui_world_model | Learn GUI Dynamics and Train in Them | harvest real (s, a, s') transitions (often goal-free) → train a next-state predictor (text diff, HTML, slots) or transition objective → roll out the policy in imagination or pretrain on transitions → fine-tune with real data as anchor |
| gui:learned_outcome_and_process_judges | Reward with Learned Outcome and Process Judges | collect trajectory (final/key screenshots, history, live terminal state) → judge success per trajectory or per step (single, ensemble, agentic probe, PRM) → use as reward, filter or weight → validate judge against humans |
| gui:mine_human_screen_videos | Mine Human Screen Recordings into Action Knowledge | find recordings (how-to posts → video search, or record one demo) → filter (screen visible, no occlusion, platform) → key-frame detection (OCR-text change, frame similarity, pixel change) → element/cursor detection + OCR (set-of-marks) → (a) VLM infers per-transition actions with narration and neighbouring frames → pretrain/SFT, or (b) sliding window of demo frames in context + reflection against the demo → act |
| gui:online_evaluation_methodology | Make Online Evaluation Discriminating | validate/clean tasks and attach reference lengths → fix step budget and resettable environment → run agents (or roll out world models closed-loop) → stratify, perturb with matched pairs, audit failure causes |
| gui:planner_grounder_interface | Decouple Planning from Grounding and Redesign the Action Interface | planner emits action + NL target description → grounder (trained on rendered-structure data) maps it to coordinates on the raw screenshot; or the action space is redefined (element tags, tool library) → execute |
| gui:rule_reward_single_step_rl | Reinforce Single-Step Actions with Rule-Checked Rewards | pool existing grounding / step-level datasets → sample the base model k times per state and keep informative (hard, not all-correct) samples → sample a response group per state → score with rule rewards against the label → GRPO update (optional SFT warm-up, KL) → evaluate on grounding and offline step benchmarks |
| gui:simulated_lookahead_selection | Select Actions by Simulated or Verified Lookahead | sample k candidate actions/trajectories → simulate next state (K01) or score directly with a verifier (K02) → rank → execute/submit the argmax |
| gui:structured_screen_observation | Expose the Screen as Indexed Elements and Pruned Structure | enumerate elements from a structural API or parse pixels (detector + OCR + captions) → assign ids / draw marks with text descriptions → rank, prune or restructure the list → policy selects an id or multiple-choice candidate → execute on the element (or its centre); probe pixel-vs-structure conflicts |
| gui:trajectory_level_policy_training | Train the Policy on Own, Replayed and Corrected Trajectories | initialise from SFT/offline data → roll out (online, semi-online over expert traces) → filter, relabel, augment with reasoning or first-error corrections → update with constrained RL, SFT or DPO |
| gui:verifiable_execution_reward | Ground Reward in Executable Checkers | define goal conditions over privileged state (or start from an evaluator library/spec) → generate task (and environment code) satisfying it → run agent → score with checker (binary or partial credit) → validate checker against faulty and legal alternatives |

主卡原文：`patterns/main/<id>.md`。子卡候选从主卡的 Sub-patterns 表中选择，按需读取 `patterns/sub/<id>.md`，输出 `gui:<id>`。仅使用本领域卡 ID；原 ResearchStudio taxonomy 不参与评分。
