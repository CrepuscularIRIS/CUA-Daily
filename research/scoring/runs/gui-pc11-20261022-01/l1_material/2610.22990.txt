title: PersonaCUABench: Benchmarking Computer-Use Agents Serving Diverse Personas
source: https://arxiv.org/abs/2610.22990

§Abstract
Computer-use agents (CUAs) are commonly evaluated against fixed task specifications, but users may omit requirements, add constraints, or require approval before consequential actions. Completing the benchmark instruction does not guarantee serving the person who asked. We introduce PersonaCUABench, which holds 74 tasks across 11 domains fixed and varies only who asks. A persona agent, playing one of 44 personas in four groups, rewrites each instruction in that user's own words and answers the CUA's questions, while the CUA sees only the dialogue, never the profile or the original instruction. Across nine backbones (3,330 runs), mean task completion falls by 36% relative to the original requests. The losses have two sources: in 59.9% of cells that lose points, the agent engages with what the user asked for and still gets it wrong, and 11.2% are stops the user requested that the checker scores as failures. Even when a persona request is fully completed, the user gives the top satisfaction rating in only 62.7% of cells, against 84.1% for the original requests. CUAs should therefore be evaluated not only on task completion but also on whether they meet the requirements and constraints users express. Code: https://github.com/MatrAIx-ai/PersonaCUABench. §Introduction (from cached fulltext; cut at ~9000 chars)
Computer-use agents (CUAs) increasingly perform multi-step tasks in web browsers and desktop applications, from gathering information to making reservations and sending messages ( Garg et al., 2025 ) . Existing benchmarks primarily evaluate whether agents complete predefined tasks ( Zhou et al., 2024 ; Xie et al., 2024 ) , including increasingly challenging long-horizon settings ( Jang et al., 2026b ; Yuan et al., 2026 ) . In real-world use, however, users may express goals incompletely, introduce personal constraints, or request confirmation before consequential actions. Satisfying a predefined task specification can therefore differ from serving the person who made the request. A fixed specification cannot reveal this gap, which raises our question: when different people ask a CUA for the same task in their own words, does it serve each of them, or only the task? Serving the person is harder than completing a fixed specification. The agent must infer what the user leaves unsaid and judge when to ask or confirm before acting, and for a CUA these judgments are consequential: a misread request can mean money spent, an email sent, or more disclosed than the user intended ( Goel and Gurevych, 2026 ; Hu et al., 2026 ) . Success is also user-dependent. An agent that drafts an offer and stops may fail a checker written for sending it, yet do exactly what a cautious user asked. Completing the specified task and serving the person can thus come apart, so an evaluation of CUAs needs to measure both. Prior work makes agents personal by giving the agent stored information about the user: a logged profile, a long-term history, or a logged-in environment ( Cai et al., 2025 ; Kim et al., 2026 ; Jang et al., 2026a ) . We give the agent no profile. It learns who the user is only from the request and from the user’s answers to its questions. Each user is built from attributes of the MatrAIx persona schema ( Li et al., 2026 ) . Holding the task fixed and changing only who asks isolates the effect of who is asking. We introduce PersonaCUABench (Figure 1 ), built around a persona-conditioned request protocol: a persona agent is given a profile and the original instruction, writes the opening request in that person’s own words, and answers the CUA’s clarifying questions in character, so the CUA works only from the dialogue. The tasks come from existing benchmarks so that outcomes stay independently checkable: information tasks on live websites and action tasks on sandboxed replicas of real sites, across everyday and work scenarios in 11 domains. Each task is asked by the four personas of its domain, one per group ( expert , senior , young , practical ), and by an original request that passes the instruction unchanged, without a persona. Because a request can leave requirements unsaid, we score whether the user raised each requirement, whether the agent engaged with it, and whether it was met, and we report this diagnosis alongside task completion and the user’s own satisfaction. Evaluating nine backbones in one shared browser harness, we find that a persona-phrased request lowers average task completion from 0.689 to 0.441 with every backbone losing between 28% and 45%. The diagnosis locates two sources of this loss: in 59.9% of the cells that lose points the agent engages with what the user raised yet still gets a requirement wrong, while another 11.2% are stops the user asked for that the original checker counts as failures. We further find that task completion and user satisfaction diverge in both directions and that, on GPT-6 Astra, neither revealing the user’s profile nor requiring a clarification question is sufficient to recover the loss in task completion. PersonaCUABench thus provides a controlled testbed for personal CUAs: it compares different personas on the same tasks, diagnoses how user requirements are handled, and measures task completion and user satisfaction.
