title: ZoneClaw: Mitigating Persistent Memory Attacks by Establishing Memory-Zoning in OpenClaw-Style Computer-Use Agents
source: https://arxiv.org/abs/2610.00450

§Abstract
Computer-use agents increasingly operate as long-running assistants through persistent workspace memory, which OpenClaw-style CUAs realize as automatically reloaded files that hold user instructions, system summaries, and external claims at the same privilege level. Here, remembering a claim confers authority over later behavior. This enables a persistent memory attack, in which an attacker who controls only benign-looking external content induces the CUA to record attacker-favored claims during a legitimate task, and those claims later govern benign tasks the attacker never touches. The attack chain extends "malicious context -> malicious response" into "malicious context -> memory injection -> malicious execution", making this a cross-environment threat. Existing defenses studied intervene either before content enters memory or at the action it later induces, not whether stored content may guide action. We propose ZoneClaw, which separates persistence from authority by replacing flat workspace memory with hierarchical trust zones carrying explicit authority levels. External claims persist in a low-trust zone and acquire action-guiding authority only by crossing an explicit authority boundary, at which promotion is cross-checked against zones the attacker cannot directly write. Role-specific processes of asymmetric privilege enforce this boundary, ensuring that no process both ingests external content and acts outward. Across four attack scenarios, two injection settings, and four backbones, ZoneClaw drives ASR from 372/480 to 6/480 while retaining utility in 458/480 trials, and remains effective against some defense-aware attackers. Attacker claims still persist in low-trust memory yet rarely cross the authority boundary, showing that ZoneClaw withholds authority rather than refusing to learn from the environment. Our code is available at: https://github.com/euph00/ZoneClaw-code.

§Introduction (from cached fulltext; cut at ~9000 chars)
Fueled by advances in large language models (LLMs), computer-use agents (CUAs) are moving from session-bound chatbots toward long-running agents operating across real-world environments ( Xie et al., 2024 ; Zhou et al., 2024 ; Xia et al., 2025 ; Zhang et al., 2026a ) . Beyond in-session tool usage, modern harnesses enable CUAs to update workspace memory that persists across environments and is automatically reloaded into subsequent contexts ( OpenClaw, 2026a ; Wang et al., 2026 ) , retaining user preferences, and tool configurations after the context window is cleared. OpenClaw ( OpenClaw, 2026b ) exemplifies this design with Markdown files that the CUA reads at startup and updates during execution. However, this mechanism introduces a new persistent memory attack : untrusted content written into persistent memory later re-enters the CUA’s operating context and governs subsequent decisions. The attacker never tampers with workspace files or user instructions, controlling only the benign-looking external content that the CUA may inspect during legitimate execution, such as emails or forum posts. This is fundamentally a cross-environment threat , where the poisoning and execution occur in separate environments bridged only by persistent memory. The attack chain extends from the prompt-injection pattern of malicious context \!\Rightarrow\! malicious response ( Greshake et al., 2023 ) to malicious context \!\Rightarrow\! memory injection \!\Rightarrow\! malicious execution . Considering that the poisoned content triggers no unsafe action when introduced, the harm emerges only when a later benign task reloads it as trusted operating context, turning the CUA’s self-evolving memory against itself. Recent works have revealed that CUAs are vulnerable to adversarial content in webpages, tool outputs, and workspaces ( Zhang et al., 2025 ; Shi et al., 2025 ; Wei et al., 2026 ; Liu et al., 2025 ) , motivating defenses that screen persistent writes or block unsafe actions ( Cheng and Tsao, 2026 ; Zhao et al., 2026 ; Liu et al., 2026b ) , while memory-poisoning studies further show that retrieved memory, skills, and tool configuration can be compromised ( Dong et al., 2025 ; Wang et al., 2026 ) . These defenses screen content before it enters memory or guard the induced actions, leaving the authority between them ungoverned. Our preliminary study shows why this matters, as a seeded convention is adopted in 14/30 tasks and suppressed only when a countervailing claim already exists in memory or instruction ( cf. Section 2.2 ). Remembering therefore confers authority by default, and revoking it requires the user to anticipate the unwanted behavior in advance. This gap motivates a trust-aware perspective on persistent memory: securing OpenClaw-style CUAs requires not only guarding the injection boundary, but also preventing injected content from silently acquiring authority over later actions. To this end, we propose ZoneClaw , a memory-zoning framework that restructures the equally-privileged workspace memory of OpenClaw-style CUAs into hierarchical trust zones with explicit authority levels. The core principle is to prevent low-trust memorized content from silently escalating into high-trust operational policy, rather than to block all suspicious writes, since CUAs must self-evolve through continuous interaction with external environments. Concretely, ZoneClaw partitions the persistent workspace memory into three trust levels, comprising an immutable user-authored policy zone that anchors the CUA’s authority semantics, a trusted zone that holds operational memory corroborated against the policy zone and existing trusted content, and a low-trust zone that retains externally extracted claims for reference without granting them action-guiding authority. It further aligns these zones with four role-specific processes of asymmetric privilege, where a Planner decomposes user instructions and an Executor carries out the resulting subtasks, both relying solely on high-trust memory, an Observer records external claims into the low-trust zone without performing outward actions, and a Gatekeeper governs whether such claims may be promoted to the trusted zone based on their consistency with high-trust memory. ZoneClaw thereby guards three trust boundaries, spanning from external environments to persistent memory, from low-trust observations to authority-bearing memory, and from authority-bearing memory to future actions. Extensive experiments across four attack scenarios, two injection settings, and four LLMs shows that persistent workspace memory forms a reliable cross-environment channel, where vanilla OpenClaw commits attacker-favored content that affects the later benign session at 372/480 ASR while every representative defense either admits substantial ASR or sacrifices utility somewhere.
