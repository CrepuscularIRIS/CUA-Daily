title: Not All Graphs Are Maps: A Task-Agnostic Exploration Framework for Mobile GUI Navigation
source: https://arxiv.org/abs/2610.22672

§Abstract
Modern mobile GUI agents can perceive visible screens and execute local actions, but they still lack persistent app-specific navigation knowledge: where functions live, which pages contain them, and which screens are equivalent across repeated visits. We introduce TAG-Nav, a Task-Agnostic Graph Navigation framework that wraps existing GUI-agent backbones with reusable destination memory. Offline exploration is distilled into compact records of app functions, target pages, and waypoint routes before any evaluated instruction is seen. When a future task's destination is covered, TAG-Nav retrieves the destination and provides route guidance without task-specific demonstrations. This separates mobile GUI destination navigation from full task completion: many tasks share the prefix of reaching the right page, while final actions may enter content, send data, make purchases, delete information, or change sensitive settings. To evaluate route finding without downstream execution confounds, we introduce DestBench, a navigation-only protocol that asks whether an agent reaches the correct pre-action destination screen. DestBench enables a controlled graph-memory study comparing no-memory agents with random, automated BFS, and clean graph memory. Graph-derived memory improves strict navigation success rate of UI-TARS-1.5-7B from 52.4% without graph memory to 58.3% with automated BFS memory, and improves Qwen-VL-Max success rate from 59.5% to 71.4% on the same conditions. Together, TAG-Nav and DestBench show that destination coverage and route cleanliness strongly shape graph-memory value, making graph quality a measured variable rather than an assumed benefit of exploration.

§Introduction (from cached fulltext; cut at ~9000 chars)
Modern multimodal GUI agents perceive screens and execute visible actions well, but they lack a persistent map of the apps they operate ( Zhang et al., 2025a ; Wen et al., 2024 ; Qin et al., 2025 ) . When asked to reach a deep setting, account-management page, privacy control, or app-specific tool, the agent must re-infer where the function lives and how to navigate there from the current screen on every task. Many user requests share the prefix of arriving at a destination before any task-specific (and often sensitive or irreversible) final action: reaching an account-privacy screen is reusable navigation, while toggling the control itself is task-specific execution. We study mobile GUI destination navigation as a problem distinct from full task completion, focused on whether the agent reaches the correct pre-action destination screen. The standard response is to explore the app offline and retrieve from the resulting graph ( Wen et al., 2024 ; Guan et al., 2025 ; Xie et al., 2025 ; Chen et al., 2025b ) , but exploration does not automatically yield a useful map: a large random graph can have low target coverage and noisy routes, while a small clean graph can be highly navigable. Two graph-construction properties decide whether explored memory actually helps: target coverage of the destinations users request, and route cleanliness from the app root to those destinations. We argue that graphs satisfying both, built by task-agnostic breadth-oriented exploration and post-processed into destination-anchored deduplicated routes, are the design that turns offline exploration into navigation memory that wraps any visual GUI actor. TAG-Nav explores apps with task-agnostic local breadth-first search (Local-BFS) and post-processes the result into compact destination records (target page summary, intents, waypoint route, transition hints); at inference time the matching record is injected as plain text into an unmodified backbone such as UI-TARS ( Qin et al., 2025 ) . The retrieved unit is a destination plus its route, not a per-task trajectory replay, so TAG-Nav can be evaluated under different graph-construction conditions while holding the actor and task set fixed. To evaluate this design on real apps, we introduce DestBench, a navigation-only protocol on real Android apps that judges whether the agent reaches the correct pre-action destination screen, with graph-aware target coverage and route cleanliness diagnostics. End-to-end task benchmarks would otherwise conflate memory quality with downstream execution, blurring the properties we want to measure.
