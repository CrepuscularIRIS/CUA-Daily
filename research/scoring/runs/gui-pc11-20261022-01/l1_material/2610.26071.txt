title: CUA-Lite: An Open Platform for Computer Use Agents
source: https://arxiv.org/abs/2610.26071

§Abstract
Open resources for computer use agents (CUAs) -- environments, datasets, and models -- remain scattered: without a standard, these resources cannot be integrated and scaled; additionally, evaluation, RL, and SFT cannot share one infrastructure. We present CUA-Lite, an open platform for developing CUAs, built around three standardized abstractions: (1) Unified environment interface, under which we integrate 12 benchmarks across desktop, browser, and mobile, plus lightweight VM-free sandboxes that replicate OSWorld's desktop at much lower cost, providing over 30,000 verifiable tasks. (2) Unified supervised data format, into which we convert the major public CUA datasets, from GUI grounding and understanding to full rollouts, and record our fresh rollouts from frontier CUAs on these verifiable environments. (3) Model harnesses shared across evaluation, RL, and SFT, one per model and implemented for 14 model families. Each harness runs its model in these computer environments, producing the rollouts that evaluation and RL consume, or renders stored supervised data into the model's own training format for SFT. We release reference scores across the integrated benchmarks, and show that RL and SFT through the same harness improve open-weight models. We release our dataset, code, and models, and the platform is open to contributions.

§Introduction (from cached fulltext; cut at ~9000 chars)
Computer use agents (CUAs) operate desktop, browser, and mobile applications in computer environments. Developing CUAs requires environments with verifiable tasks, supervised data, and models, each with a harness that runs the model in an environment. Open resources exist for all three: environments on desktop ( Xie et al., 2024 ; Yuan et al., 2026 ; Bonatti et al., 2025 ; Li et al., 2025 ; Xie et al., 2025 ; Wang et al., 2026 ; Lv et al., 2026 ; Aggarwal et al., 2026 ) , browser ( Zhou et al., 2024 ; Koh et al., 2024 ; Liu et al., 2018 ; He et al., 2024 ; Bai et al., 2026 ) , and mobile ( Rawles et al., 2025 ; Xu et al., 2025a ; Kong et al., 2026 ; Wu et al., 2026 ) ; supervised datasets, from GUI grounding labels to full rollouts ( Deng et al., 2023 ; Xu et al., 2025b ; Wang et al., 2025c ; Mu et al., 2025 ) ; and models, from specialist CUAs ( Qin et al., 2025 ; Wang et al., 2025c ; Liu et al., 2026a ; Xue et al., 2026 ) and vision–language models (VLMs) ( Bai et al., 2025b ; Bai et al., 2025a ) to API models with their own native computer use tools. However, these resources remain scattered: each environment has its own interface and runtime (e.g., a virtual machine (VM), a browser, a mobile emulator); each supervised dataset its own format; each model its own action space, prompt format, and rollout code. Without a standard, connecting models to environments means rewriting the same code: an action mapping, context management, and a rollout loop. Therefore, open resources cannot be integrated and scaled; additionally, evaluation, reinforcement learning (RL), and supervised finetuning (SFT) cannot share one infrastructure. To address this gap, we present CUA-Lite, an open platform for developing CUAs built around three standardized abstractions (Figure 1 ): CUA-Lite unifies environments under one interface, Lite.Gym ; supervised data under one format, Lite.Sample ; and adapts any model to the environment interface and the data format through the model’s own harness. (1) Unified environment interface. Lite.Gym (§ 2.1 ) exposes an environment as a Gym-style reset , step , and close loop ( Towers et al., 2025 ) . The loop standardizes one observation format across environments: a screenshot, text, or both. It also standardizes one GUI action space per platform, issued as tool calls (e.g., click and type on desktop and browser, or tap and swipe on mobile). Each environment can add extra tools of its own (e.g., bash in our desktop sandboxes). The loop wraps the environment’s own runtime: a VM, a browser, or a mobile emulator. We integrate 12 benchmarks across desktop, browser, and mobile, and add VM-free desktop sandboxes of our own. These Docker containers replicate OSWorld’s desktop at much lower cost and provide over 30{,}000 verifiable tasks for training (§ 2.1.2 ). (2) Unified supervised data format. Lite.Sample (§ 2.2 ) stores any supervised data, from GUI grounding and understanding to full rollouts, in one standardized format: multi-turn messages that interleave the model’s tool calls with the environment’s observations. We convert 9 major public CUA datasets ( Deng et al., 2023 ; Xu et al., 2025b ; Wang et al., 2025c ; Mu et al., 2025 ) and record fresh rollouts from frontier CUAs. (3) Model harnesses shared across evaluation, RL, and SFT. Each model has one harness (§ 2.3 ), the code that adapts the model to the environment interface and the data format. Through its harness, a model runs in every integrated environment, and its rollouts serve both evaluation and RL. The same harness renders any stored Lite.Sample, including other models’ rollouts, into the model’s own training format for SFT. Harnesses exist for 14 model families, including open-weight models (UI-TARS, Qwen, and others) and API models (GPT, Claude, and Gemini). We release reference scores for 15 models on the 12 integrated benchmarks (§ 3 ). We further demonstrate how the rollout data and the verifiable tasks of CUA-Lite improve an open-weight computer use agent, by SFTing Qwen3.5-4B on GPT-5.5 rollouts and then training it with GRPO on our verifiable tasks (§ 4 ). We release our dataset, code, and models, and welcome contributions.
