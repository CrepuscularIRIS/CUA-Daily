title: Web$hell: A Unified Interface for Agentic Web Access
source: https://arxiv.org/abs/2610.13416

§Abstract
Large language model (LLM) agents are becoming direct users of the open web. As they take on increasingly complex and information-intensive tasks, effective web access is becoming a core capability for agentic problem solving. Existing approaches have advanced agentic web access through different access models, including search-augmented agents, browser-based agents, and, more recently, filesystem-based agents. Nevertheless, as users expect agents to complete long-horizon, end-to-end tasks, they increasingly need to conduct broad information gathering, perform browser actions, and revisit acquired evidence within a single trajectory. Yet our preliminary analyses reveal that existing access models struggle to meet these demands. They primarily support either information gathering or browser interaction, while combining their capabilities can involve substantial costs or performance trade-offs. To this end, we present Web\$hell, an interface that unifies web access under a single access model. Using a common schema defined by WebContract, WebCompiler compiles live webpages into addressable information and action objects. These objects are maintained in WebCache and handled through a shared set of operations, providing agents with consistent, operable, and persistent web access. Through extensive experiments across web search, web navigation, and deep research benchmarks, we show that Web\$hell achieves strong task performance at lower cost. Our results further indicate the importance of interface design for effective web access, with Web\$hell opening new possibilities for more capable and efficient LLM agents on the web.

§Introduction (from cached fulltext; cut at ~9000 chars)
Large language model agents are becoming direct users of the open web. As they take on increasingly information-intensive and open-ended tasks, effective web access is becoming a core capability for agentic problem solving ( Deng et al., 2023 ; Kim et al., 2026 ) . Yet making effective use of the web is far from trivial, requiring substantial reasoning to locate information and interact with heterogeneous webpages. This raises a fundamental question of how agents should access the web. Existing research has approached this problem through different access models . Search-augmented agents ( Li et al., 2025a ; Jin et al., 2025 ; Zheng et al., 2025 ) operate through search APIs and cleaned text, while browser-based agents ( Zhou et al., 2024 ; Yang et al., 2025 ; Chae et al., 2025 ) operate through page observations and actions. More recently, filesystem-based methods ( Liu et al., 2026 ) have enabled agents to store web documents and selectively inspect their contents through shell operations (e.g., grep , read ), reducing the need to read the entire contents. For the most part, these lines of work have made substantial progress within their respective access models. However, as users expect agents to complete long-horizon, end-to-end tasks, agents are increasingly required to perform multiple forms of web access within a single trajectory. For example, a shopping query may require an agent to discover relevant products, navigate pagination to find reviews, and retain useful information for later comparison. Yet these capabilities have largely been developed through separate access models, motivating a rethinking of how they can be integrated for agentic web access. Accordingly, this paper begins by investigating how well existing access models generalize across web search and web navigation, two representative types of web tasks. The key bottleneck is that each access model supports certain capabilities at the expense of others. We find that (i) search-augmented and filesystem-based agents struggle with web navigation since clean-text representations often omit page controls, while browser-based agents are less effective at broad information gathering due to their lengthy, noisy observations; (ii) combining search and browser-based access broadens task coverage but incurs substantial costs from repeated webpage interpretation; and (iii) adding filesystem-based capabilities such as grep reduces these costs. However, selective inspection can miss the context needed to use page controls, degrading web navigation performance. Together, these findings highlight three requirements for integrating the capabilities of existing access models. First, operability requires supporting both efficient information gathering and effective webpage interaction. Second, consistency calls for unifying webpage representations under common schemas, reducing the need to reinterpret the same page. Finally, persistence requires retaining retrieved web documents for selective access, lowering cost while preserving operability. To this end, we present Web$hell , an interface that unifies web access under a single access model. Our key idea is to provide agents with an intermediary that standardizes webpage representations and browser actions. Instead of coordinating separate access models, agents interact with Web$hell through a request-response loop. Specifically, WebContract defines how information and available actions are represented as objects, organized into pages, and accessed through shared operations. Each object combines a value , an address , and associations that preserve its context and references to related objects. Following this contract, WebCompiler transforms live webpages into structured representations using deterministic rules derived from HTML semantics. WebCache then retains the compiled pages for selective access and reuse throughout a task. Importantly, Web$hell allows agents to use object addresses to specify which information to inspect or which action to execute in subsequent requests. The interface then carries out the requested operation on the agent’s behalf and returns the outcome, thereby enabling unified agentic web access. We conduct extensive experiments on six benchmarks spanning web search, web navigation, and deep research. Notably, Web$hell achieves the highest task performance on all six benchmarks at comparable or lower cost. Our analyses suggest that an effective web interface should make clear how webpage elements relate to one another. These connections help agents gather more evidence, make browser actions more intuitive, and potentially guide exploration beyond the content already inspected. We further show that Web$hell remains robust to irrelevant content and maintains its efficiency as retrieved documents accumulate.
