title: ActionEngine: From Reactive to Programmatic Web Agents via State Machine Memory
source: https://arxiv.org/abs/2602.20502

§Abstract
Many web agents operate through a reactive execution loop: they observe the current interface, reason about the next action, execute it, and repeat. This design incurs latency and cost that grow with the number of actions, while requiring agents to repeatedly rediscover how the same web application works. We present ActionEngine, a novel architecture that replaces step-by-step reasoning with programmatic execution using reusable knowledge of the application. A Crawling Agent explores the application offline and constructs an updatable state-machine memory that represents its GUI states, the operations available in each state, and the transitions between states. Unlike trajectory memory, this representation stores how the application works rather than solutions to individual tasks. At runtime, an Execution Agent uses this memory to synthesize a complete executable program in a single planning step, which is then executed deterministically without further planning calls. When the interface changes or the memory is incomplete, a reactive fallback repairs the failed action and updates the memory for future tasks. On 655 tasks across four WebArena domains, ActionEngine achieves a 91.2% success rate, outperforming the strongest reactive baseline, Claude Code, by 8.5 percentage points while reducing average task latency by 3.2x and cost by 8x.

§Introduction (from cached fulltext; cut at ~9000 chars)
LLM-based web agents automate browser tasks by observing web pages and performing actions such as clicking, typing, and extracting information Nguyen et al. (2025) . Most web agents follow a reactive execution paradigm: the agent observes the current page, reasons about the next action, executes it, and repeats Yao et al. (2022) . This is a natural approach to an unfamiliar task or environment, where the agent must explore and adapt to what it observes, much like a user encountering an application for the first time. However, web applications are not entirely new each time they are used. Tasks within the same application share a relatively stable structure: the same pages, controls, operations, and navigation paths recur across tasks. Reactive agents do not fully exploit this structure. They repeatedly rediscovers how the application works, invoking the LLM throughout execution. As a result, their cost and latency grow with the number of actions, and errors can accumulate over long trajectories Cheng et al. (2024) ; Tao et al. (2023) ; Shinn et al. (2023) ; He et al. (2024) . Prior work reuses experience by storing demonstrations or trajectories from previous executions Zheng et al. (2023) ; Gu et al. (2024) ; Chae et al. (2024) . However, a trajectory packages together the decisions made for one particular task; a new task may reuse only some of its actions, possibly in a different order or context. We argue that representing the application itself offers a more compositional form of reuse. For example, knowledge of how to search for a product, read its reviews, and edit its description can be recombined into workflows that were never previously executed. This leads to our central question: Can web agents replace step-by-step reactive reasoning with offline application knowledge and one-shot planning? We present ActionEngine , an architecture that moves application discovery offline and uses the resulting knowledge to plan and execute new tasks programmatically ( Figure 1 ). A Crawling Agent explores a web application and constructs an updatable state-machine memory . The memory represents the application’s interface states, the operations available in each state, and the transitions between states. To keep this memory representation compact, ActionEngine separates page templates from dynamic content: for example, different product pages are represented as instances of the same underlying state. Unlike trajectory memory, state-machine memory captures task-independent knowledge of how the application works, allowing operations learned from different interactions to be composed into programs for new tasks. At runtime, an Execution Agent uses this memory to synthesize a high-level program sketch in a single LLM call. A deterministic compiler then grounds each step of the sketch against operations in the state-machine memory to produce an executable plan, which runs without further model calls. In the common case, this changes the unit of LLM reasoning from one call per action to one call per task. Planning against an application-level model also gives the agent access to states and transitions beyond its current observation, rather than requiring each decision to be made locally from the current page. When the memory is incomplete, the interface has changed, or execution depends on information that could not be anticipated, ActionEngine falls back to reactive reasoning. Successful repairs to stale or incorrect application knowledge are incorporated back into the memory for future tasks. We evaluate ActionEngine on 655 tasks across four WebArena domains Zhou et al. (2023) . Using the same backbone model, ActionEngine achieves a 91.2% success rate, 8.5 percentage points higher than the strongest reactive baseline, Claude Code, while reducing average task latency by 3.2\times and query-time cost by 8\times . The offline construction cost is amortized over repeated use: across the evaluated applications, ActionEngine recovers the one-time crawling cost after 39–101 tasks through lower per-task execution cost. Our analysis also reveals the boundary of programmatic execution: tasks that depend on unpredictable or noisy search results remain difficult to plan completely in advance and often benefit from reactive observation and adaptation. Our contributions are threefold. First, we introduce state-machine memory , a task-independent and compositional representation of an application’s interface states, operations, and transitions that allows application discovery to be amortized across tasks. Second, we present ActionEngine , an architecture that automatically constructs and maintains this memory and uses it to synthesize and execute complete task programs with a single planning call, falling back to reactive reasoning when necessary.
