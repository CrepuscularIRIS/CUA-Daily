title: Task-State Governance: A Virtual Machine for Verifiable and Recoverable GUI Agent Execution
source: https://arxiv.org/abs/2610.20100

§Abstract
Graphical user interface (GUI) agents now execute workflows across real applications, but when execution drifts, users must determine what changed, what should have remained untouched, and what can still be recovered. Plan-centric interfaces leave users supervising procedure, but users live with changes to application state. We introduce task-state governance, an interaction paradigm that represents a task as an editable contract linking desired outcomes, facts that must be preserved, and observed application state. We instantiate this paradigm in TaskVM, which projects live state into editable task controls, executes user edits as genuine interface actions, verifies outcomes through independent observation, and marks each action as reversible, compensatable, or irreversible. Across an automated contract benchmark, a controlled user study, and an open live-model exploration, the paradigm strengthened contract compliance and users' recovery control and trust, while execution outcomes were held constant. Task contracts open a design space for governable agent interfaces.

§Introduction (from cached fulltext; cut at ~9000 chars)
Consider postponing a project briefing by one day. The calendar entry and the team announcement must change, while a settled flight booking must remain untouched, and a collaborator may request a different date midway through execution. A revised plan does not, by itself, say which updates have already taken effect, which records must stay protected, and which effects can no longer be undone. As Figure 1 illustrates, users ultimately live with changes to the world, not with changes to an agent’s plan. Computer-use agents (CUAs) have made this delegation technically plausible at scale. Modern agents parse complex layouts, synthesize input gestures, and execute extended operational sequences across unfamiliar interfaces ( OpenAI, 2025 ; Cheng et al., 2024 ; Lin et al., 2025 ; Zheng et al., 2024 ; Deng et al., 2023 ; He et al., 2024 ; Rawles et al., 2025 ) . Interaction research has responded by opening execution up for oversight: co-planning surfaces let users revise procedural steps, ambient displays communicate agent status, and malleable or generative interfaces reorganize the workspace around the task ( Feng et al., 2026 ; Huq et al., 2025 ; Venkatesan et al., 2026 ; Chang et al., 2026 ; Kim et al., 2026 ; Jiang and Xia, 2026 ; Xu et al., 2026 ; Cao et al., 2025 ) . These designs make the agent’s procedure the object of interaction: what the user inspects and edits is what the agent will attempt next. Two gaps persist in this procedure-centric stance. First, editing a step changes what the agent will attempt, but it cannot express what the world must keep: boundaries on side effects, records that must remain untouched, and facts that should outlive the current plan have no representation in a list of actions. Second, completion and recovery rest on the agent’s own account. When the executor’s report is the only evidence, users cannot verify what actually changed, and undo is offered without a model of which effects can be restored, inviting the over-reliance that supervisory control research has long documented ( Bainbridge, 1983 ; Parasuraman and Riley, 1997 ; Parasuraman and Manzey, 2010 ; Lee and See, 2004 ) . Both gaps follow from one representational choice: the task is modeled as a sequence of actions, so the obligations attached to its outcome have nowhere to live. Our stance extends a lineage of work that treats the object, not the procedure, as the unit of interaction. Direct manipulation established that users reason about visible objects of interest ( Shneiderman, 1983 ; Hutchins et al., 1985 ) ; undo research made recovery a first-class design concern ( Abowd and Dix, 1992 ; Myers and Kosbie, 1996 ) ; and accountability research argued that systems should expose what they did so that people can judge it ( Bellotti and Edwards, 2001 ; Suchman, 1995 ) . We extend this lineage from artifacts the user operates to agents that operate on the user’s behalf. We call the resulting stance task-state governance: a task is represented as an editable contract among three state components, not as a procedure alone. The desired state holds the target values the user authorizes the agent to establish. The preservation scope pins application facts that must remain undisturbed. The observed state captures what running applications currently display. When the three are represented together, an edit becomes a checkable commitment: the system knows what it must establish, what it must not disturb, and what evidence will count as done. The plan remains useful, but as one revisable realization of the contract rather than as the task itself. We call the runtime that maintains this contract a Task Virtual Machine , and the name is deliberate about scope. It is not an operating-system virtual machine: it owns neither the full state of third-party applications nor the power to roll them back atomically. What it owns is the task’s obligation state and an honest account of evidence. Four commitments make the abstraction tangible. Editing a desired value does not assert that the world changed; desired and observed values sit side by side until fresh observation closes the gap. Marking a record as preserved lifts that constraint out of the agent’s plan and into independent verification. An executor’s completion report does not close a task; a separate verifier checks fresh screen evidence first. And a checkpoint is not time travel; recovery is expressed as the operations the environment actually supports. We realize this stance in TaskVM , a prototype that places the observed state of live applications beside editable task controls. The runtime compiles user edits into genuine interface gestures, so authority flows through the same rendered interface a human would use.
