title: Improving LLM-based Autonomous Web Agents with Filtering
source: https://arxiv.org/abs/2609.27770

§Abstract
Autonomous web agents, powered by Large Language Models (LLMs), have garnered significant attention for automating various web-based tasks with multi-step reasoning and decision-making capabilities. An open research question in the development of these agents lies in the format of the webpage input. Raw HTML source code, with its extensive and often irrelevant details, poses difficulties for LLMs with limited context windows. To address this challenge, we first reproduce baseline models such as GPT-3.5 and LLaMA-2-70B on the WebArena (Zhou et al., 2023) benchmark, identifying common failure modes. We then propose two retrieval strategies to filter out irrelevant context for LLM agents. We develop DeBERTa-based and T5-based models that rank HTML elements by their relevance to the task. We fine-tune them on Mind2Web trajectory data and transfer them to WebArena. Experiments show that our DeBERTa-based model improves the success rate of the LLaMA-2-70B LLM agent on WebArena from 1.97% to 2.96%. Moreover, we develop a zero-shot ColBERT-based retriever that is able to retrieve the ground-truth element with a recall of 0.52 on Mind2Web and 0.47 on WebArena.

There has been significant recent interest in developing autonomous language model agents for the web pmlr-v70-shi17a ; LiuGPSL18 ; webshopyao ; deng2023mind2web ; gur2023realworld ; webarena . These are agents powered by Large Language Model (LLM) backbones, capable of multi-step reasoning, decision-making, and taking actions within an environment (e.g., webpages on the Internet). Successfully building such agents would allow us to automate a wide variety of web-based tasks, improving human efficiency and augmenting capabilities. In order to develop a capable autonomous web agent, the format of the input observation for the LLM is a crucial first consideration. Currently, LLM baselines in WebArena (e.g., GPT-3.5 and GPT-4 reasoning baselines) ingest the information processed from the HTML source of the current screen of the webpage as the “observation” of the current state of the webpage (Figure 1 ). However, the information provided in HTML source code is often extremely detailed and verbose, and significantly fills up the LLM’s context window (often with information that is irrelevant to the task at hand). Information from the HTML source (e.g. style attributes, JavaScript code snippets, CSS-related code blocks) is often unrelated to the objective of a language model agent and serve as distractors, hindering the performance of the agent. In addition, due to the dynamic nature of most websites nowadays, a lot of the HTML elements are not actually visible in the rendered state of the web page (e.g., a navigation drawer where the user could hide and show information inside through clicking or hovering). Although the raw HTML source code is the most complete observation of the state of the website, it may not be the most suitable for LLMs and thus may not result in the best agent execution accuracy. In WebArena, they utilize better input data representations through extracting the simplified accessibility tree representation with the Chromium browser. As shown in Figure 1 , the accessibility tree (right), compared with the raw HTML source (middle), is a stripped-down version with only key hierarchical information, as well as inferred semantic information of what each element’s key role and information is about. This format of input representation is heuristically created from raw HTML and can already save a lot of context length burden for LLMs. It also has clearer types of elements like button, link, textbox, or tables, etc. For similar motivations as the previous project idea, a long HTML source tends to be an issue for the limited context length that LLM can consume. As a result, a more focused and high-efficiency input data representation is desired. In WebArena webarena , several techniques are already employed to shrink down the size, e.g. using an accessibility tree instead of raw HTML, only containing elements present in the current user viewport, etc. Along with this goal, we aim to investigate ways of finding relevant portions of the current input representation based on the user intent. For example, if the user intent is about finding flight tickets to New York, then ideally the input representation to the LLM should contain only the flight search part of a travel website. We hypothesize that with this in-page retrieval with intents, we could potentially have a more efficient input. There are also previous efforts for denoising HTML or filtering out irrelevant information. For example, Mind2Web deng2023mind2web and WebAgent gur2023realworld both train specific filtering or extractive summarization models for this goal of reducing input. However, without training data, we want to explore other possible ways, e.g. retrieval for selecting the most important part of the page, given user intent. As part of this work, we reproduced results of baseline models on the WebArena benchmark. In particular, we re-ran the GPT-3.5 baseline model and achieve comparable success rate to their paper. In addition, we also implemented inference with the LLaMA-2-70B touvron2023llama model, and report its performance on WebArena. Based off these results, we perform a comprehensive quantitative and qualitative analysis, highlighting common failure modes of the model when performing certain types of tasks.
