title: VLAA-GUI: Knowing When to Stop, Recover, and Search, A Modular Framework for GUI Automation
source: https://arxiv.org/abs/2604.21375

§Abstract
Autonomous GUI agents face two fundamental challenges: early stopping, where agents prematurely declare success without verifiable evidence, and repetitive loops, where agents cycle through the same failing actions without recovery. We present VLAA-GUI, a modular GUI agentic framework built around three integrated components that guide the system on when to Stop, Recover, and Search. First, a mandatory Completeness Verifier enforces UI-observable success criteria and verification at every finish step -- with an agent-level verifier that cross-examines completion claims with decision rules, rejecting those lacking direct visual evidence. Second, a mandatory Loop Breaker provides multi-tier filtering: switching interaction mode after repeated failures, forcing strategy changes after persistent screen-state recurrence, and binding reflection signals to strategy shifts. Third, an on-demand Search Agent searches online for unfamiliar workflows by directly querying a capable LLM with search ability, returning results as plain text. We additionally integrate a Coding Agent for code-intensive actions and a Grounding Agent for precise action grounding, both invoked on demand when required. We evaluate VLAA-GUI across five top-tier backbones, including Opus 4.5, 4.6 and Gemini 3.1 Pro, on two benchmarks with Linux and Windows tasks, achieving top performance on both (77.5% on OSWorld and 61.0% on WindowsAgentArena). Notably, three of the five backbones surpass human performance (72.4%) on OSWorld in a single pass. Ablation studies show that all three proposed components consistently improve a strong backbone, while a weaker backbone benefits more from these tools when the step budget is sufficient. Further analysis also shows that the Loop Breaker nearly halves wasted steps for loop-prone models.

§Introduction (from cached fulltext; cut at ~9000 chars)
The rapid advancement of multimodal large language models (MLLMs) has catalyzed a new generation of autonomous Graphical User Interface (GUI) agents ( Qin et al., 2025 ; Agashe et al., 2025a ; Wang et al., 2025b ; Wu et al., 2025 ; Hong et al., 2024 ) capable of performing desktop tasks by observing screenshots and executing mouse and keyboard actions. Systems such as OSWorld ( Xie et al., 2024 ) , WindowsAgentArena ( Bonatti et al., 2025 ) , and related benchmarks ( Zhang et al., 2025a ; Yang et al., 2025a ) have established standardized evaluation environments spanning Linux, Windows and macOS, revealing both promises and persistent limitations of current approaches. Despite steady progress, two fundamental problems remain largely unsolved in this domain. First, GUI agents do not reliably know when a task is finished : they routinely declare success prematurely, e.g. , after toggling a setting without verifying the state changed—because completion is left to the model’s implicit judgment rather than verified against observable UI evidence ( Andrade et al., 2026 ; Cemri et al., 2025 ) . Existing planning modules primarily focus on how to complete intermediate subgoals, but provide limited mechanisms for verifying whether the requested final state has actually been achieved ( Agashe et al., 2025a ; Agashe et al., 2025b ) . Second, agents fall into repetitive loops : cycling through the same failing action without recovery. Existing anti-looping heuristics can detect repeated actions, but often lack a systematic way to change strategy when repeated attempts continue to fail ( Yao et al., 2023b ; Shinn et al., 2023 ; Madaan et al., 2023 ; Li et al., 2023 ; Kim et al., 2023 ) . We present VLAA-GUI , a modular GUI agent framework that addresses both challenges through three mechanisms, a Completeness-Aware Planner, a Loop Breaker, and a Search Agent that enable the system to determine when to STOP , RECOVER (from repetitive loops), and SEARCH online for enhanced performance. To mitigate early stopping, we further introduce the Completeness-Aware Planner (CAP), which maintains a set of UI-observable completion criteria throughout execution and uses the status of unmet criteria at each step to guide subsequent decisions. Unlike conventional planners that prescribe a sequence of intermediate steps, CAP lets the agent choose actions dynamically based on the current UI state and what remains to be completed. This design helps prevent the agent from stopping simply because it has finished its planned actions while the requested final state has not yet been achieved. To address repetitive loops, we introduce a mandatory Loop Breaker that runs after every action and escalates its intervention as evidence of a loop accumulates—from switching the interaction modality ( e.g. clicking screen elements or writing Bash commands), to forcing an outright strategy change, to acting on an external loop signal—so that the agent is redirected before repeated failures consume the step budget. Beyond the two core challenges, GUI agents frequently stall on unfamiliar application workflows, leading to poor out-of-distribution performance. Prior work addresses this via visual browser-based search ( Yang et al., 2026a ) , which requires additional agent steps and a visual grounding pipeline. We instead deploy an on-demand Search Agent that directly queries a capable LLM with search grounding ( e.g. , Gemini 3 Pro ( Google DeepMind, 2025 ) ), returning plain textual knowledge injected into the Manager’s context, avoiding the need to navigate a browser to retrieve procedural text. We further integrate a Coding Agent (Coder) for accurate command line executions and a Grounding Agent (Grounder) for visual grounding following existing works ( Gonzalez-Pumariega et al., 2026 ; Yang et al., 2026a ; Wang et al., 2024 ) . We evaluate VLAA-GUI on OSWorld-Verified ( Xie et al., 2024 ) and WindowsAgentArena (WAA) ( Bonatti et al., 2025 ) across five LLM backbones to systematically validate the framework across distinct model families and capability tiers. As shown in Figure 1 , VLAA-GUI reaches 77.5% with Opus 4.6, and Opus 4.5 and Gemini 3.1 Pro also exceed the human reference level of 72.4%, making VLAA-GUI the first GUI framework to do so. Furthermore, VLAA-GUI generalizes well to WAA, reaching 61.0% and outperforming the strongest baselines by over 4%. Ablation studies further validate the contribution of each component. The full VLAA-GUI system with Sonnet4̃.6 achieves 71.67% on OSWorld, while removing the Completeness-Aware Planner, Searcher, or Loop Breaker reduces performance to 68.81%, 70.04%, and 71.63%, respectively. To further examine whether these proposed modules are transferable to other GUI frameworks, we integrate them into CoAct-1 ( Song et al., 2026 ) .
