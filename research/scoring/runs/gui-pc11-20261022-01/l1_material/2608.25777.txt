title: LocalLSTC: A Long Short-Term Control Architecture for Locally Deployed GUI Agents
source: https://arxiv.org/abs/2608.25777

§Abstract
Modern GUI-agent frameworks achieve strong desktop task performance with frontier API models, yet persistent control information often remains implicit in growing interaction trajectories. At each step, the planner reconstructs the active task stage, accumulated evidence, and runtime feedback before deciding the next action. This dependence becomes more pronounced under weaker local reasoning backbones. Across four representative state-of-the-art frameworks, replacing GPT-5 with Qwen3.5-9B reduces average OSWorld SR-100 from 60.9\% to 35.2\%. Trajectory annotation further identifies at least one control failure in 94.7\% of failed trajectories. To address this problem, we introduce LocalLSTC, a training-free architecture that organizes control by temporal scope, maintaining persistent cross-step state to guide short-term execution commitments. The framework comprises two complementary mechanisms. Long-to-Short Planning forms each commitment from persistent state, while Short-to-Long Control integrates execution outcomes back into that state for progress assessment, recovery, and termination. With Qwen3.8-27B, LocalLSTC reaches 73.7\% SR-100 on OSWorld and 68.5\% on WindowsAgentArena, achieving the strongest local OSWorld result and a new state of the art on WindowsAgentArena. Ablations further support contributions from both mechanisms. Together, these results show that temporal organization of control information can reduce cross-step control failures and complement backbone scaling in locally deployed GUI agents.

§Introduction (from cached fulltext; cut at ~9000 chars)
GUI agents extend multimodal models from interface understanding to sequential action in computer-use tasks. Long-horizon tasks require agents to preserve the active task stage across interactions, interpret execution outcomes, recover from failures, and terminate only after task constraints are satisfied. Recent systems improve desktop task performance through hierarchical planning, specialized components, code execution, and test-time search ( Agashe et al., 2025a ; Agashe et al., 2025b ; Gonzalez-Pumariega et al., 2026 ; Yang et al., 2026b ; Song et al., 2026 ) . Yet persistent control information often remains implicit in the growing interaction trajectory. At each decision, the planner needs to reconstruct the active task stage, accumulated evidence, and relevant runtime feedback before determining how to proceed. We call this repeated reconstruction the implicit trajectory-level control burden . As illustrated in Figure 1 (a), reconstruction errors can manifest as loss of stage commitment, incorrect progress assessment, repeated no-progress behavior, mismatched recovery, or premature termination. We refer to these observable manifestations as control failures . Local deployment makes this control burden particularly consequential. Keeping inference local allows screenshots, files, credentials, browser state, and application data to remain within the local deployment boundary, while reducing dependence on external-service latency, availability, and recurring invocation costs ( Liu et al., 2024 ; Xue et al., 2024 ) . However, public benchmarks and open-model studies continue to show a substantial capability gap between locally deployed open models and strong API models on desktop tasks ( Xie et al., 2024 ; Bonatti et al., 2025 ; Wang et al., 2025c ) . Recent reasoning models narrow this gap ( Qwen Team, 2026a ; Qwen Team, 2026b ; Qwen Team, 2026c ; Google DeepMind, 2026 ) , but deployable model scale remains constrained by local hardware capacity, compute, and inference throughput ( Liu et al., 2024 ; Xue et al., 2024 ) . Existing approaches primarily strengthen model parameters or system composition through GUI-specific training, specialized components, or additional inference-time computation ( Agashe et al., 2025b ; Song et al., 2026 ; Qin et al., 2025 ; Xu et al., 2025 ) . Runtime interfaces for adapting off-the-shelf general backbones to long-horizon desktop control remain less systematically studied ( Xu et al., 2026b ) . Across four representative state-of-the-art GUI-agent frameworks, our Qwen3.5-9B evaluations average 35.2% OSWorld SR-100, 25.7 percentage points below the reported GPT-5 average of 60.9%, as shown in Figure 1 (b). Averaged equally across the four frameworks, 94.7% of failed local-backbone trajectories contain at least one control failure. Figure 1 (c) shows that these failures span stage maintenance, progress assessment, repeated no-progress behavior, recovery, and termination, with the dominant category varying across frameworks. To address this problem, we introduce LocalLSTC, a Long Short-Term Control Architecture for Locally Deployed GUI Agents. LocalLSTC organizes control by temporal scope, maintaining persistent cross-step state to guide bounded short-term execution commitments. The framework comprises two complementary mechanisms. Long-to-Short Planning (L2S) forms each commitment from the persistent state and current observation, while Short-to-Long Control (S2L) integrates execution outcomes back into that state for subsequent progress assessment, recovery, and termination. The resulting L2S–S2L loop, illustrated in Figure 1 (d), carries the active subgoal, accumulated evidence, and runtime feedback across interactions without requiring each planner call to reconstruct them from the full trajectory. Empirically, LocalLSTC improves both task performance and cross-step control behavior under constrained local backbones. As shown in Figure 1 (b), under the same Qwen3.5-9B backbone, LocalLSTC reaches 47.6% SR-100, outperforming the four-framework baseline average of 35.2% by 12.4 percentage points. Figure 1 (c) further shows that LocalLSTC reduces Any control-failure incidence from the 63.7% baseline average to 41.7%. With Qwen3.8-27B, LocalLSTC reaches 73.7% SR-100 on OSWorld and 68.5% on WindowsAgentArena, achieving the strongest local OSWorld result and a new state of the art on WindowsAgentArena. Fixed-backbone ablations further show contributions from both L2S and S2L. Together, these results indicate that explicitly organizing control information across temporal scopes can reduce cross-step control failures and complement backbone scaling in locally deployed GUI agents.
