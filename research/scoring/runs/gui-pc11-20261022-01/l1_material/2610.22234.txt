title: OS-Helix: Unifying GUI Interaction and Code Execution in Native Computer-Using Agents
source: https://arxiv.org/abs/2610.22234

§Abstract
Real desktop automation is neither purely visual nor purely programmatic. Agents must understand user-facing interfaces while efficiently manipulating files, scripts, and system state. However, native GUI/code coordination cannot be obtained by prompt-level tool composition. In our preliminary experiments, naively adding a code tool degrades a GUI agent, revealing that GUI/code routing must be internalized through training on high-quality hybrid data. We present OS-Helix, an end-to-end trained multimodal computer-using agent that unifies GUI actions and code execution in one action space. To construct the required supervision, we introduce application-artifact composition, pairing desktop applications with authentic file artifacts to instantiate executable Ubuntu states, and a decoupled instruction/evaluator generation pipeline that produces environment-grounded tasks whose final states can be verified regardless of the solution modality. We cold-start the policy with SFT on filtered hybrid data and further improve it through online RL in live desktop environments. For RL, we propose Step-balanced GSPO, which aggregates importance weight by action step rather than raw assistant tokens to prevent long code actions from dominating heterogeneous-action optimization. On OSWorld-Verified, OS-Helix-27B and OS-Helix-35B-A3B achieve relative improvements of 35.0% and 33.7% over their matched Qwen3.5 hybrid baselines, while OS-Helix-27B-RL further improves by 42.9% to reach 66.44% success. Ablations provide evidence consistent with contributions from learned GUI/code coordination, scalable verifiable supervision, and action step balanced optimization, while demonstrating cross-platform transfer on WindowsAgentArena. Our project homepage is at https://os-copilot.github.io/OS-Helix/.

§Introduction (from cached fulltext; cut at ~9000 chars)
The rapid progress of vision-language models (VLMs) ( Team, 2026 ; Wang et al., 2025b ; Team et al., 2026a ; Anthropic, 2025b ; Zeng et al., 2026 ; OpenAI, 2025 ; Bai et al., 2026 ; Zou et al., 2026 ) has accelerated the development of computer-using agents (CUAs), which aim to execute open-ended tasks in human-facing digital environments. Most existing CUAs formulate digital automation as graphical interaction, where agents perceive screenshots, reason over interface states, and act through mouse and keyboard operations. However, GUI-centric CUAs ( Liu et al., 2026 ; Xue et al., 2026 ; Wang et al., 2026b ; Zhang et al., 2026a ; Luo et al., 2025 ; Cheng et al., 2024 ; Feizi et al., 2026 ) still face practical bottlenecks in realistic desktop workflows. Visual grounding can fail on small or ambiguous interface elements, and fine-grained interaction can make structured state manipulation cumbersome even with batched actions. A complementary interface is programmatic control, through which command-line and code agents can inspect files, access system state, and execute compound operations directly through the shell ( Yang et al., 2026e ; Yang et al., 2024 ; Wang et al., 2025c ) . Yet code execution alone cannot fully address the long tail of desktop task scenarios that depends on visual layout, application-specific UI state, or software behavior exposed only through the interface. As illustrated in Figure 1 , these complementary strengths motivate a single agent that coordinates GUI and code, where GUI provides general visual access to arbitrary applications while code provides efficient and precise manipulation of programmatic state. Despite this complementarity, building a native hybrid GUI/code CUA remains an open problem. Simply attaching a code tool to a GUI model does not teach it when or why to use either modality. In our preliminary experiments, as shown in Table 14 , Qwen3-VL-32B-Instruct ( Bai et al., 2025 ) achieves over \sim 34% success on OSWorld-Verified ( Xie et al., 2025 ) with GUI actions alone, but falls to roughly \sim 32% when code execution is naively exposed. Prompt-level composition can therefore disrupt an existing GUI policy rather than create coordinated behavior, making it essential to internalize hybrid coordination capabilities into the model through training on high-quality hybrid data. Several existing approaches have explored hybrid execution paradigms that combine GUI interaction with code-like actions. Framework-centric systems ( Gonzalez-Pumariega et al., 2025 ; Hou et al., 2024 ; Yang et al., 2026a ) rely on external harnesses to coordinate GUI, code, memory, and recovery; tool-call-based approaches ( Jia et al., 2025 ; Yang et al., 2025b ; Shi et al., 2026 ) expose programmatic operations through predefined application-specific interfaces; and model-fusion approaches ( Wang et al., 2025a ; Qin et al., 2025 ) combine complementary capabilities through predefined designs. Although these systems expand the scope of hybrid computer use, they leave open how a single policy can learn the routing between the GUI and code actions through hybrid training. To address these challenges, we present OS-Helix, an end-to-end trained computer-using agent that unifies GUI interaction and code execution within a single policy. On the infrastructure side, we introduce application–artifact composition, which combines versioned applications with authentic artifacts to instantiate diverse and reproducible desktop states. An Exploration Agent proposes instructions grounded in these states through brief exploration of the initialized environment, while an independent Evaluator Agent constructs task-specific, primarily rule-based evaluators. Together, this pipeline supports scalable synthesis, filtering, and collection of high-quality GUI/code trajectories for model training, thereby providing the data foundation necessary to internalize hybrid coordination capabilities into the model. On the training side, we first use filtered hybrid trajectories to internalize basic action semantics and modality routing, and then optimize the policy through online RL in executable desktop environments. In early RL experiments, we observe a steady increase in the proportion of code actions accompanied by a degradation in performance. We attribute this to the token-count asymmetry between short GUI actions and substantially longer code actions, which causes the optimization signal to be dominated by code steps. To address this, we propose Step-balanced GSPO , which constructs the sample-level importance ratio over action steps rather than raw assistant-token counts, enabling more balanced optimization of the two modalities. These training components directly answer the open question of how a single policy can natively learn to coordinate GUI and code actions through hybrid training, yielding an agent that performs strongly and reliably across diverse desktop tasks.
