title: Securing Computer-Use Agents Against Branch Steering Attacks
source: https://arxiv.org/abs/2610.03089

§Abstract
Modern Computer Use Agents (CUAs) directly interact with graphical user interfaces and execute third-party web tools, exposing them to indirect prompt injection across every rendered page and tool response. While the Dual-LLM pattern is the primary system-level architecture offering formal security guarantees - using an isolated Planner LLM (P-LLM) to fix execution paths before processing untrusted inputs via a Quarantined LLM (Q-LLM) - these guarantees break down in graphical environments. Because CUA interaction is inherently dynamic, plans cannot remain data-independent; they must branch based on anticipated runtime web content - covering all possible cases the agent may encounter. This exposes agents to branch steering attacks, where an adversary crafts untrusted data to coerce a CUA down a hazardous, pre-approved branch without injecting explicit instructions. We systematically study branch steering attacks and introduce STEER-Bench (101 tasks across 9 domains), showing high attack success against both standard (94.4%) and vanilla Dual-LLM (89.5%) CUAs. We then propose COBRA, an architecture that pairs trusted branching plans with ahead-of-time capability constraints, strictly bounding the parameters and destinations each branch may execute. On STEER-Bench, COBRA reduces attack success to 0% while retaining 97% benign utility.

§Introduction (from cached fulltext; cut at ~9000 chars)
Computer-use agents (CUAs) carry out natural language tasks by interpreting on-screen visual content and executing mouse and keyboard actions. Most CUAs follow a ReAct-style loop in which a single model repeatedly observes the environment, reasons over it, and selects the next action; increasingly, agents also invoke Model Context Protocol (MCP) tools exposed by website vendors, giving them direct access to backend capabilities alongside the graphical user interface (GUI). This architecture makes CUAs acutely vulnerable to indirect prompt injection (IPI) across two surfaces. The first is rendered web content – because a model processes both the user’s trusted request and untrusted web pages, documents, and messages, untrusted text can become indistinguishable from instructions within the shared context ( Greshake et al., 2023 ; Debenedetti et al., 2024 ; Zhang et al., 2025b ; Aichberger et al., 2025 ; Chen et al., 2025 ) . The second is the MCP interface , where a malicious server can embed instructions in tool descriptions ( tool poisoning ), register tools that impersonate approved endpoints ( tool shadowing ), or alter tool behavior post-approval ( Beurer-Kellner and Fischer, 2025 ) . Unlike webpage content, MCP tool descriptions may be presented to the agent during initialization, before it visits any website. Crucially, these two surfaces can be composed: a CUA task may interleave GUI actions with MCP invocations, injected page text can steer external tool calls, and poisoned tool responses can hijack GUI behavior. Defending either channel in isolation leaves the composite system vulnerable. The Dual-LLM architecture mitigates IPI by strictly separating trusted planning from untrusted interaction ( Willison, 2023 ; Debenedetti et al., 2026 ) . A privileged planner (P-LLM) derives the entire execution sequence in advance from the trusted user query alone; a quarantined model (Q-LLM) then processes untrusted content but is structurally barred from altering the plan. This yields control-flow integrity (CFI): every action the agent executes must follow a pre-authorized plan. While CFI provides robust security for structured tool-use agents whose parameters and sequences can be fixed a priori (e.g., scheduling a meeting across known calendar APIs), it fundamentally breaks down in dynamic CUA environments. Because web layout and state cannot be known before a page renders, control flow is tightly interleaved with runtime data. Plans must therefore incorporate branches over anticipated runtime states ( Foerster et al., 2026 ) . Under branching execution, an adversary can manipulate untrusted page content to drive the agent down a hazardous, pre-approved path without injecting novel instructions, an exploit known as a branch steering attack ( Foerster et al., 2026 ) . Branch steering demonstrates that CFI alone is insufficient for CUAs: agents additionally require data-flow integrity (DFI). That is, untrusted data must not manipulate which branch is taken, nor determine the critical parameters its actions receive. Enforcing DFI is uniquely challenging in CUAs because graphical primitives carry no intrinsic semantics: the same mouse click may open an innocuous tab or confirm an irreversible wire transfer, and static plans cannot differentiate between them. A standard Dual-LLM architecture bounds an agent to authorized action paths, but leaves this runtime data-flow channel unprotected. To address this challenge, we present COBRA , a system-level defense enforcing both CFI and DFI for CUAs. COBRA eliminates branch steering by constraining, ahead of time, the capabilities each branch may exercise (e.g., allowed destination domains, endpoints, and tool parameters). As illustrated in Figure 1 , before observing any untrusted runtime data, the P-LLM compiles the user’s request along with approved site and tool metadata into an executable program annotated with branch-level constraints. A deterministic interpreter executes this program, querying a quarantined vision-language model (Q-VLM) strictly for visual perception. Because Q-VLM outputs remain untrusted, a central Branch Resolution Hub (BRH) dynamically validates branch conditions and action parameters against the plan’s constraints before execution proceeds. Deterministic HTTP and MCP proxy enforcers then intercept and police all external operations at the network boundary. By unifying GUI-mediated web traffic and MCP tool calls under identical constraint contracts, COBRA secures both injection channels even across deeply nested branches.
