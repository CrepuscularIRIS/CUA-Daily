arxiv: 2610.16778 (2610.16778v1)
title: PrivacyGuard: Source-Linked Sanitization and Locally Resolvable PII References for Cloud GUI Agents
source: https://arxiv.org/abs/2610.16778

§Abstract
Cloud graphical user interface (GUI) agents send instructions and screenshots to remote planners, exposing personally identifiable information (PII). Existing placeholder defenses mask detected spans and reuse exact strings. Fragmented or changed forms can expose PII or break entity continuity across turns. PrivacyGuard addresses this private reference problem with source-linked sanitization (SAN) and a structured reference lifecycle (REF). SAN reconstructs fragmented or overlapping evidence and rewrites the complete source extent. REF links changed appearances to session entities and supports locally resolvable references without returning raw values to the upload path. In five-turn sessions scored against common gold, PrivacyGuard reduces audited source-value leakage by 33.55\%--82.60\% relative to the closest prior full-pipeline system in all four reader--language combinations. REF raises strict cross-form continuity from 0.04 under exact-value reuse to 0.81. In reference-required Android tasks, verified completion rises from 8/30 and 7/30 to 17/30 and 20/30. On AndroidLab, PrivacyGuard achieves the highest or tied-highest task-success point estimate among protection pipelines for all four planners. On PrivScreen, it reduces fixed-reader field exposure by 62.72\%--62.84\% relative to the same baseline. PrivacyGuard lowers upload exposure while preserving a locally resolvable task path.

§Introduction (from cached fulltext; cut at ~9000 chars)
Cloud-based graphical user interface (GUI) agents send an instruction and the current screen to a remote planner before device execution begins [ 31 ] . Personally identifiable information (PII) can appear directly in an uploaded view. Reusable references create a second privacy risk: visible type, equality, projection, and layout cues may support reconstruction when several protected uploads are examined together [ 36 , 1 , 9 ] . PrivacyGuard reduces exposure at this boundary by combining source-linked sanitization (SAN) with a structured reference lifecycle (REF). We use Full for the combined SAN+REF pipeline. SAN rewrites complete source extents before upload, and REF preserves a locally resolvable task path without returning raw values to the upload path. The problem arises when a protected entity appears in different forms. Consider a delivery task containing 350 5th Avenue, Apt. 24B, New York, NY . A later screen may show 5th Ave. in one optical character recognition (OCR) region and Apt. 24B in another, followed by a request for the city. These fragments refer to the same destination, but neither is an exact copy of the original value. This case exposes the need for entity-level continuity, which keeps changed appearances linked and supports later component requests without exposing the raw address. We call this the private reference problem : the protection unit is an entity and its references, not only a repeated string. Privacy requires removing the value from each upload, but task completion may still depend on the entity represented by that value. Existing value-placeholder systems do not address both sides of the problem. AbI [ 35 ] , the closest prior full-pipeline system, uses deterministic placeholders, a session value map with exact lookup and fuzzy OCR alignment, and whole-value local restoration. Such value-level mapping cannot represent a complete value and later abbreviations, fragments, or component-only appearances as structured views of the same entity. Whole-value restoration cannot express a request for one supported component. The private reference problem has two coupled parts. The first is recovering complete, rewriteable source extents from fragmented OCR boxes and partial or overlapping detector outputs. The second is preserving entity continuity after source removal so that a later task can refer to the protected entity without releasing its raw value. PrivacyGuard parses each accepted occurrence once into a source trace and a typed entity record. PrivacyGuard reconstructs fragmented evidence and resolves competing candidates before finalizing the source trace, which preserves the prompt offsets or screenshot regions that produced the occurrence. SAN uses this trace to rewrite the complete source extent instead of the detected span. This source-linked design reduces the risk that partial detections leave visible characters or divide one occurrence into unrelated protected regions. The typed entity record supports REF. It retains the entity identity and locally available components needed to connect changed appearances. Compatible appearances reuse a session root, and supported address components can be requested by projection and resolved against local session state. Addresses provide the main evaluated projection case. The remaining supported PII types retain type-appropriate state. This distinction matters when a protected value is needed for task completion. Removing such a value can reduce GUI-agent success [ 24 ] , but REF preserves a locally resolvable path without placing the raw value back into the upload path. We evaluate task execution with protocol-conforming remote planners and privacy exposure with fixed readers. A released-view audit examines one sanitized instruction or screenshot, and a five-turn audit examines the ordered Full uploads from the same session. The Full-pipeline privacy endpoint, audited source-value leakage , is the deduplicated union of per-view exposure and five-turn reconstruction. Task success remains a separate endpoint. Controlled and external experiments isolate SAN source completeness, REF cross-form continuity and reference-mediated execution, and the resulting Full-pipeline privacy and utility. PrivacyGuard lowers audited source-value leakage by 33.55%–82.60% relative to the closest prior full-pipeline system in all four reader–language combinations. REF raises strict cross-form continuity from 0.04 with exact-value reuse to 0.81. In reference-required Android tasks, verified completion rises from 8/30 and 7/30 with exact-value reuse to 17/30 and 20/30 with PrivacyGuard. On the 138-task AndroidLab benchmark, PrivacyGuard achieves the highest or tied-highest task-success point estimate among protection pipelines for all four planners. On PrivScreen, it lowers fixed-reader field exposure by 62.72%–62.84% relative to the same full-pipeline baseline.
