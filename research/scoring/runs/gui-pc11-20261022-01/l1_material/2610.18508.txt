title: Towards Safe Autonomy for Computer Use
source: https://arxiv.org/abs/2610.18508

§Abstract
The safety of LLM-based agents currently rests on alignment training and safety classifiers, neither of which can rule out that a sophisticated indirect prompt injection (IPI) goes through and causes significant harm. Recent work therefore builds agents with information-flow guarantees that rely on structured tool interfaces to interact with the environment. Computer Use Agents (CUAs) act visually on the computer screen, which does not provide a boundary between trusted first-party interfaces and untrusted, potentially attacker-authored content. Actions are equally ambiguous: a click may land on an application toolbar or a button controlled by an attacker. Treating the user as the source of trust and confirming each sensitive decision produces confirmation fatigue, with the risk of missing harmful actions. We introduce SA-CUA, a dual-LLM framework that generates a reliable trust boundary for CUAs by deriving conservative deterministic rules from the accessibility tree for unmasking trusted regions from the privileged LLM's screenshot, keeping trusted and untrusted content separated. Human interaction is only required for proper task specification in the beginning. During the task a robust endorsement channel allows values to pass from the untrusted to the trusted domain by verifying information via trusted channels. This allows the agent to autonomously handle tasks involving untrusted information. SA-CUA maintains much higher utility than CaMeL-CUA while keeping the attack success rate at zero.

§Introduction (from cached fulltext; cut at ~9000 chars)
LLM-based agents have moved from demonstrations into deployments with real-world consequences. Most deployed systems are tool-use agents that act through structured tools with the environment, but there is growing interest in computer use agents (CUAs), which perceive a GUI environment and act on it via mouse and keyboard. CUAs provide the possibility to interact with every application a human can operate without requiring special integration ( Xie et al., 2024 ) and are offered by many frontier labs such as Anthropic ( Anthropic, 2026 ) . For the agent to complete a task it has to potentially interact with environments that third parties can write to, and an adversary who anticipates this can leave malicious instructions behind for the agent to act on. Such indirect prompt injections (IPIs) ( Greshake et al., 2023 ) attempt to hijack the agent’s trajectory, manipulating the user task toward an attacker-chosen malicious goal such as exfiltrating credentials or private files, sending messages, authorizing payments, or removing data. Khodayari et al. (2026) show the realism of this threat by crawling 1.2B URLs and finding 15.3K injections. IPIs can be mitigated by making the model itself more resistant through alignment training ( Bai et al., 2022 ; Guan et al., 2024 ) and/or filtering inputs and outputs with additional safety classifiers ( Sharma et al., 2025 ; Inan et al., 2023 ) . Instead we focus on enforcing security by the system architecture. CaMeL ( Debenedetti et al., 2026 ) and FIDES ( Costa et al., 2025 ) establish frameworks for tool-use agents that secure control- and data-flow by ensuring integrity and confidentiality. Both build on a dual-LLM approach ( Willison, 2023 ) , where a privileged model plans and operates tools interacting only with trusted content. Untrusted content is handled by a quarantined model, which can be queried by the privileged model in a structured fashion. Recently, CaMeL-CUA ( Foerster et al., 2026 ) and untrusted content masking (UCM; ( Nikolić et al., 2026 ) extend this to computer use. The main problem is that in a screenshot processed by the CUA trusted and untrusted content are entangled, with no typed values to carry labels, so the initial trust labeling that CaMeL/FIDES depend on becomes a crucial step. CaMeL-CUA keeps the privileged model blind to the environment restricting utility, whereas UCM relies on active page owners to mark untrusted regions in the Document Object Model (DOM). Their experiments show that labeling untrusted content by LLMs is not reliable. To achieve data-flow control, both systems bound the type the quarantined model can return to limit the channel capacity. However, we argue that already a single bit can be sufficient to steer the privileged model into an adversarial branch. For data-dependent tasks that require higher-capacity return values, CaMeL-CUA and UCM fall back to asking the user to confirm. However, repeated security prompts can drive the user into confirmation fatigue, auto-approving requests without checking them, a well-known problem in security ( Furnell & Thomson, 2009 ) . Our framework SA-CUA builds on the dual-LLM approach ( Willison, 2023 ) . By default the full screen is masked in SA-CUA and we derive deterministic rules based on the accessibility tree to unmask trusted content before it reaches the privileged model, instead of masking untrusted content in the DOM as in UCM. Therefore, the privileged LLM only gets a screenshot where every untrusted element is masked, so its context remains trusted and its integrity to issue actions is preserved in the sense of Biba (1977) . For data-dependent tasks we introduce an endorsement channel, which overcomes the data-flow problem of prior work without compromising the agent’s autonomy by repeated confirmation requests. We endorse by verifying each value that traverses the trust boundary with the help of independent trusted sources, e.g. the parametric knowledge of the privileged LLM, trusted domains/contacts etc. This follows the principle of robust endorsement ( Zdancewic & Myers, 2001 ; Myers et al., 2006 ) , under which the value being endorsed cannot influence the endorsement check. Our contributions are: • SA-CUA performs trust labeling using AT-SPI accessibility trees for hybrid web–OS environments and thus can handle general CUA tasks, while UCM is restricted to the browser as it uses the DOM. Our automatic labeling is reliable and has zero leakage of untrusted free text ( \mathrm{FNR}_{\text{free}} ) in contrast to UCM, e.g. 0% for SA-CUA vs 44.1% for UCM for Qwen3.8-27B. • SA-CUA introduces an endorsement channel for untrusted content where values are verified using independent sources.
