arxiv: 2607.08147 (2607.08147v1)
title: Prismata: Confining Cross-Site Prompt Injection in Web Agents
source: https://arxiv.org/abs/2607.08147

§Abstract
Autonomous web agents promise to automate everyday browsing tasks, but inherit one of the web's oldest attack surfaces. Cross-Site Scripting proved that mixing trusted and untrusted content is dangerous, even on benign pages. Agents resurface this risk by interpreting natural language as instructions, allowing third-party and user-generated content to hijack the agent via prompt injection. The core challenge is that deriving a task-specific security policy requires reasoning over page structure that is entangled with the attacker's content. We present Prismata, a defense enforcing contextual least privilege for web agents, constraining both what the agent sees and what it can do. Prismata's dynamic trust derivation produces permission labels for page content, with structural confinement guarantees, inspired by classical integrity models, that bound any labeling errors so that labels can only decrease in privilege and mislabelings are bounded. Prismata's mechanical confinement enforces these labels by redacting content and restricting agent capabilities. Importantly, these mechanisms require no developer annotations, so Prismata supports the long tail of websites. Across recent published web agent attacks, including adaptive variants, Prismata substantially reduces attack success while preserving benign task utility.

§Introduction (from cached fulltext; cut at ~9000 chars)
Autonomous browser-based web agents have surged in popularity, promising to automate tedious browsing workflows, boost workplace productivity, reclaim personal time, and accelerate research ( OpenAI, 2025b ; Anthropic, 2024 ; Deng et al., 2023 ; Zhou et al., 2024b ; Yang et al., 2025b ; Xu et al., 2025b ; Marreed et al., 2025 ; Zhou et al., 2024a ; Koh et al., 2024 ; OpenAI, 2025a ; Google, 2024 ; Perplexity, 2025 ) . In doing so, they inherit one of the web’s oldest attack surfaces: even on benign sites, trusted and untrusted origins intersperse content on the same page. Consider a site like shopping.com (Fig. 1 ), which mixes site developer content (navigation menus, product listings, purchase buttons), user content (product reviews, ratings), and external advertisements (sponsored placements, banner ads). Alice tasks her web agent to order the best-reviewed bow from the site, unaware that Eve, a malicious actor, has planted a prompt-injection payload in a review on the bow’s product page. The payload instructs Alice’s agent to reply to the review with the user’s credit card details. Recent work demonstrates that such attacks, from natural-language injections to adversarial image perturbations, are both feasible and effective against current web agents ( Zou et al., 2023 ; Gong et al., 2025 ; Zhang et al., 2024b ; Liao et al., 2025 ; Ma et al., 2024 ; Xu et al., 2025a ; Kim et al., 2025 ; Wang et al., 2025a ; Wang et al., 2025b ; Syros et al., 2026 ) . The web has faced similar threats before: Cross-Site Scripting (XSS) allows malicious scripts injected into a benign website to execute in a victim’s browser. We call the agent-side analogue Cross-Site Prompting (XSP) , where indirect prompt injections placed on a benign site manipulate a victim’s web agent. As with XSS, XSP exploits the site’s own features to carry out the attack, such as exfiltrating data via direct messages, posting content through reviews, or modifying permissions via account settings. Unfortunately, XSS defenses do not transfer: XSP payloads are not executable code but natural language and images, input sanitizers cannot distinguish instructions from data, and external content cannot be sandboxed from the agent’s context ( OWASP, [n. d.] ; Grossman et al., 2007 ; MDN contributors, 2025b ) . Formalizing XSP as a class lets us design defenses that hold regardless of the attack’s delivery mechanism, and generalizing to novel variants. Mitigations for prompt injection tend to fall into two categories: (1) model-level defenses, which rely on a model to resist such attacks ( Wallace et al., 2024 ; Liu et al., 2025 ; Nasr et al., 2025 ; Chen et al., 2024 ) , and (2) system-level defenses that apply classical security principles in agent designs to provide stronger security properties ( Debenedetti et al., 2025 ; Wu et al., 2024 ; Shi et al., 2025 ; Tsai and Bagdasarian, 2025 ) . Despite gradual improvements, adaptive attacks continue to bypass model-level defenses at high rates ( Zhan et al., 2025 ; Wen et al., 2025 ; Jia et al., 2025 ; Choudhary et al., 2025 ; Shi et al., 2026 ; Wang et al., 2026a ; Chang et al., 2026 ; Kaya et al., 2026 ; Zou et al., 2025 ; Abdelnabi et al., 2025 ) . Existing web agent defenses fall primarily into the former category ( Zheng et al., 2025 ; Yang et al., 2025a ; Zhang et al., 2025 ; Chen et al., 2026 ; Wang et al., 2026b ; Lan and Kaul, 2026 ; Wu et al., 2026 ; Hu et al., 2025 ; Google, 2025a ) . System-level approaches such as CaMeL ( Debenedetti et al., 2025 ) require pre-planning all actions before execution and struggle to generalize to data-dependent web tasks ( Foerster et al., 2026 ) , while others provide origin-level controls such as read-only domains ( Google, 2025a ) . Fine-grained, page-level policies that address XSP have thus far required exhaustive site maps that must be developers manually construct per site ( Meng et al., 2025 ) . The fundamental challenge for web agents is that determining the security implications of an action requires reading the site’s structure, which is itself entangled with untrusted content. On shopping.com , the same click(id) might complete Alice’s purchase, reply to Eve’s review, or interact with a sponsored ad; it is the site, not the action, that carries the security meaning. We refer to this as the web entanglement problem (Fig. 2 ): a general web-agent defense must separate the structural signals from the untrusted content to derive a security policy for the agent, yet the act of separation itself exposes the defense to adversarial manipulation. An ideal least-privilege defense would grant the agent only the capabilities its task requires, and nothing more. This is desirable because, without such restrictions, a web agent can interact with every element on a page.
