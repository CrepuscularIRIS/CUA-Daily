title: SPIDES: Information-Flow Control for Browser Agents
source: https://arxiv.org/abs/2610.24277

§Abstract
Browser agents automate complex workflows by reading and acting on arbitrary page content, but this flexibility exposes them to prompt injection attacks and unintended data exfiltration. Recent work argues that LLM-driven browser agents erode traditional web security boundaries such as the Same-Origin Policy (SOP) by acting across origins with the user's authority and no built-in isolation. We argue that restoring SOP is neither sufficient (a same-origin public sink can leak private data) nor necessary (legitimate tasks require authorized cross-origin flows) for protecting the security of users. We propose SPIDES, which instead enforces information-flow control by gating primitive browser actions such as typing, clicking and navigating on labels propagated from element-level HTML confidentiality and integrity annotations. Untrusted and confidential content is masked from the agent's context, while policies block unauthorized flows, providing security guarantees against both prompt injection and data exfiltration that hold independently of the model driving the agent. To evaluate SPIDES and baseline defenses under a common threat model, we build MicroNet, a closed ecosystem of 28 interlinked websites with element-level ground-truth labels and paired benign/adversarial tasks. SPIDES achieves 0% attack success rate by design while retaining high task completion rate and autonomy. Our findings demonstrate that information-flow control is an effective technique to extend web security to browser agents, gaining on autonomy and utility against state-of-the-art baselines. The source code and data are openly accessible at https://github.com/microsoft/SPIDES.

§Introduction (from cached fulltext; cut at ~9000 chars)
Browser-use agents (BUAs) such as Perplexity Comet ( Perplexity AI, 2025 ) , Chrome Auto Browse ( Tabriz, 2026 ) and Skyvern ( Skyvern AI, 2026 ) automate browser-based workflows on a user’s behalf. BUAs act with the user’s authority across different websites, exposing them to indirect prompt injection attacks ( Greshake et al., 2023 ; Liao et al., 2025 ; Zhang et al., 2025 ; Zhang et al., 2026 ) , where malicious content causes the agent to perform harmful actions or leak sensitive information. For instance, content embedded in an advertisement on a shopping website may cause the agent to make an unauthorized purchase with a saved payment method. Traditional browser security mechanisms aim to prevent unauthorized information flow across websites. Notably, the same-origin policy (SOP) limits how code from one origin (the scheme, host and port of a URL) can interact with resources from another origin ( MDN Web Docs, 2026c ) . But the SOP does not govern the user-mediated flows often required to automate tasks, e.g., copying and pasting data across websites. For instance, a user shopping for a laptop may ask an agent to collect specifications from several retailers and compile them into a comparison in a note-taking web app. Mechanisms proposed to secure BUAs generally fall short of providing integrity and confidentiality guarantees while preserving autonomy ( Wang et al., 2026 ; Nikolić et al., 2026 ; Meng et al., 2026 ) . SOPGuard ( Wang et al., 2026 ) restores SOP and requires human approval for cross-origin flows, hindering autonomous task completion and still allowing same-origin attacks. Others provide integrity guarantees within one origin, but do not enforce policy on cross-origin flows ( Nikolić et al., 2026 ) . ceLLMate ( Meng et al., 2026 ) blocks HTTP requests that violate task-specific policies selected at runtime, but does not track whether untrusted or confidential content influenced a request. We posit that securing browser-use agents requires novel mechanisms that tell benign from unintended flows, allowing cross-origin actions needed to complete tasks while preventing untrusted data from influencing consequential actions and confidential data from reaching unintended recipients. We present SPIDES , an information-flow control framework that secures browser-use agents against prompt injection and data exfiltration by design, independently of the model driving the agent. SPIDES builds on an emerging line of defenses ( Debenedetti et al., 2026 ; Costa et al., 2025 ; Kim et al., 2025 ) that combine information-flow control (IFC) ( Denning, 1976 ) with the dual LLM pattern ( Willison, 2023 ) . These defenses track the integrity and confidentiality of data that enters the agent’s context. They require tools to return results with confidentiality and integrity labels and assume that each tool has a specific, well-defined effect, e.g., sending an email. However, web browsers break both assumptions (§ 3 ). A browser has no such metadata beyond a page’s origin, yet one origin may serve trusted operator-provided content, untrusted user reviews, and confidential messages side-by-side, and only the operator knows which is which. Likewise, a single tool like browser_click may follow a link or delete an account. SPIDES addresses these two challenges. First, users list the origins whose operators they trust, and operators of these origins annotate DOM (Document Object Model) elements with integrity and confidentiality labels; content from other origins is treated as untrusted. SPIDES propagates the labels to the accessibility snapshots the agent observes and hides untrusted and confidential content behind variables to track information flow deterministically. Second, SPIDES assigns a policy to each browser action based on its target origin. Because users may create accounts on trusted origins, clicks, navigations, and form submissions targeting a trusted origin may act under the user’s account. SPIDES treats them as consequential and allows them only when there is no influence from untrusted data. Any actions that send data, including actions that target untrusted origins, may send data only to origins authorized to see it. SPIDES asks the user to approve any action that violates these policies. For evaluation, since no existing benchmark has benign cross-origin tasks with same- and cross-origin attacks, we build MicroNet, a closed ecosystem of 28 interlinked websites with element-level ground-truth labels. MicroNet contains 56 benign tasks, 22 of which require cross-origin flows. It includes 56 attacks injected through attacker-run websites, user-generated content, and third-party iframes. Across 5 frontier models and under a worst-case adversary that controls a model’s output on input tainted with untrusted content, SPIDES blocks all attacks, while 53.273.2\text{\,}\mathrm{\%} succeed against SOPGuard and 4.66.8\text{\,}\mathrm{\%} against UCM.
