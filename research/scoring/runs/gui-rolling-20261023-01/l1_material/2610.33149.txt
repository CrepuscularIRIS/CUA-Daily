title: WebUniverse: Scaling Verified Training Data for Agentic Web Development
source: https://arxiv.org/abs/2610.33149

§Abstract
Training agents for front-end web development requires demonstrations of code editing, execution, browser inspection and revision, yet public trajectories and reusable task environments remain limited. We introduce WebUniverse, a pipeline that constructs verifiable tasks with verified development trajectories from open-source repositories and real web pages. The tasks cover text-grounded application development in standalone and iterative settings and vision-grounded reproduction across pages and viewports. We collect agent trajectories for these tasks and verify the resulting applications against task-specific functional or visual requirements. We release WebUniverse-Env, containing 15K executable task environments, and WebUniverse-Mix, containing the corresponding 15K development trajectories with verification records and scores. Fine-tuning Qwen3.5-35B-A3B on WebUniverse-Mix raises the Vision2Web average score from 51.7 to 68.3, WebGen-Bench accuracy from 34.5% to 63.9%, and Web-Bench pass@2 from 12.2% to 23.1%. The resulting model also outperforms a public-data baseline trained with the same configuration and sample budget across all reported metrics. Ablations show complementary benefits from text and visual trajectories and continued gains as training data scales from 5K to 15K trajectories.

Building a web application requires a coding agent to implement interactive behavior and produce the intended interface. An application may resemble its target design while failing to respond correctly to user actions; conversely, a functional implementation may differ substantially from a visual reference. Assessing these requirements involves running the application, interacting with it in a browser, and inspecting its rendered appearance ( Lu et al., 2025 ; He et al., 2026 ) . Front-end development therefore provides a setting in which agents must connect code changes with observable outcomes and revise their implementations when those outcomes fall short. Training data for this process should capture how agents develop and check applications. Instruction–code and screenshot–code pairs provide supervision for producing implementations, but do not demonstrate the sequence of editing, execution, inspection and correction in a real completed application. Development trajectories expose these intermediate actions and the feedback available to the agent. Collecting such trajectories requires executable task environments: a development request, a designated starting workspace, applicable reference materials, and criteria for assessing the resulting application. Releasing these environments alongside trajectories also enables researchers to collect new attempts and verify their solutions. Existing resources cover different parts of this need. Screenshot–code datasets provide visual supervision ( Laurençon et al., 2024 ; Yun et al., 2024 ) , while software engineering and command-line pipelines construct executable tasks with tests ( Pan et al., 2025 ; Hua et al., 2026 ) . Public resources for front-end development trajectories remain limited. WebGen-Agent releases a small collection generated from textual requests ( Lu et al., 2026a ) , while FullStack-Agent does not release its trajectories ( Lu et al., 2026b ) . The training trajectories in both works address individual tasks specified in text, without covering development from visual references or iterative task sequences that build on earlier solutions. Table 1 compares task coverage and released resources. We introduce WebUniverse , which provides 15K executable task environments for front-end web development (Figure 2 ). We construct the task environments from open-source repositories and crawled pages. The text-grounded tasks ask an agent to build an application from written requirements, either as a standalone task or through a sequence of changes to the same codebase. The vision-grounded tasks ask the agent to reproduce real web pages from screenshots, including multiple pages and viewport widths. Each environment preserves the task inputs, starting workspace and verification criteria, supporting further solving, verification and trajectory collection. We collect trajectories through independent attempts and refinement of failed or interrupted attempts. Verification follows the requirements of each task: browser scripts or a GUI agent check application behavior, while a visual judge compares rendered pages with their references. We retain trajectories that pass task-specific verification and trajectory quality checks, and release each trajectory with its verification record and score. Together, the environments and trajectories provide both training demonstrations and the means to collect additional demonstrations under the same task requirements. Qwen3.5-WebUniverse improves performance on Vision2Web ( He et al., 2026 ) , WebGen-Bench ( Lu et al., 2025 ) , and Web-Bench ( Xu et al., 2025a ) , and outperforms StepFun-Mix ( StepFun, 2026a ) using the same starting checkpoint, training configuration and sample count. Our contributions are: (1) A scalable construction pipeline. We introduce WebUniverse , which constructs verifiable front-end development tasks from open-source repositories and real web pages, covering text-grounded development and vision-grounded reproduction. (2) Reusable environments and verified trajectories.
