title: LADS: Lease-Aware Delivery Scheduling of Tool Results for Language Model Agents
source: https://arxiv.org/abs/2611.00881

§Abstract
Web agents complete multi-step online tasks through repeated browser actions and model calls. Their returned observations lie on the critical path to subsequent decisions. When concurrent browser actions finish in bursts, observations can accumulate on a constrained return path to a shared inference service, while waiting histories compete for reusable cache state. Conventional delivery rules prioritize short transfers or immediate cache reuse but overlook how sending a result earlier can help a request resume sooner and free cache-protection capacity for other waiting requests. We present LADS (Lease-Aware Delivery Scheduling), a tool-result scheduler that couples cache-aware delivery with bounded prefix leases. Its key insight is that resumption lets extra protection references retire, making lease quota available to protect another waiting history. LADS prioritizes timely handoffs using current lease ownership and an estimated resumption delay, with bounded departures from Cache-first order. Compared with ReAct using first-in, first-out (FIFO) tool-result delivery, LADS reduces mean complete-workflow latency by 44.6% under bursty tool returns and by 42.4% on Web-derived burst replay.

§Introduction (from cached fulltext; cut at ~9000 chars)
Web agents advance through observations: a returned page, retrieved passage, or tool response supplies the context for the next model decision. ReAct makes this reasoning–action–observation loop explicit ( Yao et al., 2023 ) . When concurrent agents share an inference service, completed observations also share a return path. Waiting on that path delays the next model call and every dependent action. We study how to order these completed results to reduce complete-workflow latency. The difficulty is that delivery order affects both communication waiting and the computation needed to resume an agent. Concurrent tool completions can create a backlog on a constrained return path, while their model histories compete for reusable key–value (KV) cache state. First-in, first-out (FIFO) follows readiness order; Size-first advances short transfers; Cache-first prioritizes results whose associated history prefixes are currently resident in the KV cache. A history observed in cache must still survive committed traffic and engine waiting before reuse. The useful scheduling signal therefore extends beyond result size or an immediate cache hit. Existing systems offer controls at several points in this process. PagedAttention supplies block-based KV management ( Kwon et al., 2023 ) ; InferCept and Continuum manage state across interruptions and multi-turn execution ( Abhyankar et al., 2024 ; Li et al., 2026 ) . Application-aware serving uses dependencies and program progress to schedule model calls ( Lin et al., 2024 ; Luo et al., 2026 ) . Tail-aware Release separates readiness from commitment and combines priority with feedback-driven control of committed model work ( Feng et al., 2026 ) . Before completed tool results are committed for transmission, a further question arises: how can delivery order preserve reusable histories and make bounded prefix-cache protection available to other waiting agents? Our key insight is that engine-native resumption—handled by vLLM’s own scheduler and block manager—can return protection quota before inference finishes. A bounded prefix lease adds references to keep a resident history available while its observation waits. Once the inference engine acquires that history and allocates new tokens, the extra references can retire. Their logical quota can protect another waiting history while the resumed request continues using its physical cache blocks. Delivery can thus influence who receives protection next. Exploiting this opportunity requires identifying owners with exclusive quota and estimating whether their results can reach allocation before the leases expire. We present LADS (Lease-Aware Delivery Scheduling), which connects result ordering to bounded prefix protection. Its cache-aware base order favors currently reusable histories. Leases are granted in FIFO order with a fixed maximum lifetime. The protection budget is based on expected near-term prefix reuse and capped to reserve cache space for model execution. A turnover priority advances a protected result when an estimated timely handoff can return exclusive quota for another waiting history. Each actual promotion is followed by a base-order choice, bounding consecutive interventions. Fully received observations continue through ordinary FIFO model entry; the engine verifies native ownership and positive-token allocation before retiring the extra references. We evaluate the complete method and its components through controlled bursts and Web-derived burst replay, and additionally validate delivery on captured Web-agent task paths. The two main workloads compare LADS with FIFO, Size-first, and a delivery-side adaptation of Tail-aware Release retaining its work accounting and feedback. Web-derived replay supplies Web observations within the controlled workload construction. Across five input seeds in the controlled cohort-8 realization, LADS reduces mean complete-workflow latency by 44.6% relative to FIFO. On Web-derived burst replay, the corresponding reduction is 42.4% across three input seeds. Our main contributions are summarized as follows: • We introduce LADS, a tool-result delivery scheduler that reduces complete-workflow latency for concurrent Web agents by coordinating result ordering with prefix-cache protection. • We identify resumption as an opportunity to return cache-protection quota before inference completes. Bounded prefix leases and an allocation-time ownership check make this quota available to other waiting histories while active requests continue using their cached prefixes. • Across five input seeds in the controlled cohort-8 realization and three input seeds in Web-derived burst replay, LADS reduces mean complete-workflow latency by 44.6% and 42.4%, respectively, relative to first-in, first-out delivery.
