§Abstract
Scaling computer-use agents from individual actions to complex software work requires experience that connects decisions to complete outcomes. We present NorthCUA, an integrated system for turbocharging computer-use agents through experience at scale. Its Experience Flywheel supplies diverse executable tasks to the NorthCUA Harness, which sustains long interactions, records decisions, and checks task outcomes. The Flywheel uses these records to curate verified trajectories. For unsolved tasks, recursive self-improvement evolves reusable skills and preserves verified milestones so later attempts build on earlier progress. Staged Learning combines this experience with grounding data from the Flywheel to develop GUI competence through mid-training and long-horizon supervised fine-tuning. The policy then learns from fresh attempts in the same Harness through joint desktop-web reinforcement learning, closing the loop between experience production and policy improvement. The resulting Nano, Mini, and Pro family achieves state-of-the-art results among open-source models across GUI grounding, desktop execution, and Web interaction under the reported evaluation settings. For more responsive Web workflows, NorthCUA-Ultrafast pairs direct action selection with open-ended generation on pre-RL Nano, offering a measured quality-latency tradeoff. Together, these advances establish NorthCUA as a high-performing model family and a reusable foundation for agents that carry complex software work from intent to completion.

§Introduction (from cached fulltext; cut at ~9000 chars)
Computer-use agents (CUAs) extend the capabilities of large language models from generating responses to operating computers and automating software tasks ( Zhang et al., 2025b ; Wang et al., 2025b ) . They can invoke software functions through application programming interfaces (APIs) and command-line interfaces (CLIs). Graphical user interfaces (GUIs) extend this access to functions that applications do not expose programmatically, providing a critical last mile for software automation ( Zhang et al., 2025a ; Zhang et al., 2025c ) . Through GUI interaction, agents interpret the screen and translate natural-language goals into mouse and keyboard actions. Advances in visual grounding and action generation have expanded the range of operations these agents can perform ( Qin et al., 2025 ; Wang et al., 2025c ; Zhou et al., 2025 ) . As agents combine these operations into longer workflows, earlier actions shape the software state on which later decisions depend. Reliable completion requires agents to preserve intermediate progress and the user’s constraints, adapt to changing interfaces, and recover from errors while keeping the overall goal in view ( Zhang et al., 2026 ; Lu et al., 2026 ) . Training agents to coordinate such workflows therefore requires experience that develops precise interface skills and connects successive decisions to complete task outcomes. Obtaining this experience at scale begins with constructing varied tasks, each of which needs a request grounded in available software and content, a usable initial environment, and a reliable way to judge success ( Ge et al., 2026 ; Zhou et al., 2026b ) . Once these tasks are available, collecting experience from them requires an agent framework that sustains long interactions and records decisions and outcomes across desktop and web environments. The resulting demonstrations can teach the policy how to complete workflows, but independent execution may lead it into states absent from those demonstrations. Continued improvement therefore requires fresh interaction and outcome feedback from the policy’s own attempts ( Wang et al., 2025c ; Jung et al., 2026 ; Lu et al., 2026 ) . Meeting these linked needs calls for co-designing how tasks are constructed, how agents execute them, and how the resulting experience is used for learning. We present NorthCUA , an integrated system for turbocharging computer-use agents through experience at scale . Our central idea is to co-design the production and use of experience, making software interaction a continuing source of learning. We connect executable tasks to policy updates through three components (Figure 2 ), focusing on GUI-based software operation. The Experience Flywheel constructs executable tasks for the NorthCUA Harness to run and assess. The recorded trajectories and outcome evidence guide curation, supplying Staged Learning with demonstrations that complement the Flywheel’s separately constructed grounding examples. This mixture develops interface understanding and workflow completion. Shared execution and outcome interfaces also let the learner collect fresh attempts from the policy itself, extending the same system from demonstration collection to continued policy improvement. NorthCUA Harness: full-lifecycle infrastructure. We design the NorthCUA Harness as full-lifecycle infrastructure that executes software tasks and turns the resulting attempts into inspectable experience for learning. This requires keeping the agent’s decisions connected to its workspace and outcomes, from environment preparation through execution and evaluation to record preservation. Within the shared runtime, visual context and task memory help agents build on progress across long workflows ( Zhang et al., 2026 ; Zhang et al., 2025d ) . An evaluator uses the execution record and live workspace to check task completion and execution quality, supplementing task-specific verifiers where their coverage is incomplete ( Zhuge et al., 2025 ) . To scale this process, the Batch Rollout Service coordinates parallel workers and overlaps lifecycle stages, supporting efficient, high-concurrency experience collection (Section 3 ). Experience Flywheel: scaling grounding and agentic experience. With a runtime for collecting and checking software experience, the next challenge is to supply enough varied, useful work for the agent to learn. The Experience Flywheel addresses two levels of supervision: single-step grounding examples for locating controls and assessed agent trajectories for completing tasks. Grounding pairs screenshots with queries and target locations. Visual and structural annotations provide broad coverage ( Lu et al., 2024 ; Li et al., 2025a ) , while application documentation helps explain a control’s function when appearance alone is insufficient.
