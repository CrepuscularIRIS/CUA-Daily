title: Empowering Edge Agents: A Systematic Analysis of Edge-Cloud Collaboration in LLM Agent Execution
source: https://arxiv.org/abs/2610.17816

§Abstract
Edge-cloud collaboration combines the lower inference overhead and greater data locality of edge-side execution with the stronger capabilities of cloud-hosted models. However, as LLM agents increasingly operate in long-horizon scenarios, cloud participation becomes interleaved throughout execution rather than a one-shot decision for each query. Such interleaved participation introduces trajectory-level effects that remain insufficiently understood. To address this gap, we introduce EC2-Bench, a benchmark for evaluating edge-cloud collaboration in long-horizon agent execution. It provides executable digital-workspace agent tasks and a unified evaluation framework covering task performance, resource usage, and privacy exposure. Using this benchmark, we empirically study diverse forms of edge-cloud collaboration. Our study reveals three findings. First, collaboration achieves a favorable balance among task performance, resource usage, and privacy exposure compared with edge-only and cloud-only execution. Second, as edge models become stronger, collaborative execution approaches cloud-only performance, and performance differences across strategies shrink, while privacy exposure remains strongly strategy-dependent. Third, stronger edge capability shifts preferred collaboration from externally controlled cloud participation and direct cloud execution toward more edge-controlled collaboration. Further analyses identify cloud-invocation decision-making and instruction following as important edge-side abilities for effective collaboration. These findings provide a systematic understanding of edge-cloud collaboration in long-horizon agent execution and insights for designing future edge agents that effectively collaborate with cloud models. Code and resources are available at https://github.com/OpenBMB/EC2-Bench.

§Introduction (from cached fulltext; cut at ~9000 chars)
Recent advances in large language models (LLMs) ( Achiam et al., 2023 ) , together with the emergence of agent harnesses such as Claude Code ( Anthropic, 2025 ) and OpenClaw ( OpenClaw, 2025 ) , have shifted LLM applications from isolated prompt–response interactions toward long-horizon, goal-directed agent execution ( Wang et al., 2024a ) . These agents tackle complex end-to-end workflows, including software development, data analysis, information seeking, and workplace automation, through iterative interaction with external environments and tool use ( Yao et al., 2022 ; Yang et al., 2024 ; Hu et al., 2024b ; Shen et al., 2023 ; Zhou et al., 2024 ; Wang et al., 2024b ) . Bringing such agents to edge devices, however, remains challenging because edge platforms are inherently constrained by limited computational resources and memory ( Qu et al., 2025 ) . Consequently, practical on-device deployment often relies on relatively small LLMs (e.g., models with \leq 10B parameters), which can struggle with demanding reasoning, planning, and tool-use tasks ( Choi et al., 2026 ) , making reliable long-horizon execution challenging ( Liu et al., 2024 ) . To address this limitation, recent work has explored edge–cloud LLM collaboration, where lightweight edge models are complemented by cloud-hosted frontier LLMs when additional capability is required ( Zhang et al., 2026b ) . This paradigm combines efficient edge-side execution with stronger cloud capabilities, but requires effective coordination of edge and cloud participation to realize these complementary benefits ( Ding et al., 2024 ; Sun et al., 2024 ; Agrawal and Mayer, ) . Prior edge–cloud LLM systems largely treated collaboration as a one-shot coordination process for each query, typically through routing or escalation decisions ( Pozi and Sato, 2025 ; Han et al., 2026 ) . In long-horizon agent execution, however, collaboration can become more interleaved, with edge and cloud models participating at different points along the trajectory as capability requirements change ( Yi et al., 2025 ; Zhang et al., 2026b ) . Such interleaving introduces trajectory-level dependencies: cloud participation decisions can influence subsequent execution steps, accumulate resource costs over the trajectory, and determine how much potentially sensitive information leaves the local environment. Yet existing analysis still largely focuses on isolated routing or escalation decisions at the query level, leaving these trajectory-level effects underexplored ( Hu et al., 2024a ; Lu et al., 2025 ; Li et al., 2026a ; Li et al., 2025 ) . To close this gap, in this paper, we conduct a systematic empirical study of edge–cloud collaboration in long-horizon agentic execution. Specifically, we organize our study around three research questions. We first ask: does edge–cloud collaboration remain effective for realistic long-horizon agent execution? ( RQ1 ) We evaluate this question jointly in terms of task performance, resource usage, and privacy exposure. As edge models become more capable, more execution can be handled locally while cloud assistance is reserved for capability-demanding operations. We therefore ask: how does increasing edge capability impact edge–cloud collaborative execution? ( RQ2 ); As increasing edge capability changes how computation is distributed between edge and cloud, collaboration strategies that are effective under one capability regime may not remain equally suitable under another. This motivates our final question: how should edge–cloud collaboration evolve as edge capability advances? ( RQ3 ). To provide a common empirical basis for this study, we introduce EC 2 -Bench ( E dge– C loud C ollaborative Agent Benchmark), an evaluation framework that combines a diverse suite of real-world digital-workspace agent tasks with a unified execution and evaluation environment for edge–cloud collaboration. EC 2 -Bench characterizes each configuration along three dimensions: task performance ( Yuan et al., 2026b ) , resource usage ( Fang et al., 2025 ) , and privacy exposure. We explicitly consider privacy because cloud participation may reveal sensitive workspace information encountered during agent execution, making privacy exposure an important dimension of evaluating such collaboration ( Fu et al., 2026 ) . Using EC 2 -Bench , we systematically investigate edge–cloud collaboration across diverse agent tasks, collaboration strategies, and edge-capability regimes. Our study yields three main findings. First, edge–cloud collaboration remains effective for long-horizon agents: partial cloud participation improves task performance over edge-only execution while requiring substantially less cloud resource usage and privacy exposure than cloud-only execution.
