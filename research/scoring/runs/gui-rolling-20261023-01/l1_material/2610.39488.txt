title: InterA11y: Interactive Web Accessibility Error Detection with LLM Agents
source: https://arxiv.org/abs/2610.39488

§Abstract
Large Language Models (LLMs) have shown potential to expand the coverage of web accessibility evaluation. However, current LLM-based checkers neglect much of the interactive and dynamic web contexts, resulting in limited coverage, high false discovery rates, and inconsistent performance across models. We present InterA11y, an agentic accessibility evaluation system that combines rubrics and interactive tools to support LLM agents in evaluating accessibility effectively. The rubrics decompose WCAG success criteria (SC) into testable aspects and guide agents in collecting and interpreting evidence. The interactive tools inspect or operate a webpage deterministically to collect evidence, such as focus appearances and error messages. We developed these rubrics and tools on 682 curated test cases grounded in established accessibility guidelines that target 10 commonly violated SC. We evaluated InterA11y on 197 expert-annotated cases sampled from 54 real webpages. Results show InterA11y achieves higher recall than the strongest evaluated LLM-driven baseline (79.0% vs. 44.4%), while maintaining comparable precision to best rule-based checkers (93.1% vs. 90.3-97.6%), with little variability between models. Further, when equipped with our interactive tools, general-purpose web agents detect more accessibility errors with fewer false positives and less token usage than without these tools.

§Introduction (from cached fulltext; cut at ~9000 chars)
Identifying accessibility barriers in websites and web applications is essential to ensuring equitable web access. The growing use of LLMs in web development makes the need for reliable accessibility evaluation more urgent ( Mowar et al., 2025 ; Gurita and Vatavu, 2025 ) . Currently, web accessibility evaluation requires substantial expertise ( Seixas Pereira and Duarte, 2025 ) and manual efforts ( Velleman and Abou-Zahra, 2014 ; Google Developers, 2025 ) , because automated rule-based checkers provide limited coverage of guidelines ( Deque, 2026 ; WebAIM, 2024 ) and relying on them alone can be risky ( Vigo et al., 2013 ; Calò et al., 2026 ) . LLM-based checkers have been proposed to address this coverage gap, especially for assessing errors that require semantic understanding of webpage structure and content ( Fathallah et al., 2025 ; He et al., 2025 ; López‑Gil and Pereira, 2025 ; Paternò et al., 2025 ) . Despite these potential benefits, current LLM-based checkers are limited in two respects: (1) lack of dynamic or interactive probing and (2) high variability across models. First, current checkers examine static web contexts, such as HTML, JavaScript, and screenshots. Accessibility evaluation under the four Web Content Accessibility Guidelines (WCAG) principles—perceivable, operable, understandable, and robust—involves examining how webpages behave during user interaction, particularly for criteria related to keyboard navigation, focus management, and feedback ( Campbell et al., 2024 ) . In particular, “operable” targets the accessible interaction of web components but is largely left out by current LLM-based checkers, which have mostly targeted static content such as text alternatives and labels ( Aljedaani and Mollik, 2026 ) . Second, as we will show through our evaluation of current checkers, they are susceptible to different foundation models when tested on the same detection tasks, with false discovery rates (FDR) varying up to 26.5 percentage points across models. Such variability raises concerns about the reliability of LLM-based checkers in practical web development and testing workflows. Similarly, prior work has shown that general-purpose AI agents also face reliability challenges on several WCAG success criteria ( Santana et al., 2026 ) . To improve LLMs’ performance in web accessibility evaluation, motivated by prior work where LLM agents are used to identify accessibility errors through interaction ( Zhong et al., 2026 ) , we introduce InterA11y , an agentic accessibility evaluation system supported by interactive tools and rubrics . The tools render and interact with a page programmatically, collecting evidence of markups and metadata, rendered appearance, and how it responds to keyboard, focus, and screen reader usage. The rubrics support an LLM agent in interpreting this evidence and running additional tools in multiple turns to determine whether an aspect of a WCAG success criterion (SC) is met. Our rubrics are informed by existing checkers (GenA11y ( He et al., 2025 ) ), guidelines ( Campbell et al., 2024 ; W3C Web Accessibility Initiative, 2026b ) , and regulations ( of Homeland Security (DHS) Accessibility and Usability, 2024 ; European Telecommunications Standards Institute (ETSI), 2021 ) . In this paper, we focus on 10 success criteria that are particularly relevant to interactive web contexts, covering all four WCAG principles, e.g., Non-text Content (1.1.1), Focus Order (2.4.3), Error Identification (3.3.1), and Status Messages (4.1.3). To develop our system, we curated 682 test cases covering these 10 success criteria. The test set includes 223 cases from the W3C’s Accessibility Conformance Testing (ACT) test cases ( W3C Web Accessibility Initiative, 2026b ) and 459 AI-generated cases independently validated by the authors. We separately analyze the contributions of rubrics and agentic interactive tools using this test set. Results show that adding InterA11y rubrics over GenA11y improved recall from 31.0% to 64.2%, while reducing false discovery rate (FDR) from 39.2% to 31.1%. Adding interactive tool use further increased recall to 76.4% and decreased FDR to 9.4%—lower than many rule-based checkers. We evaluated InterA11y with 197 expert-labeled cases sampled from 54 real webpages. We compared against three types of baselines: (1) rule-based checkers, (2) existing LLM-based checkers, and (3) general-purpose web agents. Results show that InterA11y achieves higher recall (79.0%) than the strongest evaluated general-purpose web agent (36.0%) and LLM-based checker (44.4%). InterA11y maintains comparable precision to rule-based checkers (93.1% vs. 95.7%), while general-purpose web agents had much lower precision ( \sim\!77\% ). Further, adding InterA11y’s interactive tools to the general-purpose web agents improved both their precision and recall while lowering token usage and execution time.
