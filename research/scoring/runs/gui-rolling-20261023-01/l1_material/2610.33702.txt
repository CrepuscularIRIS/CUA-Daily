title: Seeing the Options: Typed Decisions over Visual Candidates with Reusable Option Memory
source: https://arxiv.org/abs/2610.33702

§Abstract
Agents end many steps in a typed decision over a set of candidates: which screen element to click, which product to pick. System One models answer in one forward pass, and Jeva showed that four properties the setting demands - a "none of the above" probability, invariance to candidate order, scalability in the number of candidates, and reuse of candidate computation - follow from encoding the request and each candidate separately and letting a request state read a candidate memory. Jeva is text-only, and existing multimodal System One models (OneJev, Jev-Omni) put images in the request while candidates stay text in letter slots. This paper asks what happens to the four properties, and to accuracy, when the candidates themselves are images. Iris admits image, text, or mixed candidates and leaves Jeva's decision module untouched. On a visual-candidate benchmark built from Multimodal-Mind2Web (every candidate is the element's screenshot crop, K=16, three splits), independent encoding reaches 78.4/72.1/74.8% with a flip rate of exactly zero, while joint encoding (OneJev-4B fine-tuned on the same data) reaches 90.6/89.5/91.6% but changes its answer on 8-10% of records when the crops are reordered. Most of the gap is the candidate not seeing the request: a third design that encodes each candidate after the state - but never after another candidate - keeps order invariance exactly, shares the state pass through a forked cache, and reaches 92.1/87.0/90.2% at a third of OneJev's latency with a calibrated null probability (AUROC 0.93-0.97). Letting pooled candidates see each other (set attention, token-level reads, multi-vector memory) buys nothing, because the encoder maps visually distinct elements to vectors within cosine 0.999 of each other. Reusing image candidates across requests cuts latency 37x at K=256 and 191x at K=2048. Code: https://github.com/lllfx/Iris

§Introduction (from cached fulltext; cut at ~9000 chars)
Much of what an agent does between two generations is not generation. It picks a tool, selects an element on a page, keeps or drops a retrieved document, checks a precondition, grades an outcome. These are typed decisions—a choice among K candidates, a yes/no judgement, an ordinal score—and System One models [ 3 ] answer them in a single forward pass with calibrated probabilities instead of a chain of tokens. The dominant way to build one is to concatenate the request and all candidates into one sequence and read the answer from the logits of answer letters or from a pointer head (SemIf, JevK5, Intern-Decision, KEV; § 6 ). Jeva [ 1 ] observed that this joint encoding is the source of four structural failures—the answer depends on candidate order, the candidate count is bounded by the answer alphabet, “none of the above” has no principled probability, and nothing computed for a candidate can be reused—and removed all four by construction: a shared encoder maps the request to a state z_{0} and each candidate to a vector u_{i} on its own ; a decision block updates only the state by attending over the set \{u_{i}\} ; a coverage gate decides whether any candidate applies at all. Jeva is text-only, and so are its candidates. Yet the candidates agents choose among are frequently visual. A web agent chooses a region of a screenshot; a shopping agent chooses among product photos; a research agent matches an announcement to the chart it refers to. The multimodal System One models released so far— OneJev [ 2 ] and Jev-Omni—accept images and video, but only in the request ; candidates remain text rendered into at most 256 letter slots, with every joint-encoding cost above intact. Concurrently, Liu et al. [ 9 ] rerank images by listing them in letter slots and Runoff [ 8 ] removes order dependence at inference time with K+m^{2} encodings per request; neither makes the candidate computation reusable. There is, to our knowledge, no System One model whose candidates can be pictures and whose decision is order-invariant and cacheable by construction. This paper makes the case that visual candidates are not a feature to add to System One models but the setting in which Jeva ’s four properties stop being conveniences and become requirements (Figure 1 ): • Order. Elements on a page, photos in a catalogue, charts in a market have no canonical order. A model whose answer depends on the order in which crops were listed is reporting an artefact of serialisation, not a decision. • Count. A page has hundreds of clickable elements and a market has thousands of instruments. Joint encoding must place every candidate’s image tokens in one sequence: at K{=}16 and 256 tokens per image the candidates alone are 4k tokens per request; K{=}2{,}048 would be half a million. • Null. In agent traces the correct element is often not among the candidates offered, and a model without a null output must pick one anyway. • Reuse. A text candidate costs tens of language-model tokens to encode; an image candidate costs a vision-tower pass plus hundreds of tokens. Whatever a cache saves per hit, it saves one to two orders of magnitude more when the candidate is a picture (§ 3.3 ). We present Iris , a System One model whose request and candidates are segments —text with images—and whose decision module is Jeva ’s, unchanged. The design is deliberately minimal, because it makes the claim falsifiable: if the four properties belong to the decision module, then changing the encoder and nothing else must preserve them exactly, and the gain from reuse must scale with the encoding cost of the modality. Both are borne out. Contributions. 1. Problem. We formalise typed decisions over visual candidates (§ 2 ) and show that the letter-slot interface used by existing multimodal System One models cannot express them without reintroducing all four joint-encoding costs. 2. Model and guarantees. Iris (§ 3 ) keeps the full Qwen3.5 vision–language backbone that Jeva loads and discards, and extends candidate memory to image content. Proposition 1 states that order invariance and exact cache reuse hold for any per-candidate encoder, and Proposition 2 gives the latency reduction from reuse in closed form as a function of the reuse ratio and the encoding cost ratio between modalities. 3.
