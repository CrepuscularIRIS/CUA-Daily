title: Task Success Is Not Enough: Side-effect-Aware Evaluation of Tool-Using Language Model Agents
source: https://arxiv.org/abs/2610.34167

§Abstract
Tool-using language model agents are usually evaluated by whether they finish the user's task. That metric misses a common failure: an agent can complete the requested work while also taking an unauthorized side-effecting action, such as writing to the wrong object, expanding the scope of the request, or contacting an unintended recipient. We call this failure mode collateral damage (CD). We introduce SABench (Side-effect-Aware Benchmark), a benchmark of 201 email, calendar, and ticket tasks. Each task crosses one of four state structures (independent, dependent, externally reachable, cross-tool) with one of four trap families (ambiguity, mis-targeting, cascade harm, overreach), and each task has a deterministic trace-based oracle for both goal satisfaction and authorization compliance. Across 2,211 model-task pairs from 11 frontier LLMs spanning major commercial and open model families, 15.2% of all runs incur CD, with risk concentrated in ambiguity tasks (38.8% violation rate) while non-ambiguous traps average 8.4% CD. Among goal-satisfied runs, 12.8% still produce unauthorized writes. Cross-tool and dependent states have about twice the CD rate of independent states. CD rates vary by 4.7x across models at comparable goal rates, which suggests that task success alone is a poor proxy for safe tool use. The SABench task corpus is released at https://huggingface.co/datasets/Phaedrus/sabench; the traces, oracle, code, and analysis pipeline are released at https://github.com/hjj194/sabench-artifact.

§Introduction (from cached fulltext; cut at ~9000 chars)
Language model agents are increasingly evaluated by whether they can accomplish user-specified tasks in interactive environments. This framing appears in general agent benchmarks and reasoning-agent protocols ( 1 , 2 , 3 ) , and it has been pushed further in web, desktop, and workplace settings ( 4 , 5 , 6 , 7 ) . The result is real progress in navigation, tool use, and multi-step planning, but it has also made task success the default lens for judging agent behavior. That lens is too narrow for agents that can write to shared state. In realistic tool-use settings, the failure is often not that the agent does nothing. The failure is that it does the requested thing and something extra: replying and forwarding, moving one calendar occurrence and notifying unrelated attendees, updating a linked ticket while answering a customer email, or choosing one plausible target without resolving ambiguity. Consider an assistant asked to forward Alice’s “Q3 Plan” email when two same-subject messages from Alice appear in the same thread. A model that guesses one message may look helpful, and a final-state checker may mark the task complete, but the agent has sent an externally visible message without knowing which email the user intended. We refer to this category of failure as collateral damage (CD): writes produced during ordinary task execution that fall outside the user’s authorization boundary. Collateral damage is different from misuse. The request is benign, and the agent is not being asked to cause harm; the risk comes from overreach while trying to help. This is especially relevant in office-style workflows, where ambiguous references, linked records, recurring structures, and external recipients routinely appear in the same state. Recent stateful benchmarks have moved toward database-backed tools and programmatic checking ( 8 , 9 , 10 ) , while CRM-style tasks make the same issue visible in business workflows ( 11 ) . Their main measurement target, however, is still usually task completion. Prior work on agent safety studies malicious requests and harmful tool use ( 12 , 13 , 14 ) , and another line focuses on prompt injection or indirect instruction attacks ( 15 , 16 , 17 , 18 ) . Those settings are important, but they leave a separate deployment question open: how often do agents over-act under ordinary benign instructions? Measuring CD requires more than a final-state goal checker. The evaluator needs to know which writes were authorized by the user, which writes the agent executed, and whether any extra writes affected external parties. The central shift is from asking only whether the final state satisfies the request to asking whether every state-changing step was authorized. We therefore treat CD as a trace property: given an initial state and a tool-call trace, the oracle extracts successful writes, replays them deterministically, checks goal satisfaction, and compares the realized writes with an explicit authorization set. This also changes what a benchmark task must specify. A normal task benchmark can define the desired final condition and leave the rest implicit; CD evaluation must specify the boundary of permission: which object may be edited, which fields may change, whether notification is allowed, and whether a related object in another tool is part of the request. Rescheduling one occurrence is not authorization to cancel the series; replying to a customer is not authorization to update an internal ticket. We avoid free-form judging for this reason. Authorization is easier to audit as state: a normalized write either targets an authorized entity and field or it does not, and an email either leaves the workspace or it does not. Our benchmark starts from a simple observation: collateral damage depends on the state as well as the wording of the instruction. The same request can be safe when the target is isolated and risky when the state contains a recurring series, a look-alike email, a linked ticket, or an external distribution list. SABench crosses four state structures with four trap families so that ambiguity, mis-targeting, cascade harm, and overreach can be measured under controlled conditions. The four state structures cover common ways ordinary work becomes coupled: independent targets, dependent threads or series, externally reachable recipients, and cross-tool evidence split across email, calendar, and tickets. The paper makes three contributions. First, we formalize CD as writes outside an explicit task authorization boundary (Section 2 ). Second, we release SABench , a 201-task / 47-template benchmark with a deterministic oracle for goal, CD, ambiguity, and visibility (Section 3 ). Third, we evaluate 11 frontier LLMs on 2,211 model–task pairs: 15.2% of all runs and 12.8% of goal-satisfied runs incur CD, with strong variation by model, trap family, and state structure (Section 6 ).
