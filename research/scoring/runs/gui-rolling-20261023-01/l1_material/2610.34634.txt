title: AgentProofBench: Benchmarking Reusable Verifiers for Web Agents
source: https://arxiv.org/abs/2610.34634

§Abstract
Reusable Web-agent verification requires a rule to follow changing requirements and support subsequent execution. We introduce AgentProofBench, which connects paired tests of a frozen acceptance rule to execution from identical saved openings. The resource spans 97 tasks, 79 families, and four Web services. Experiments with DeepSeek Flash/Pro establish two linked measurements. Across 48 families, complete-panel and decision-replay tests retain 82/96 Flash and 79/96 Pro source programs; paired reuse-rebuild BA intervals are [-5.47, 1.57] and [-10.16, 0.00] percentage points. Across 22 execution families, deployment-state panel correctness separates program assignments whose two saved openings are both delivered correctly: 32/33 assignments with error-free panels, versus 1/11 with panel errors. All reference-defined program-gate regressions and withheld deliveries occur in the latter group. Neutral continuation attains the highest correct delivery under the tested generic feedback, providing a concrete baseline for measuring the value added by a gate. Released instructions, states, programs, reference rules, and trajectories connect each test failure to its execution consequences. AgentProofBench makes reusable verification assessable at both the requirement and policy levels.

§Introduction (from cached fulltext; cut at ~9000 chars)
Reusable acceptance checks can make Web-agent operation fast and inspectable. A program can encode the conditions for completing a task, inspect the relevant business state, and issue the same explicit checks on subsequent executions. The central challenge is that the public instruction can stay fixed while the required work changes. The current owner of a name, the files belonging to a collection, or the value that must be preserved comes from the initial state of each execution. A verifier that remembers an earlier answer can produce a convincing decision for the wrong requirement. The decision also becomes part of the agent’s environment. Rejection can trigger further edits, and acceptance can release the resulting state. Evaluating a reusable verifier therefore requires a link between the conditions its tests exercise and the outcomes of the policy that consumes its decisions. Matched continuation histories make that link observable: the same completed work can be preserved, changed, or withheld under different stopping policies. Existing Web-agent environments establish executable task evaluation ( Zhou et al., 2023 ; Yao et al., 2024 ; Xie et al., 2024 ; Trivedi et al., 2024 ; Pyskło et al., 2026 ) . Work on automatic assessment and generated verifiers demonstrates the importance of evidence and acceptance of valid alternatives ( Lù et al., 2025 ; Rosset et al., 2026 ; Yin et al., 2026 ) . Reusable execution policies further show the value of experience across workflow instances ( Suh et al., 2026 ) . These advances motivate an evaluation that connects three properties of an acceptance rule. It must recognize the permitted terminal outcomes, recover the requirements of a changed initial state, and support effective continuation and delivery decisions. We introduce AgentProofBench around this connection. An acceptance program is executable code that judges task completion through ordinary before/after APIs. A reuse contract fixes the public instruction and evidence permissions while initial business data vary. Matched terminal outcomes make the consequences of this variation observable. Shared actor openings then connect the same verifier to the actions taken after its decision. Every measurement is linked to versioned reference predicates, program source, API evidence, and a reconstructable business state. The benchmark provides three contributions. • A paired reuse test that holds the public instruction and generated program fixed while changing its required initial-state bindings. Complete outcome panels and replayed decisions measure complementary obligations. • An execution-validity test linking deployment-state panel correctness to matched policy outcomes. The 22-family study preserves 44 program assignments, two openings per assignment, and 352 policy outcomes. • An executable resource with 97 tasks across four Web services, including versioned reference rules, legal alternatives, reconstructable states, programs, and action histories. The central empirical result is the connection between tests and execution. Programs with error-free deployment-state panels correctly deliver both saved openings in 32 of 33 assignments, compared with one of eleven assignments whose panels contain errors. The paired reuse study explains which requirements those panels exercise; replay witnesses expose additional errors in three source programs. Fixed-instance acceptance and cost profiles then describe the operating tradeoffs of the same verification interface. The reported generator, judge, and actor results use DeepSeek Flash/Pro with thinking disabled.
