title: EnvOS: Auditing Computer-Use Agents When the World Moves On : Phenomenon-Based Task Construction, Certification, and Evidence-Based Evaluation
source: https://arxiv.org/abs/2610.40246

§Abstract
Computer-use agents built on large language models (LLMs) work in software that can change while they act: an appointment moves, a policy is revised, a record is updated. Testing agents under such changes is harder than it looks. When an agent fails, the cause may be the agent, but it may also be a change that did not fire as intended, an update the agent never received, or a grader that scored the episode wrongly. We introduce EnvOS, a framework for building and certifying environments that change mid-task. Before any agent runs, EnvOS checks that each change fires correctly, that the task remains solvable, and that the grader separates correct from incorrect behavior; after each run, separate code re-checks the verdict from archived evidence. We apply it to stale information, where a value the agent has already seen changes before the agent acts on it. In clinic booking, Claude Opus 5 succeeds on 0/16 tasks when nothing extra is shown, 2/16 when reminded to re-check the source, and 15/16 when the updated value is shown; the gain over the reminder holds after correcting for all tests (p = 0.00293). In insurance-claim approval, Opus 5 re-checks on its own and succeeds on 10/10, whereas Claude Sonnet 5 rises from 1/10 to 9/10 when the current policy is shown again, a gain significant in its pre-registered test but not after correcting for all tests. Whether an agent caught a change thus varied with the model and the interface. We also stress-test the grading itself: on corrupted episodes designed blind from the rules, the EnvOS pipeline accepted none of 26 as clean, and on an externally generated set it caught 25 of 39, against 4 for simple log checks. Because every EnvOS environment is generated from a seed and graded by an audited automatic verifier, the same environments are natural candidates for training agents with reinforcement learning from verifiable rewards.

§Introduction (from cached fulltext; cut at ~9000 chars)
Computer-use agents increasingly execute multi-step workflows over stateful applications, but evaluation commonly treats the application state as fixed once an episode begins. In deployed workflows, an appointment can move, a reimbursement policy can be revised, or a selected resource can become unavailable independently of the agent’s actions. These changes are not merely visual perturbations: they modify the authoritative records against which later actions are judged. Existing work has expanded interactive evaluation to long-horizon tasks, temporal disruptions, and evolving environments ( Yuan et al., 2026 ; Hui et al., 2026 ; Froger et al., 2026 ; Zou et al., 2026 ) . A complementary methodological problem remains: how can such changes be instantiated as valid test cases and how can one establish that an observed failure belongs to the agent rather than to the benchmark machinery? The question is sharper when the same environments supply a training signal: reinforcement learning with verifiable rewards trains agents against programmatic checkers ( Wang et al., 2026 ; Wei et al., 2026 ) , so an intervention that silently fails or a checker that accepts a corrupted episode yields a wrong reward, not only a wrong benchmark number ( Zhu et al., 2025 ) . The question involves two different sources of uncertainty. Intervention validity concerns whether the environment underwent the intended state transition, at the intended point in the workflow, without unintended side effects or an impossible endpoint. Evaluation validity concerns whether the policy received its assigned observations, whether attempted rollouts were classified under fixed rules, and whether the scorer’s verdict is supported by archived evidence. A terminal pass/fail label alone cannot resolve these distinctions. For example, a booking agent may appear to use an outdated clinic location even when the update occurred before it saw the original value, or when the promised review information never reached the model. Either case invalidates the intended interpretation without requiring a failure of the agent’s decision policy. We present EnvOS , a phenomenon-based framework linking task construction with executable certification and auditable outcome analysis (Figure 2 ). A phenomenon specifies an application-independent class of changes to authoritative state. An executable perturbation implements one instance of that class, defining the state operator, triggering condition, observation channel, and single-execution guard. The resulting task, seeded world, perturbation, endpoint criteria, and verifier form a candidate evaluation artifact. EnvOS admits that artifact for model evaluation only after scoped tests of the state transition, observation consistency, feasibility, behavioral discrimination, and checker robustness. Prospective experiments additionally freeze their design and counting rules, isolate the policy from evaluator data, and reconstruct supported verdict terms through separate implementations. The principal empirical analysis focuses on stale authoritative information : the agent is first served a task-relevant value, the underlying application state changes on a later eligible request, and the agent subsequently makes a consequential decision. The timing is important: changing a value before it is served does not establish that the agent’s earlier observation became stale. Figure 1 separates the mutation of the authoritative record from the later interfaces through which its updated value may be disclosed. A recorded page serve, a delivered model observation, and the agent’s comprehension are distinct events; the first two can be audited, whereas comprehension cannot be assumed from either. For clarity, we retain the preregistered condition codes throughout. In the clinic experiment, OFF-A denotes no additional information at confirmation; CUE-A denotes a verification reminder and a link to the original record, with the updated location withheld; and LIVE-A denotes the same reminder and link with the current location shown. In the insurance experiment, OFF-A provides no additional policy information, whereas ON-A presents the current policy at approval. In both workflows, these conditions change the information presented to the agent, not the underlying state transition. We investigate two applications of this evaluation design: clinic booking, where a session location changes, and insurance-claim approval, where a policy limit changes before the agent calculates an approved amount. In the principal paired comparisons the application-side change occurs in every condition; the manipulated variable is what appears at the review step. In clinic booking the agent receives either no additional review display, a review display pointing to the source page, or the current location itself.
