title: Harness Matters: Measuring and Dissecting Security Resilience in Web Agents

§Abstract
Web agents extend LLMs from text generation to real-world web interaction by relying on execution harnesses that interpret user goals, perceive webpages, plan actions, and ground model decisions into browser operations. While prior work has recognized that agent security depends on more than the backend model alone, how harness design quantitatively shapes web-agent security remains insufficiently measured. To systematically study web-agent harness security, we first characterize web-agent harnesses as a four-stage execution workflow covering goal interpretation, webpage perception, reasoning and planning, and action execution. Based on this abstraction, we build WebTrap Farm, a systematic and extensible evaluation framework covering three representative attack categories: malicious user prompts, malicious prompt injection, and deceptive web design. To avoid conflating security with task capability, we use paired usability calibration tasks to separate genuine defensive behavior from capability limitations. Our evaluation shows that existing web-agent harnesses remain vulnerable to typical attacks, with some unsafe behaviors occurring even without explicit attack content, revealing harness-intrinsic security failures (RQ1). Statistical analysis further shows that both harness and backend model significantly affect security outcomes, indicating that deployed-agent security is jointly shaped by the harness and backend model (RQ2). Finally, we localize where defensive behavior emerges across workflow stages and identify more secure design mechanisms, providing actionable guidance for building more robust web agents (RQ3). These findings highlight the web-agent harness as an important security boundary and motivate moving beyond model-centric defenses toward harness-level security design.

Large language models (LLMs) are increasingly integrated into agents that autonomously interact with real web environments. Unlike chatbots, web agents automate practical tasks such as information retrieval, online transactions, and appointment scheduling [ 51 , 46 , 38 , 1 ] . However, exposing LLMs to untrusted webpages and connecting model outputs to real-world actions introduce broad security threats, including malicious user prompts [ 30 , 52 ] , webpage prompt injection [ 9 , 21 , 31 , 59 ] , and deceptive webpage designs [ 57 , 20 ] . Prior studies have shown that web agents can be easily attacked, but they provide limited insight into why unsafe actions are executed. Most evaluations focus on the robustness of backend models against malicious instructions or adversarial webpage content [ 21 , 62 ] . Although recent academic and industry efforts have recognized that system-level design choices beyond the backend model can affect agent security [ 42 , 13 , 22 ] , how harness design quantitatively shapes web-agent security across different systems and attack surfaces remains insufficiently measured. Existing evaluations provide limited support for such measurement because they often entangle harness-level security with model robustness and task capability. Specifically, these works face three limitations. First, they often focus on a specific type of attack, making it difficult to understand the overall security exposure of web agents across different attack surfaces. Second, they may conflate attack failures caused by insufficient task capability with successful defenses, which overestimates the agent’s security resilience and introduces bias into the evaluation. Third, existing benchmarks are often coupled to specific agent harnesses, imposing substantial manual effort on cross-harness and systematic evaluation. Our Work. Therefore, we present WebTrap Farm , a unified framework for quantitatively measuring and dissecting security resilience in web agents. WebTrap Farm enables systematic cross-harness evaluation while separating security behavior from task incapability and localizing where defensive behavior emerges in the execution workflow. It includes an extensible benchmark covering three major attack categories across different attack surfaces: Malicious User Prompts, Malicious Prompt Injection, and Deceptive Website Design. To avoid conflating security with task failure, WebTrap Farm introduces paired usability calibration tasks that distinguish defense success from cases where an agent simply cannot complete the original task. It also provides a cross-harness execution and monitoring suite based on webpage instrumentation, enabling consistent evaluation without additional manual effort. We conduct experiments around three research questions: RQ1: How vulnerable are web-agent harnesses and backend models under different attack surfaces? We first evaluate the end-to-end vulnerability of both open-source harnesses and commercial web agents. We instantiate representative harnesses with multiple backend models and measure their attack success rates, including naive attacks that contain no explicit injected instruction or deceptive content. This design allows us to test whether unsafe execution depends on specific harnesses or models, and whether it can arise from ordinary task execution. Our results show that vulnerabilities persist across the open-source harnesses, with an overall attack success rate of 32.55%. The evaluated commercial systems achieve lower attack success rates but still exhibit meaningful vulnerabilities. RQ2: How much does the web-agent harness matter for agent security resilience? We next examine the effects of harness and backend model on security resilience. Using usability calibration, we apply a mixed-effects logistic regression to quantify harness and model effects while accounting for repeated tasks and attack-category effects. Our results show that the harness, backend model, and their interaction all have significant effects on security outcomes ( p<10^{-45} ), and remain robust under sensitivity analyses for capability-dependent missingness. These results show that deployed-agent security is jointly shaped by the harness and backend model, rather than being determined by either factor alone. RQ3: Where does defensive behavior emerge within web-agent harnesses, and which design mechanisms strengthen security? Finally, we localize observed defensive behavior across the four workflow stages. Using execution traces, we identify effective defenses after excluding attacks mitigated at earlier stages. The resulting stage-level analysis reveals different defensive patterns across attack surfaces, which we further examine through controlled ablations. For user-side attacks, the ablations support the security benefits of fine-grained intent interpretation and risk-aware reasoning. ## II Web Agent Harness
A web agent is an automated system that uses large language models (LLMs) or large multimodal models (LMMs) as its core controller to complete complex tasks in real and dynamic web environments [ 18 , 37 , 65 , 50 ] . Unlike conventional conversational LLMs that operate mainly over textual inputs and outputs, web agents are embedded in an execution harness that connects model decisions to concrete interaction primitives. While such a harness enables agents to perform long-horizon tasks, it also expands the attack surface beyond the model itself and weakens the conventional security boundary assumed for standalone LLMs [ 61 , 44 , 14 ] . To characterize web-agent harnesses, we survey 40 web-agent papers published in top venues (from 2021 to 2026) and collect 68 GitHub projects with at least 1,000 stars using “web agent” and “browser agent” as search keywords. We exclude repositories that do not implement agentic web interaction. From these sources, we abstract the common web-agent workflow into four stages, as shown in Figure 1 . TABLE I : Taxonomy of Web Agent Harness Components Stage I: Goal Interpretation. The agent first interprets the user’s natural-language instruction and converts it into an internal task representation. This stage determines the task objective, relevant constraints, and implicit execution intent, which guide all subsequent decisions. Stage II: Webpage Perception. The agent obtains the current webpage state through browser interfaces, such as DOM extraction, accessibility trees, screenshots, or multimodal observations. This stage determines what webpage content, interface elements, hidden or off-screen text, and browser states are exposed to the backend model. Stage III: Reasoning and Planning. Given the interpreted goal and perceived webpage content, the agent reasons about the task context and decides how to proceed. This stage generates a single next action or a multi-step plan, including selecting target elements, choosing input values, and updating the plan based on new browser states. Stage IV: Action Execution. The planned action is grounded into concrete browser operations, such as selecting a target element, clicking a button, and typing into a field. The agent then executes these operations through browser automation interfaces, observes the resulting page state, and returns it to the agent loop for subsequent decisions. Although existing web agents largely follow this four-stage workflow, their harnesses differ in how each stage is implemented. In other words, workflow stages provide a common abstraction, whereas harness components capture the concrete design choices within each stage. We therefore categorize the harness components used at each workflow stage in the 68 GitHub projects. Our analysis shows that common designs include LLM-based parsers for goal interpretation (85.0%), text-only webpage perception (67.7%), single-controller reasoning structures (73.0%), and rule-based grounding methods for action execution (83.8%). Prior security studies on web agents often evaluate attacks against specific harnesses and implicitly treat the observed behaviors as broader web-agent security properties [ 30 , 31 , 57 ] . However, these observations can be affected by harness design. For example, a backend model that appears more defensive in one harness may not be more resistant to the attack itself, as the difference may instead come from harness mechanisms. Therefore, studying web-agent security requires systematic comparisons across harness designs and analysis of where defensive behavior emerges. This motivates our focus on web-agent harness security: rather than treating the agent as a monolithic LLM-driven system, we analyze how harness components shape the agent’s security boundary.
