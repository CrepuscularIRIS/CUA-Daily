title: TabAgent: Distilling LLM Agent Components into Cheap Classifiers
source: https://arxiv.org/abs/2602.16429

§Abstract
Agentic systems, AI architectures that autonomously execute multi-step workflows to achieve complex goals, are often built using repeated large language model (LLM) calls for closed-set decision tasks such as routing, shortlisting, gating, and verification. While convenient, this design makes deployments slow and expensive due to cumulative latency and token usage. We propose TabAgent, a framework for replacing generative decision components in closed-set selection tasks with a compact textual-tabular classifier trained on execution traces. TabAgent (i) extracts structured schema, state, and dependency features from trajectories (TabSchema), (ii) augments coverage with schema-aligned synthetic supervision (TabSynth), and (iii) scores candidates with a lightweight classifier (TabHead). On the long-horizon AppWorld benchmark, TabAgent maintains task-level success while eliminating shortlist-time LLM calls, reducing latency by approximately 95% and inference cost by 85-91%. Beyond tool shortlisting, TabAgent generalizes to other agentic decision heads, establishing a paradigm for learned discriminative replacements of generative bottlenecks in production agent architectures.

§Introduction (from cached fulltext; cut at ~9000 chars)
Agentic systems repeatedly call an LLM ( Schneider, 2025 ) to make closed-set decisions, which are both expensive and slow. Throughout a long-horizon execution, decisions often require selecting an answer from a fixed, bounded set of candidates: which skill to invoke, which tool to call next, which application to route to, or which sub-task to gate. Tool shortlisting epitomizes this need, the task of picking a small subset from a catalog of hundreds to thousands of tools ( Li et al., 2023 ; Wang et al., 2024b ; Qu et al., 2025 ) where a “tool” is any externally callable capability (API endpoint, function, or GUI operation) with a typed schema and observable outputs. Shortlisting is especially costly as serialization can run to tens of thousands of tokens per call. In our measurements, a GPT-5.4 shortlisting call takes 7.5 s (App. Table 15 ), and across a long-horizon task’s steps it dominates per-task latency and cost. Prior work cuts this cost along several axes, but each keeps one of two things an agent’s execution needs. One line removes the generative call yet stays blind to live state: retrieval selectors ( Anantha et al., 2023 ; Hong et al., 2026 ) and discriminative selectors ( Moon et al., 2024 ) score a static catalog or fixed embeddings, ignoring the agent’s schema, state, and dependency signals. The other line reads that state yet keeps the generative call: LLM-centric controllers ( Qin et al., 2024 ) leave the loop on the critical path where its latency compounds across steps, and cost-aware routing, cascades, and self-training ( Chen et al., 2024 ; Moslem & Kelleher, 2026 ; Zelikman et al., 2022 ) only make that call cheaper or smaller. An agent, though, emits exactly the state signals the first line ignores, and it emits them while solving its task. We therefore take both at once: following the view that small, specialized models should carry most agentic work ( Belcak et al., 2025 ) , we cast each decision’s snapshot into a textual-tabular representation, letting a cheap, non-generative discriminator read the live state and replace the generative call. TabAgent replaces a generative decision head in a running LLM agent with a compact classifier trained on the agent’s own successful execution traces. It has two trace-processing stages and one classifier. TabSchema turns execution traces into a tabular feature card: each row is a (task context, candidate tool) pair, each column a behavior-grounded feature (e.g., the agent’s current thought, the step index, or whether the candidate has co-occurred with other tools in similar traces), and the label is whether the successful trajectory used the candidate (Fig. 1(a) ). TabSynth adds schema-aligned synthetic rows where trajectory coverage is thin, lifting AppWorld shortlisting quality by {\sim}23\% on average. TabHead scores each candidate in one classifier pass (Fig. 1(b) ), replacing the multi-call generative shortlister. We evaluate TabAgent as a drop-in replacement for the frontier-LLM decision heads (e.g., GPT-5.4) in SOTA open-source agents ( Marreed et al., 2025 ; Wang et al., 2024c ; Yao et al., 2023 ) , changing only the label space and its feature card, across three closed-set decision families and seven benchmarks ( Trivedi et al., 2024 ; Barres et al., 2026 ; CUGA Project, 2026 ; Shlomov et al., 2026 ; Li et al., 2026b ; Deng et al., 2023 ; Li et al., 2026a ) . On tool shortlisting it recovers essentially all of the tools GPT-5.4’s successful runs used on AppWorld (Recall@9) while replacing that generative call at {\sim}10^{3}\times lower latency and {\sim}10^{5}\times lower cost per call (Fig. 4 ). It also ranks first on the classification decisions and is on par with a strong fixed default on routing and gating at far lower latency and cost, where a costly generative router does worse (Table 1 ). A small classifier can stand in for a frontier head because the signal lives in the representation rather than the model: given the TabSchema card, heads as different as decision trees and tabular foundation models reach comparable accuracy, and all collapse once the card is reduced to the raw task and candidate text (§ 5 ). The head is thus off-the-shelf and interchangeable, and ports across settings. One head moves across LLM backbones within a shared scaffold at a cost of about 3.1 percentage points of \mathrm{P}\!@\!\mathrm{R} , and a single universal head stays within {\sim}3 points of per-task specialists on five of seven decisions (§ G ). It does not win everywhere: a fine-tuned 8B small LLM scores higher on four of five AppWorld applications but stays in the generative loop at 10^{2} to 10^{4}\times the per-call cost (§ 3 ), and TabAgent is best on in-distribution decisions, leaving the rare novel cases to the LLM (§ 3 ). Beyond these offline comparisons, hot-swapping the head into a live agent leaves end-to-end task success on par with the generative shortlister (§ 4 ). Contributions.
