title: Correct Answers, Closed Gates: SolveBind for GUI Agents at the Verification Barrier
source: https://arxiv.org/abs/2610.32223

§Abstract
Websites and applications deploy CAPTCHAs and anti-automation mechanisms that use behavioral signals such as interaction trajectories and timing, not outcomes alone, to distinguish humans from automated agents. We call these protected GUI environments, where correctly solving a verification task is insufficient for end-to-end task completion. Agents must turn solver outputs into accepted interactions and adapt execution to runtime feedback under time constraints. We introduce SolveBind, a GUI-agent framework combining hierarchical solving with runtime supervision. A hierarchical solving tree decomposes verification into interdependent Perceive, Ground, Solve, Act, and Verify capabilities. A runtime supervisor grounds action commitments in tool-derived evidence, revises them as evidence arrives, and mediates execution under explicit recovery budgets. Across nine CAPTCHA task families and nine backbone models, SolveBind achieves the highest success rate on eight backbones, outperforming the strongest baseline by 13.3-34.5 percentage points. It achieves the highest success rate on all six AndroidWorld backbones. In a paired GPT-5.5 analysis, MobileAgent produces correct answers but fails dynamic verification on 13 of 90 tasks; SolveBind succeeds on seven of these tasks. With automatic submission, removing binding reduces success from 82.22% to 71.56% and increases latency and token usage. Recovery caps reduce execution cost with a small observed success trade-off: removing them raises success from 82.22% to 83.56%, while increasing latency and token usage to 3.7x and 2.4x their full-supervision values, respectively. These results support evidence-grounded execution control while identifying a success-cost trade-off in recovery and failure boundaries of heuristic submission rules.

§Introduction (from cached fulltext; cut at ~9000 chars)
GUI agents aim to translate users’ task intents into complete interaction workflows, transforming requests such as retrieving information, filling out forms, or managing files into action sequences that span multiple pages and applications ( He et al., 2024 ; Agashe et al., 2025a ; Rawles et al., 2025 ) . Real-world services, however, often deploy anti-automation mechanisms that rely on behavioral signals, such as interaction trajectories and timing, rather than outcomes alone, to distinguish human operators from automated agents ( Acien et al., 2022 ; Wang et al., 2026 ) . Even if an agent has identified a viable solution, it must still advance the task through interactions accepted by the environment within the available time budget, so verification checkpoints become an integral part of task execution rather than an external obstacle to it. Consider the invoice-download task in Figure 1 . The agent locates the booking, requests the invoice, and reaches a human-verification gate before saving the file. Although it correctly identifies the target, the attempt can still be rejected because the verification mechanism also evaluates behavioral signals such as the drag trajectory and timing ( Acien et al., 2022 ; Song et al., 2026 ) . The bottleneck therefore lies not only in solving the local challenge, but also in executing the solution in a manner accepted by the environment. Re-solving may not resolve the rejection, while repeated attempts consume the limited verification budget and delay task completion. This illustrates why protected GUI environments require agents to coordinate local solving with feedback-aware execution. Interactive verification and behavioral discrimination make this a broader execution problem rather than an issue confined to a single CAPTCHA type. HLL ( Song et al., 2026 ) jointly evaluates task responses and interaction evidence in dynamic CAPTCHA tasks, revealing a gap between correctly solving a challenge and passing verification. Turing Test on Screen ( Zhu et al., 2026 ) further shows that touch behavior alone can distinguish agents from humans. We refer to GUI environments equipped with anti-automation mechanisms that monitor interaction behavior and distinguish automated from human operation as protected GUI environments . Such evidence may derive from a single action, a local interaction sequence, or a longer execution history, shaping the conditions under which subsequent execution proceeds ( Acien et al., 2022 ; Song et al., 2026 ; Wang et al., 2026 ) . We focus on two outcomes in these environments: task success rate and end-to-end latency. Existing GUI-agent frameworks combine hierarchical planning with specialized tools to improve long-horizon decision making and interface grounding ( Agashe et al., 2025a ; Agashe et al., 2025b ) . In protected settings, however, these capabilities must be coordinated with the agent’s current execution state. Redundant actions and costly planning or reflection calls increase end-to-end latency ( Abhyankar et al., 2026 ) , while undetected action failures can lead to ineffective repetition and error accumulation ( Zhang et al., 2026 ) . The central challenge is therefore determining which solver outputs should constrain execution and which observations should cause the agent to revise its next action . Our key idea is to treat solver outputs as runtime evidence that can be retained and revised. When the evidence supports a concrete action, the runtime records it as an action commitment and prioritizes that action until new observations update that evidence or trigger reconsideration. This coordination is motivated by rational metareasoning: computation should be weighed against both its cost and its expected value for the next decision ( Russell and Wefald, 1991 ; Hay et al., 2012 ) . Building on this idea, we introduce SolveBind, a GUI-agent framework combining hierarchical tool-based solving with runtime supervision. A hierarchical solving tree organizes capability dependencies and alternative tool branches, allowing the model to select the capabilities needed for the current execution state. The runtime supervisor binds tool-derived evidence to action commitments and, under full supervision, prioritizes admissible pending commitments over conflicting action proposals. Execution feedback then updates a shared protocol state that governs workflow progression, verification, and bounded recovery, enabling subsequent attempts to preserve still-valid evidence and revise affected assumptions invalidated by new observations. Task adapters connect this protocol to different environments through task-specific primitives, tools, and completion interfaces. We evaluate SolveBind on nine HLL dynamic verification families ( Song et al., 2026 ) and AndroidWorld ( Rawles et al., 2025 ) , across nine foundation models and three baseline harnesses.
