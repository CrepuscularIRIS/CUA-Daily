title: VeriCUA: Verification as Agentic Exploration for Computer-Using Agents
source: https://arxiv.org/abs/2610.40578

§Abstract
Building and scaling computer-using agents (CUAs) across desktop, mobile, and web environments requires reliable task-completion verification for data curation, evaluation, and reinforcement learning. Typical automated approaches prompt vision-language models (VLMs) to judge trajectories or generate programs to inspect application state. However, both rely on partial views of complex digital environments. VLM judges are restricted to supplied observations, while generated programs depend on accessible state. These views can omit decisive evidence or leave completion judgments unsupported. Tailoring separate verifiers to different platforms and access settings adds further engineering cost. We present VeriCUA, a platform-agnostic framework for verification through agentic exploration. It treats verification as dynamic evidence gathering and assessment within a shared procedure for online and offline settings across platforms and observation modalities. After inspecting the available context to construct a task rubric, the verifier selects GUI or code checks for unresolved requirements and combines their findings under explicit evidence rules. Experiments show improved agreement with reference labels over the compared baselines across these settings, with the largest offline gains on hard cases and stronger rejection of false completion claims online. Further analyses connect these gains to complementary evidence and test-time exploration.

§Introduction (from cached fulltext; cut at ~9000 chars)
Vision-language models (VLMs) have enabled computer-using agents (CUAs) to navigate the digital world through software interfaces ( Xie et al., 2024 ; Zhou et al., 2024 ; Rawles et al., 2025 ) . Given a natural-language instruction, an agent observes the interface, plans, and acts, leaving a trajectory of thoughts, actions, and observations. Digital tasks span applications in which success can depend on visual presentation, application records, or changes to persisted files. A trajectory can appear successful even when edits remain unsaved or an operation fails without a visible warning. The agent may also report completion after fulfilling only part of the instruction. Accepting such a run as successful produces a false positive, making the distinction between attempted actions and their actual effects central to verification. Developing these agents therefore requires reliable judgments throughout evaluation, data curation ( Sun et al., 2025 ) , and reinforcement learning ( Xue et al., 2026a ) , including applications for which no task-specific checker has been supplied. An execution can be verified online from the resulting machine state or offline from its retained trajectory. Evidence can come from rendered interfaces, structured observations, or artifacts such as files and database records. VLM judges assess trajectories from selected observations ( Pan et al., 2024 ) , while automatically generated checkers inspect application state through model-written programs ( Xue et al., 2026b ) . A fixed set of frames may omit a decisive effect, and a generated query may target state that does not answer the verification question. Platform-native signals support more specialized judgments and validation ( Chae et al., 2025 ; Sun et al., 2026b ) , but their availability varies with the application and access setting. Agentic approaches actively inspect trajectories or environments ( Wan et al., 2026 ; Cui et al., 2026 ; Sanayei et al., 2026 ) . A shared procedure must seek relevant evidence under these access constraints and ground its conclusions in the observations. To address these evidence and access limitations, we present VeriCUA, a platform-agnostic framework that formulates CUA verification as agentic exploration (Figure 1 ). It provides a shared procedure for offline and online verification using the sources and inspection tools available in each setting. Verification begins after the executing agent’s attempt ends. The verifier first explores the available context to understand the app and its task artifacts, then uses these observations with the instruction to construct a rubric of fine-grained requirements. This context helps interpret task concepts and locate potential evidence, especially when the application is unfamiliar. The verifier chooses GUI or code tools to check the rubric’s requirements. Findings from these checks reveal what remains unresolved and guide further inspection of relevant frames, artifacts, or another available source. VeriCUA’s unified design separates the verification workflow from the interfaces through which evidence is obtained. Offline verification navigates retained screen frames and action logs, using structured observations such as accessibility trees when recorded. Online verification can inspect the accessible machine state left by the executing agent through GUI or code tools, including files, databases, and system services. These sources answer different questions about the requested outcome. An action log records an attempted edit, while a file read can show whether the edited content persisted. A report that the task is complete remains a claim to verify. The framework links findings to their supporting observations and records source properties such as frame timing or state persistence. Explicit evidence rules combine the findings into a task verdict while retaining which requirements are supported, refuted, or unresolved. We evaluate this shared procedure in offline and online scenarios on multiple platforms. VeriCUA achieves higher agreement with reference labels than the compared baselines in both settings. It also rejects more false completion claims than the VLM judge in the online study. The action-space study shows that adding code-based state reads enables more decisions without increasing false positives. At a matched number of verification passes, adding visual evidence improves agreement and decision coverage compared with repeating the same configuration.
