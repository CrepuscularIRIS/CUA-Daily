title: The Agent in the Middle: How AI-Mediated Access Reshapes Web Vulnerability Exploitation
source: https://arxiv.org/abs/2610.35541

§Abstract
Web services increasingly expose backend interfaces that let users delegate tasks to AI agents, which invoke service operations directly without navigating websites. This shift changes how existing Web vulnerabilities can be exploited. We investigate these changes through VELA, an executable benchmark covering 44 vulnerabilities across twelve Web application families. The benchmark preserves vulnerable backends and derives agent-facing interfaces from legitimate workflows. We evaluate three commercial agents across multiple interface configurations, using controlled comparisons to separate interface effects from agent behavior and independent oracles to verify attack outcomes. Our results show that the agent realizes every attack that direct interface invocation realizes in the reference configuration, so exploitability is set mainly by the interface: 91% of vulnerabilities remain exploitable under the reference design. Interface restrictions prevent some attacks by removing required operations or limiting input control, while retention remains high across vulnerability classes. No case-level loss in the reference configuration is attributed to agent refusal or input normalization, and in one case the agent completed an attack by supplying calls the attacker omitted. Across the tested configurations, interface design affects exploitability more than agent choice, moving retention from 39% to 95% against at most 4.5 points across agents, but some restrictive interfaces also limit legitimate workflows. Our study provides a systematic empirical account of how agent-mediated access reshapes existing Web vulnerabilities, grounding future Web architecture design in measured security outcomes and trade-offs between reducing attack exposure and preserving legitimate functionality in agent-facing services.

§Introduction (from cached fulltext; cut at ~9000 chars)
AI agents are changing how users access Web services. A user can describe a shopping need or an account-management task to an agent and let it carry out the necessary steps. Web-agent research has demonstrated this capability through agents that navigate pages and interact with existing websites ( Zhou et al., 2024 ; Deng et al., 2023 ; Yao et al., 2022 ) . A further shift is now taking shape: services are exposing capabilities that agents can access directly, without navigating a website. OpenAI’s Agentic Commerce Protocol connects ChatGPT with merchant catalogs and shopping experiences ( OpenAI, 2026 ) , while Google’s Universal Commerce Protocol supports agent access to merchant capabilities such as product discovery and checkout ( Google, 2026 ) . These initiatives move the interaction between agents and services toward dedicated interfaces through which business tasks can be completed. Figure 1 illustrates this change using the task of reordering a previous purchase. In the conventional workflow, the user navigates the website to find the order and complete checkout. Through agent-mediated access, the user states the goal, and the agent invokes the corresponding operations through an agent-facing interface. Both paths reach the same backend, where business logic and application data remain, but the latter no longer requires the service’s pages and forms. This shift opens the possibility of a Web in which agents become the primary means of accessing services, and individual websites are no longer necessary user-facing entry points. As this access model develops, service providers need to understand its security implications. Malicious users can also use this path to target backend services. Existing backend vulnerabilities may persist, while interface restrictions and agent behavior change whether and how they can be exploited. For developers and operators, the central question is how much of the harm enabled by existing vulnerabilities remains possible through agent-mediated access, and how the resulting security consequences change. A natural expectation is that agent-mediated access provides additional protection. Agent-facing interfaces can restrict operations and inputs needed for exploitation, while safety training and runtime safeguards aim to prevent agents from following harmful instructions ( Anthropic, 2026 ) . A critical question is whether these safeguards actually prevent existing backend vulnerabilities from causing harm. Attacks using ordinary business operations may remain possible, and agents may help complete them by supplying missing steps or combining calls. Stronger restrictions may also make legitimate operations unavailable. Prior studies primarily focus on agents themselves, examining their offensive capabilities, susceptibility to malicious inputs, and handling of harmful instructions ( Zhu et al., 2025 ; Greshake et al., 2023 ; Debenedetti et al., 2024 ; Zhan et al., 2024 ; Kumar et al., 2024 ; Jones et al., 2026 ) . The implications of this architectural shift for existing backend vulnerabilities remain insufficiently understood. A systematic empirical evaluation is needed to quantify changes in exploitability and security consequences, distinguish interface effects from agent behavior, and assess the accompanying impact on legitimate functionality. To conduct this evaluation, we develop Vela , an executable benchmark comprising 44 documented vulnerabilities from twelve Web application families. For each application, we construct agent-facing interfaces from legitimate workflows. We then compare direct Web access, direct invocation of these interfaces, and execution through an agent on the same vulnerable backend. These comparisons isolate the effects of interface design and agent execution, with independent oracles verifying the resulting security consequences. We evaluate three commercial agents and three interface designs, measuring vulnerability exploitability alongside support for legitimate tasks. Under the reference configuration, the agent succeeds in at least one attempt on every case realized by direct interface invocation, so it removes none of the attacks the interface lets through, and in one case it supplies missing steps. As a result, 91% of the vulnerabilities still produce verified security consequences, and the prevented attacks depend on operations or input control that the interface no longer exposes. Retention remains high across all three analysis groups. Across the tested configurations, changing the interface moves retention between 39% and 95%, against at most 4.5 percentage points across agents, although some reductions come with a loss of legitimate functionality. These results quantify both the persistence of backend security risks and the functional costs of restricting access, providing evidence for the design of future agent-facing Web services.
