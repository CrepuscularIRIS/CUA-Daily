title: ViBench 2.0: A Benchmark for Long-Horizon Software Building
source: https://arxiv.org/abs/2611.05620

§Abstract
On Replit, our agentic engineering platform, users now build entire products without writing code, through successive feature requests to an agent. Yet existing coding benchmarks evaluate single, fully specified tasks, and many are near saturation. We introduce ViBench 2.0, a benchmark for long-horizon software building that we use to select our platform's models. Its 17 full-stack web products, modeled on widely used software, grow over 241 feature requests and are judged only when finished, as a user would judge them: a browser agent runs 544 test plans, and a build passes only if every plan does, under a grading protocol validated to keep this strict score reliable. Evaluating nine models, we find a reliability gap: the three strongest pass up to 98% of test plans yet deliver a fully working product in at most 65% of builds, and no open-weight model delivers one. The gap is closing fast: across three releases of one model family, pass@1 on the public products rises from 3% to 53% while the cost per build falls by more than half. We release eight products with the harness and grader, hold out nine, and report lessons from production use.

§Introduction (from cached fulltext; cut at ~9000 chars)
Consider a ride-hailing app that an agent builds from an empty project: riders first book rides, and later requests add cancellation fees, drivers with several cars, per-trip earnings and split fares, each built on code the agent wrote earlier (Figure 2 ). Projects on Replit start greenfield, from an empty project, and grow this way through agentic engineering, in which a user describes software in natural language and a coding agent builds and extends it, one request at a time; users who work this way favor iteration over written specifications ( Pimenova et al., 2025 ) . Agentic engineering is what vibe coding ( Karpathy, 2025 ) , from which ViBench ( Zhong et al., 2026a ) takes its name, has matured into: agents that once delivered near-functional prototypes now build, extend and maintain the products businesses run. Agents can now sustain such long-horizon work for hours or days ( Kwa et al., 2025 ; Carlini, 2026 ; Lin, 2026 ) , yet the benchmarks used to compare them saturate quickly: over 40% of those less than two years old have already saturated ( Akhtar et al., 2026 ) . Agentic engineering benchmarks are no exception. ViBench ( Zhong et al., 2026a ) has an agent build a minimum viable product (MVP) or add one feature to it, and a browser agent test the result through its interface; its pass@1 ( Chen et al., 2021 ) counts a build only if every test plan passes. In our rerun of its Vibe-on-Vibe tasks, in which the agent extends its own MVP, GPT-6.1 Sol, GPT-6 Astra and Opus 5.5 (hereafter Sol, Astra and Opus) reach 82 to 89% pass@1, against 51% for the best model at its release (Appendix H ). On Vibe Code Bench, in which an agent builds an app from one specification, the best score rose from 61.8% in March 2026 ( Tran et al., 2026a ) to over 90% for six models by late October ( Vals AI, 2026 ) . Like most coding benchmarks ( Jimenez et al., 2024 ; Deng et al., 2026 ; Zhao et al., 2025 ; Ding et al., 2026 ) , both give the agent a single task, while multi-turn benchmarks score each step as it is completed ( Xu et al., 2025 ; Orlanski et al., 2026 ; Shen et al., 2026 ) . Vibe Code Bench 1-100 ( Tran et al., 2026b ) , released in September 2026, grows an application over up to ten requests and tops out at 34.0% ( Vals AI, 2026 ) , but from a finished reference app and only until the first failure, so it measures how far an agent gets rather than what it delivers. None of these asks the question such users face: whether a product built from nothing still works as a whole after the last request (Appendix A ). Such a product can only be checked through its interface, the way users who never read the code judge it ( Karpathy, 2025 ; Fawzy et al., 2025 ; Sarkar and Drosos, 2025 ) , and a build should count only if every plan passes. We introduce ViBench 2.0, which extends ViBench to evaluate whether agents can build a complete product over a long horizon. The agent receives a product’s requirements one feature at a time in a single conversation, starting from an empty project, and a browser agent tests only the finished product (Figure 1 ). The horizon is long in three ways: each of 9 to 18 feature requests builds on code the agent wrote itself, the conversation can exceed 200k tokens, and every feature must survive every request after it, with no feedback between requests. Across 17 products, ViBench 2.0 comprises 241 feature requests and 544 test plans, 85% of which combine features. ViBench 2.0 is built for deployment decisions: we use it to choose the models Replit serves and to evaluate changes to its production agent. This paper advances the evaluation of coding agents in four ways. First, a benchmark that measures frontier models on greenfield software building without saturating: pass@1 spans 0 to 65% across nine models and rises across successive versions of one model family; we release eight products on Harbor ( Harbor Framework Team, 2026 ) and hold out nine. Second, a grading protocol, extending the grader of ViBench ( Zhong et al., 2026a ) , that makes an all-or-nothing score reliable: it re-grades failed plans until three of up to five grades agree, caught all 34 planted bugs, and only 0.8% of its passes are false (Section 2.3 ). Third, independent runs of all nine models: an external team at Fireworks ( Fireworks AI, 2026 ) set up the released benchmark and ran each model with one command, with no other changes. These runs show that the headroom lies in reliability: most failed builds of the top three models miss only one or two plans (Section 4 ). Fourth, lessons from using the benchmark across Replit’s deployment decisions, from which models serve its workflows to how its agent manages context (Section 5 ).
