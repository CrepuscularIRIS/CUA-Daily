title: Agentic Scene Policies

§Abstract
Designing or learning robot policies that generalize zero-shot across a range of language instructions and objects is a core problem in robotics. Vision-Language-Action models (VLAs) learn such policies end-to-end by repurposing existing Vision-Language Models (VLMs), but generalization to new instructions and objects remains challenging. An alternative is to implement a modular policy by leveraging an explicit VLM-based 3D scene representation and motion planning. While modular policies show strong zero-shot potential, they typically retrieve objects based on semantics without explicit spatial reasoning, severely restricting their overall grounding capabilities. They also interact with objects using basic grasping and navigation skills. In this work, we address these limitations by unifying grounding capabilities and robot skills in a single agentic action space through a scene-agent tool interface. By leveraging part-level affordances, our skills generalize across diverse objects and enable zero-shot interactions such as unplugging chargers and opening drawers. We name the resulting framework Agentic Scene Policies (ASP). Through extensive real-world experiments, we show how ASP consistently outperforms leading VLAs in the zero-shot setting. We also demonstrate the extensibility of our framework by introducing a mobile version of ASP to tackle room-level queries. See our project page (https://montrealrobotics.ca/agentic-scene-policies.github.io/) for more results.

§Introduction (from cached fulltext; cut at ~9000 chars)
Language-conditioned robot policies need to manage the complex interplay between language, space, and action. Much of the recent progress on this problem has been driven by vision-language models (VLMs) trained on internet-scale data and showing strong general visual understanding in the open-world. Recent methods use VLMs as backbones for end-to-end policy learning, yielding Vision-Language-Action models (VLAs) [ 1 , 2 , 3 ] that directly map sensor data and language commands to robot actions. VLAs aim to leverage the broad multimodal reasoning and instruction following capabilities of VLMs to achieve more general robot control. However, there is accumulating evidence that VLAs can struggle with semantic generalization [ 4 ] and diminish the capabilities of the underlying VLM during fine-tuning [ 5 ] . There is therefore substantial interest in using VLMs as is for robot planning and control. This can be achieved by using VLMs to build explicit open-vocabulary 3D scene representations. Combining language-based object retrieval in these representations with motion planning has yielded capable modular systems for zero-shot language-conditioned mobile manipulation [ 6 , 7 , 8 , 9 ] . We refer to such systems as Scene-based Policies . While they preserve the generality of VLMs, scene-based policies face some key limitations and cannot act as drop-in replacements for VLAs. First, they are limited in terms of grounding capabilities, often implementing “argmax” queries where they simply interact with the object that is most similar with the current language query, with limited contextual understanding of the scene or the task. Second, they are limited in terms of physical interactions and are often constrained to navigation and grasping. In this work, we address both limitations by modeling a scene-based policy as an LLM agent. We propose a tool-centric scene interface to unify object grounding and robot execution capabilities. We define skills at the level of affordances , allowing the agent to reuse them across a variety of objects and language instructions in a zero-shot manner. We name the resulting framework Agentic Scene Policies ( ASP ). Our key contributions are 1. We introduce ASP , a scene-based agentic policy managing a symbolic inventory of objects for spatial grounding and affordance-based skill execution (Section IV ). 2. We find that the orchestration of the ASP grounding and skills tools consistently outperforms leading VLAs ( \pi_{0} -FAST , \pi_{0.5} ) in the zero-shot setting over a range of objects and commands (Section VI ). Our experiments provide a valuable data point in the ongoing debate between modular and end-to-end methods. 3. We introduce a mobile version of ASP , demonstrating the extensibility of our framework (Section V-C ), and evaluate it against a policy based on ConceptGraphs [ 8 ] .

## IV METHOD
Overview and Example Query. Agentic Scene Policies ( ASP ) models a scene-based policy by conditioning the tool set of an LLM agent on the object set \mathcal{M}_{t} , which we denote as \pi_{\textit{ASP}{}}(\tilde{a}_{t}|\mathcal{M}_{t},q_{task},c_{t})=\text{LLM}(\mathcal{T}({\mathcal{M}_{t}}),q_{task},c_{t}) . We will introduce tools using an example query q_{task}= "Pick up the cup on the left" in a scene with distractors (Fig. 2 ). The tool set \mathcal{T}({\mathcal{M}_{t}}) first includes a set of grounding tools \mathcal{T}_{G} for object retrieval ( Which objects in \mathcal{M}_{t} are cups? ) and spatial reasoning ( Which cup is on the left? ). Once the task-relevant objects are grounded, \pi_{\textit{ASP}{}} can employ affordance-based skill tools \mathcal{T}_{\pi} available through a language-conditioned skill switch \tau_{\pi} ( Which skill achieves the "pick up" action on the cup? ). We design \mathcal{T}(\mathcal{M}_{t}) such that \pi_{\textit{ASP}{}} can infer the correct order of grounding and skill tool calls to solve a large number of manipulation queries. We will provide implementation details for each tool in Section V . Agent State Variables. Tools return scene information to \pi_{\textit{ASP}{}} using a symbolic state tuple \langle\mathcal{I}_{t},\mathbf{h}_{t}\rangle . The set \mathcal{I}_{t}\subseteq\mathcal{M}_{t} represents an inventory of task-relevant objects that are retrieved from the scene and can be processed by other tools, while the variable \mathbf{h}_{t} describes the currently held object (if any). We initialize \mathcal{I}_{0}=\emptyset and \mathbf{h}_{0}=\mathtt{None} . Grounding Tools. The agent \pi_{\textit{ASP}{}} will first rely on the grounding tools \mathcal{T}_{G} to understand the scene context and ground the objects that are relevant to the query q_{task} . Tools in \mathcal{T}_{G} are only used for reasoning . They expand the current agent context c_{t} using information from \mathcal{M}_{t} , without actuating the robot. To identify task-relevant objects, the agent \pi_{\textit{ASP}{}} will iteratively grow the inventory \mathcal{I}_{t} using a retrieval tool \tau_{R}(q_{R})=\mathcal{I}_{t+1}=\mathcal{I}_{t}\cup\mathcal{M}_{t}(q_{R}) where q_{R} is a text query and \mathcal{M}_{t}(q_{R})\subseteq\mathcal{M}_{t} is the subset of objects that match q_{R} . We emphasize that (i) \mathcal{M}_{t}(q_{R}) may include multiple relevant objects (Fig. 2 -A, the two cups in the scene), and (ii) \pi_{\textit{ASP}{}} may choose to make multiple calls to \tau_{R} to ground distinct objects that are relevant to q_{task} (e.g., make a separate call for "plate" if we need to place the left cup on a plate). Language-conditioned policies are expected to understand multi-object referencing and need to differentiate inventory objects based on relative positions or properties. We therefore extend \mathcal{T}_{G} with spatial reasoning tools that can measure quantities (e.g., distances) or check predicates in between objects in \mathcal{I}_{t} . For example, a left of predicate tool would take the form \mathtt{left}(\mathbf{o}_{1},\mathbf{o}_{2}):\mathcal{I}_{t}\times\mathcal{I}_{t}\mapsto\{\mathtt{True,False}\} and return a boolean based on the available geometry in \mathcal{M}_{t} (Fig. 2 -B). The combination of retrieval and spatial reasoning tools in \mathcal{T}_{G} will allow \pi_{\textit{ASP}{}} to ground an arbitrary number of task-relevant objects in the scene. Spatial reasoning tools return primitive types (e.g., float , bool ) without changing \mathcal{I}_{t} and \mathbf{h}_{t} . Skill Switch Tool. Once a relevant object has been identified, \pi_{\textit{ASP}{}} can act on it using a set of object-centric skills \mathcal{T}_{\pi}=\{\pi_{i}\}_{i=1}^{k} , which includes a range of part-level interactions such as grasping, pushing, and pulling. \mathcal{T}_{\pi} is not directly available to \pi_{\textit{ASP}{}} . Instead, we expose a language-conditioned skill switch \tau_{\pi}(\mathbf{o},q_{a}) where \pi_{\textit{ASP}{}} specifies \mathbf{o}\in\mathcal{I}_{t} and the intended action q_{a} in text form (e.g., pick up , open , unplug ). Internally, \tau_{\pi} first runs a VLM-based affordance predictor \mathcal{U}_{\text{VLM}}(\mathbf{o},q_{a})=\langle\pi_{i},\mathcal{P}_{\text{part}}\rangle , representing an affordance as the combination of a skill \pi_{i}\in\mathcal{T}_{\pi} and the relevant 3D part-level point cloud \mathcal{P}_{\text{part}} (Fig. 2 -C). The skill switch \tau_{\pi} then calls the selected skill \pi_{i}(\mathbf{o},\mathcal{P}_{\text{part}}) . Skill Tools. A skill \pi_{i} computes a robot action a_{t}\in\mathcal{A} using motion planning and \mathcal{P}_{\text{part}} . In practice, our skills output sequences of end-effector positions (Section V-B ). Skills then run a_{t} on the robot and return the updated state variables \langle\mathcal{I}_{t+1} , \mathbf{h}_{t+1}\rangle to the agent. For example, a picking tool may remove an object from \mathcal{I}_{t+1} and add it to held object variable \mathbf{h}_{t+1} (Fig. 2 -D) while a placing tool may set \mathbf{h}_{t+1} to None . Action Design. The design of \tau_{\pi} and \mathcal{T}_{\pi} is guided by three primary considerations. First, affordance-based skills are specific enough to have tractable implementations, and general enough to be reused zero-shot across multiple objects. We hypothesize that the composition of \mathcal{T}_{G} and the affordance-based \mathcal{T}_{\pi} will enable interactions with a broad variety of objects and outperform end-to-end learning in the zero-shot setting. Second, \mathcal{U}_{\text{VLM}} allows skill selection to be informed by vision (given \mathbf{I}^{rgb}_{i} in \mathbf{o}_{i} , see Section V-B ) and influenced by the existence of a part (e.g., not all cups have handles) and their shapes (e.g., to try hooking or pulling depending on the handle shape). Third, we only compute affordances when the agent requests an object interaction, avoiding the perception overhead of running affordance detection on all objects in \mathcal{M}_{t} which can be high when using general skills with “dense” support over many objects. For example, any small object can be potentially grasped, pushed or pulled. Tool Feedback. Tools can verify some pre-conditions. Examples include checking if \mathbf{o}\in\mathcal{I}_{t} when calling a spatial reasoning tool or ensuring that the held object \mathbf{h}_{t}=\mathtt{None} when grasping. Tools validate these conditions explicitly and may return a feedback string to \pi_{\textit{ASP}{}} in addition to their usual outputs, allowing \pi_{\textit{ASP}{}} to reattempt tool calls. Remapping. Skills in \mathcal{T}_{\pi} may verify post-conditions (e.g., is the gripper holding something). In case of failure, they may trigger remapping and return an empty inventory \mathcal{I}_{t+1}=\emptyset , signaling to \pi_{\textit{ASP}{}} that regrounding will be necessary. In this case, we refresh the object set \mathcal{M}_{t+1}=\mathcal{F}_{VLM}(X_{t+1}) to account for possible object movements caused by a manipulation failure. Absent a remapping trigger, we simply set \mathcal{M}_{t+1}=\mathcal{M}_{t} to minimize perception overhead. Object Identifiers. For simplicity of exposition, tools in this section use objects or object sets as inputs and outputs. In practice however, the \pi_{\textit{ASP}{}} agent only interacts with unique string identifiers generated by the grounding tool \tau_{R} (e.g., cup_0 ), as opposed to a full serialization of the object content. Tools internally use the identifier to retrieve the relevant object from \mathcal{M}_{t} .
