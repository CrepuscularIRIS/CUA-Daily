title: Coati: Host-Grounded Execution for Installable Mobile GUI Agents
source: https://arxiv.org/abs/2611.02644

§Abstract
Mobile GUI agents can carry out tasks across apps, yet most run on a separate computer that drives a phone over the Android Debug Bridge (ADB), out of reach of ordinary users and of the apps through which most people reach Web services. We present Coati, a source-available agent that users install as an Android app. Its runtime on the phone, the host, records what a model alone cannot see: the effect of each action at its target, result screens across apps, and the progress of repeated steps. VerifyLoop checks action outcomes and completion claims against host evidence and reports a completion it cannot audit as unverified. AppMemory builds per-app procedural memory from observations that the interface supports and reuses it on later visits. A routed fast executor lets a lightweight selection model take simple, confident steps and lets the host repeat loops of simple steps that the large model plans once. On all 116 AndroidWorld tasks, with Gemini 3.8 Flash as every agent's backbone, Coati succeeds on 86.5% of the tasks over three trials, ahead of the strongest open-source agent Artemis (77.6% with the same accessibility-only access, 76.5% even when allowed ADB) and far ahead of FinalRun and Midscene (about 59%), and VerifyLoop cuts false completion claims by about a third at comparable success. In everyday use, the fast executor cuts the median time of phone tasks by 39% at comparable success and runs three of four loop tasks 2.8-5.4x faster with 6-9x fewer model tokens, while AppMemory shortens a repeated deep route in an unfamiliar app from 18.5 steps to 6-7. On an Android 16 phone, routed execution completes all 27 benchmark runs with 76% fewer Reasoning calls on the critical path. Host evidence, not model self-assessment, makes an installable agent reliable and fast.

§Introduction (from cached fulltext; cut at ~9000 chars)
Multimodal large language models can now operate graphical user interfaces (GUIs) directly: they read a screenshot or an interface tree and act through taps, swipes and text entry ( Hong et al., 2024 ; Zheng et al., 2024 ; Nguyen et al., 2025 ) . On mobile devices this matters more than anywhere else, because most applications expose no programmable interface and their layouts change across versions, languages and device states ( Rawles et al., 2023 ; Rawles et al., 2025 ) . People also access many Web services through mobile applications. A mobile GUI agent intended for everyday use should therefore run directly on the phone and operate these applications. However, most mobile GUI agents run on a separate computer that drives the phone over the Android Debug Bridge (ADB) ( Appium Contributors, 2026 ; Rawles et al., 2025 ) . The computer sends actions to the phone and receives observations in return. For ordinary users, installing and operating such a system can be difficult. More importantly, the agent can understand the phone only through the information returned by the bridge. Therefore, it may miss fine-grained changes after an action, making it difficult to determine whether the action succeeded and whether the task actually reached its target state ( Lee et al., 2025 ; Wu et al., 2025 ; Zhang et al., 2026 ) . These limitations suggest a more direct and promising deployment model: an agent installed directly on the phone. Because its runtime and the interface it operates reside on the same device, the agent can observe the interface state and action outcomes in real time. It can also maintain records of cross-application results and the progress of repeated actions. Running an agent directly on the phone also imposes practical requirements. Each step should avoid unnecessary waiting and model calls. Since users may not continuously monitor the screen, a task reported as complete must actually reach the requested state. Repeated tasks should not require the agent to rediscover the same route each time. Existing mobile GUI agents do not fully satisfy these requirements. They typically ask a large model to make decisions step by step, rely on the model to judge whether a task is complete, and treat repeated actions as separate model decisions. These choices can increase latency and token costs, while making execution failures more difficult to detect ( Wang et al., 2024a ; Wen et al., 2024 ; Li et al., 2025 ) . A mobile agent must therefore use local evidence not only to execute actions, but also to verify their outcomes, assess task completion, and retain useful experience. This calls for a different execution principle: the model may propose an action, but the runtime on the phone should determine what actually happened from evidence recorded by the host ( Lee et al., 2025 ; Wu et al., 2025 ; Zhang et al., 2026 ) . We present Coati , a source-available Android agent that users install as an app. Coati is designed to address the reliability, execution-efficiency, and repeated-use challenges of installable mobile agents. Its core principle is host-grounded execution : the model proposes an action, while evidence recorded by the host—the information collected by Coati’s runtime on the phone—determines the outcome. We implement this principle with three mechanisms. (1)VerifyLoop checks each action against the interface changes it causes and audits completion claims using the result screens of the applications involved and the progress of delegated loops. When the available evidence is insufficient, it reports the task as unverified rather than complete. (2)AppMemory stores interface observations as per-application guidance only when they are supported by the interface and the task passes the completion audit. It then retrieves this guidance during later visits. (3)Routed fast executor reduces the cost of model calls. A lightweight typed selector handles simple, confident actions from host-built candidates, while the Reasoning model handles uncertain steps, application switches, and text entry under a user-selectable speed–accuracy mode. For repeated simple actions, the Reasoning model plans the loop once, and the host executes it item by item while recording the handled items. Together, these mechanisms use the same host evidence to improve execution efficiency and constrain what the agent can claim and remember. We compare Coati with the strongest open-source agents on all 116 AndroidWorld tasks. All agents use Gemini 3.8 Flash as the backbone model and run on the same device with the same task instances and execution protocol. Coati achieves an average task success rate of 86.5% across three trials, ahead of the strongest open-source agent Artemis (77.6% with the same accessibility-only access, and 76.5% even when allowed ADB), and far ahead of FinalRun and Midscene (about 59%).
