title: BoxWorld: Let World Engines Control and Video Generators Render
source: https://arxiv.org/abs/2610.36371

§Abstract
We tackle the challenge of building real-time interactive video worlds with user-defined behaviors. Such worlds must track object states, apply interaction rules, and render the resulting consequences as users act. Yet existing end-to-end video world models typically learn interaction dynamics within the generator, making it difficult to specify object-level rules and reason about their consequences. In this work, we introduce BoxWorld, which separates interaction reasoning from generative rendering. Given user-specified rules, a coding agent creates a Box World Engine that determines interaction outcomes and exposes the resulting object states through a lightweight interface of layout boxes, persistent object attributes, and dynamic status variables, leaving appearance and physical effects to generative rendering. A Box-State Generative Renderer then renders this evolving state stream into video autoregressively, enabling online control over object motion, state switches, and conditional events. Rendering this state stream is non-trivial: the renderer must respond to object-level state updates in real time while remaining coherent with the generated history. To this end, we introduce a three-stage training strategy that learns object grounding from open-domain videos and state transitions from gameplay videos, both annotated automatically, and finally performs rollout distillation on self-generated histories. We further propose PairedStateBench, a paired benchmark for fine-grained interaction control. BoxWorld substantially outperforms end-to-end world models and remains competitive across multiple public benchmarks. Project page: https://boxworld-web.github.io.

§Introduction (from cached fulltext; cut at ~9000 chars)
Building models that can understand, simulate, and interact with the physical world has long been an ambitious goal of artificial intelligence ( Ha and Schmidhuber, 2018 ) . Recent progress in video generation ( Team Wan et al., 2025 ; Google DeepMind, 2025 ; Team Seedance et al., 2026 ) has given this goal a concrete instantiation: interactive video worlds , where users can act in a generated world and experience it unfolding over time in response to their actions ( Brooks et al., 2024 ; Bruce et al., 2024 ; Parker-Holder et al., 2024 ; Ball et al., 2025 ) . We are interested in real-time interactive video worlds with user-defined behaviors, where users also specify how the world responds to their actions. For example, a user may specify that a flower blooms only when nurtured (Figure 1 (top)), or that a door opens only if the cat has collected the key (Figure 1 (bottom)). Realizing such behaviors requires the world to track object states, apply interaction rules, and render the consequences as users act. A prevailing approach learns interactive video worlds end to end, mapping visual history and user actions directly to future frames with a video generator that generalizes across diverse scenes ( Bruce et al., 2024 ; Robbyant Team et al., 2026 ) (Figure 2 (a)). However, the generator must then handle all three tasks implicitly, reasoning about whether rules are satisfied and what consequences should follow, which makes object-level rules and their consequences difficult to specify and control. A complementary direction instead conditions video generation on explicit states, ranging from trajectories ( Li et al., 2025a ) and layouts ( Feng et al., 2025b ) to physical priors ( Zhang et al., 2025 ) , 3D caches ( Ren et al., 2025 ) , and full simulators ( Xie et al., 2025 ) (Figure 2 (b)). These states provide finer control, but grow heavier and more domain-specific as control becomes finer, making them expensive to construct and simulate, and difficult to obtain from videos at scale. Taken together, these lines of work reveal a trade-off between generalization and fine-grained control in interactive video worlds. This motivates separating interaction reasoning from generative rendering: interaction rules are applied explicitly outside the generator, while the generator retains its broad visual priors and focuses on faithfully rendering the resulting object states. The two sides are connected by an explicit-but-minimal Object-Centric State Interface , which exposes only the variables needed for object-level interaction while remaining simple to specify, update, and apply across diverse scenes. Crucially, these state variables should be identifiable from videos with off-the-shelf perception models, so that learning the renderer is not restricted to predefined simulators or scarce action-paired interaction data. Following this design, we present BoxWorld , a framework for real-time interactive video worlds with user-defined behaviors. Given user-specified rules, a coding agent creates a Box World Engine , which applies these rules to user actions, determines the resulting interaction outcomes, and updates object states. The engine exposes these states through the Object-Centric State Interface , composed of layout boxes, persistent object attributes, and dynamic status variables, leaving texture, lighting, style, and physical effects such as smoke and splashing water to generative rendering. A Box-State Generative Renderer then renders this evolving state stream into video autoregressively, enabling online control over object motion, state switches, and conditional events (Figure 2 (c)). However, rendering this state stream is non-trivial: the renderer must respond to object-level state updates in real time while remaining coherent with the generated history. First, states arrive online, so generation must be few-step and causal, whereas existing layout-to-video methods rely on multi-step bidirectional generation over the entire layout sequence ( Li et al., 2025a ; Lian et al., 2024 ; Tian et al., 2024 ; Feng et al., 2025b ) . Second, an update makes part of the generated history outdated, so the renderer must distinguish what to preserve from what to change. Third, the renderer must synthesize the new state of the affected object, such as a door swinging open. Existing video editing methods achieve similar localized changes, but rely on precise masks, costly inversion, or per-video optimization ( Jiang et al., 2025 ; Mou et al., 2024 ; Ku et al., 2024 ; Gao et al., 2026a ) , making them unsuitable for online rendering from coarse boxes. To address these challenges, we build the Box-State Generative Renderer on an autoregressive video generator ( Yang et al., 2025a ) and train it in three stages, each with a training scheme matched to its role (Sec. 3.3 ).
