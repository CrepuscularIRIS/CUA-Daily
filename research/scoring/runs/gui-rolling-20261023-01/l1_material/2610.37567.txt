title: Gym-Anything-RT: Scaling Real-Time Environments for Vision-Language Agents
source: https://arxiv.org/abs/2610.37567

§Abstract
AI agents have made substantial progress in domains where they have a non-trivial amount of time to deliberate between actions, such as mathematics, software engineering, and performing tasks on desktop applications. It is less clear how such models fare in settings that demand real-time interaction, such as playing a video game or operating a physical device. In these settings, the environment state may evolve as the agent is reasoning, or even as the underlying model is performing a forward pass. To gain insight into the real-time interaction capabilities of vision-language agents, we introduce Gym-Anything-RT. Our key idea is to construct visual minigames that demand a portfolio of capabilities required for interactive real-time settings. Gym-Anything-RT uses an agentic pipeline to automatically generate such environments based on a taxonomy of six capabilities required for real-time interaction, including the ability to perceive the environment and act under an evolving environment state. A key feature of Gym-Anything-RT is that it allows for controlled comparison of real-time interaction capabilities: we can run the same minigame in real time, or pause or slow down the environment to relax the requirement for real-time actions. We use Gym-Anything-RT to construct 100 real-time minigames and evaluate AI agents on them. We find large capability gaps in real-time interaction. For example, GPT-6 Astra (xHigh) achieves a pass rate of only 9.0% on the real-time minigames, which rises to 75.0% when the environment is paused. We also identify intriguing behaviors by the most powerful frontier agents: for instance, when given the ability to write code, these agents write code that bypasses the need to perceive and act in real time. We publicly release Gym-Anything-RT and the generated minigames to spur further research on AI agents in real-time interactive settings.

§Introduction (from cached fulltext; cut at ~9000 chars)
AI agents have made substantial progress in domains where they have time to deliberate between actions, such as mathematics ( DeepSeek-AI, 2025 ) , software engineering ( Jimenez et al., 2024 ) , and performing tasks on desktop applications ( Yuan et al., 2026 ; Aggarwal et al., 2026 ; Jang et al., 2026 ) . However, these agents have a key limitation: they are slow, often taking more than ten seconds to choose a single action. This is acceptable when the environment waits for the agent, but not in settings that demand real-time interaction , such as playing a video game or operating a physical device ( Zhang et al., 2026 ; Black et al., 2025 ) . There, the environment keeps changing while the agent reasons, or even while the model performs a forward pass. By the time an action executes, it may no longer be valid, and the agent cannot react to what happened in the meantime. Existing evaluations shed little light on this limitation. Computer-use benchmarks wait for the agent between actions, so they never test acting under an evolving state ( Xie et al., 2024 ; Yuan et al., 2026 ; Aggarwal et al., 2026 ) . Video game benchmarks do run in real time. However, frontier models make little progress on them ( Zhang et al., 2026 ; Ying et al., 2026 ; Ouyang et al., 2026 ) . Furthermore, each game combines many capabilities, such as 3D spatial understanding, temporal reasoning, and learning unfamiliar controls, in a single fixed task. This makes it difficult to tell whether models fail because they are too slow or because they lack some other capabilities. Separating these two causes requires controlled comparisons that vary how much time an agent has to respond on the same task. To address these challenges, we introduce Gym-Anything-RT , a framework for creating environments for studying the real-time interaction capabilities of vision-language agents. Our key idea is to construct visual minigames that demand a portfolio of capabilities required for interactive real-time settings, while avoiding the complexity of complete games. For instance, in Rotating On-Screen Keyboard (Figure 1 ), the agent must enter a code by clicking keys that keep moving in three-dimensional space between its observation and its action. Furthermore, we build an evaluation stack that controls the clock of each minigame, so we can run the same task live at its natural speed, slow it down to give the agent more time to respond, or pause it between observation and action to remove the need for real-time actions. Since each minigame is a program, we can also modify it, for instance, to remove its temporal dynamics or to increase its difficulty. By comparing an agent’s performance on these variants of the same task, we can tell whether it fails because it cannot act in time as the environment changes, or because the task is hard for other reasons. Building such minigames by hand is laborious, since each needs its own visuals, dynamics, controls, and verifier. We therefore build an agentic pipeline that generates the minigames automatically. We first survey prior work on embodied agents ( Savva et al., 2019 ; Srivastava et al., 2021 ; Yang et al., 2025c ) , video games ( Zhang et al., 2026 ) , and computer use ( Cheng et al., 2024 ; Xie et al., 2024 ) to identify six capabilities required for real-time interaction, such as 3D visual understanding, temporal reasoning, and acting under an evolving environment state, and select minigames that cover the capabilities. We then build on the creator-auditor procedure of Gym-Anything ( Aggarwal et al., 2026 ) , in which one coding agent builds an environment and an independent agent audits it. In our setting, a creator agent implements each minigame as a program, and additionally writes an oracle solution that uses the program’s internal state to show that the task is solvable. Independent audit agents then test the minigame and report problems to the creator agent, which fixes them until the minigame behaves as intended. Finally, review agents label the capabilities that each minigame requires. Each program also defines four easier difficulty levels and a simplified interaction mode, which let us evaluate weaker models and study what makes a task hard. Using this pipeline, we construct a benchmark of 100 real-time minigames and their non-real-time counterparts, and use it to evaluate frontier and open-weight models. We find that current agents perform poorly in real time. GPT-6 Astra (xHigh) solves only 9.0% of the real-time tasks, while it solves 66.0% of their non-real-time counterparts, which we obtain by modifying each program so that it no longer requires real-time interaction. Other models perform even worse: Claude Opus 5.5 (xHigh) and GPT-6 Luna (xHigh) solve only 5.0% and 1.0% of the real-time tasks, and the open-weight Qwen3.8-27B and Qwen3.5-9B solve only 1.0% and 0.0%, respectively.
