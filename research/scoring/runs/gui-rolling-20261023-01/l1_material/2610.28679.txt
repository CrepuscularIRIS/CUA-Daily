title: VerifierBench: Benchmarking the Generation of Executable Verifiers for LLM Agents
source: https://arxiv.org/abs/2610.28679

§Abstract
Agents need reliable ways to validate their outputs, both when completing tasks and when filtering synthetic training data. We study verifier generation: from the instruction and environment available for solving a task, an agent writes an executable verifier that must accept every valid solution and reject invalid ones. We introduce VerifierBench, a benchmark of 222 tasks from six agent benchmarks spanning tool-call, state-based, and code verification, with 4,993 hidden test cases that include alternative valid solutions and attacks; Verifier4Verifier (V4V), a six-check audit, screens its source verifiers and test suites. Across 19 models in a common agent harness, normalized balanced accuracy ranges from 10.6 to 62.1, with generated verifiers consistently rejecting invalid solutions more reliably than they accept valid ones. This apparent strength can mask overly restrictive verification: most false rejections in the analyzed records come from verifiers that accept no tested solution to a task. Case studies reveal unsupported assumptions about solution formats, tool use, and code changes that exclude valid solutions. These errors survive self-testing because agents test solutions that share the verifier's mistaken assumptions, or submit verifiers without confirming that any correct solution passes. These findings suggest testing both whether a verifier accepts a correct solution and whether it accepts other solutions permitted by the task. The project page and dataset are publicly available.

§Introduction (from cached fulltext; cut at ~9000 chars)
In data-oriented recursive self-improvement (RSI) ( Yin et al., 2025 ; Min et al., 2026 ) , agents construct training data for their own subsequent learning and can jointly generate tasks and verification functions that provide reinforcement learning rewards ( Zhou et al., 2026 ) . These verifiers judge candidate solutions, determining which receive rewards or enter the training data. An incorrect verifier can therefore repeatedly reward a violation or discard a valid solution, making the reliability of agent-generated verifiers critical to this learning process. To examine this reliability, we study verifier generation ( Zhang et al., 2025 ; Dinella et al., 2022 ) : given the instruction and environment a solver would receive, an agent writes an executable verifier that returns PASS or FAIL for any candidate solution. Unlike a solver, which needs one valid solution, a verifier must accept all valid solutions while rejecting invalid ones. It must therefore distinguish task requirements from choices that can vary across valid solutions. Figure 2 shows a verifier rejecting a permitted read-only query because the agent omits its tool from an allowlist. The self-tests omit the same query and never establish that a complete valid solution passes. A verifier that accepts one expected solution may still reject other valid ways to complete a task, while one that catches ordinary mistakes may still accept solutions that exploit gaps in its checks. Evaluating verifier generation therefore requires testing both acceptance of valid alternatives and rejection of invalid solutions, including deliberate attacks. Prior work evaluates generated test assertions ( Dinella et al., 2022 ) , unit tests ( Jain et al., 2025 ) , issue-reproducing tests ( Mündler et al., 2024 ) , and executable specifications ( Endres et al., 2024 ; Chen et al., 2026 ) . We extend this line of evaluation to agent task completion, where correctness can depend on tool interactions, resulting environment states, and code changes. To this end, we build VerifierBench : 222 tasks from six open-source agent benchmarks with 4,993 hidden test cases, comprising reference solutions, valid alternatives, ordinary errors, and attacks on verification. This design tests whether generated verifiers distinguish task success from failure across different ways of carrying out the same task. Reliable measurement also requires trustworthy evaluation labels. Because both the benchmarks’ source verifiers and our constructed test cases can contain errors, we audit them with Verifier4Verifier (V4V) , six checks that include replay, repeatability, and mutation testing. Source verifiers that pass this audit serve as the reference verifiers. Evaluating 19 models in a common harness and 17 further model–harness configurations, we report three findings. First, generated verifiers accept valid solutions less reliably than they reject invalid ones: as reported in Section 3.2 , true positive rates range from 21.1% to 70.2%, whereas true negative rates range from 79.2% to 96.3%. Second, as analyzed in Section 3.4 , these false rejections concentrate in all-reject verifiers , which return FAIL on every test case of their task and produce 87.9–96.0% of false rejections in the analyzed records. Third, in selected cases examined in Section 4 , these verifiers impose checks that the task does not require, and the agents’ self-tests either exercise only solutions those checks allow or never confirm that any valid solution passes. We thus contribute a benchmark and screening procedure for verifier generation in Section 2 , together with an analysis in Section 5 that motivates testing generated verifiers on permitted variations, not only on a chosen solution.
