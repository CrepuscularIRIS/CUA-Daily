title: OctoNest: Adaptive Cross-Device Execution through Stateful Control
source: https://arxiv.org/abs/2606.20487

§Abstract
Computer use agents are expanding from single-device operation toward cross-device systems that coordinate tasks across heterogeneous environments. Execution conditions are often only partially known at planning time and revealed through interaction. Failures may require intra-device modality switching or inter-device reassignment; failing to distinguish these cases can lead to repeated failures or premature termination. However, existing systems primarily scale up single-device agents without sufficiently distinguishing device-level and modality-specific execution conditions. We propose OctoNest, which coordinates stateful cross-device orchestration and iterative device-local modality control. Device Agents refine subtasks and select modalities, while an Orchestrator uses execution feedback to revise plans and device assignments. We also introduce CAPEBench, comprising 158 instances from 23 cross-device seed tasks with controlled perturbations. OctoNest leads all three quality metrics, improving Perfect Pass over the strongest baseline by 18.35 percentage points and reducing token cost per perfect pass by 39.8\%. Further analyses support the complementary roles of local refinement and global revision and demonstrate CAPEBench's ability to distinguish control limitations under changing execution conditions.

§Introduction (from cached fulltext; cut at ~9000 chars)
Recent advances in LLMs have extended them beyond conversational response generation toward agents that perceive and act in external environments ( Yao et al., 2023 ; Schick et al., 2023 ) . Among them, computer use agents, which operate digital applications and systems on users’ behalf, have become a rapidly growing research direction ( Zhou et al., 2024 ; Rawles et al., 2025 ; Xu et al., 2025a ) . They act through three primary execution modalities: 1) GUIs across web, desktop, and mobile ( ByteDance Seed, 2025 ; Xu et al., 2026 ; Rawles et al., 2025 ) ; 2) structured APIs for direct application and service operations ( Trivedi et al., 2024 ; Yan et al., 2025 ) ; and 3) CLIs for code, shell commands, and system operations ( Yang et al., 2024 ; Merrill et al., 2026 ) . Recent systems further combine multiple execution modalities, including hybrid API–GUI control and GUI interaction augmented with Python or Bash execution ( Yan et al., 2025 ; Zhang et al., 2026 ; Song et al., 2026 ) . Within a single device, these modalities provide complementary ways to accomplish a task. In practice, many user requests span multiple devices because task-relevant information, applications, and execution capabilities are distributed across phones, personal computers, and remote machines ( Xu et al., 2025b ; Chen et al., 2026b ; Li et al., 2026a ) . CRAB centralizes perception across environments, planning, and action selection in a primary agent ( Xu et al., 2025b ) . TopoClaw similarly relies on a primary agent to coordinate multiple devices while making both planning and execution decisions ( Huang et al., 2026 ) . UFO 3 separates global graph orchestration from device execution, maintaining a mutable task graph and dispatching its nodes to device agents tied to device-specific execution modalities ( Zhang et al., 2025c ) . Despite their different organizations, these systems coordinate endpoints bound to a modality, grounding cross-device decisions into the action spaces exposed by their modalities and returning observations to the global agent. Cross-device execution depends on both global task dependencies and execution states local to each device and its modalities. However, existing systems largely leave the global agent to interpret modality-level observations for cross-device coordination, without sufficiently distinguishing between adaptation within a device and reassignment across devices. For example, a write operation blocked by a CLI’s read-only sandbox may still be completed through the GUI on the same device, whereas a device-wide network disconnection may make a network-dependent subtask infeasible on that device. Access to modalities subject to different runtime constraints can enable continued execution when one modality becomes unavailable ( Hu et al., 2026 ; Zhou et al., 2026 ) , while failures that leave no feasible alternative on the current device require reassignment. The states governing these possibilities are only partially known at planning time and progressively revealed through interaction ( Zhu et al., 2026 ; Bonatti et al., 2025 ) , making execution a failure-prone process of state discovery. This motivates supporting multiple modalities and updating execution state from feedback to distinguish modality feasibility from device feasibility, guiding intra-device or inter-device switching while preserving task constraints. We propose OctoNest , a stateful cross-device execution framework that coordinates intra-device and inter-device switching through nested control. The orchestrator maintains orchestration state to plan and assign device-level subtasks. Each device agent maintains device-local state to progressively refine its subtask, select API, CLI, or GUI modality executors, and switch modalities when needed. When no viable local continuation can be identified, it returns execution evidence to the orchestrator, which revises the remaining plan and device assignments. As illustrated in Figure 1 , this design preserves progress through local adaptation when possible and enables reassignment when necessary, supporting continued execution under changing conditions. We introduce CAPEBench ( Cross-device Adaptation to Perturbations in Execution ), comprising 158 instances derived from 23 seed tasks. CAPEBench covers unperturbed, modality-level, device-level, and mixed conditions, with modality-level perturbations testing intra-device switching, device-level perturbations testing inter-device switching, and mixed perturbations testing both. Compared with the strongest baseline, OctoNest improves Completion, Adherence, and Perfect Pass by 10.51, 11.36, and 18.35 percentage points, respectively, while reducing token cost per perfect pass by 39.8%. Further analysis shows that OctoNest selects capability-compatible modality sequences and achieves higher affected-step recovery under perturbations, supporting the complementary roles of device-local control and cross-device orchestration.
