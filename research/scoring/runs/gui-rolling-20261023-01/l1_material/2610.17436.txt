title: SchemaWeaver: Accelerating On-Device Mobile Agentic AI via Schema-Guided Parallel LLM Decoding
source: https://arxiv.org/abs/2610.17436

§Abstract
Large language models (LLMs) on mobile devices can act as agents that call external software tools to complete complex tasks, but the major challenge of supporting on-device mobile agentic AI with LLMs is the long latency of LLM tool calling on mobile devices. In particular, the decode phase is the main contributor of such long latency, but is hard to speed up on mobile processors as it is bound by memory bandwidth rather than compute power. To address this limitation, in this paper we present SchemaWeaver, a new on-device mobile agentic AI technique that enforces schema-guided parallel decoding in the decode phase of LLM tool calling, to reduce its latency by producing multiple tokens in each decode pass. SchemaWeaver can be generically applied to the LLM inference engine on mobile devices without involving any training efforts or changes on LLMs, and our experiment results on major mobile SoCs and LLM families show that SchemaWeaver can reduce the LLM tool calling latency by up to 3.9 times, compared to the competitive baselines.

§Introduction (from cached fulltext; cut at ~9000 chars)
In recent years, Large Language Models (LLMs) have been used as the backbone of agentic AI systems. When given proper context, LLM agents can interpret user instructions, select the proper external software tools, and call these tools to complete complex tasks ( Schick et al., 2023 ; Yao et al., 2023 ; Qin et al., 2024 ; Hou et al., 2025 ) . For example in Figure 1 , when being asked for driving directions, the LLM agent selects the get_route software tool from the available tools for this task. It then calls this tool for route planning and returns the results back to the user in natural language. In this process, the LLM agent perceives each tool from its schema , which is a machine-readable description that gives the tool’s description and the names and types of its arguments ( Hou et al., 2025 ) . The LLM agent, then, calls the tool by generating the text command with values of the tool’s arguments. Currently, LLM agents on mobile devices (e.g., smartphones) have become increasingly popular, allowing intelligent and automated operations on the user’s personal data ( Chen et al., 2025a ; Nong et al., 2024 ; Wen et al., 2024a ) . Agentic AI functionalities on mobile devices have also been supported by mainstream mobile OSes, via Android AppFunctions ( Android Developers, 2026 ; Android Developers Blog, 2026 ) and iOS App Intents ( Apple Developer Documentation, 2024 ) . In particular, running on-device LLM agents on local devices well preserves the user’s data privacy ( Xu et al., 2024 ; Yin et al., 2024 ; Li et al., 2024b ) , and quantized LLMs with 1B-3B parameters, which fit in a smartphone’s memory budget ( Liu et al., 2024c ; Frantar et al., 2023 ; Lin et al., 2024 ; Gerganov et al., 2023 ) , have been capable of launching tool calls with reasonable accuracy ( Zhang et al., 2025a ; Paramanayakam et al., 2025 ; Haque et al., 2025 ) . The major challenge of supporting on-device mobile agentic AI, however, is the long latency of LLM tool calling on mobile devices. In inference, an LLM produces its output through repeated forward passes that constitute a prefill phase and a decode phase . The prefill phase uses the first pass to read the input prompt, and the decode phase then generates the response using the other passes, each of which produces one output token ( Pope et al., 2023 ; Xu et al., 2025b ) . As shown in Figure 2 (a), in traditional conversation-based LLM uses, one prefill is usually followed by a large quantity of decoded text tokens that the user reads as they arrive, and most of the decode latency is hence “hidden” in user reading ( Liu et al., 2024a ; Xiao and Yang, 2025 ) . Agentic LLM operations, in contrast, first decode a structured tool call command for tool execution, and text tokens in response can only be produced after the completion of tool execution. The decode latency experienced by the user, hence, becomes significantly longer, especially when executing complicated agentic tasks such as on-device content search that involves multiple tool calls of different types. In these tasks, our experiments show that the decode latency constitutes up to 81% of the wall-clock time being taken (Sec 2.2 ). Unfortunately, it is difficult to accelerate this decode phase on mobile devices, which is bound by the device’s limited memory bandwidth rather than by compute power ( Pope et al., 2023 ; Huang et al., 2025 ) . More specifically, on mobile devices, the LLM’s weights have to be repeatedly loaded from memory to mobile processors by every pass, due to the processors’ limited cache capacities ( Pope et al., 2023 ; Alizadeh et al., 2024 ) . Since each decode pass only produces one output token, the decode latency is determined by the speed of memory bus, which is usually much slower than the mobile processor speed and hence causes processor starvation. Our experiment results on the OnePlus 12R phone with Snapdragon 8 Gen 2 SoC show that the decode speed on mobile CPU is >5\times slower than the prefill speed (Sec 2.3 ). Using mobile GPU or NPU cannot help much, due to the shared memory architecture in mobile SoCs ( Chen et al., 2025a ; Xu et al., 2025b ; Li et al., 2026b ; Cai et al., 2026 ) . The key to accelerating the decode phase in mobile agentic AI, hence, is how to allow producing multiple output tokens in one decode pass, to fully utilize the on-device compute power. One straightforward approach is speculative decoding ( Leviathan et al., 2023 ; Cai et al., 2024 ; Fu et al., 2024 ) , which first uses a much smaller draft model to guess the next few tokens and then lets the target model check the correctness of these guesses in one pass. Since a tool call is highly structured, most output tokens are highly predictable. For example, with a SmolLM2-1.7B as the target model and SmolLM2-135M as the draft model, 74% of guesses are correct.
