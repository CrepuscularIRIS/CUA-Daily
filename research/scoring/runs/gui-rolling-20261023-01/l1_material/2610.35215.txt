title: SkillLifeBench: Benchmarking Security Across the Lifecycle of Agent Skills
source: https://arxiv.org/abs/2610.35215

§Abstract
Web agents reuse skills whose stored code, selected version, and loaded implementation can diverge across tasks and updates. SkillLifeBench links these states to task outcomes in 388 paired scenarios spanning implementation, interface, runtime, composition, and version changes. We evaluate 14 models on two paired decision tracks: 89 runtime tasks and 60 autonomous lifecycle tasks spanning 12 templates derived from introduced cases. Lifecycle tasks allow agents to inspect, select, and reconfigure skills while completing verifiable user requests. Joint success requires task completion without the registered attack goal. GPT-5.6-Sol and Sonnet 4.6 both achieve 82.0% on runtime tasks, but reach 96.7% and 56.7% on lifecycle tasks. Across lifecycle evaluations, challenged task success is 77.5%, while joint success is 65.2%; 103 runs complete the task and the attack goal. Adding execution provenance in a matched recovery study raises utility joint success from 49.35% with logs and metadata to 65.58%. A deterministic execution-consistency rule reaches 64.94% with higher benign utility, while full restoration reaches 69.48%. Lifecycle tasks distinguish models with similar runtime scores, and execution evidence improves recovery.

§Introduction (from cached fulltext; cut at ~9000 chars)
Web agents use reusable skills to access email, cloud storage, and Web APIs ( Xu and Yan, 2026 ; Ling et al., 2026 ; Yao et al., 2023 ) . A skill packages reusable instructions or executable functions for an agent. Stale or altered skills can expose private data or trigger unauthorized actions, making lifecycle integrity a Web security and privacy concern. Evaluation measures task completion and adherence to authorized data access, destinations, and state changes. An agent can deliver a correct report while copying data without authorization, or select a repaired skill while a saved execution reference ( handle ) still invokes the vulnerable previous version (Figure 2 ). Existing benchmarks cover attacks through skill content, composition, persistence, and updates ( Debenedetti et al., 2024 ; Zhuang et al., 2026 ; Xie et al., 2026 ; Liao et al., 2026 ; Ning et al., 2026 ; Mao et al., 2026 ; Badhe and Tiwari, 2026 ) . Outputs and version records alone cannot establish which code ran or whether its actions were authorized. Evaluation must link calls to executed code, check task completion and unauthorized effects separately, and test agents’ version, permission, and workflow choices. We introduce SkillLifeBench , with 388 paired cases spanning the skill lifecycle. Each pair holds the user request and authorization fixed while changing an implementation, interface, runtime response, composition, or version. Two paired decision tracks evaluate 14 models: 89 runtime tasks and 60 autonomous lifecycle tasks (Table 2 ). On lifecycle tasks, agents can inspect and change skill state or use available tools directly. Task and attack-goal checks define joint success: fulfilling the request without achieving the registered attack goal. Prescribed-call cases measure implementation behavior under a fixed invocation; the two decision tracks measure model choices with complete task checks. Lifecycle tasks reveal differences beyond runtime performance: GPT-5.6-Sol and Sonnet 4.6 tie at 82.0% runtime joint success, but score 96.7% and 56.7% on lifecycle tasks. Across Qwen3.5-4B and Qwen3.5-9B, authorization checking improves runtime joint success, but attack-goal successes also increase from 19 to 21 (Section 4.3 ). For these two models, adding execution provenance to logs and metadata raises risk-task joint success from 76/154 to 101/154 under matched conditions.
