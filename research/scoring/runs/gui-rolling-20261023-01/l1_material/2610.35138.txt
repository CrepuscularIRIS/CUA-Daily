title: Co-Design Bench: Multimodal Collaborative Coding Evaluation for Agentic Models
source: https://arxiv.org/abs/2610.35138

§Abstract
Evaluating human-AI co-design requires testing whether coding agents can translate real users' multimodal requests into working application revisions. We introduce Co-Design Bench, a reference-free benchmark of 273 tasks curated from 37,463 deduplicated queries across 26,314 real user coding sessions. Its two tracks, Multimodal Editing (ME) and Repository Editing (RE), cover localized edits with optional image, audio, video, or document inputs and coordinated repository revisions. Tasks span three capability dimensions: Grounded Understanding, UI Transformation, and Functional Implementation. The tasks pair normalized requests and runnable pre-edit applications with 2,331 hidden expert-authored acceptance criteria. Our judge-then-refute protocol grades criteria using source and browser evidence, challenges positive verdicts with a separate LLM verifier, and audits visual and interaction claims without gold code or target screenshots. Under a shared agentic harness, the strongest of ten model endpoints passes an average of 69.9% of criteria per task but fully satisfies only 26.4% of tasks. All ten endpoints achieve lower criterion completion on repository edits spanning three or four change types than on those spanning one or two. Co-Design Bench provides a testbed for studying the gap between partial requirement satisfaction and complete task success under agentic execution for real-user application revisions.

§Introduction (from cached fulltext; cut at ~9000 chars)
Web application co-design follows an iterative cycle of inspecting an existing artifact, requesting changes, and assessing the result ( Schön, 1983 ) . Coding agents can participate in this cycle by inspecting visual context, modifying source files, and executing applications ( Yang et al., 2024a ; Anthropic, 2025 ; OpenAI, 2026a ; Qwen Team, 2026b ) . Success requires translating user intent into working revisions of the current application. A request may combine image, audio, video, or document inputs with changes to layout, interaction, and application state, requiring the agent to connect multimodal evidence to dependent revisions across the application’s interface and behavior. Existing benchmarks capture important parts of this problem: reference reconstruction ( Si et al., 2024 ; Lai et al., 2025 ; Chen et al., 2025 ) , synthetic or predefined edits and repairs ( Li et al., 2026 ; Lei et al., 2026 ) , edits extracted from version histories ( Xiao et al., 2025 ) , and implementation of repository issues or freelance requests ( Jimenez et al., 2023 ; Yang et al., 2024b ; Miserendino et al., 2025 ) . Coverage remains limited for compound revisions drawn from coding sessions across both localized multimodal edits and coordinated repository changes (Table 1 ). For example, the sports clip editor request in Figure 1 (b) couples clip-count and duration limits, timeline alignment under zoom, and state updates that re-enable insertion after clip removal or splitting. Such a request ties success to the behavior of the edited application across several interacting requirements at once. Agentic execution also changes how benchmark scores should be interpreted. On the same 150 WebCompass-edit tasks ( Lei et al., 2026 ) , switching qwen3.7-plus ( Qwen Team, 2026a ) from single-shot to agentic execution raises mean graded feature completion from 73.6\% to 95.1\% , with the feature rubric, judge, and render pipeline held fixed (Figure 1 (a); Appendix A ). On these 150 tasks, opus-4-8 ( Anthropic, 2026a ) reaches 99.4\% mean graded feature completion with agentic execution. The 21.5 -point gain shows that execution conditions materially affect measured completion in this setting. We therefore evaluate real-user revisions with iterative tool access and report both criterion satisfaction and complete task success. We introduce Co-Design Bench , comprising 273 tasks and 2{,}331 expert-authored acceptance criteria, curated from 37{,}463 deduplicated queries across 26{,}314 real user coding sessions. We recover and validate runnable pre-edit applications, retain available session context and attachments, and consolidate user requests into bounded editing tasks. The benchmark covers two complementary settings: Multimodal Editing (ME) evaluates localized visual, structural, and content edits with optional image, audio, video, or document inputs; Repository Editing (RE) evaluates coordinated UI and feature changes across components, routes, state, and data flow. Both tracks pair the starting application with a normalized request and hidden acceptance criteria that specify the requested changes while allowing multiple valid implementations. A document-grounded edit can require consistent updates to a displayed value and its dependent summaries, while a repository request can couple visible controls with state transitions across components. The shared task formulation captures these dependencies as auditable requirements, connecting the interpretation of user evidence to observable visual changes and state transitions in the edited application. Evaluating these tasks requires checking whether requested features are reachable and behave correctly in the edited application. Our judge-then-refute protocol first grades hidden criteria using source code and browser execution evidence. A separate LLM verifier challenges Pass and Partial verdicts against the collected evidence, checking for stubs, hardcoding, unreachable functionality, and requirement mismatches. Audits require successful renders and screenshots for visual claims and recorded browser actions for interaction claims; missing evidence aborts evaluation before score aggregation. The pre-edit application grounds the requested changes, enabling reference-free acceptance without gold code or target screenshots, while retained verdicts and traces link each criterion judgment to its supporting evidence for inspection. We evaluate ten model endpoints under a shared agentic harness. The strongest endpoint passes an average of 69.9\% of criteria per task but fully satisfies only 26.4\% of tasks. Model rankings vary between tracks, and all ten endpoints achieve lower criterion completion on repository edits spanning three or four change types than on those spanning one or two. These results show that substantial coverage of individual requirements can coexist with limited complete-task success, motivating evaluation of both criterion satisfaction and complete delivery.
