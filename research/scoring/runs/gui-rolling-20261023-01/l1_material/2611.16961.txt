title: The Value of Thinking: Learning When to Reason in Hybrid Decision Models
source: https://arxiv.org/abs/2611.16961

§Abstract
Existing adaptive-reasoning methods shorten the explicit reasoning a model writes, or skip it by switching modes; either way the answer is still written out token by token. \emph{Rather than deciding how much to think}, we explore a different paradigm, \emph{zero-or-$T$ thinking}: a single model either answers from the implicit thinking inside one forward pass, generating no token, or performs full autoregressive reasoning at a cost of $T$ tokens when that is worth paying. We realise it in a \emph{hybrid decision model} (HDM), where one frozen backbone serves both modes and a lightweight \emph{self-routing block} chooses between them. The block estimates the \emph{value of thinking}, the utility the slow mode is expected to add over the fast one, from what that implicit thinking has already produced, and the slow mode runs only where that value exceeds a price $λ$ set per request. Where no per-decision label exists, as in episodic agentic tasks, we introduce \emph{Calibrated Decision Policy Optimisation} (CDPO), a reinforcement-learning recipe that trains the block from episode-level returns. We evaluate HDM on MMLU-Pro, AGIEval, GPQA-Diamond, JevBench, BANKING77 and MiniWoB. Specifically, on JevBench HDM-4B scores $0.857$ against Jev's $0.851$ ($+0.7\%$) at a median $0.179$\,s against $0.652$ ($-72.5\%$). On the agentic venue MiniWoB HDM-27B cuts token cost by $80.1\%$.

§Introduction (from cached fulltext; cut at ~9000 chars)
In Kahneman’s dual-process theory of cognition, “System 1 operates automatically and quickly, with little or no effort and no sense of voluntary control,” whereas “System 2 allocates attention to the effortful mental activities that demand it” ( Kahneman, 2011 ) . This division has shaped the design philosophy of reasoning in large language models (LLMs) ( Wang, 2025 ) , but the work it has influenced builds either a good System Two or a good System One, and a model that is both remains underexplored. Most current System Two models (like reasoning models) raise their capability through autoregressive test-time scaling, including OpenAI’s GPT-6, Anthropic’s Claude Fable 5 and the open-weight Qwen3.8, which write a chain of thought before the answer, at a cost in tokens and latency on every question. A recent class of System One models, Jev ( TypeSafe AI, 2026 ) and AnyJev ( Nokia Applied Research, 2026 ) among them, takes the strict case, emitting no tokens at inference and producing the answer in a single non-autoregressive pass, each adapting a reasoning-model backbone rather than training a different kind of model. One line of work seeks efficiency inside reasoning models themselves, shortening the chain of thought without losing accuracy ( Snell et al., 2024 ; Muennighoff et al., 2025 ; Zhang et al., 2025b ; Aggarwal and Welleck, 2025 ; Zhang et al., 2025a ) . These methods make the chain cheaper rather than optional: they ask how long the reasoning should run, not whether a given question needs it at all. Another relieves the cost by routing between models, or down a cascade until an answer is accepted ( Chen et al., 2023 ; Ong et al., 2024 ) . Every branch is a model generating an answer, so the choice on offer is between an expensive answer and a cheaper one. Can one model keep both advantages and switch between them when it should, generating nothing at all where that suffices and reasoning where it does not? In this work, we introduce zero-or- T thinking , an adaptive-inference paradigm that unifies token-free fast decision with full autoregressive reasoning inside a single language model: rather than deciding how much to think, the model decides whether autoregressive thinking is needed at all , and a question costs either no generated token or the T a reasoning pass takes. Specifically, we define the value of thinking on a question as the utility the slow-thinking mode is expected to add over the fast-thinking one, and a question is escalated only when that value exceeds a price \lambda set on the request. We instantiate zero-or- T thinking in a hybrid decision model (HDM): a fast-and-slow model, its fast-thinking mode producing a decision directly from the implicit thinking with no token generated, its slow-thinking mode the backbone’s own reasoning inherited unchanged, and a learned self-routing block choosing between them before any token is generated. HDM estimates the conditional gain of thinking from hidden representations the fast mode has already computed, and completes cost-aware routing before inference begins. We also address how the block is trained. On single-turn questions a gold answer is available, so running both modes constructs the better choice directly and supervision suffices; in episodic tasks the return is decided by many successive actions and no per-decision label exists, so we introduce a PPO-based reinforcement-learning recipe for training HDM, Calibrated Decision Policy Optimisation (CDPO). CDPO maximises the return an episode earns discounted by the escalations it spent, with that one episode-level signal shared by every decision inside it. We evaluate HDM on MMLU-Pro, AGIEval, GPQA-Diamond, JevBench, BANKING77 and MiniWoB. On JevBench HDM-4B reaches 0.857 against Jev’s 0.851 at a median 0.179 s against 0.652 ; on AGIEval HDM-27B trades 1.5 accuracy points for 37\% fewer thinking tokens, and on MiniWoB 5 points of reward for 80\% fewer. Our contribution is threefold. First , we propose zero-or- T thinking , a paradigm in which a question costs either no generated token or the T a reasoning pass takes and one frozen backbone serves both modes, switched by a self-routing block of a few hundred kilobytes that reads representations the fast pass has already computed, so the choice costs no forward pass and no token. Second , we introduce the value of thinking as the criterion that block switches on: the utility the slow-thinking mode is expected to add over the fast-thinking one, one interpretable quantity thresholded against a price \lambda set on the request rather than a number tuned per benchmark. Last , we introduce CDPO , which trains the block where no per-decision label exists, from the return an episode earns discounted by the escalations it spent.
