title: Cross-Interface Authorization for AI Computer-Use Agents

§Abstract
Computer-use agents act through graphical interfaces, command lines, APIs, scripts, and Model Context Protocol servers. A policy decision can be interface-invariant while its executable authorization is not: another route can bypass mediation, alter a security-relevant default, or commit after the authorized state has changed. We present a profile-bounded protocol for a fixed, versioned computer-use deployment. It enumerates effect-bearing routes and durable sinks, checks a route-to-sink enforcement cut, normalizes each concrete request to a canonical effect, issues a route-bound prepare ticket, and verifies the route, effect, grant, trace, profile, inventory, and authoritative state again at commit. A committed result requires an agreeing sink receipt. Under explicit assumptions, we prove profile-bounded refinement, matched-effect decision invariance, resistance to alternate-route laundering and declared cross-surface recomposition, commit-time state safety, and receipt-grounded outcomes. The reference profile registers 12 effect families, five interfaces, and 60 routes. Two structurally distinct runtime mappings produce 3,464 traces over 1,732 scenarios each: 960 commits, 2,312 denials, and 192 commits after re-preparation. An independent checker accepts every retained trace and pair and rejects 26/26 semantic regressions; coverage and normalizer suites reject 24/24 and 720/720 mutants; and 168/168 commit probes match their declared outcomes. A frozen-source audit passes 52 checks over 12 files from two independent hybrid runtimes and one public authorization substrate. Source-shaped adapter refinements commit 48/48 instrumented calls and reject 15/15 unbound cases. The resulting guarantees bind the declared profile and its effect semantics.

§Introduction (from cached fulltext; cut at ~9000 chars)
Computer-use agents no longer operate through one uniform tool interface. A single task may inspect a screen, activate a graphical control, invoke a shell command, call an application API, run a generated script, and use a Model Context Protocol (MCP) server. Reproducible agent environments make this execution style explicit: WebArena exposes stateful web applications ( Zhou et al., 2024 ) , OSWorld exercises real computer applications ( Xie et al., 2024 ) , WeaveBench requires long-horizon GUI and CLI orchestration ( Li et al., 2026b ) , and CUA-Universe constructs shared-state GUI+CLI environments ( Shi et al., 2026 ) . AgentDojo further demonstrates why a tool execution environment must account for adversarially influenced inputs ( Debenedetti et al., 2024 ) . Matched-interface studies show that the available operation set and its coverage materially shape agent performance ( Zhou et al., 2026 ) . These systems expose one resource through several representations and call paths. The resulting security problem is not solved by placing a sound policy check beside one entry point. Consider an agent authorized to grant read access to a particular repository. The graphical dialog is guarded, but an equivalent CLI subcommand reaches the same persistence layer through an unregistered handler. The agent can therefore preserve the apparent intent while bypassing the decision point. Even if both paths call the same policy, a GUI approval token may be reusable after switching to an API route whose defaults differ. Between approval and commit, the named repository can be rebound, a policy epoch can advance, or the target version can change. Finally, an authorized confidential read followed through another interface by an otherwise authorized external send can disclose data through a composition absent from either local request. These are boundary failures. They arise because the deployer has not made a checkable statement about (1) which effect-bearing routes exist, (2) where all registered paths meet enforcement, (3) whether their representations refine the same canonical effect, and (4) which authoritative state and trace prefix remain valid when the sink commits. Classical complete mediation requires every access to be checked ( Saltzer and Schroeder, 1975 ) ; runtime-monitor theory characterizes policies enforceable over event sequences ( Schneider, 2000 ) ; usage control accounts for mutable attributes during use ( Park and Sandhu, 2004 ) . Hybrid agent runtimes require these principles to be discharged against a versioned, concrete interface inventory. Recent agent-security systems provide substantial adjacent mechanisms. Secure-CUA protects GUI execution from untrusted interface influence with per-action transactions ( Choudhary et al., 2026 ) ; CSAgent protects GUI, API, and CLI activity using system-level contextual policy ( Gong et al., 2025 ) ; CaMeLs extends architectural isolation to computer use ( Foerster et al., 2026 ) ; and AIRGuard normalizes heterogeneous tool calls and enforces action-time authority ( Qin et al., 2026 ) . Temporary Authority, Permanent Effects shows why authorization evidence must remain fresh, causally valid, effect-bound, and eligible when a durable action commits ( Santos-Grueiro, 2026 ) . AID-Guard binds authorization through provider settlement and recovery ( Tong et al., 2026 ) , while EBL-Core defines an execution-boundary profile for narrowly scoped execution authority ( Wu et al., 2026 ) . Most directly, CONTINUITY defines consequence integrity, effect-class complete mediation, current authorization witnesses, finality sinks, and compositional security-context contracts ( Zheng and Yang, 2026 ) . Our question is narrower and operational: before a commit-time mechanism can protect a declared hybrid CUA stack, what finite evidence establishes the stack’s protected route surface, and how does each concrete route refine a stateful canonical effect protocol without making a prepare ticket portable across routes? 1.1. Versioned effect-surface closure We define a surface profile that binds an identifier and epoch to five objects: an inventory of effect-bearing entries; a directed route-to-sink graph; an interceptor cut through every registered entry-to-durable-sink path; typed per-interface normalizers; and commit adapters for authoritative sinks. A verifiable surface witness commits to the inventory, graph, cut, normalizers, and sink set. Its statement is deliberately finite: it concerns one enumerated deployment profile, not every operation a host might possibly perform. We present a route-bound prepare/commit protocol over that profile. A surface adapter normalizes a concrete action into an effect tuple containing the principal, operation, resource, recipient, fields, quantity, purpose, data class, state key, and sink.
