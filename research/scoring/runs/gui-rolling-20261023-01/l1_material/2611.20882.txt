title: Accelerate Bench: Evaluating Agents for Application-Level Program Optimization
source: https://arxiv.org/abs/2611.20882

§Abstract
Application optimization requires coding agents to discover useful changes and coordinate them across a complete program while preserving the required computation. We introduce Accelerate Bench, a benchmark of 32 CPU optimization tasks adapted from scientific applications and supercomputing competitions. Each task provides a working program and specifies the workload, correctness requirements, timing boundaries, and permitted edits, leaving agents to choose where and how to optimize. Public testing supports iterative development, and a separate verifier scores the final submission. On benchmark version 1.1, we evaluate 16 coding agents, each pairing a model with a harness. Their Score@1 ranges from 25.5% to 67.4%. Most of their programs are correct, and the size of the speedup separates them: the two leading agents are at least 2x faster on 22 or more of the 32 tasks, while the other fourteen reach 2x on 8 to 17 and leave 125 of their 412 correct outcomes below 1.25x. Controlled replays show why coordination across an application matters: identical source code runs between 0.29x and 2.12x depending only on build and runtime settings, and one code change is worth 1.01x or 6.4x depending on another. Accelerate Bench pairs executable workloads with agents' programs and trajectories to evaluate both their gains and the process behind them.

§Introduction (from cached fulltext; cut at ~9000 chars)
Software performance engineering improves application performance by identifying and addressing inefficiencies in software and the way it executes ( Woodside et al., 2007 ; Leiserson et al., 2020 ) . Effective optimization often requires interventions across multiple layers of the software stack, from compiler and build configurations to algorithms, data structures, dependencies, and hardware parallelism ( Leiserson et al., 2020 ; Balaprakash et al., 2018 ) . For an existing application, this is typically an iterative engineering process: measuring execution, locating performance bottlenecks, implementing targeted changes, and evaluating their end-to-end impact while preserving correctness ( Woodside et al., 2007 ; Balaprakash et al., 2018 ) . Application-level optimization therefore extends beyond localized code editing. A valid patch may leave end-to-end runtime unchanged, and effective speedups can depend on interactions among changes made across different layers of the software stack. Success requires discovering where performance is lost, deciding where to intervene, and verifying that the resulting program is both correct and faster at the workload level. Coding agents offer a path toward automating this process. Existing benchmarks such as SWE-Perf, GSO, and SWE-fficiency evaluate performance optimization in real software repositories using tasks derived from human optimization commits or pull requests ( He et al., 2026 ; Shetty et al., 2025 ; Ma et al., 2026 ) . These benchmarks anchor evaluation around known optimization instances, providing realistic repositories and expert optimization references. We study a complementary setting: can an agent optimize an application when the required behavior and workload are specified, but no known optimization patch determines where or how the agent should intervene? Inspired by behavioral specification in ProgramBench ( Yang et al., 2026 ) , we define optimization tasks by the computation that must be preserved and the workload that must become faster. Within a permitted edit scope, the agent may modify algorithms, implementation, build settings, dependencies, and runtime configuration. We introduce Accelerate Bench , a benchmark of 32 CPU optimization tasks adapted from scientific applications and supercomputing competition problems. Each task provides a working initial program together with correctness requirements, timing boundaries, permitted edits, and a public testing interface. Agents iteratively edit, build, execute, and evaluate candidate programs, while a separate verifier scores the final submission. This setup requires agents to discover optimization opportunities and convert them into verified end-to-end acceleration. We evaluate 16 coding agents on version 1.1 of Accelerate Bench, comparing correctness and end-to-end acceleration across the 32 tasks. Most of their programs are correct, so correctness alone does not separate the agents; the size of the speedup does. The two leading agents are at least 2\times faster on 22 or more tasks, whereas the other fourteen reach 2\times on 8 to 17 tasks and leave 125 of their 412 correct outcomes below 1.25\times . Accelerate Bench also records how agents optimize. From annotated trajectories of five agents on benchmark v1.0 and controlled replays of their programs, we ask what changes agents make to an application, how they test and develop candidate programs, and how optimization choices interact; the analysis characterizes optimization on these tasks rather than explaining the v1.1 ranking. Our contributions are: • A workload-defined optimization benchmark. Each of the 32 tasks fixes the computation, complete outputs, stateful checks such as checkpoint recovery, and timing boundaries; public tests support iteration, and a private verifier scores the final submission. In 14 planned controls on two tasks, every valid variant passes and all eight invalid variants fail the check they violate (Section 2 ). • An evaluation of 16 coding agents on benchmark v1.1. Correctness alone does not separate the agents: each is correct on 26 to 32 of the 32 tasks, while Score@1 ranges from 25.5% to 67.4% and the number of tasks with at least a 2\times speedup from 8 to 23 (Section 4 ). • An analysis of how agents optimize. From 480 runs of five agents on benchmark v1.0 and controlled replays of their programs, we find that these agents mostly change the computation and rarely the build, although build and runtime settings alone move one unchanged \tasknamebox Ag GROMACS program between 0.29\times and 2.12\times . Code changes also interact: one change in a \tasknamebox Ag QiboTN program is worth 1.01\times on its own and 6.4\times once another change is in place (Section 5 ). We will release the versioned task packages, including public tests and verifiers.
