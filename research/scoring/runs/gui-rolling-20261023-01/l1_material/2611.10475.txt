title: WordEval: Evaluating Word-Native Operation Fidelity in Document Editing
source: https://arxiv.org/abs/2611.10475

§Abstract
Microsoft Word is a central environment for office automation, and the faithful execution of its editing operations is an important capability for document agents. Unlike plain-text editing, editing in Word modifies a structured object model, where the requested effect is realized in object properties. Existing benchmarks, however, evaluate office workflows or desktop automation, treating word-processor documents as one task domain among many and verifying outcomes with keyword matching, per-task property checks, or screenshot comparison. We introduce WordEval, an operation-fidelity benchmark that instead centers evaluation on Word editing operations, testing whether each requested edit is realized as intended changes to Word objects and properties. It contains 642 cases across 15 Word feature areas, ranging from text and lists to charts, shape geometry, and SmartArt. 546 atomic cases cover 231 commands, 96 compositional cases combine multiple edits in a single document, and a Word-native oracle checks task-specific object properties and preservation conditions. Cases are constructed from editing-unit specifications, yielding controlled input documents, reference documents, and aligned oracle checks. Each compositional case is linked to corresponding atomic cases, supporting fine-grained diagnosis of editing failures. We evaluate eight agent systems and find that many struggle on the Atomic track, with performance varying across feature areas. Moreover, every system scores lower on Compositional than on Atomic, with gaps that vary substantially by system. Exact atomic-intent links and recorded failure diagnoses provide complementary views of this variation.

§Introduction (from cached fulltext; cut at ~9000 chars)
AI assistants have begun to operate inside the software where users work, including word processors such as Microsoft Word [ 1 , 17 , 7 ] . In this context, their output is no longer merely a natural-language reply, but a document that the user or agent itself can create, edit, and reuse. A Word document, however, is not merely a text canvas: it contains underlying information that the word processor reads and applies across subsequent document operations. A heading can be used for navigation or table-of-contents generation, a list can maintain continuous numbering as items are added or removed, and a field can be dynamically updated. Therefore, the central question is whether the requested operation takes effect in the document in a native form that Word can recognize and apply. Current evaluations of document agents, however, do not isolate this ability well. Existing benchmarks largely evaluate document generation, file I/O, information extraction, or GUI task completion [ 24 , 22 , 25 , 3 , 27 ] . They show that an agent can access a document and produce an output file, but not whether the effect of each Word-editing operation was faithfully realized. To address this gap, we introduce WordEval, a benchmark that evaluates how faithfully a Word agent realizes a user’s editing intent as a change in document state. We call this ability operation fidelity : whether the intended effect of an editing operation is realized in the resulting document as a state change with the correct target, attribute, and parameters. WordEval evaluates the output document itself, independent of the action path (e.g., GUI clicks, ribbon commands, or API calls) used to produce it. WordEval organizes evaluation into Atomic and Compositional tracks. Atomic cases isolate whether the intended effect of a single editing operation is realized. Compositional cases examine whether the agent can manage dependencies, ordering, interference, and preservation when multiple edits are issued together. This design lets us separately analyze the ability to perform individual Word-editing operations and to integrate multiple edits into a coherent document state. Contributions. (i) A Word-native operation-fidelity benchmark. WordEval comprises 642 cases spanning 15 Word feature areas, each generated from an editing-unit specification with an aligned Word-native oracle, with an Atomic track of 546 cases over 231 Word commands and a Compositional track of 96 cases from 27 composition scenarios. (ii) Evaluation revealing a compositional gap. Across eight agent systems, many still struggle on the Atomic track, with system-specific Atomic-to-Compositional gaps. (iii) Fine-grained failure diagnosis. Atomic-intent links, which connect each editing unit of a Compositional case to the Atomic case with the same command, trace compositional failures to individual operations, and a failure-mode analysis characterizes how incorrect outputs differ from the reference.
