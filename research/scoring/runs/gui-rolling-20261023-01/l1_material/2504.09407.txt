title: UXAgent: A System for Simulating Usability Testing of Web Design with LLM Agents
source: https://arxiv.org/abs/2504.09407

§Abstract
Usability testing is a fundamental research method that user experience (UX) researchers use to evaluate and iterate their new designs. But what about evaluating and iterating the usability testing study design itself? Recent advances in Large Language Model-simulated Agent (LLM Agent) research inspired us to design UXAgent to support UX researchers in evaluating and iterating their study design before they conduct the real human-subject study. Our system features a Persona Generator module, an LLM Agent module, and a Universal Browser Connector module to automatically generate thousands of simulated users and to interactively test the target website. The system also provides a Result Viewer Interface so that the UX researchers can easily review and analyze the generated qualitative (e.g., agents' post-study surveys) and quantitative data (e.g., agents' interaction logs), or even interview agents directly. Through a heuristic evaluation with 16 UX researchers, participants praised the innovation of our system but also expressed concerns about the future of LLM Agent usage in UX studies.

§Introduction (from cached fulltext; cut at ~9000 chars)
Usability testing is a fundamental research method for evaluating the user experience (UX) of a new feature or a new webpage design ( Shaw, 1996 ) . Typically, a UX researcher (or a UI/UX designer, product manager, etc.) leads the design and execution of a usability testing study: they start with a new feature or web design, and then they need to come up with a UX study design (e.g., A/B testing and the user tasks), recruit participants, execute the study, monitor, and analyze the data. However, the current process of conducting usability testing often faces challenges, especially in the study design stage and the study execution stage ( Følstad et al., 2012 ; Hertzum and Jacobsen, 2003 ; Kuang et al., 2022 ; Nørgaard and Hornbæk, 2006 ) . In the study design stage, researchers often focus on collecting early feedback on new feature design to iterate the feature, but the study design itself is left unevaluated ( Shaw, 1996 ) . Study design flaws that surface only during execution can lead to costly consequences. This is especially critical when working with underrepresented groups (e.g., non-binary shoppers), where participants are a limited and valuable resource, thus the findings may not be significant or insightful. In such cases, a UX practitioner in a company may not even have a second chance to iterate the study design. To alleviate this issue, researchers have practiced using pilot study sessions ( Decker-Maurer, 2012 ) or empathy-based research methods ( Särkelä and Suoranta, 2020 ) : Researchers often conduct a limited number of pilot study sessions before the actual study execution to test validity and uncover design flaws. However, these sessions are time-consuming and financially costly, since their data are not considered valid test data and require additional participant recruitment ( Decker-Maurer, 2012 ) . Researchers sometimes also apply an empathy-based research method, during which they attempt to put themselves in the shoes of their target users, especially when designing and studying for an underrepresented user population ( Särkelä and Suoranta, 2020 ) . However, this method is inherently limited, as researchers may fail to accurately represent the target population and may unintentionally introduce bias ( Wharton et al., 1992 ) . These limitations highlight the need for novel methods and systems that can offer early feedback on the study design as well as on the feature designs to support UX researchers. With the advancement of Large-Language Models (LLMs), some researchers have prompted LLMs to act as autonomous agents (i.e., LLM Agent ) that can perceive the environment and generate human-like actions to interact with the environment ( Wang et al., 2024 ) . For example, researchers have successfully empowered LLM Agents to simulate a group of 25 human agents living in a village ( Park et al., 2023 ) , replicate participants in a social science study ( Park et al., 2024 ; Schmidgall et al., 2024 ; Lee et al., [n. d.] ; Gurcan, 2024 ) , act as patients and clinicians in a hospital ( Li et al., 2024b ) , and behave as programmers for a software development company ( Qian et al., 2024 ) . The advances in LLM agent research inspire us that: if we can simulate diverse user behaviors and perspectives with an LLM agent as surrogates for real human-subject participants, then these surrogates can interact with real-world web environments to produce rich usability testing data. Such data can support UX researchers to analyze and identify potential flaws in their study design before conducting real user studies, as well as offer UX researchers early feedback for feature designs. Recently, a few LLM Agent-based systems (e.g., WebAgent ( Gur et al., 2023 ) , WebVoyager ( He et al., 2024 ) , etc.) have explored simulating human interaction behaviors with web-based systems. For example, ReAct ( Yao et al., 2023 ) can generate both reasoning and action trace and simulate human customers on WebShop ( Yao et al., 2022 ) , a commonly used sandbox environment for e-commerce platforms. Another example is Computer-Using Agent systems such as OpenAI Operator and Claude’s Computer-use API that can complete tasks in computer environments. However, these systems fall short of our use case: we need an LLM Agent to be able to operate with the dynamically changing web pages, to think (generate reasonings) as human users do, and to interact with the web page within a human-like responsive time interval. The aforementioned LLM Agent systems (1) are restricted to a sandbox simulation instead of a real-world complex web system (e.g., ReAct ( Yao et al., 2023 ) ), (2) rely only on complex and heavy reasoning architectures that hinder real-time responsiveness with the web (e.g., ( Ma et al., 2024 ; He et al., 2024 ; Gur et al., 2023 ) ), (3) do not have the reasoning depth so the simulated behavior trace output is too simple in comparison to real-human’s actions ( Sodhi et al., 2024 ) .
