title: MobiInfer: Accelerating On-Device GUI Agents with Workload-Aware Inference
source: https://arxiv.org/abs/2611.08496

§Abstract
Mobile GUI agents assist users in executing phone tasks through iterative observe-reason-act loops. However, deploy ing multimodal GUI agents directly on smartphones is challenging due to strict end-to-end latency requirements and significant memory overhead. We observe that GUI-agent work loads exhibit recurring workflows and structured I/O: their prompts contain reusable context, while their outputs follow fixed schemas with phase-dependent predictability. Based on this observation, we present MobiInfer, a workload-aware inference engine for on-device multimodal GUI agents. MobiInfer combines trajectory-aware prefix reuse, phase-indexed vocabulary specialization, and schema-guided speculative decoding to eliminate redundant prefill computation and reduce structured-generation overhead. We implement MobiInfer on top of MNN and evaluate it on AndroidWorld and a real world dataset using three real Android devices. Across the four model-benchmark settings, MobiInfer achieves average speedups of 2.6x in prefill and 2.5x in decoding, reduces end-to-end task latency by 2.4x on average, and cuts total deployment storage by 30%, while limiting task-success degradation to less than one percentage point.

§Introduction (from cached fulltext; cut at ~9000 chars)
Multimodal GUI agents turn a user goal and the current smartphone screen into an executable action, then repeat this observe–reason–act loop until the task is complete. Even when applications expose APIs, GUI agents remain necessary for the long tail of mobile tasks whose functionality is available only through visual interfaces, whose state is visible only on screen, or whose completion requires composing actions across multiple applications. Running this loop on the phone is attractive for latency, privacy, and connectivity reasons, but it makes every model invocation part of an interactive control path. The practical bottleneck is not only model size: mobile runtimes repeatedly prefill long multimodal prompts and decode structured actions under tight compute, memory-bandwidth, and RAM budgets. General-purpose on-device inference runtimes are not designed around this trajectory structure. When a GUI agent is executed step by step, the runtime often receives each model call as a separate request. Stable instructions can be prepared offline, task context can be reused within a trajectory, and only the current screenshot and recent UI state must be recomputed at every step. Yet these fields are often encoded together from scratch. Outputs are likewise decoded through a full-vocabulary projection despite moving through phases with different predictability and execution risk: reasoning errors may be recoverable, whereas an incorrect action label or coordinate can control the wrong UI element. We present MobiInfer , an inference engine built around this diagnosis. GUI trajectory-aware prefill canonicalizes prompt fields by lifetime, materializes compatible fixed and semi-fixed KV states, and evaluates only the dynamic suffix. Phase-indexed vocabulary specialization selects a compact output head from the committed generation phase. Schema-guided speculative decoding drafts only predictable structure and reasoning; it stops before action labels, coordinates, and other execution-critical values, which the target model generates and verifies. Together, these mechanisms align prefill reuse and decoding acceleration with the structure and risk profile of each GUI-agent trajectory without retraining the agent model or changing its external action interface. Figure 1 summarizes how these mechanisms map onto the repeated agent loop. We implement MobiInfer over MNN and evaluate it on AndroidWorld and a real-world dataset using three real Android devices. Against the deployment MNN baseline, MobiInfer achieves average speedups of 2.6\times in prefill, 2.5\times in decoding, and 2.4\times in end-to-end task latency while keeping task-success degradation below one percentage point. Moreover, the peak memory footprint decreases by 31.8%, and total deployment storage decreases by 30.0%. We make three contributions: • We identify GUI-agent inference as a long-lived trajectory with reusable prompt prefixes and phase-structured, risk-sensitive outputs. • We design a workload-aware runtime that jointly accelerates prefill and structured decoding without retraining the agent model. • We evaluate MobiInfer on Android devices with matched mobile baselines, measuring task latency, stage throughput, task success, memory, and deployment storage.

## Motivation and Characterization
We quantify two workload regularities exploited by MobiInfer: reusable prompt regions and phase-structured outputs. Reusable Prompt Regions Across a GUI-agent trajectory, large prompt spans remain unchanged across model calls: instructions, tool descriptions, output schemas, the user goal, and committed history often reappear as the screen observation changes. This creates substantial repeated prefill work, but it is reusable only when the repeated tokens form a contiguous autoregressive prefix. If a prompt template interleaves observation-dependent fields with stable fields, a small screen change can invalidate the KV states of all following tokens. Phase-Structured Outputs GUI-agent outputs are structured but not uniformly predictable. A response moves through JSON structure, reasoning, an action label, and typed arguments such as text or coordinates. These phases differ in both token space and execution risk: schema tokens are narrow and repetitive, reasoning is broader, and actions or coordinates depend on the current screen and directly control the device. Figure 2 first measures repeated consecutive token spans across task-disjoint outputs. Figure 3 then shows that GUI-agent outputs use only a small fraction of the tokenizer vocabulary, with a few hundred token types covering most occurrences. This concentration suggests that many decoding steps do not require full-vocabulary projection. Longer spans remain recurrent across task-disjoint outputs: 69.1% of 3-token windows and 57.6% of 4-token windows occur in at least 20 distinct collected real-world GUI-agent traces. Together, token concentration and span recurrence motivate MobiInfer’s output-side design: phase-indexed projection reduces large-head cost, while drafting is enabled only for predictable, non-critical phases.

## Method
MobiInfer combines three runtime mechanisms: GUI trajectory-aware prefill, phase-indexed vocabulary specialization, and schema-guided speculative decoding. All fast paths preserve the original token interface and commit drafted tokens only after target-model verification. GUI Trajectory-Aware Prefill Prompt canonicalization. Let a rendered prompt contain fixed fields P_{f} , semi-fixed fields P_{s} , and dynamic fields P_{d} . MobiInfer constructs P_{\mathrm{can}}=P_{f}\mathbin{\|}P_{s}\mathbin{\|}P_{d}, (1) where \| denotes concatenation with explicit template delimiters. Order is preserved within each region. System instructions, tool definitions, and the output schema belong to P_{f} ; the user goal and stable task context belong to P_{s} ; screenshots, visual tokens, OCR, and recent UI state belong to P_{d} . Any field that cannot be classified safely is assigned to P_{d} . This transformation makes P_{f}\|P_{s} a reusable autoregressive prefix. Prefix materialization and restoration. For a reusable prefix P_{r} , MobiInfer runs the target model once and stores the layer-wise key and value tensors. Globally fixed states are prepared offline, stored on disk as part of the deployment package, and paired with the exact model, tokenizer, and canonical template used at deployment. Semi-fixed states are materialized after the user goal is known and reused only within that trajectory. The cached-prefix package stores enough metadata to validate token, position, model, and backend compatibility before restoration. At runtime, the engine loads and restores the fixed cached prefix and, when available, the semi-fixed state. It sets the cached sequence length as the past-context length and begins P_{d} at the immediately following position. A changed user goal creates a new semi-fixed state rather than reusing the preceding task’s state. Under identical tokens, positions, weights, and runtime kernels, restoration is functionally equivalent to recomputing the prefix. Within a running task, MobiInfer also supports delta prefill. If the current canonical prompt extends the previous prompt, the engine retains the active KV state and processes only newly appended tokens. Phase-Indexed Vocabulary Specialization MobiInfer reduces vocabulary cost in two stages: (1) global row pruning and (2) phase-indexed active-head selection . First, it performs global row pruning on both the token embedding and LM-head matrices. As shown in Figure 3 , our collected real-world GUI-agent data uses only 14,162 of the 151,669 tokenizer entries. MobiInfer keeps these observed token rows, plus schema-required tokens, special tokens, and the complete base-byte alphabet, and removes the remaining rows from both matrices. The byte alphabet, consisting of 256 tokens, provides coverage fallback, so with BPE-style tokenization, text can still be emitted through byte tokens even when a larger merged token is pruned. Second, MobiInfer selects a smaller active head for each output phase. It represents the output schema as an incremental automaton \mathcal{A} whose state q indicates whether the model is generating structure, reasoning, an action label, coordinates, another typed parameter, or completion. Using collected outputs labeled by this automaton, MobiInfer builds a phase vocabulary V_{q}=V_{\mathrm{schema}}(q)\cup V_{\mathrm{freq}}(q)\cup V_{\mathrm{byte}}\cup V_{\mathrm{special}}. (2) V_{\mathrm{schema}}(q) contains tokens required by legal schema transitions, V_{\mathrm{freq}}(q) contains frequent tokens from collected output segments assigned to phase q by the automaton, V_{\mathrm{byte}} contains the 256 byte tokens, and V_{\mathrm{special}} contains required control and termination tokens. Structure, action, and coordinate phases therefore use narrow vocabularies, while reasoning keeps a broader set of frequent tokens. At runtime, the current automaton state q selects the phase head for hidden state h and output matrix W : W_{q}=W[V_{q},:],\qquad\ell_{q}=W_{q}h. (3) The schema mask is applied inside V_{q} , and the selected row is mapped back to the original tokenizer ID before the token is committed. Thus MobiInfer keeps the external token interface unchanged while avoiding full-vocabulary projection for phases that need only a small part of the vocabulary. MobiInfer separates output phases into speculative states and protected states: \displaystyle\mathcal{S}_{\mathrm{spec}} \displaystyle=\{q_{\mathrm{struct}},q_{\mathrm{reason}}\}, (4) \displaystyle\mathcal{S}_{\mathrm{prot}} \displaystyle=\{q_{\mathrm{action}},q_{\mathrm{coord}},q_{\mathrm{param}}\}. (5) MobiInfer uses a learning-free n-gram drafting algorithm. To construct G , MobiInfer tokenizes the collected real-world agent-output sequences, assigns each token span to an automaton phase, and stores frequent next-token continuations for reasoning states. In addition to this offline table, MobiInfer maintains a trajectory-local n-gram cache from verified agent outputs produced earlier in the current task. Task-local entries are preferred over offline entries when both match the same suffix, and the cache is discarded at the end of the trajectory. During decoding, structure states propose fixed schema literals, such as field names and delimiters, as draft candidates. Reasoning states query G with the longest suffix of the committed output y to obtain a short candidate continuation. Protected states use target-only decoding; action labels and coordinates are always protected. If a draft would cross into a protected state, MobiInfer simulates it on a copy of \mathcal{A} and keeps only the longest safe prefix. For example, if a draft contains a reasoning suffix followed by the opening token of an action value, SafePrefix retains only the reasoning suffix and leaves the entire action value to target-only decoding. Algorithm 1 shows the joint decoding path. Verification evaluates the draft with the target model in one batched pass and commits only the longest matching prefix. Under greedy decoding, speculation preserves the output of the phase-specialized target policy; vocabulary specialization itself is approximate and may differ from full-vocabulary decoding. When no safe draft exists, MobiInfer falls back to one-token decoding. When outputs contain little recurring structure, the n-gram drafter may provide no useful continuation; MobiInfer then uses this fallback without changing the phase-specialized policy’s output.
