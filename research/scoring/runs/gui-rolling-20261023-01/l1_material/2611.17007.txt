title: Skill Adapter: Personalized Modification and Online Routing of General-Purpose Skills
source: https://arxiv.org/abs/2611.17007

§Abstract
Large language model (LLM) agents use external skills to reuse task procedures and experience with tools. General-purpose skills describe shared execution procedures, while specific tool choices, operating practices, and output requirements vary across users. In long-horizon tasks, subgoals, available inputs, and environmental states change as execution progresses. Agents must select currently applicable skills from an expanding skill pool and prepare candidates for subsequent steps. We propose Skill Adapter, which enables personalized modification and online routing of general-purpose skills. The system distills local adjustments from user requirements and execution feedback and stores them as Adapters linked to general-purpose skills. The routing agent selects general-purpose skills and applicable Adapters based on the current subtask, execution progress, and environmental feedback, incrementally maintaining a task-level online skill library that the main LLM reads on demand. The system preloads candidates for subsequent nodes and rechecks their applicability once actual inputs are determined. Reinforcement learning optimizes the two types of decisions using modification gains and routing outcomes, respectively. We evaluate Skill Adapter on ALFWorld, WebShop, and SkillsBench. Compared with SkillRL, it improves task success rates by an average of 11.43 percentage points and reduces mean execution time on all three benchmarks. Skill Adapter retains its performance advantage when the skill pool grows to 1,000 skills.

§Introduction (from cached fulltext; cut at ~9000 chars)
Large language model (LLM) agents are increasingly capable of planning, invoking tools, and interacting continuously with their environments. Their applications have expanded from single-turn question answering to web interaction, embodied decision-making, and complex workflows (Yao et al. 2023; Schick et al. 2023; Liu et al. 2023; Wu et al. 2023). In these tasks, organizing past experience into reusable skills helps reduce repeated exploration and improve the stability of long-horizon execution (Wang et al. 2023; Zhao et al. 2023; Shinn et al. 2023). Skill pools thus provide an external capability layer that connects task experience to agent execution. General-purpose skills describe shared procedures for a class of tasks, while specific execution procedures vary with user requirements. For example, when translating an English contract into a Chinese PDF, some users focus on the translated content, while others need to preserve the original pagination, layout, and annotations. Both sets of requirements involve document extraction, translation, and PDF generation, but differ in the fields to extract, tool parameters, and checks to perform. Personalized modification must express user-specific operating requirements within shared procedures. Online routing must select the general-purpose skills and applicable Adapters for the current subtask according to the execution state. Semantic matching between tasks and skills provides initial candidates, while actual inputs, tool availability, and execution feedback determine whether each candidate can be used at the current step. Subsequent steps in long-horizon tasks depend on the actual results of preceding operations. For example, contract layout reconstruction requires selecting a procedure based on the extracted layout information, and feedback from checking the generated output may introduce further processing requirements. Routing must therefore update skill provision as execution progresses, reusing valid entries and adding or replacing candidates. Growth of the global skill pool also increases the cost of retrieval and selection. To address these challenges, we propose Skill Adapter . The framework uses general-purpose skills as a shared foundation and stores user-specific modifications as Adapters linked to their original skills. Each Adapter describes applicability conditions and local adjustments to tools, parameters, operating steps, and output checks. As the task progresses, online routing selects general-purpose skills and their applicable Adapters and organizes the results into a task-level online skill library. The main LLM reads the skills needed for the current node on demand, while the routing agent prepares candidates for subsequent nodes and incrementally updates library entries in response to new inputs and feedback. We use group relative policy optimization (GRPO) to train the modification and routing policies. The modification policy receives rewards based on changes in task success rate, while the routing policy receives rewards based on task execution outcomes and the quality of skill selection. Our contributions are threefold: • We introduce a personalized modification mechanism for general-purpose skills that expresses user requirements through local Adapters and preserves their links to original skills and supporting feedback. • We introduce an online routing mechanism for long-horizon tasks that selects general-purpose skills and their Adapters according to the execution state, supporting continued execution through incremental updates to the online skill library and preloading for subsequent nodes. • On ALFWorld, WebShop, and SkillsBench, Skill Adapter achieves higher task success rates than all compared baselines. Compared with SkillRL, it improves success rates by an average of 11.43 percentage points and reduces mean execution time on all three benchmarks. Skill Adapter retains a success-rate advantage in the scaling experiment with 1,000 skills.

## Method
As shown in Figure 2 , Skill Adapter implements personalized modification and online routing over a shared pool of general-purpose skills, using reinforcement learning to optimize both types of decisions. Given a user u and a task q , the system represents the user’s explicitly stated preferences, operational requirements, and historical feedback through a personalization context P_{u} . At step t of a long-horizon task, the available context is x_{u,t}=\langle q,P_{u},h_{t}\rangle, (1) where h_{t} contains completed steps, current environment observations, and available intermediate results. The context P_{u} combines the current request with previously obtained information and is updated as user feedback arrives. Task-specific requirements are used for the current task, while preferences that generalize across tasks are used for subsequent adaptation. Personalized Modification General-Purpose Skills and Execution Evidence The system first constructs a general-purpose skill pool \mathcal{G} by extracting reusable task objectives, operation sequences, tool invocation procedures, and input and output constraints from historical trajectories. Existing skills can also serve directly as the shared foundation. Each general-purpose skill is represented as s_{i}=\langle n_{i},d_{i},c_{i},I_{i},O_{i}\rangle, (2) where n_{i} and d_{i} denote its name and functional description, c_{i} is its general execution procedure, and I_{i} and O_{i} specify input and output constraints. Skills are organized by topic and retain directed composition relations supported by successful trajectories, allowing candidate expansion during routing. The trajectory pool records tasks, personalization contexts, the skills and versions actually invoked, environment observations, and final feedback. A trajectory for user u is represented as \tau_{u}=\langle q,P_{u},\{e_{t}\}_{t=1}^{L_{\tau}},F,y\rangle, (3) where F denotes user feedback or environment diagnostics, and y denotes the task outcome. Each execution step e_{t} records the general-purpose skill ID, Adapter ID, environment action, and observation. The system distills general procedures that can be reused across tasks from trajectories and generates personalized modifications using execution evidence relevant to the current user’s requirements. Personalized Adapters For a general-purpose skill s_{i} , an Adapter for user u is defined as \displaystyle a_{u,i,k} \displaystyle=\langle i,p_{u,i,k},\Delta_{u,i,k},\kappa_{u,i,k}\rangle, (4) \displaystyle\widetilde{s}_{u,i,k} \displaystyle=\operatorname{Apply}(s_{i},\Delta_{u,i,k}). Here, i identifies the associated general-purpose skill, and k distinguishes the user’s adapted versions for different conditions. The term p_{u,i,k} describes the applicability conditions, \Delta_{u,i,k} is a local modification to the skill’s execution instructions, and \kappa_{u,i,k} stores usage records and associated feedback evidence. At execution time, the local modification is applied to the general procedure to obtain the personalized skill \widetilde{s}_{u,i,k} . Local modifications may concern tool selection, parameter settings, the addition or removal of steps, output formats, and verification requirements. For example, to meet a requirement to preserve the layout of a contract, an Adapter can add requirements to extract text positions, page numbers, and reading order to the general-purpose PDF extraction procedure. Let \mathcal{A}_{u} denote the set of Adapters for user u . Based on the general-purpose skill, personalization context, and relevant trajectories, the modification policy proposes an action to add, update, or delete an Adapter: \displaystyle m_{t} \displaystyle\sim\pi_{\mathrm{mod}}\!\left(\cdot\mid s_{i},P_{u},\mathcal{B}_{u,i},\mathcal{A}_{u}\right), (5) \displaystyle\mathcal{A}_{u}^{\prime} \displaystyle=\operatorname{Update}(\mathcal{A}_{u},m_{t}). Here, \mathcal{B}_{u,i} contains historical records relevant to the user’s requirements and skill s_{i} . The system distills reusable modifications from recurring deviations and applies them according to their applicability conditions. When the user’s requirements change, the corresponding Adapter is updated based on feedback. Adapters and general-purpose skills are stored separately, and the same general-purpose skill can be associated with adapted versions for multiple users. Online Routing Online Selection of Skills and Adapters Online routing continues throughout the execution of a long-horizon task. The main LLM decomposes the task into a directed acyclic graph (DAG) \mathcal{D} . The routing agent processes ready nodes according to the current execution progress and prepares candidate skills for subsequent nodes. For task node q_{j} at step t , the available context is x_{u,j,t}=\langle q_{j},P_{u},h_{t}\rangle . Based on the node’s objective and available intermediate results, the system retrieves a candidate set from the general-purpose skill pool: \mathcal{R}_{j,t}=\operatorname{Retrieve}(q_{j},h_{t},\mathcal{G}). (6) Retrieval uses topic-based search and semantic matching, followed by candidate expansion along skill composition relations. Each candidate skill is associated with its Adapters. The system filters these Adapters according to the current inputs, tool states, and applicability conditions to construct skill-version pairs: \displaystyle\mathcal{C}_{u,j,t}=\bigl\{(s_{i},a):s_{i}\in\mathcal{R}_{j,t}, (7) \displaystyle a\in\mathcal{A}_{u,i}(x_{u,j,t})\cup\{\varnothing\}\bigr\}. The symbol \varnothing denotes direct use of the general procedure. Candidate pairs must satisfy skill input requirements, tool availability, and task constraints. The online routing policy selects an ordered sequence of skill-Adapter pairs from the valid candidates: Z_{u,j,t}\sim\pi_{\mathrm{route}}\!\left(\cdot\mid x_{u,j,t},\mathcal{C}_{u,j,t}\right). (8) Online routing combines user preferences, historical feedback, and the current execution state to select general-purpose skills and their associated Adapters. When the general procedure satisfies the current requirements, routing can use it directly. As task inputs or environment states change, routing can rematch the skill with an Adapter or select other general-purpose skills and their adapted versions. Incremental Maintenance of the Online Skill Library Routing results are written to the task-level online skill library \mathcal{L}_{u,q,t} . Each entry stores a reference to the general-purpose skill, the selected Adapter, applicable nodes, composition relations, and usage guidance. The library is updated as follows: \displaystyle\mathcal{L}_{u,q,t+1}={} \displaystyle\operatorname{Refresh}\!\bigl(\mathcal{L}_{u,q,t},Z_{u,j,t}, (9) \displaystyle E_{u,j,t}^{\mathrm{comp}},U_{u,j,t},x_{u,j,t}\bigr). Here, E_{u,j,t}^{\mathrm{comp}} denotes valid input-output connections within the current skill composition, and U_{u,j,t} denotes node-level usage guidance. During initialization, the routing agent creates entries for the first ready nodes in the DAG. The main LLM reads the skills and Adapters required by the current node and executes them, while the routing agent preloads candidates for subsequent nodes. Based on execution feedback, the system reuses applicable entries, removes or replaces invalid entries, and retrieves skills and reselects Adapters for new requirements. For subsequent nodes that depend on upstream results, the system prepares candidates in advance, then checks applicability conditions and completes selection once the actual inputs are determined. The main LLM returns environment actions, execution observations, and the IDs of the skills and Adapters actually used, providing state information for the next routing round. After the task is completed, its trajectory and feedback support subsequent learning, and user Adapters can be reused in later tasks. Reinforcement Learning Optimization Objective Personalized modification produces skill versions that satisfy specific requirements, while online routing determines the skills and Adapters to use at each step according to the execution state. We use GRPO to train \pi_{\mathrm{mod}} and \pi_{\mathrm{route}} separately. For the same input, we sample K candidate decisions and compute group-relative advantages from their rewards: \widehat{A}_{k}=\frac{R_{k}-\operatorname{Mean}(\{R_{l}\}_{l=1}^{K})}{\operatorname{Std}(\{R_{l}\}_{l=1}^{K})+\epsilon}. (10) Both policies are updated using the following objective: \displaystyle J(\theta)={} \displaystyle\mathbb{E}\Biggl[\frac{1}{K}\sum_{k=1}^{K}\min\Bigl(\rho_{k}(\theta)\widehat{A}_{k}, (11) \displaystyle\operatorname{clip}\bigl(\rho_{k}(\theta),1-\epsilon_{c}, \displaystyle 1+\epsilon_{c}\bigr)\widehat{A}_{k}\Bigr) \displaystyle-\beta_{\mathrm{KL}}D_{\mathrm{KL}}(\pi_{\theta}\|\pi_{\mathrm{ref}})\Biggr]. Here, \rho_{k}(\theta) is the ratio of the current policy’s probability of a candidate decision to that of the old policy, \epsilon_{c} is the clipping coefficient, and \pi_{\mathrm{ref}} is the reference policy. The main LLM remains frozen during policy training. Reward for Personalized Modification The modification policy uses a set of trajectories to propose candidate Adapter updates and evaluates their effects on a held-out task set \mathcal{Q}_{u}^{\mathrm{eval}} . The general-purpose skill pool, user conditions, executor, and routing configuration are kept identical before and after modification. The modification reward is defined as the change in task success rate in percentage points: \displaystyle R^{\mathrm{mod}}=100\Bigl[ \displaystyle\operatorname{SR}\!\bigl(\mathcal{Q}_{u}^{\mathrm{eval}};\mathcal{G},\mathcal{A}_{u}^{\prime}\bigr) (12) \displaystyle-\operatorname{SR}\!\bigl(\mathcal{Q}_{u}^{\mathrm{eval}};\mathcal{G},\mathcal{A}_{u}\bigr)\Bigr]. The modification policy generates candidates from historical trajectories and evaluates execution outcomes using the requirements and feedback of the held-out tasks. Modifications that increase task success rate receive positive rewards, while those that decrease it receive negative rewards. Reward for Online Routing After training the modification policy, we train the routing policy with the current general-purpose skill pool and Adapter set. The routing action Z_{u,j,t} is provided to the main LLM through the online skill library, and the task outcome y_{j} is obtained after execution is complete.
