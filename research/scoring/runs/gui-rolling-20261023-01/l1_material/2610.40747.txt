§Abstract
Effective computer-use agents (CUAs) should seamlessly combine visual GUI interaction with code and terminal execution within a single policy. We present Mage-VL-Cowork, a 4B hybrid CUA trained from a general multimodally aligned checkpoint through an end-to-end, progressive five-stage curriculum across midtraining, SFT, and RL. To power this curriculum at scale, Mage-CUA-Forge replaces per-task agent construction with reusable, skill-conditioned generation workflows and application-specific preparers, synthesizing 293,806 desktop and web tasks across 6,915 skills while reducing recurring per-task expenditure by 82.6%. Rather than directly distilling a default teacher, we evolve the teacher harness and instantiate specialized CUA harnesses to yield high-quality trajectories alongside stage-specific supervision. Mage-VL-Cowork-4B finally climbs to 66.0% on OSWorld-Verified through different training stages with more efficient reasoning cost, achieving state-of-the-art performance at its parameter size and pushing forward the frontier of on-device intelligence.

§Introduction (from cached fulltext; cut at ~9000 chars)
Computer-use agents (CUAs) for productivity perceive graphical desktops through screenshots and act through keyboard and mouse commands. This GUI channel is universal, but it is a modeling choice rather than a property of the domain, and an expensive one: a typical screenshot can require thousands of tokens, increasing the cost of processing high-resolution visual input and grounding interface elements. A person fluent with a computer does not confine themselves to the mouse: they open a terminal when a terminal is faster and read a file to confirm what a dialog claims to have saved. Restricting the policy to pixels forces it to re-derive through the GUI what a single command would accomplish, and removes the most reliable channel it has for checking its own work. We therefore train a hybrid CUA that acts through two action channels: the GUI channel, with visual observation and coordinate control, and the terminal channel, a persistent shell environment in which it may run code, invoke command-line utilities, and call application libraries directly. Hybrid access does not by itself produce hybrid competence, even for frontier teachers. Prior work shows that access to application tools does not ensure their effective use, and that the same tool set can affect different models differently [ 1 , 2 ] . The policy must learn which channel is appropriate for the current operation and at what level of abstraction to act. Effective hybrid execution routes each operation to the channel where it fits best: coding and terminal execution for structured files (such as updating a spreadsheet with one library call rather than dozens of clicks), and GUI interaction for visual or live application state (such as browser settings that a running browser caches in memory and overwrites on exit). Because even frontier models exhibit suboptimal channel routing under a naive setup, distilling their default rollouts passes those same limits on to the student. The harness is not a neutral container: its tool interfaces, context handling, and guidance directly shape how a fixed teacher model acts. Evolving the harness before large-scale rollout elicits stronger hybrid execution than the teacher achieves by default and carries those improvements across the entire training corpus. Moreover, whereas existing pipelines such as ProCUA and ScaleCUA [ 3 , 4 ] post-train models that already have strong grounding, coding, and agent capabilities, we present an end-to-end, progressive five-stage curriculum starting from a general multimodally aligned checkpoint: GUI-oriented midtraining, GUI agent SFT, coding and terminal SFT, hybrid CUA SFT, and online hybrid RL. Sustaining such a multi-stage curriculum requires massive, diverse training environments and trajectories, for which we propose the Mage-CUA-Forge environment synthesis pipeline. Unlike prior agent-first approaches that rely on open-ended agent execution to construct each task from scratch, Mage-CUA-Forge uses an authoring agent to construct application-specific preparers and reusable generation workflows tailored to each application and its atomic functionalities, scaling task and environment synthesis with high consistency and low recurring cost. We introduce Mage-VL-Cowork, a hybrid CUA trained on 318,837 teacher trajectories over 293,806 synthesized tasks and environments that cover 6,915 atomic skills in an agent-constructed skill taxonomy. Three design decisions define the pipeline: 1. Learning from an evolved hybrid CUA harness. To collect high-quality demonstrations even when a frontier teacher’s default channel routing is imperfect, we evolve the harness including its scaffold, tool interfaces, prompts, and terminal execution environment, before large-scale rollout. Evolution here is as much pruning as growth: unlike skill libraries that continuously accumulate tools [ 5 , 6 , 7 ] , we remove overlapping or ill-suited tools so the teacher produces clean hybrid trajectories that yield much larger gains when distilled into the student (§ 3.1 , § 6.7 ). Moreover, harness evolution produces specialized configurations with different tool sets—including a GUI harness, a terminal harness, and the hybrid CUA harness—allowing us to roll out the same synthesized tasks under multiple harnesses to collect trajectories emphasizing distinct capabilities across our training stages (§ 4 ). 2. A single policy that learns the hybrid execution policy. Mage-VL-Cowork observes full-desktop screenshots and emits coordinate mouse and keyboard actions, and in the same episode may execute code and terminal commands on the machine it is operating. The two channels are complementary: pixels are the only channel that reaches spatial, canvas, and rendering-dependent state, while code edits at the abstraction the instruction is written in and lets the agent check its work against ground truth rather than against a screenshot of a dialog. ## Synthesized Data Generation for Hybrid Computer Use
We construct supervised fine-tuning data through a pipeline that combines a skill taxonomy \mathcal{S} , reusable generation workflows W , and an evolved hybrid computer-use harness H . Each skill describes an atomic capability in a specific application. We sample several skills to form a composite capability and combine their workflows to generate a task instruction, an environment setup script, and an evaluation rubric. Executing the setup script prepares a sandbox with the preconditions needed to attempt the task. A teacher agent, whose harness is optimized before large-scale trajectory collection, then executes the task. Rubric-based LLM judging and trajectory-quality filtering produce the retained trajectory dataset \mathcal{D} , which is used to train the student model M . Student performance feedback guides adaptive expansion and refinement of the skill taxonomy across generation rounds. Figure 2 gives an overview of the pipeline. We first describe teacher-agent evolution, then workflow-first generation, and finally the taxonomy feedback loop. Evolution of the Hybrid Computer-Use Harness Collecting high-quality hybrid trajectories requires more than a strong frontier model: the teacher must also select, sequence, and combine GUI actions and terminal commands effectively, a strategy we call the hybrid execution policy . Under a standard setup, even frontier models show suboptimal channel habits—such as clicking through repetitive file edits or modifying files on disk that a running application caches in memory. Distilling directly from such rollouts passes the teacher’s default limitations on to the student. We improve the teacher’s hybrid execution by evolving its external harness while keeping the underlying model weights fixed. We write the teacher agent as A_{T}=(M_{T},H),\qquad H=(F,\mathcal{T},P,\mathcal{E}), (1) where M_{T} is the teacher model and the harness H consists of four components. The scaffold F organizes the execution loop and context handling. The tool interface \mathcal{T} exposes the actions of each action channel—GUI mouse and keyboard actions and terminal commands—together with their argument schemas. The prompt P , i.e., the system prompt, guides tool use and the hybrid execution policy. The terminal execution environment \mathcal{E} comprises the command-line utilities and application libraries preinstalled in the Docker sandbox and accessible through the terminal channel. Operational deployments require explicit authorization and sandbox isolation for terminal execution. Harness evolution optimizes F , \mathcal{T} , P , and \mathcal{E} on a shared development set. An authoring agent uses rubric-based task success, per-task token cost, execution feedback, and application-level channel statistics to select revisions that improve the success–cost trade-off. Harness evolution includes removing redundant tools as well as adding useful ones. Removing xdotool in favor of native screenshot-grounded GUI actions avoids duplicate mouse/keyboard routes and fragile window-focus handling that would split supervision across unequal choices. Conversely, providing domain libraries such as python-pptx in the terminal environment lets the teacher operate directly on slides, shapes, and text runs rather than manually editing unpacked OOXML files. The GUI-and-coding variant achieves higher task success with fewer execution steps than its AX-augmented counterpart; as shown in Section 6.7 , this advantage widens into a 12.5-percentage-point gain when distilled into the 4B student. This comparison guides joint optimization of the tool interface and prompt for effective hybrid execution. Figure 3 presents selected teacher–harness configurations across channel, scaffold, teacher-model, and prompt refinements. Once selected, the harness remains essentially fixed across subsequent data-generation rounds. We use gpt-5.6-terra as the rubric judge to verify task completion, while a trajectory-quality filter retains demonstrations with clean channel routing and tool use. Optimizing the harness before large-scale rollout ensures that \mathcal{D} captures strong hybrid execution for training M (Section 4 ). Workflow-First Task and Environment Generation A computer-use task package combines an instruction, an executable environment setup, and an evaluation rubric. Workflow-first generation reuses the construction procedure for these three coordinated components across task instances. Mage-CUA-Forge builds a reusable generation workflow for each atomic skill. Each workflow combines LLM nodes, file preparers, and setup operations. For a composite capability, the workflows share a unified specification of the requested outcome, required files, and application preconditions, producing a coordinated task package. The source-file and setup-script branches share the task specification. Branch-specific checks feed a final consistency gate over the complete task package. The workflow routes each required file to a preparer appropriate for its type, reusing application-specific preparation logic across skill workflows. These preparers materialize the input artifacts needed by the task. Other workflow nodes produce the remaining setup code and combine it with shared setup utilities, such as application launching and desktop-state adjustment. The result is an environment setup script ( env setup script ), whose purpose is to establish the required task preconditions and initial desktop state inside the sandbox. Workflow-specific generation logic is thus separated from reusable file and application preparation, as well as from generic setup operations that are not tied to an individual skill. Dedicated LLM nodes generate the user instruction and its evaluation rubric from the shared specification. Task completion is judged by an LLM against this rubric. Application setup details remain in the setup script, while the instruction describes the user’s intended outcome. Validation operates at two levels. File-level gates check artifacts against the shared specification, and a package-level gate checks consistency among the instruction, setup requirements, and rubric. Gate feedback improves the reusable workflow and shared preparers. Subsequent trajectory evaluation assesses the teacher’s execution of accepted tasks. Workflow reuse separates one-time construction from recurring generation. LLM nodes supply task-specific content within an established procedure, while shared preparers provide reusable file and application setup logic across skills and task instances. For browser and cross-application workflows, such as retrieving structured records from a website and compiling them into a spreadsheet or document, live websites introduce anti-bot blocks, content drift, and non-resettable backend state. We therefore pair desktop application preparers with self-hosted, deterministic web environments combining synthesized InfiniteWeb [ 19 ] sites and high-fidelity website replicas built upon and extending WebHarbor [ 20 ] , where each replica resets from a local seed database per episode to support verifiable web and cross-application task generation (Appendix A.1 ). Iterative Skill Taxonomy Expansion and Refinement An exploration agent builds the initial skill taxonomy \mathcal{S} by traversing desktop applications and recording their atomic skills. Rather than keeping \mathcal{S} fixed, we refine and expand it across generation rounds using feedback from student evaluations, adjusting skill granularity, enriching descriptions, and adding application-specific variations where needed. The first generation round balances task coverage across atomic skills. Composite capabilities instantiate these skills through their workflows; teacher collection and filtering produce the supervision used to train M . Student evaluation identifies capability areas that need denser coverage in the next round. We add or refine the corresponding skill entries in \mathcal{S} , update their workflows, and generate additional tasks and teacher trajectories. Keeping the evolved harness fixed while expanding \mathcal{S} across three rounds cleanly separates improving how the teacher executes tasks from improving which tasks the pipeline supplies . Dataset Statistics Mage-CUA-Forge produces 293,806 distinct tasks covering 6,915 atomic skills. Single-application and multi-application tasks account for 61.76% and 38.24%, respectively. Teacher execution and quality filtering yield 318,837 retained trajectories. The task inventory contains 877,608 task–file references, counted as distinct extracted paths or filenames within each task. Selected reference families include coding (136,736), spreadsheets (135,805), text or Markdown (134,050), documents (74,052), PDFs (53,996), and presentations (93,784). File references occur in 266,030 tasks (90.5%), averaging 2.99 references per task. The inventory spans 278 suffix categories: 277 named suffixes and one no-extension category. Figure 4 summarizes application involvement and reference families; Appendix A defines the counting rules. These synthesized tasks are rolled out under different harness configurations, including the GUI harness, the terminal harness, and the evolved hybrid CUA harness, to collect trajectory data that solve the tasks through different channels and emphasize distinct capabilities for the subsequent training stages described in Section 4 . Moreover, we also synthesize the reasoning content before tool call with a multi-stage annotation by GPT-5.4-mini. Within the retained hybrid CUA dataset \mathcal{D} , supervision covers both execution channels: GUI and terminal actions account for 68.19% and 31.81% of teacher tool calls, respectively.
