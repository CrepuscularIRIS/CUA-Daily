title: Trace2World: Reconstructing App Worlds from Real Interaction Traces for Scalable GUI Agent Training
source: https://arxiv.org/abs/2610.30792

§Abstract
Scaling GUI reinforcement learning requires environments that preserve real-app behavior. Yet coupling behavior inference with coding can turn partial traces into runnable mocks with incorrect state transitions. We introduce \textbf{Trace2World}, which separates global behavior reconstruction from implementation. It reconciles traces into a shared, source-linked app model, then compiles an executable environment. Independent replay of source workflows localizes mismatches for bounded implementation repair. Validated worlds then support learner-adaptive task and environment augmentation within source-supported behavior. From 1,570 traces, Trace2World constructs 50 environments. On 200 workflows across ten apps, 91.1% are reproduced end to end, versus 59.8% for the strongest matched task-local baseline. Source-grounded validation retains 94.0% of simulated training gains on real devices, versus 54.7% under self-validation. Learner guidance raises benchmark success from 56.9% to 61.1%. Training in Trace2World further improves the model by 20.2 points on our benchmark, 5.4--16.2 points across four external GUI benchmarks, and 16.3 points on 100 real-device tasks. Reliable reconstruction separates what behavior source evidence supports from whether the implementation preserves it.

§Introduction (from cached fulltext; cut at ~9000 chars)
Online reinforcement learning improves GUI agents through repeated interaction ( Bai et al., 2024 ; Qi et al., 2025 ; Qin et al., 2025 ; Xu et al., 2025 ) . Real apps are hard to reset, and exploratory actions can change remote state or commit transactions ( Rawles et al., 2025 ; Xie et al., 2024 ; Kong et al., 2026 ; Yan et al., 2025 ) . Simulators offer controlled starts, yet training value depends on transfer: visual ( Rusu et al., 2017 ) or dynamics ( Peng et al., 2018 ) gaps can break learned policies. For pixel-based GUI agents, these gaps lie in what the policy sees and what its actions do, so we use fidelity to mean preserving the source app’s task-relevant observations and action semantics, including state, data, intermediate effects, and outcomes, not only its look or final value. Obtaining faithful environments at scale, however, remains difficult. MobileGym authors app behavior by hand ( Wu et al., 2026 ) . Coding agents reduce this manual work, and every existing route hands them the semantics as well: CUA-Gym codes mocks from topic specifications ( Wang et al., 2026 ) , GUI-GENESIS codes a task-local site from one trace ( Cao et al., 2026 ) , and PhoneWorld, in concurrent work, codes reusable Android pages from frequency-ranked screen types, consecutive-screen transitions, and page specifications written from two or three screenshots, then checks representative flows with human QA ( Liu et al., 2026 ) . None asks which shared identities, initial states, data, guards, or conflicting effects the traces support: the coding agent settles them while writing the mock, and builder tests or a human comparison of representative flows then close fidelity. Reconstruction reduced to implementation fails on the app’s own workflows even at the level of structure: on the same recordings, our matched PhoneWorld-style build preserves source page surfaces on only 39.3% of workflows, 1.8 pp above a topic-specification builder (Table 1 ). Automating code has not settled which app behavior the code may commit to, and two failures follow. Partial paths do not define the app. Each trace exposes only one path from one initial state ( Rawles et al., 2023 ; Deng et al., 2023 ) : Home screens showing Xi’an and Beijing may be two pages or one page in two city states, while one control can have state-dependent effects (Section 3.2 ). A page-transition graph records what was observed, not the state condition that explains it, so coding before reconciliation hardens one interpretation into the app. Across our matched builds of this family, routes reach 50.4–94.8% of endpoints yet preserve only 16.7–59.8% of source workflows (Table 1 ; Figure 1 a and Appendix F.1 ). Passing tests do not establish fidelity. An implementation and the tests derived from the same interpretation can agree while both diverge from the source ( Barr et al., 2015 ) . In Meituan, tapping Disable quick pay opens a confirmation without changing the saved setting; our PhoneWorld-style reconstruction disables it immediately yet passes a final-value check (Figure 2 ), rewarding a policy for a transition the real app does not perform. Thus the terminal value alone cannot show that the workflow matches the source. Both failures arise when an ambiguous page identity, state value, or action effect becomes a coding choice before the traces are reconciled or an independent check can contest it. The remaining challenge is therefore not a better coding loop but a question no existing route poses: Which app semantics do partial traces actually support, and what evidence may accept an implementation of them? Trace2World answers with two boundaries, semantic commitment before implementation and source acceptance afterward : it resolves open-ended app semantics before construction, then reduces later failures to local repair over a concrete package. It first reconciles repeated observations into shared page and entity identities, then separates mutable state, reusable data, and task-specific initial values. When observed state explains different effects, the model records a conditional rule; otherwise the conflict remains unresolved and outside executable scope. Because every supported relation keeps its source links, additional traces widen supported behavior without admitting unsupported shortcuts (Figure 3 ). Bounded API calls then compile the fixed model into an initial browser environment per app. Code checks and independent replay of each original workflow compare information, intermediate effects, and terminal state with the source and only report defects; a bounded repair loop edits the package under the frozen model, and a workflow that cannot pass without changing the model is excluded. Finally, learner feedback guides task composition from a read-only index of the validated world: it changes what is practiced or instantiates supported behavior, but never redefines what the app means.
