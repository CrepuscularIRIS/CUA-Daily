title: From Code to Playable Systems: CEGame-Bench for Long-Horizon Game Creation Agents
source: https://arxiv.org/abs/2610.26098

§Abstract
A game ships when a player can launch it, finish it, and return to a saved world, none of which a successful build guarantees, yet game-creation agents are mostly tested on one engine or on one-prompt browser games. We present CEGame-Bench, the first long-horizon benchmark for complete-game creation across five production engines: Defold, Godot, Roblox Studio, Unity, and Unreal Engine. Agents build each game from an empty project and a design document in runs averaging up to 295 steps and 65M tokens; the document doubles as a contract, and a hidden evaluator accepts a game only by real-input play. Under four scaffolds, agents earn most integration points but usually under half the gameplay points, and their games reach the ending in only 16% of runs, while references built by engineers with coding agents score near the maximum, which places this artifact-to-play gap in the agents. No two engines rank configurations alike (Kendall's tau 0.14-0.62), and the same game usually scores higher on Unity and Unreal Engine, which check more before play. We release Game Completion Boost, an agent skill for requirement-driven playtesting and repair that raises the execution-based score of three models by 14.1-24.3 points.

§Introduction (from cached fulltext; cut at ~9000 chars)
In a game studio, a build ships only after QA plays it to the ending, quits, and finds the save intact. Coding agents are often shown on one-prompt browser games ( Jiang et al., 2026b ) , which rarely test what makes a game complete: interdependent parts, where a combat fix must not break restart. We call the distance between a build and a playable game the artifact-to-play gap (Figure 1 ). Beyond entertainment, Unity and Unreal Engine, the most demanding engines to drive, power industrial 3D applications ( La et al., 2026 ) and embodied-AI simulators ( Zhong et al., 2025 ) that coding agents have begun to build ( Kang et al., 2026 ) ; making games on them is a step toward building such worlds from specifications. Because studios choose an engine per project, a benchmark must span engines to distinguish game-making skill from fluency in one toolchain. Existing benchmarks each cover one slice: scoped edits to Godot and Unreal projects ( Chi et al., 2026 ; La et al., 2026 ) , browser games ( Jiang et al., 2026b ; Zhang et al., 2026a ; Zhang et al., 2026b ) , Godot-to-Unity ports ( Chen et al., 2026c ) , or whole games on a single engine ( Luo et al., 2026 ; Yin et al., 2026 ) . None asks an agent to turn an empty project into a complete game on several production engines, Unity and Unreal Engine included, or judges all engines by the same rules (Table 1 ). We introduce C ross- E ngine Game Bench ( CEGame-Bench ), which holds every engine to one execution-based standard. Its 50 tasks are studio handoffs, ten on each of five production engines, from script-centric Defold, Godot, and Roblox Studio to heavyweight Unity and Unreal Engine. In each task, the agent builds a complete game from an empty project and a design document in a fully logged run. The document is a natural-language contract of checkable rules and a required state interface, so one hidden evaluator accepts any implementation on any engine only by playing it with real input. The gap is large. Autonomous agents earn most integration points but usually under half the gameplay points, and their games reach the ending in only 16% of runs, while references built by engineers with coding agents score near the maximum. The engine is a first-class variable: no two engines rank configurations alike (Kendall’s \tau 0.14–0.62), and the same game scores higher on the heavyweight engine in five of six engine pairs, by up to 21.5 points, in line with its stricter checks before play. Nor does effort close the gap: nine in ten runs deliver before the time limit, and neither steps nor tokens track the score. These failures motivate Game Completion Boost (GCB), a lightweight agent skill that maps requirements to player checkpoints, compares state with visible outcomes, and replays affected paths after repair. On high-difficulty games from each track, GCB raises the execution-based F of three models under Codex CLI by 14.1–24.3 points and their overall score by 14.7–25.8. We contribute (i) CEGame-Bench , the first long-horizon benchmark for complete-game creation on five production engines, with controlled engine variation; (ii) a contract-driven evaluation that turns a natural-language design document into executable checks, accepts a game only by play, and logs its construction; and (iii) a cross-engine study of six frontier models under four scaffolds, motivating reusable GCB.
