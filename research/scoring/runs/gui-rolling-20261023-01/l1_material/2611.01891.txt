arxiv: 2611.01891 (2611.01891v1)
title: Interface Quilt: Modifying Applications with Computer Use Agents and Generative UI
source: https://arxiv.org/abs/2611.01891

§Abstract
Modifying an existing application is difficult when it does not provide programmatic access for that change. Recent advances in computer-use agents (CUAs) enable richer understanding and operation of existing interfaces, while generative UI (GenUI) makes it practical to generate new ones. We examine how these advances expand software modification through a design space of what can be changed and a framework for how modifications can be implemented. We then introduce Interface Quilt, a system that combines CUAs and GenUI to generate interface patches, which are new interfaces displayed over an existing application to modify its presentation, interaction, and capabilities. Through demonstrations across a variety of applications, we show that interface patches support a range of modifications without source code, APIs, or accessibility data.

§Introduction (from cached fulltext; cut at ~9000 chars)
Software today is typically designed to be able to satisfy most users’ needs most of the time, but it rarely fits how all users work all of the time. One may want to hide or surface controls based on their tasks, replace one interaction technique with another, or make use of the powerful capabilities locked away by professional software without learning the complex interface. This vision of software reshaped for individual users has long been a pursuit of HCI research ( Kay and Goldberg, 1977 ; Stallman, 1981 ; MacLean et al., 1990 ; Henderson and Kyng, 2020 ) . Prior approaches to achieving this were through customization and tailoring ( MacLean et al., 1990 ; Page et al., 1996 ; Myers, 1998 ; Cook, 2007 ) , adaptive and adaptable interfaces ( Findlater and McGrenere, 2004 ; Gajos and Weld, 2004 ; Todi et al., 2021 ) , end-user programming and development ( Nardi, 1993 ; Lieberman et al., 2006 ; Ko et al., 2011 ) , meta-design ( Fischer et al., 2004 ) , and malleable software ( Klokmose et al., 2015 ; Rädle et al., 2017 ; Borowski et al., 2022 ; Litt et al., 2025 ; Beaudouin-Lafon, 2023 ; Mackay and Beaudouin-Lafon, 2025 ) . In this work, we use modification broadly to describe any departure from the software shipped, including changes to what a user perceives (presentation), how they interact (interaction), or what they can do with it (capability). The term follows communities such as game modders and hardware hackers, who alter, extend and retrofit artifacts beyond what their maker anticipated ( Thiel and Lyle, 2019 ; Paul and Mandryk, 2026 ; Tanenbaum et al., 2013 ; Hurst and Tobias, 2011 ; Ramakers et al., 2016 ) , as well as designers who repurpose existing applications and devices as prototyping tools for new behaviours ( Hartmann et al., 2006 ; Ledo et al., 2019 ) . Prior modification efforts largely rely on adapting the software through programmatic access pathways provided by the developer, such as scripts, plugins, APIs, or source code. These pathways can limit the extent to which a modification can be applied. Modifying an application without developer support can be more difficult, but it is not impossible. Prior HCI systems have used pathways not designed for modification, ranging from websites’ DOM ( Bolin et al., 2005 ; Nichols et al., 2008 ; Zhang and Guo, 2018 ) , operating system (OS) window APIs ( Stuerzlinger et al., 2006 ; Tan et al., 2004 ) , accessibility APIs ( Zhang et al., 2017 ; Li et al., 2017 ; Lu et al., 2024c ) , to runtime code injection to specific application frameworks ( Eagan et al., 2011 ; Meng et al., 2014 ) . However, not all applications provide these pathways, and there have been various systems that use the graphical user interface (GUI) directly and pixel-based techniques to modify applications. Systems such as Prefab add advanced interaction techniques by identifying common UI elements ( Dixon and Fogarty, 2010 ; Dixon et al., 2011 ; Dixon, 2013 ) and Sikuli provided interface scripting through icons ( Yeh et al., 2009 ) . These systems demonstrate that interface structure and actions can be recovered without source-code access. However, these techniques require custom-authored models and templates targeting specific UI toolkits, limiting their applicability. Recent advances in UI understanding ( Zhang et al., 2021 ; Wu et al., 2021 ; Lu et al., 2024a ; You et al., 2024 ) and computer-use agents (CUAs) ( Agashe et al., 2024 ; Zhang et al., 2025b ; Qin et al., 2025 ) make it possible to recover richer structure and semantics from rendered interfaces and act through them. At the same time, advances in generative UI (GenUI) ( Wu et al., 2024 ; Chen et al., 2025b ; Leviathan et al., 2026 ; Cao et al., 2025 ; Chen et al., 2025a ) make it increasingly practical to generate new interactive surfaces. To understand how these capabilities expand software modification, we first develop a design space that characterizes what a modification can change, including changes enabled by CUAs and GenUI to how users perceive and interact with existing software. We then develop a framework for how modifications are achieved, characterizing both the access a modifying system has to an application and the level of synchronization between the modifying system and the target application. Together, the design space and framework help us examine what is possible when modifying applications that reveal rendered pixel data alone. We introduce Interface Quilt, a system for modifying existing applications by generating and running interface patches : generated interfaces that change an application’s presentation, interaction, or capabilities while leaving the application itself unchanged. At build time, Interface Quilt provides a harness for computer-use agents to explore the target application, inspect its interface state, and discover the controls needed for a modification.
