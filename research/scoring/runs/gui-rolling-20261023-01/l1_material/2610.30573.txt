title: Diagnosing Personalization Failures in Mobile GUI Agents
source: https://arxiv.org/abs/2610.30573

§Abstract
Unlike conventional GUI agents, personalized GUI agents require user preferences to guide sequential execution over changing GUI states. This raises two challenges: determining HOW each preference should alter execution strategy and WHEN it should take effect along the interaction trajectory. Existing benchmarks primarily evaluate overall task success, offering limited insight into these questions. We introduce PrefDiag-Bench with two components: (1) a categorization of preferences into five types, characterizing HOW they affect execution; and (2) a stage-wise diagnostic framework with 1,664 probes, tracing WHEN preferences should take effect and where failures occur. We evaluate eleven GUI agent systems, including end-to-end agents and agentic workflows, under two forms of user context: explicit user profiles and behavioral memory logs. Although existing agents achieve relatively high completion rates on non-personalized tasks, performance is substantially lower on preference-personalized tasks. Even the best-performing model, Seed-2.0-Pro, achieves only 47.17% on Process preferences under explicit user profiles. Agents struggle particularly with Ranking and Process preferences. Further analysis reveals two key capability bottlenecks: selecting relevant evidence from user history and recognizing when preferences should take effect during execution. Controlled interventions that explicitly provide relevant evidence improve end-to-end task success by up to 7.06%. PrefDiag-Bench offers a more systematic evaluation of GUI agents' personalization capabilities beyond overall task success. Code and data are available at https://github.com/Zhixin-L/PrefDiag-Bench.

§Introduction (from cached fulltext; cut at ~9000 chars)
Recent mobile GUI agents powered by large language models (LLMs) have made substantial progress in GUI perception, task planning, and task execution in real-world applications, bringing them closer to personalized assistants. In such a personalization setting, simply completing a user request is no longer sufficient; agents also are required to draw on users’ past behavior, habits, and preferences to make decisions that meet individual needs during execution. For example, for the same base task “order a milk tea according to my usual preferences and add it to the cart” the agent may need to select the preferred drink options, satisfy a price constraint, prioritize a store with faster delivery, or compare multiple candidates. Therefore, the same GUI task may impose different execution requirements under different user preferences. The example above highlights two challenges for personalized GUI agents. First, an agent is required to determine HOW each preference should alter execution: it may change the desired outcome, restrict valid choices, change candidate priorities, or constrain the execution process or interaction behavior. Second, the agent is required to determine WHEN a preference should take effect along the interaction trajectory, based on the current task and GUI state. Figure 1 illustrates these two complementary challenges: preferences impose distinct execution requirements, while a task-relevant preference should only be applied when its trigger state is reached. These challenges require evaluation beyond task completion. A benchmark should assess whether an agent can determine HOW a preference should alter execution and WHEN it should take effect, while also identifying where failures arise along the path from user context to GUI actions. Existing evaluations centered on task-level success or preference-sensitive progress provide limited information about this process. To address these challenges from a data-centric perspective, we introduce PrefDiag-Bench, a fine-grained diagnostic benchmark for personalized GUI agents. PrefDiag-Bench contains two complementary components corresponding to the challenges above. First, while the benchmark spans diverse application domains, including shopping, workflow, and transportation, its main evaluation axis is the primary effect of each preference on agent execution. We organize user preferences into five execution-oriented types, i.e. , Outcome, Constraint, Ranking, Process, and Interaction—characterizing HOW they affect agent execution, and construct corresponding end-to-end tasks to compare agents under different execution requirements. Second, we develop a stage-wise diagnostic framework that covers three high-level phases, i.e. , information processing, contextual reasoning, and action formulation, and further divides them into five diagnostic stages. The framework probes the capabilities required to apply preferences from user context to GUI actions, including recognizing WHEN a preference should take effect, and identifies capability bottlenecks arise during personalized execution. Based on this design, PrefDiag-Bench contains 318 end-to-end GUI tasks and 1,664 associated diagnostic probes. Each end-to-end task is paired with a set of diagnostic probes built around the same underlying preference instance. This paired design allows us not only to evaluate whether an agent completes the task while satisfying the user’s preference in an interactive GUI environment, but also to connect end-to-end performance with specific diagnostic stages. In addition, we construct explicit user profiles and behavioral memory logs as two user-context representations at different levels of abstraction, enabling us to study how the form of user context affects personalized execution. Experimentally, we systematically evaluate 11 existing popular personalized GUI agentic designs, including nine end-to-end agents and two agentic workflows, M3A and T3A, using explicit user profiles and behavioral memory logs. Our results indicate three main findings. First, performance varies substantially across the five preference types, showing that collapsing performance across preference types into a single aggregate score can obscure important capability differences. Second, explicit user profiles do not consistently outperform behavioral memory logs, suggesting that compact preference summaries are not always more useful than logs that retain concrete behavioral evidence. Third, selecting relevant evidence from user history and recognizing when preferences should take effect emerge as the two main bottlenecks. Controlled interventions on a representative subset of systems further show that explicit evidence guidance improves end-to-end task success by up to 7.06 percentage points, demonstrating that evidence selection has a measurable impact on personalized execution and provides a concrete target for system improvement.
