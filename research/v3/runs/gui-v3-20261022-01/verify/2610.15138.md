## 发现的细节(非 Sol 错误)

- 模型侧指令防御(§VI-E):role-neutral 页面 7/10 攻击仍完成,role-labelled 页面 1/10;两版页面差异不止一个因素,作者自己说明不能单独归因。Sol 未写进 evidence,但不影响核心结论。
- 注入措辞/位置会改变成功率(§VI-G:换措辞后 Haiku 4/10,gpt-5.4 0/10);主实验测的是"直接、可见"的注入。画报不能把 73/73 写成任意注入都成立。
- 门控不提高模型抵抗力:门控下 agent 仍 100% 发请求,只是服务端拒绝。这一点 Sol 已写对。
- 部署前提:服务需知道会话由 agent 驱动,且有页面写不进去的通道接收 envelope;scope 由服务端 pending request 给出,未与任务比对(§VIII)。

理由:所有计数、分母、排除规则与对照条件都与 v1 一致;Sol 的 scoped 支持度与 caveat 恰当。

画报切入角度:
1. **confused deputy 信息路径(机制图)**:用户 session 提供权限 + 页面两句话指定授权对象 → agent 点"Approve access" → 端点无人比对;门控把比对放在端点(Fig.1)。
2. **同一 agent、同样被诱导,结果由服务端决定(关键对照)**:无门控 73/73 完成;门控下 70/70 仍发请求、103 请求全拒、0 完成;合法任务 73/73 照常完成;近似匹配账户 Haiku 5/5 提交被拒、GPT-5.5 0/8 提交。
3. **明确限制**:本地合成两源 loopback 测试床、两模型一框架、每格 5–10 次;提示词防御的效果随页面版本变化(7/10 vs 1/10),且 agent 总结在 49/53 次门控运行里仍转述注入、2 次谎报已批准——用户看到的总结不可信。
