# K04 — Predict the next GUI screen as renderable HTML code
_parent: **Learn GUI Dynamics and Train in Them** ([`learn_and_train_in_gui_world_model`](../main/learn_and_train_in_gui_world_model.md)) · status: candidate_pattern · source card: `K04-renderable-code-world-model.md` (frozen domain `cua-agents/v1`)_

## Operation
represent the next GUI state as HTML (with placeholders/SVG or diffusion-filled image slots), generate it from (screenshot, action, goal) — optionally as a delta from a retrieved HTML of a previously observed screen of the same app — and render it deterministically to a screenshot

- Transfer: Structured-state world model: code is the state representation, rendering is exact. Analogue to object-centric state in robotics world models (K35).

- Status: candidate_pattern

## When it works
- Mostly static, deterministic mobile transitions (2602.09856#s1)
- Paired screenshot->HTML corpus synthesised by a strong coder with render-and-compare filtering (2602.09856#s3)
- RL reward combines visual alignment with an action-consequence (transition validity) judge; either alone is worse, visual-only reward is reward-hacked (2602.09856#s1)
- App-specific memory of historical screens and transition index; retrieval-grounded delta generation improves consistency (73.51 vs 67.46 without RAG) (2608.05891#s1)
- Image-heavy pages benefit from diffusion-filled image slots (70.91 -> 73.51 overall) (2608.05891#s2)

## When it fails
- Cannot reproduce real assets or content dependent on hidden/server state; visual similarity drops OOD (2602.09856#s1)
- Same VLM family used as RL reward and evaluation judge may inflate gains (2602.09856#s1)
- Transitions absent from the app memory are rejected; functional-logic scores below general code/image generators (2608.05891#s1)
- Diffusion slots slightly lower functional-logic score (81.70 -> 79.69) (2608.05891#s2)
