# C12 — Normalise heterogeneous trajectories into one declared action schema for end-to-end screenshot policy SFT
_parent: **Decouple Planning from Grounding and Redesign the Action Interface** ([`planner_grounder_interface`](../main/planner_grounder_interface.md)) · status: candidate_pattern · source card: `K12-unified-action-schema-sft.md` (frozen domain `cua-agents-core/v1`, where it is K12) · domain: cua-agents-core_

## Operation

- rewrite actions from many datasets/platforms (or raw input-event logs) into a small shared schema (click(x,y), type, scroll plus prompt-declared custom actions, JSON with relative positions), and fine-tune a screenshot policy on it.
- Status: candidate_pattern (4 full-text paper(s)).
- Transfer notes: n/a

## When it works

- Unified action space (17 -> 10 types) helps zero-shot OOD transfer; OS-Atlas-7B beats GPT-4o on several OOD sets. [2410.23218#s2]
- JSON action format with per-device README and short interleaved visual history modestly improves AITW / MiniWob. [2411.17465#s2]
- Rule-based compression of raw mouse/keyboard events into pyautogui actions with backtracked keyframes makes human demos trainable. [2508.09123#s1]
- Grounding-pretrained backbone fine-tuned per benchmark beats same-data baselines on MiniWob and AITW. [2401.10935#s3]

## When it fails

- Zero-shot navigation remains weak (ShowUI AITW 35.9; OS-Atlas-4B below GPT-4o on OmniAct); offline evaluation with lenient click tolerance. [2410.23218#s2, 2411.17465#s2]
- Pixel-only coordinate agents trail HTML-based methods on Mind2Web (SeeClick 25.5 vs MindAct 52.0) and unified multi-platform training slightly hurts. [2401.10935#s3]
- Event compression may lose fine-grained actions (letter-level drag-select). [2508.09123#s1]
