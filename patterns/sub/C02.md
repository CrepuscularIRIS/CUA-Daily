# C02 — Parse raw pixels into an indexed, text-described element list (detectors, OCR, captions, region marks)
_parent: **Expose the Screen as Indexed Elements and Pruned Structure** ([`structured_screen_observation`](../main/structured_screen_observation.md)) · status: candidate_pattern · source card: `K02-pixel-parse-element-list.md` (frozen domain `cua-agents-core/v1`, where it is K02) · domain: cua-agents-core_

## Operation

- run pixel-level detectors (segmenter, interactable-region detector, OCR, icon detector) and optionally a captioner on the screenshot, assign ids/marks to the resulting regions with functional text descriptions, and let the MLLM select an id or coordinate from that list.
- Status: candidate_pattern (5 full-text paper(s)).
- Transfer notes: Origin is natural-image SoM; transfer to GUIs holds when the detector is trained on UI-style interactable elements and the policy reads numeric marks; breaks on dense small elements and duplicate icons.

## When it works

- A frontier MLLM that can read and 'speak' marks gains large grounding accuracy over raw coordinate prediction (GPT-4V RefCOCOg 86.4 vs 25.7). [2310.11441#s1]
- A detector fine-tuned on DOM-derived interactable boxes beats generic Grounding DINO (ScreenSpot 68.7 -> 73.0; Mind2Web LS+ID > LS+GD in all splits). [2408.00203#s1]
- Offloading icon recognition to captions helps most on dense screens (SeeAssign >40 boxes 0.620 -> 0.900); captions into a11y tree help text-only GPT-4 on VWA (7.25% -> 12.75%). [2408.00203#s2, 2401.13649#s2]
- Works without any XML/a11y access when pixel perception (OCR + icon detection + captions) feeds coordinates to a strong decision MLLM (Mobile-Agent-v2 GPT-4V 92.7/83.5 single-step SR). [2406.01014#s4]
- Fusing UIA elements with pixel detectors raised GPT-4V-1106 WindowsAgentArena SR 12.5% -> 19.5% with OmniParser. [2409.08264#s2]

## When it fails

- Accuracy is capped by proposal quality: missed regions are unrecoverable (GT masks raise mIoU 75.6 -> 90.1). [2310.11441#s1]
- Coarse OCR boxes and repeated identical icons/text make centre-click or id choice land on the wrong element; context-free icon captions misread page-dependent icons. [2408.00203#s1, 2408.00203#s2]
- Captions miss fine-grained content (OCR, logos); weak LLMs gain nothing from captions. [2401.13649#s2]
- Mark placement heuristics can attach marks to the wrong object; dense small UI elements not evaluated for the original SoM. [2310.11441#s2]
- Parser inference cost dominates run time (OmniParser runs 37.8-82.2 min vs 6.5-21.4 min) and imprecise SoM boxes cause wrong element selection. [2409.08264#s2, 2409.08264#s1]

## Counterexamples

- Adding UIA to OmniParser lowered GPT-4o (9.4% -> 8.6%) and GPT-4o-mini (7.2% -> 2.6%) WindowsAgentArena success, so fusion benefit is model-dependent. [2409.08264#s2]
- Weaker open LMMs (LLaVA-1.5, MiniGPT-v2) can hardly interpret marks. [2310.11441#s1]
- A white-box captioner in the observation pipeline becomes an attack channel (92% of attacked captions carry adversarial text). [2406.12814#s3]
