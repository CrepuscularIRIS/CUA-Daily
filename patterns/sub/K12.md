# K12 — Score episodes with execution-based checkers that read privileged environment state
_parent: **Ground Reward in Executable Checkers** ([`verifiable_execution_reward`](../main/verifiable_execution_reward.md)) · status: candidate_pattern · source card: `K12-privileged-state-execution-checker.md` (frozen domain `cua-agents/v1`)_

## Operation
after the episode, read environment internals the agent cannot see (files, configs, backend/localStorage fields, instrumentation flags, logs) and compare them to goal conditions or gold artefacts to produce a binary or partial-credit reward

- Transfer: Software-testing analogue: test oracles. See K34 for the two-sided validity check (legal alternatives must not be rejected).

- Status: candidate_pattern

## When it works
- Environment internals are accessible (open-source apps, generated code, instrumented simulators) (2404.07972#s1, 2601.04126#s2, 2609.07712#s2)
- Outcome-only checking accepts alternative correct paths (2404.07972#s1, 2609.07712#s2)
- Instrumented checkpoints give dense partial credit: 767 vs 174 discriminative GRPO groups (4.4x) (2601.04126#s2)

## When it fails
- Checkers are per-task manual work (~2 man-hours each) and do not exist for unannotated tasks (2404.07972#s1)
- Residual false positives/negatives unquantified; checkpoint weights LLM-chosen and unvalidated (2404.07972#s1, 2601.04126#s2)
- Screenshots alone cannot see some state (e.g. file size), so screenshot judges and scripts are complementary (2404.07972#s1)

## Counterexamples
- none found in the readings
