# K16 — Judge trajectory success with a passive LLM/VLM outcome reward model
_parent: **Reward with Learned Outcome and Process Judges** ([`learned_outcome_and_process_judges`](../main/learned_outcome_and_process_judges.md)) · status: candidate_pattern · source card: `K16-passive-outcome-judge.md` (frozen domain `cua-agents/v1`)_

## Operation
give an LLM/VLM the task plus final screenshot/HTML, selected key screenshots, or the action history, and have it output a binary or graded success label used as reward, filter or SFT weight

- Transfer: See K17/K18 for reliability-oriented variants (abstention, active probing).

- Status: candidate_pattern

## When it works
- Completion visible in a single screenshot or final-state HTML; narrow task phrasing (2406.11896#s2, 2411.02337#s2)
- Key-point extraction plus key-screenshot selection keeps agreement over long trajectories (~85-87% with humans) (2504.01382#s1)
- Graded scores used as sampling weights rather than hard filters (2412.19723#s2)
- Zero-mean reward noise only adds variance, which more rollouts remove (2605.06732#s3)

## When it fails
- ~13-20% disagreement with humans; free-form tasks lower precision (2411.02337#s2, 2504.01382#s1, 2406.11896#s2)
- Visual reasoning dominates judge quality; GUI-specialised RMs no better than base VLMs; reasoning and visual errors dominate (2510.18596#s2)
- Systematic judge bias is not removed by more rollouts (2605.06732#s3)
- Judges see only partial state (last screenshots), so mid-trajectory or hidden-state errors are missed (2412.19723#s2, 2510.18596#s2)
- Policy exploitation of judge errors not analysed (2406.11896#s2, 2411.02337#s2)

## Counterexamples
- none found in the readings
