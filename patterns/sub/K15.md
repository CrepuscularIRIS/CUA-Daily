# K15 — Propose new tasks conditioned on the agent's history, failures or coverage
_parent: **Synthesise Tasks from Exploration and History** ([`exploration_driven_task_synthesis`](../main/exploration_driven_task_synthesis.md)) · status: candidate_pattern · source card: `K15-history-conditioned-task-proposal.md` (frozen domain `cua-agents/v1`)_

## Operation
generate the next tasks/intents from stored history — failed instructions, coverage of activities/functionalities, clusters of the UI transition graph, or searched new sites — filter by feasibility/difficulty, and execute them

- Transfer: GUI-testing analogue: coverage-guided test generation. In agents it doubles as curriculum generation.

- Status: candidate_pattern

## When it works
- Coverage/feasibility signals available (activity lists, critic value band [0.05, 0.75], feasibility rules) (2311.08649#s1, 2411.02337#s1)
- History presented per cluster rather than whole graph or recent states only (coverage 36.94 vs 26.09/31.51) (2609.10031#s1)
- Self-evolving curriculum from failures improves online RL and transfers to DigiRL (2411.02337#s1)

## When it fails
- Widgets without text and single views with sub-regions are poorly explored (2311.08649#s1)
- Task generation randomness raises variance; feasibility rules hand-written per environment (2411.02337#s1)
- Judge precision for kept trajectories not measured; self-reinforcing loops may overfit easy/popular sites (2510.09038#s2)
- Residual duplicate intents and occasional intents for non-existent functionality (2609.10031#s1)

## Counterexamples
- none found in the readings
