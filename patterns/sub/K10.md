# K10 — Build a task-scoped digital twin of the specific target environment
_parent: **Calibrate a Simulator or Digital Twin to the Real Target** ([`calibrate_simulator_to_real`](../main/calibrate_simulator_to_real.md)) · status: candidate_pattern · source card: `K10-task-scoped-digital-twin.md` (frozen domain `cua-agents/v1`)_

## Operation
reconstruct (scan, re-implement, or synchronise) the specific deployment environment as a resettable simulator restricted to the task-relevant subset, and use it for training/evaluation in place of the real environment

- Transfer: APPSim-Bench is the GUI instance; robotics twins add continuous synchronisation (Real-is-Sim) that GUI twins do not yet have.

- Status: candidate_pattern

## When it works
- Tasks touch only a task-relevant subset of functionality; pruned regions rendered as explicit placeholders (2609.07712#s1)
- Twin of the exact target scene beats generic assets (90% vs 10% real success) (2403.03949#s1)
- Offline twin evaluation preserves relative checkpoint ordering with 5-8x speedup (2504.03597#s1)
- Human-in-the-loop construction is affordable (~15 min scene; ~2.3 review rounds per page, hours per app) (2403.03949#s1, 2609.07712#s1)

## When it fails
- Fidelity bounded by the underlying simulator; dynamic content, network, personalisation, long-tail data are omitted (2609.07712#s1, 2504.03597#s1)
- Policies trained without real demos exploit twin inaccuracies (2403.03949#s1)
- Behavioural fidelity measured only indirectly (placeholder residual up to 20.6%) (2609.07712#s1)

- none found in the readings
