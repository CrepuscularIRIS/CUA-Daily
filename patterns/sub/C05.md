# C05 — Coordinate-free grounding with an attention action head over visual patches
_parent: **Localise Small Targets with Resolution, Zoom, Verification and Pointer Heads** ([`high_resolution_target_localisation`](../main/high_resolution_target_localisation.md)) · status: case · source card: `K05-patch-attention-action-head.md` (frozen domain `cua-agents-core/v1`, where it is K05) · domain: cua-agents-core_

## Operation

- replace numeric coordinate tokens with a special <ACTOR> token whose hidden state is matched against contextualised patch features to give an attention map over patches, trained with KL to a box-rasterised patch mask; click at the selected patch.
- Status: case (1 full-text paper(s)).
- Transfer notes: Analogue of pointer/action heads in robotics VLAs; holds for single-point click targets, does not cover typing or drags.

## When it works

- Outperforms same-data coordinate generation on high-resolution grounding (ScreenSpot-Pro 40.7 vs 15.6 Aguvis-7B point supervision). [2506.03143#s1]
- Box-mask supervision tolerates spatial ambiguity, whereas giving a coordinate model bbox targets does not help. [2506.03143#s2]
- Training only the head on a frozen backbone already recovers much grounding (ScreenSpot-Pro 1.6 -> 22.9), suggesting backbones perceive UI elements and coordinate SFT mostly learns the mapping. [2506.03143#s4]

## When it fails

- Elements smaller than one patch are under-represented (CAD-like precision tasks); icon accuracy on ScreenSpot-Pro stays low (16.4). [2506.03143#s1, 2506.03143#s2]
- Frozen-backbone LiteTrain without verifier stays well below full fine-tuning (22.9 vs 40.7). [2506.03143#s4]
- Only click grounding evaluated; agent use requires a separate planner. [2506.03143#s1]

## Counterexamples

- UI-TARS-7B still beats GUI-Actor-7B without verifier on ScreenSpot (89.5 vs 88.3). [2506.03143#s1]
