# C11 — Mix GUI actions with code / shell / SDK calls in one action space
_parent: **Decouple Planning from Grounding and Redesign the Action Interface** ([`planner_grounder_interface`](../main/planner_grounder_interface.md)) · status: candidate_pattern · source card: `K11-hybrid-gui-code-actions.md` (frozen domain `cua-agents-core/v1`, where it is K11) · domain: cua-agents-core_

## Operation

- let the policy (or an orchestrator choosing between a GUI operator and a programmer) invoke scripts, terminal commands or tool/SDK functions alongside clicks and typing, with a shared file system.
- Status: candidate_pattern (3 full-text paper(s)).
- Transfer notes: Requires that the environment exposes a shell/interpreter with user credentials; widens the attack surface (code execution goals in injection benchmarks).

## When it works

- Hybrid beats GUI-only and code-only on OSWorld-Verified (60.76% vs 50.68% / 35.73%) with fewer steps per passed task. [2508.03923#s1]
- SDK access greatly lifts information-seeking tasks (BrowseComp-en 7.0 -> 29.6) and enables terminal / SWE tasks. [2509.02544#s1]
- Scriptable apps (openpyxl, AppleScript) can be controlled via generated code tools. [2402.07456#s1]
- Joint RL over both interfaces is reported to improve pure-GUI performance despite halved GUI data. [2509.02544#s5]

## When it fails

- Code-only cannot handle apps without scripting access; OS-Copilot has no screenshot-to-action GUI control. [2402.07456#s1, 2508.03923#s1]
- Needs a strong reasoning orchestrator (o4-mini drops to 43.43%); at 15 steps the hybrid trails other agents; GUI-only beats hybrid on OS category. [2508.03923#s1]
- SDK effect on OSWorld/AndroidWorld not separated; mixed-interface gain shown only as training curves. [2509.02544#s1, 2509.02544#s5]

## Counterexamples

- None recorded.
