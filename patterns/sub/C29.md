# C29 — Render fake UI elements (pop-ups, cookie banners) that direct the agent's click
_parent: **Hijack Agents Through the Environment and Measure Attempt vs Completion** ([`environmental_injection_attacks`](../main/environmental_injection_attacks.md)) · status: candidate_pattern · source card: `K29-fake-ui-element-attack.md` (frozen domain `cua-agents-core/v1`, where it is K29) · domain: cua-agents-core_

## Operation

- draw attacker-controlled UI on screen (pop-up with attention hook, click instruction and OK banner; fake cookie popup in ad banners) so the agent or its quarantined perception returns the attacker's element.
- Status: candidate_pattern (2 full-text paper(s)).
- Transfer notes: n/a

## When it works

- Pop-ups hijack prompted VLM agents at 62-100% step ASR; a hook guessed from the screen still works (avg 33.3%). [2411.02391#s1, 2411.02391#s2]
- Fake cookie popups steer a CaMeL-style fixed plan down an attacker-preferred branch, evading verifiers in the HTML5 case. [2601.09923#s3]

## When it fails

- Fails when the agent ends from history, the answer is already on the page, or more confident actionable elements exist; delayed attacks are weaker. [2411.02391#s1]
- Cookie attack fails when the plan queries restricted element types against static ads. [2601.09923#s3]

## Counterexamples

- None recorded.
