# C01 — Element-id actions over interactive elements enumerated from DOM / a11y / view hierarchy / UIA
_parent: **Expose the Screen as Indexed Elements and Pruned Structure** ([`structured_screen_observation`](../main/structured_screen_observation.md)) · status: candidate_pattern · source card: `K01-structural-element-marks.md` (frozen domain `cua-agents-core/v1`, where it is K01) · domain: cua-agents-core_

## Operation

- enumerate interactive elements from a structural view (DOM, accessibility tree, Android XML, Windows UI Automation), give each a unique id (text list and/or numbered marks drawn on the screenshot), and restrict the policy to id-indexed actions executed on the element object or its centre.
- Status: candidate_pattern (7 full-text paper(s)).
- Transfer notes: Requires a platform API that enumerates interactive elements with geometry; fails to transfer to canvas/game UIs or apps without accessibility support.

## When it works

- Works when the app/page exposes its interactive elements structurally (XML view hierarchy, DOM element types, UIA controls); switching GPT-4 from a raw action API to element-indexed actions raised AppAgent SR 2.2% -> 48.9%. [2312.13771#s1, 2402.07939#s2, 2401.13919#s1]
- Marked screenshots help a frontier MLLM on visually complex pages: WebVoyager 59.1% vs 40.1% with a11y tree only, largest on Booking / Google Flights; VWA GPT-4V 15.05% -> 16.37% with SoM. [2401.13919#s1, 2401.13649#s1]
- Element ids turn grounding into n-way classification and allow modality-agnostic comparison in the environment interface. [2307.13854#s2]
- Supplementing a11y marks with an OCR + MLLM text locator lets the agent target document text the a11y tree does not expose (PC-Agent: removing APM drops instruction SR 56% -> 20%). [2502.14282#s1]

## When it fails

- Elements missing from the structural view (canvas content, controls unsupported by UIA, e.g. Adobe Acrobat at 60% success) are not addressable. [2402.07939#s2, 2312.13771#s1, 2502.14282#s1]
- Only strong VLMs read marks: SoM did not help IDEFICS-80B, CogVLM or Gemini-Pro on VWA. [2401.13649#s1]
- Dense text-heavy pages: marking DOM candidates on the screenshot hallucinates / mislinks labels (SeeAct step SR 20.3 vs 39.1 for textual choices); WebVoyager attributes 24.8% of failures to visual grounding errors (adjacent elements, calendar numbers mistaken for marks) and text-heavy sites show no gain. [2401.01614#s2, 2401.13919#s1]
- Label-indexed action spaces exclude drag and continuous actions, and wrong-box typing raises no execution error. [2401.13919#s2, 2312.13771#s1]

## Counterexamples

- On OSWorld a screenshot GPT-4o agent with SoM scored 4.59 vs 5.03 without it. [2410.23218#s3]
- In AndroidWorld M3A, SoM screenshot input lowered SR (25.4% vs 30.6% a11y text) while helping on MobileMiniWoB++ WebView tasks. [2405.14573#s2]
- Element-id actions follow a swapped structural label 0.64 of the time vs 0.11 for coordinate actions, i.e. binding actions to structure inherits structure errors. [2607.04334#s3]
