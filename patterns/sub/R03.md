# R03 — Mine operational knowledge and trajectories from human screen-recording videos
_parent: **Mine Human Screen Recordings into Action Knowledge** ([`mine_human_screen_videos`](../main/mine_human_screen_videos.md)) · status: candidate_pattern · domain: board-induced (2026-10-19), from wave-1 weak fits_

## Operation
collect human screen recordings (instructional/tutorial videos found via web how-to posts, or a single recorded demonstration), cut them into key frames (similarity/OCR-text change or second-order pixel change), localise UI elements and cursor (detector + OCR, set-of-marks), and either (a) have a strong VLM infer the action between consecutive key frames — using narration and neighbouring frames — to build (screen, action) trajectories for pretraining/SFT, or (b) feed a sliding window of demo key frames into the acting agent's context as operational knowledge, with a reflection agent checking each action against the demo

- Transfer: learning-from-observation / video pretraining (inverse dynamics labelling of unlabelled video) moved to GUIs, where text changes on screen make scene cuts and actions easier to recover than in natural video.

- Status: candidate_pattern (4 member records; 2505.13887 is an abstract-only duplicate of 2502.17110)

## When it works
- The extraction pipeline is validated against human annotation of held-out videos: OCR-based scene detection F1 95.04 vs 82.27 / 70.86 for visual baselines, UI-element hit ratio 99.87 vs 91.83 for OmniParser, action identification 80.90% overall / 91.84% touch, at $0.34 vs $5.76 per video for expert annotation (2505.12632#board)
- Mined cross-platform data is used as pretraining and tested on an unseen platform: on Windows Mobile, SeeClick 38.54 -> 51.71 and Llama-3.2 26.83 -> 50.24 (AitW-finetuned) (2505.12632#board)
- Narration and temporal context are given to the labeller and ablated: overall action accuracy 80.90 vs 78.20 without narration, 77.22 with a single-image first step, 70.63 with one-step identification (2505.12632#board)
- A recorded demo replaces hand-written knowledge at lower authoring cost: SR 86.7 vs 63.3 for the best agent with manually written knowledge, near expert-written knowledge (90.0) at 0.7 vs 5 minutes of authoring; 31.3 vs 18.9 on AndroidWorld tasks given only the simplest task's video (2502.17110#board)
- Key frames and cursor/OCR text are compressed into a textual schema for the model: BLEU-2 0.135 -> 0.190 over plain fine-tuning (LLaVA-13B) for current-action description (2503.20978#board)

## When it fails
- The demo matches the test task: 30 author-crafted tasks each come with their own video; when the video's actions differ from the task, SR and decision accuracy drop on normal and advanced instructions (2502.17110#board)
- Action labels are inferred by a proprietary VLM and stay noisy (80.90% overall action accuracy); heavy filtering keeps 20K of 129K videos (no hand occlusion, phone OS only) (2505.12632#board)
- Evidence is offline: exact action matching on static test sets, or captioning metrics for action description on one application's tutorials, with no acting agent evaluated (2505.12632#board, 2503.20978#board)
- Key-frame sampling can drop essential frames and larger windows add irrelevant ones, so performance declines beyond a window size; the decision agent skips steps in long multi-frame input without a reflection pass (2502.17110#board)

## Counterexamples
- Where human-authored artefacts can be replayed by a scripted bot, actions are logged rather than inferred from pixels, but the synthetic videos lack natural variability and a behaviour-cloned policy still reaches only 41.0% Chamfer success vs 88.2% for human experts (2505.24838#board)
