# K22 — Split each step into a language planner and a specialised visual grounder
_parent: **Decouple Planning from Grounding and Redesign the Action Interface** ([`planner_grounder_interface`](../main/planner_grounder_interface.md)) · status: candidate_pattern · source card: `K22-planner-grounder-split.md` (frozen domain `cua-agents/v1`)_

## Operation
a general (M)LLM planner emits the next action and a natural-language description of its target; a separate pure-vision grounding model maps the description to pixel coordinates on the raw screenshot

- Transfer: Hierarchical controller analogue (high-level policy + low-level skill).

- Status: candidate_pattern

## When it works
- Planner strong at reasoning but weak at pixel grounding (o3 23.0 -> 51.0, GPT-4o 5.0 -> 27.0 on OSWorld with Jedi) (2505.13227#s2)
- Grounder trained at dynamic high resolution on screenshot-only inputs (2410.05243#s2, 2412.04454#s3)

## When it fails
- Planning errors (wrong/vague element descriptions) dominate failures; planner errors propagate through the NL interface (2410.05243#s2, 2505.13227#s2)
- End-to-end single model is weaker than with a strong external planner (2412.04454#s3)
- Idiosyncratic icons cause grounding errors on mobile/desktop (2410.05243#s2)

## Counterexamples
- none found in the readings
