# C10 — Split a generalist planner that describes the target from a specialist grounder that localises it
_parent: **Decouple Planning from Grounding and Redesign the Action Interface** ([`planner_grounder_interface`](../main/planner_grounder_interface.md)) · status: candidate_pattern · source card: `K10-planner-grounder-split.md` (frozen domain `cua-agents-core/v1`, where it is K10) · domain: cua-agents-core_

## Operation

- have a (prompted) MLLM plan and emit a natural-language target description or semantic argument, then dispatch localisation to a separate grounder (UI grounding VLM, OCR span locator, CLIP icon matcher, app API) that returns coordinates.
- Status: candidate_pattern (3 full-text paper(s)).
- Transfer notes: n/a

## When it works

- Replacing GPT-4o's own coordinates with a grounding model's triples OSWorld SR (5.03 -> 14.63 with OS-Atlas-7B). [2410.23218#s3]
- Routing to visual / textual / structural experts raises OSWorld subset success (27.69 -> 30.77 at 15 steps); composition beats monolithic native agents on OSWorld, WAA and AndroidWorld. [2504.00906#s1, 2504.00906#s3]
- Semantic target naming plus OCR/icon detection enables screenshot-only mobile operation without XML. [2401.16158#s1]

## When it fails

- Residual failures are dominated by planning in spreadsheet and multi-app tasks (Calc, Workflow, Office remain low). [2410.23218#s3, 2504.00906#s3]
- Grounding errors persist; structural expert needs an app API; ablation on a 65-task subset. [2504.00906#s1]
- OCR misses when the planner hallucinates target text; similar icons with only a coarse position hint. [2401.16158#s1]

## Counterexamples

- Agent states the right target in text but picks the wrong SoM id (visual-language misalignment) when the same model both plans and grounds. [2409.08264#s3]
