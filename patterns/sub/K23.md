# K23 — Synthesise grounding data from rendered UI structure
_parent: **Decouple Planning from Grounding and Redesign the Action Interface** ([`planner_grounder_interface`](../main/planner_grounder_interface.md)) · status: candidate_pattern · source card: `K23-synthetic-grounding-from-rendered-structure.md` (frozen domain `cua-agents/v1`)_

## Operation
render web pages, UI-component code or parsed screens, read exact element boxes/attributes from the DOM/element tree, synthesise referring expressions (attributes, MLLM descriptions, positional/contextual phrases) and actions in a unified cross-platform action space, and train a coordinate grounder

- Status: candidate_pattern

## When it works
- GUI visual conventions shared across platforms: web-only data transfers to desktop/mobile (2410.05243#s1)
- Mixed data types and multiple levels (icon/component/layout) scale without saturation (2505.13227#s1)
- Unified pyautogui action space and packing multiple pairs per screenshot (2412.04454#s1)
- Knowledge-free refined instructions show small models suffice for pure localisation (2505.13227#s3)

## When it fails
- Diminishing returns after ~100K screenshots; long-tail icons (2410.05243#s1)
- Models rarely refuse; ambiguous instructions cause ~40% of errors (2505.13227#s1, 2412.04454#s1)
- ScreenSpot v1/v2 saturate; offline-online gap (2501.12326#s3)

## Counterexamples
- none found in the readings
