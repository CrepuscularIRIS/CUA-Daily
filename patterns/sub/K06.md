# K06 — Pretrain the policy backbone on transition-understanding objectives
_parent: **Learn GUI Dynamics and Train in Them** ([`learn_and_train_in_gui_world_model`](../main/learn_and_train_in_gui_world_model.md)) · status: candidate_pattern · source card: `K06-transition-objective-pretraining.md` (frozen domain `cua-agents/v1`)_

## Operation
before agent fine-tuning, train the VLM policy on self-supervised tasks over (s_t, a_t, s_t+1) triples: forward next-state description, action verification, action reversal, or mistake-informed re-grounding

- Transfer: Analogue of world-model representation learning as an auxiliary loss in RL; the world model is internal to the policy, not a separate simulator.

- Status: candidate_pattern

## When it works
- Forward-dynamics objective beats inverse/backward variants under identical SFT (EM 53.9/54.4 vs 51.0 baseline) (2604.02345#s3)
- Same post-training data for both arms; in-domain evaluation on the exploration ecosystem (2604.02345#s2)
- Regular GUI pretraining erodes verification/reversal ability; explicit auxiliary tasks restore it (87.56 verification, 93.81 reversal) (2506.08012#s3)

## When it fails
- Inverse-dynamics variants can fall below baseline (sparse output tokens, fast saturation — author interpretation) (2604.02345#s3)
- On OOD AndroidControl transitions the dynamics-pretrained 7B stays below a larger base model (2604.02345#s3)
- Downstream task-success effect of auxiliary reflection tasks not separately ablated (2506.08012#s3)
- Online evaluation is a single 149-task in-house benchmark without seeds (2604.02345#s2)

## Counterexamples
- none found in the readings
