# K13 — Synthesise tasks from checkers/specs so verifiable reward exists by construction
_parent: **Ground Reward in Executable Checkers** ([`verifiable_execution_reward`](../main/verifiable_execution_reward.md)) · status: candidate_pattern · source card: `K13-checker-first-task-synthesis.md` (frozen domain `cua-agents/v1`)_

## Operation
start from a verification condition (composed evaluator functions, or tests derived from a shared spec) and generate the task (and, for generated sites, the implementation) that satisfies it, so every synthetic task ships with a programmatic reward

- Transfer: Inverts the usual order (task then checker). Related to K12 (consumes privileged checkers).

- Status: candidate_pattern

## When it works
- An evaluator library or generated environment code exists for the target environment (2510.17790#s2, 2601.04126#s1)
- Test-driven repair loop until task-relevant tests pass (removing it: 85.6 -> 82.6) (2601.04126#s1)
- Difficulty-band filtering of tasks before RL (2510.17790#s2)

## When it fails
- Evaluator-first tasks are harder and fewer; RL gain ~2 points (2510.17790#s2)
- Generated sites have no real server logic; single-site, single-user scope (2601.04126#s1)
- Overlap with test distribution not analysed (2510.17790#s2)

## Counterexamples
- none found in the readings
